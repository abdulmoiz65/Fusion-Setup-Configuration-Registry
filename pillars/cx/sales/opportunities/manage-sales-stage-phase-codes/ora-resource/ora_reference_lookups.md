## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Parent/code GET returns 401/403 or fails | Stop after at most the owning client's one permitted cache-token refresh; never report absence or switch lookup view |
| Completed export omits seeded rows | Validate baseline shape and apply standard-parent support recovery with fresh live state; no fallback from emptiness alone |
| CSV exhausted with a valid receipt | Return fallback_required to the router; restart fresh resolution as REST_FALLBACK before dedicated eligibility and separate preview approval |
| Prior jobs pending, uncertain, partially applied or incompletely diagnosed | Block fallback; reconcile through the later explicit Core Data Loader results workflow |
| All intended values already applied and jobs terminal | Return verified result without another write |
