# Manage Set Enabled Lookups Reference Lookups

## FSM Task Identity Policy

Require exact task code/name, selected task `SKILL.md`, target environment, and
immutable archive SHA-256 throughout review, export, package preparation, and
validation.

- Review, export, and package preparation do not require Data Loader task context.
- Every Core Data Loader mutation handoff requires a persisted project
  `TaskContextPath`, exact `TaskName`, and positive `TaskSequence`.
- The selected context entry must resolve to this task's exact skill path,
  `TaskCode`, `TaskName`, offering, and functional area.

The persisted context may come from a project setup-task plan without creating
an Oracle Run Book. Never hand-author, infer, or synthesize it solely to satisfy
Data Loader.

Use these read-only Apps Common lookups to resolve each exact lookup parent,
its returned reference group, every affected set, and current lookup-code
state. Lookup resolution never authorizes a mutation.

For every set-scoped request, require `SetSelectionDecision` before resolving
a set. Ask whether Common Set should be used or a different set should be
specified. Resolve a confirmed Common Set from its actual `SetCode`/`SetId`;
never infer Common Set or hard-code its numeric identifier.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A parent can't be resolved exactly or returns blank ReferenceGroupName | Stop before set or assignment resolution; never assume the reference group from LookupType |
| Package Export has no set or row scope | Resolve both owned parents, then skip set and code resolution and continue to export readiness without inventing a selector |
| A set can't be resolved exactly | Stop before reading codes or creating a preview |
| SetId is not an integer, SetCode is blank, or the exact selected-environment set does not exist | Return missing or failed identity evidence and stop; do not substitute Common Set, another environment's set, or a close match. A live-resolved zero is valid; never infer its set identity |
| SetId and SetCode resolve to different sets, confirmed Common Set resolves to a non-Common set, or the resolved set conflicts with the requested BU/organization assignment or package row | Stop as a set-scope conflict, disclose the sanitized returned identities, and require one corrected explicit set decision |
| A requested business-unit assignment is absent or its ReferenceGroupName doesn't equal the parent-returned value | Return the owning record-set prerequisite task and do not change the assignment here |
| Inventory returns zero or more codes for one resolved set | Return the sanitized collection without mutation |
| A single-code or package-row lookup returns one exact item | Preserve its current state, read timestamp, and returned child identifier or link as state-lock evidence |
| No exact code is found | Continue only for a Create state lock; Read, Update, Disable, and Delete remain blocked |
| A package includes several rows or both owned types | Resolve every unique parent, then every row's set and code independently; one invalid row blocks the complete package |
| A collection reports hasMore=true | Continue with the next offset; never report absence or a complete inventory until hasMore=false |
| Fusion returns 401 or 403 | Stop as authentication or privilege failure; do not treat the parent, set, assignment, or code as absent |
| A mutation is requested through a reference lookup | Refuse; pass only validated identity and current state to dependency readiness and the route-specific execution gate |

## Omitted Parent and Final Fallback Rules

| Situation | What Happens |
|---|---|
| Completed exact-task export is header-only or omits owned seeded types while retaining other data | Validate process/metadata/member/header evidence and apply the task recovery procedure; omission is not live absence or fallback eligibility |
| Changed child has no matching unchanged in-package parent | Block handoff; retain or add exactly one fresh live support parent per affected owned type and validate FND_APP_SET_ENABLED_LOOKUP.LookupType plus the exact resolved SetCode |
| Exact-task CSV recovery is exhausted for Create, Update, or Disable | Return fallback_required only with the same-target classified failure/recovery receipt and complete prior-submission reconciliation; router resumes unchanged intent once with fresh reads |
| REST_FALLBACK selected | Return fallback_candidate then verify_set_lookup_rest_fallback; no native ZIP/context or borrowed approval is required |
| All requested values already applied | Return verified result without another write; partial or uncertain results block switching |
