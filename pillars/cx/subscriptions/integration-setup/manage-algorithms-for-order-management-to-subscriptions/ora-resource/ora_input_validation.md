# Input Validation

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|

| FOM-to-OSS Algorithm_BO XML identity | A parseable AlgorithmSetupVO with Name equal to Subscription Management and Order Management Integration | Stop algorithm logic inspection, draft preparation, or artifact creation | Request the correct Algorithm_BO.xml export | The request needs existing algorithm logic inspection, a draft, or an artifact |  |
| Active version | The highest numeric nonprotected VersionNum with ActiveFlag equal to Y, when present | Create the next unused nonprotected numeric VersionNum with ActiveFlag Y | User may ensure an active Algorithm version exists; do not use P as a generated target state | A reviewable draft or local Algorithm_BO.xml artifact will be created |  |

A direct target-to-source relation is supplementary evidence only | Stop draft preparation | Supply the missing outcome or mapping assessment; state null, blank, and overwrite behavior in the draft | A reviewable draft or local artifact is requested |  |
| Conditional-value Algorithm contract | Confirmed primary and fallback aliases, compatible types, explicit primary absence test, target overwrite behavior, and deterministic source cardinalities or selection rules | Stop implementation-ready drafting and artifact preparation | Obtain the exact contracts from the companion assessment. | Mapping assessment | Validated service_mapping_assessment with context, source and target evidence, permissions, direct-assignment evidence, metadata status, mapping_status, algorithm_recommendation, assumptions, and prerequisites | Stop the algorithm recommendation or change request | Obtain a validated assessment from the companion Service Mapping task | Every FOM-to-OSS algorithm recommendation or change request |  |

## Dependency-Aware Validation

| Applies When | Result | Next Action | Resolver |
|---|---|---|---|
| A Service Mapping XML is supplied | Valid only when the root transformContext contextName is OMIntegration | Stop before using XML entities, attributes, mappings, or transformations as algorithm evidence |  |
| An Algorithm_BO.xml is needed or supplied | Valid only when its AlgorithmSetupVO Name is Subscription Management and Order Management Integration | Stop before reviewing or changing algorithm content |  |
| A reviewable draft or artifact is requested | Update the latest nonprotected active version. If none exists, create the next unused numeric version with ActiveFlag Y | Preserve nonselected versions and never generate P state |  |
| An algorithm recommendation or change is requested | Valid only when the companion assessment is complete, validated, and matches the requested OMIntegration outcome | Resolve the mapping assessment dependency before deciding whether an algorithm is needed | resolve_service_mapping_assessment |
| The assessment has a mapping gap and a provisional draft is requested | A complete exact UI plan is required for an approval-ready provisional draft. If the user explicitly requests code without that plan, a placeholder-only provisional source draft is permitted | Label every unknown entity, attribute, provider, permission, and action-layout assumption with literal `<PLACEHOLDER>` syntax; do not claim that the Service Mapping is resolved or permit artifact generation | resolve_service_mapping_assessment |
| A provisional artifact is requested | Valid only after the exact provisional draft is approved and the user separately answers yes after the warning is displayed | Show the warning and ask whether to continue; do not treat draft approval as continuation |  |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Service Mapping XML contextName | Accept only OMIntegration | Every supplied Service Mapping XML |  |
| Algorithm identity | Accept only Subscription Management and Order Management Integration | Every supplied Algorithm_BO.xml |  |
| Algorithm version selection | Select the latest nonprotected active version and edit it in place; if none exists, create the next unused numeric version with ActiveFlag Y | A reviewable draft or local artifact is requested |  |
| Historical action versions | Treat P and N versions as structural reference evidence only; never copy their business content, aliases, action text, IDs, or version values into a new change | Every supplied Algorithm_BO.xml |  |
| Protected algorithm versions | Treat Versions 0 and 1 as immutable regardless of ActiveFlag or position in the export | Every supplied Algorithm_BO.xml |  |
| Interface-table correlation | Accept a cross-entity Algorithm proposal only when the assessment identifies the evidenced interface entity, bridge keys, and intended cardinality. Do not infer SDO collection names, lookup methods, or arbitrary duplicate handling from the Service Mapping XML | Every cross-entity Algorithm draft or artifact |  |
| Interface-table action selection | Preserve the delivered RUN_SCRIPT step. Prefer a separate `ConditionalAction` that starts from OSSTransactions, contains each related set with `ZeroOrOne` cardinality and an evidenced join, then applies guarded values in `onEach`. A direct product-to-fulfillment-line key is supplementary only | Every product-level Algorithm draft or artifact |  |
| Conditional-value action selection | Assign the primary value only when its exact absence predicate is false; evaluate fallback only when that predicate is true. When either source can repeat, draft only the confirmed deterministic selection rule. If neither selected value exists, leave the target unchanged. | Every primary/fallback Algorithm draft or artifact | resolve_service_mapping_assessment |
| Custom EFF action selection | Require the EFF-to-owner-to-OSSTransactions-to-target path. Prefer a `ConditionalAction` chain of OSSTransactions, Product or ProductReferenced, FullfillLines, and EFF source. If the active version has no compatible action, add a separate canonical CONDITIONAL_ACTION after the preserved RUN_SCRIPT with the next sequence number; otherwise use the existing compatible action layout | Every Custom EFF Algorithm draft or artifact |  |
| Custom-indicator target contract | Accept a custom-indicator Algorithm target only when the assessment identifies the exact source EFF, owner-key join, target alias, permissions, compatible types or approved conversion, and allowed-value behavior | Every custom-indicator Algorithm recommendation, draft, or artifact | resolve_service_mapping_assessment |
| Mapping assessment classifications | Accept only mapping_status values existing_mapping, source_target_available, mapping_gap, metadata_blocked, or incompatible and algorithm_recommendation values algorithm_not_required, algorithm_assessment_required, or service_mapping_prerequisite | Every FOM-to-OSS algorithm recommendation or change request | resolve_service_mapping_assessment |
| Provisional mapping-gap draft | A complete exact UI plan is required for an approval-ready provisional draft. A companion `service_mapping_validation_skipped=true` marker is accepted only when it records the Service Mapping task's explicit validation-skip question and affirmative user answer. On an explicit request for code, an incomplete plan permits only a placeholder-only source draft. Label it provisional and retain every unresolved source, provider, service-permission, action assumption, and skipped validation | A provisional draft is requested | resolve_service_mapping_assessment |
| Provisional continuation | Require an explicit affirmative answer after the exact warning has been displayed; approval of the exact draft is a separate decision | A provisional local artifact is requested |  |
| Algorithm draft response | Present the recommendation and reviewable source directly in chat. Use a fenced `groovy` code block for Algorithm code and state the selected version, changes, null/blank behavior, and unfulfilled prerequisites | Every Algorithm draft response |  |
| Algorithm recommendation output | Return the mapping_status, whether an algorithm is required, the rationale, exact missing prerequisites when blocked, and the selected latest active version or new active version only when a draft is possible | Every FOM-to-OSS algorithm recommendation or change request |  |
| Returned artifact scope | Accept only a well-formed Algorithm_BO.xml whose approved draft changes only the latest active version, or adds a sole new ActiveFlag Y version when none exists, retains the baseline terminal action unless its replacement was explicitly approved, and whose every nontarget source VersionSetupVORow subtree compares unchanged. For a provisional artifact, record `provisional=true` and the unfulfilled mapping prerequisite in the validation result and registry, not in the XML schema | After explicit approval and local artifact preparation |  |
