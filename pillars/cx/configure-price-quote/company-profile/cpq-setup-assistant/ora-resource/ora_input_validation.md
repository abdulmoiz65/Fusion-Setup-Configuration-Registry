# Input Validation

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Approved environment | Target Fusion environment and information needed to locate the assistant | Stop before discovery | Confirm the target and access needed to inspect the assistant state | Preflight only | resolve_cpq_setup_assistant_record |
| CPQ deployment | Unauthenticated deployment-version lookup does not return `404` | Stop before authorization validation, initialization, or any Setup Assistant call | Use `resolve_cpq_deployment` without OAuth credentials, an Authorization header, or any other authentication material | Configuration-workflow preflight | resolve_cpq_deployment |
| Pre-initialization status | One read-only CPQ Setup Assistant status result | Stop before initialization when the status is complete, processing, error, or indeterminate | Use `resolve_cpq_preinitialization_status` once after deployment validation; only `SETUP_NOT_DONE` can proceed to initialization approval | Configuration-workflow preflight | resolve_cpq_preinitialization_status |
| CPQ initialization | Separate explicit approval of the validated initialization preview at execution | Allow preapproval preparation and preview; stop before initialization and enterprise-data assessment until approval | When the pre-initialization status is `SETUP_NOT_DONE`, initialize CPQ once, then rediscover before evaluating Legal Entity, Business Unit, or other enterprise data | Setup entry | |
| Loader transport fields | Current registered business-object metadata/template for `RestAction`, `REST-Framework-Version`, and `Content-Type` | Stop before approval or upload | Reject `SAMPLE_VALUE`; omit optional transport fields unless the current registration explicitly requires a value. Do not infer loader-row values from HTTP-client defaults. | Every Data Loader source | |
| Assistant state | Discovered `Status` and `IsDataExisting` | Reject any proposed payload that includes `IsDataExisting` or includes `Status` outside the final approved payload `{ "Status": "SUBMITTED" }` | Use both fields for workflow branching; permit only the governed final `Status` to `SUBMITTED` transition after all submission prerequisites and approval pass | Every request | resolve_cpq_setup_assistant_record |
| Company profile change | Discovered Company Profile ID plus the fields changed in the selected UI-equivalent branch | Stop before preparing a CompanyProfiles Data Loader row | Map the unique CPQ Company Identifier / CPQ Company Name to `CompanyName` and Fusion Enterprise Name to `EnterpriseName`. Bind the registered Company Profile patch route with the discovered identity, exclude `IsDataExisting`, and validate only the fields applicable to the selected branch; do not require or send unchanged values. | Company-information configuration | resolve_cpq_setup_assistant_record |
| Existing company data | Discovered Company Profile ID, translated company state, CPQ company identifier, and Setup Assistant LOV data | Stop before approval or preparing a CompanyProfiles Data Loader row | For `EXISTS` and `EXISTS_WITH_BU`, show eligible Legal Entity display values upfront and require an explicit selection from that current LOV response. For `EXISTS`, also require CPQ company identifier and Business Unit; accept Business Unit only from the current LOV response. For `EXISTS_WITH_BU`, require CPQ company identifier, preserve the discovered Business Unit, and reject a Business Unit replacement. For either existing-company branch, allow currency only when present and changed, or require it when absent. | Post-discovery company-information validation | resolve_cpq_setup_assistant_record |
| New company data | Enterprise name, CPQ company identifier, Legal Address Address Line 1, country, corporate currency, and current LOV data | Stop before approval or preparing a CompanyProfiles Data Loader row | For `DOESNT_EXIST`, require enterprise name, CPQ company identifier, Address Line 1, country, and currency; reject Legal Entity or Business Unit collection. For populated configurable fields, show each current value (redacting tax registration number) and require the user to confirm retention or provide an update. Require only missing values and requested changes. Address Line 1 must contain only the single street, building, premises, or locality line; reject and recollect a complete address or a value including city, state/province, postal or PIN code, country text, or extra address lines. A retained or updated country and currency must match the current LOV response; require tax registration number when Brazil is selected. | Post-discovery new-company validation | resolve_cpq_setup_assistant_record |
| CPQ administrators | Current-user administrator decision, additional-administrator decision, requested first name, last name, email, and discovered CPQ users | Stop before CPQ-user creation or submission | On initial setup, first ask whether the current logged-in user should be an administrator and collect their details only if yes. Then ask whether to add more administrators and collect details for each if yes. Require at least one existing `CPQUsers` record or one approved, validated proposed administrator. In this Setup Assistant contract, a returned `CPQUsers` record is a CPQ administrator. For a new user, the registered create contract requires first name, last name, and valid unique email only; do not invent or collect an identifier. | Administrator provisioning | resolve_cpq_setup_assistant_record |
| Change approval | Exact validated stage preview and explicit approval at execution | Allow validation and preview with approval pending; stop before mutation | Present the exact intended company profile, user, target, and submission effect | Every mutation | |

## Collection Boundaries

| Discovered State | Collect | Do Not Collect | Collection Outcome |
|---|---|---|---|
| `DOESNT_EXIST` | Enterprise name, CPQ company identifier, Legal Address Address Line 1, country, corporate currency, and Brazil tax registration number when applicable | Legal Entity, Business Unit, complete address, city, state/province, postal or PIN code, country text, or additional address lines | Retain confirmed values or collect only missing required values and requested changes |
| `EXISTS` | CPQ company identifier, Legal Entity, Business Unit, and currency only when absent or changed | Enterprise Name changes, address, or country | Show eligible Legal Entity display values upfront; preserve discovered read-only values and collect only applicable selections |
| `EXISTS_WITH_BU` | CPQ company identifier, Legal Entity, and currency only when absent or changed | Business Unit replacement, Enterprise Name changes, address, or country | Show eligible Legal Entity display values upfront and preserve the discovered Business Unit as read-only |
| `PARTIAL` or `ESSJOBALREADYSCHEDULED` | Nothing | Any company change or administrator proposal | Stop and return the task-specific issue |

## Dependency-Aware Validation

| Applies When | Result | Next Action | Resolver |
|---|---|---|---|
| Required values are complete and the target assistant state is unambiguous | Passed | Validate direct-API readiness | resolve_cpq_setup_assistant_record |
| Values are missing, invalid, or the assistant state is ambiguous | Blocked | Correct inputs or resolve the target assistant record | resolve_cpq_setup_assistant_record |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Email is missing or is not a usable email address | Reject before mutation | Before CPQ-user creation | |
| No existing `CPQUsers` record is present and no approved CPQ administrator is proposed for the initial setup | Require at least one existing `CPQUsers` record or one validated, approved proposed administrator; stop before CPQ-user creation and submission | After the current-user and additional-administrator decisions | |
| A required field for the selected company branch is missing | Reject before approval or mutation | After discovery and collection, before CompanyProfiles Data Loader preparation | |
| CPQ company identifier / Company Name is missing, exceeds 80 UTF-16 code units, or does not match `^[A-Za-z0-9][A-Za-z0-9-]{0,79}$` for `DOESNT_EXIST`, `EXISTS`, or `EXISTS_WITH_BU` | Reject before approval or mutation. The value must start with an ASCII letter or digit and then contain only ASCII letters, digits, or hyphens; reject spaces, underscores, punctuation, and a leading hyphen. Map only a validated value to `CompanyName`. | After discovery and collection, before CompanyProfiles Data Loader preparation | |
| Address is absent while Legal Entity and Business Unit are both present | Do not reject solely for the missing address | Existing-company CompanyProfiles Data Loader preparation | |
| Address Line 1 is a complete address or includes city, state/province, postal or PIN code, country text, or additional address-line content | Reject and request Legal Address Address Line 1 alone; do not collect non-required legal-address components during this initial setup | After discovery and collection, before a new-company CompanyProfiles Data Loader preparation | |
| Country, currency, legal entity, or business unit is not present in the current Setup Assistant LOV response | Reject before mutation | Before a Company Profile PATCH that changes that field | |
| `IsDataExisting` is `PARTIAL` | Stop before collecting changes or PATCH; show: “Partial setups are completed and hence unable to proceed.” | Company-profile discovery | |
| `IsDataExisting` is `DOESNT_EXIST` after CPQ initialization and configurable Company Profile fields are populated | Inform the user of the populated values, redacting tax registration number, and require a retain-or-update decision for each before collecting missing fields or proposing a PATCH. | Post-initialization company-profile discovery | |
| `IsDataExisting` is `DOESNT_EXIST` after CPQ initialization and no configurable Company Profile fields are populated | Collect enterprise name, currency, country, Legal Address Address Line 1 only, and CPQ company identifier. Do not collect city, state/province, postal or PIN code, country text, additional address lines, Legal Entity, or Business Unit; Company Profile Setup creates the latter two. | Post-initialization company-profile discovery | |
| `IsDataExisting` is `ESSJOBALREADYSCHEDULED` | Stop before collecting changes or PATCH; show: “A Retrieve Latest LDAP Changes or Send Pending LDAP Requests job is active. You must cancel the existing jobs before continuing with Setup Assistant.” | Company-profile discovery | |
