# Specify Ledger Options Secondary-Ledger Reference Lookups

This file alone defines lookup mechanics. All live operations are read-only, exact-match, paginated through hasMore false, and failure preserving. An authorization, client, paging, or HTTP failure is never reported as value not found.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Both ID and name are supplied | Resolve both and require one object; conflicting identifiers block. |
| Exact REST filter is used | Encode documented ADF predicates without contains, fuzzy spelling, or case-folded guessing. For retained earnings, q contains only _CHART_OF_ACCOUNTS_ID equal to StructureInstanceNumber; compare dynamic segment values locally. |
| Describe-backed q attributes | Use Name or LedgerId for ledgers, StructureInstanceNumber or Name for charts, PeriodSetNameId for periods, LanguageTag, LanguageCode, or Description for languages, and _CHART_OF_ACCOUNTS_ID or _CODE_COMBINATION_ID for account combinations. Do not invent display aliases as q fields. |
| Response has more pages | limit=500 is only a page size. Advance offset until hasMore is false before evaluating exact cardinality. |
| A displayed or exported value is returned | Mark it proposed until explicit user confirmation when it is FirstLedgerPeriodName, FutureEnterablePeriodsLimit, or RetEarnCcidSegments. |
| Exactly one eligible match | Map only requested authoritative values and retain sanitized evidence. |
| Zero or many matches | Report the exact supplied raw business key, resolver, eligibility filter, and match count; ask for a supported correction. |
| 401 or 403 | Refresh an existing cached OAuth token once when allowed, retry the identical GET once, then stop as auth or authz. |
| Timeout, 429, or 5xx GET | Use bounded backoff only for the idempotent read; stop after the bound. |
| Other HTTP, paging, parsing, serialization, or client error | Preserve the exact failure class and sanitized response context; never say the business value is missing. |
| HTTP 400 or Oracle 29140 | Persist the sanitized q and response and classify a resolver-contract failure. Do not retry the identical invalid attribute or malformed expression and do not reinterpret it as zero matches. |
| Accounting method is omitted or Standard Accrual is supplied | Keep STANDARD_ACCRUAL and S without asking for method code/type; when carrier language is blank, apply the controlled English default and resolve its authoritative code without a user language question. |
| Retained-earnings lookup source | Do not trigger GL_MANAGE_CHART_OF_ACCOUNTS_VALUE_SETS or any other export. Reuse the already-resolved secondary COA segment order and physical-column mapping, then query accountCombinationsLOV directly. |
| accountCombinationsLOV fixed fields | Treat _CODE_COMBINATION_ID as the CCID and _CHART_OF_ACCOUNTS_ID as the COA structure number. The fixed schema exposes EnabledFlag, StartDateActive, EndDateActive, AccountType, DetailPostingAllowedFlag, SummaryFlag, FinancialCategory, JgzzReconFlag, DetailBudgetingAllowedFlag, Reference3, Reference4, and Reference5. It does not expose ConcatenatedSegments, BalanceEnabledFlag, or fixed SEGMENT1 through SEGMENT30 fields. Omit fields from the GET so dynamic values remain present. |
| Dynamic segment mapping | Dynamic attribute spelling varies by chart of accounts. Map against exported SegmentCode, Name, and ColumnName using the resolver's unique precedence algorithm; never hardcode a tenant segment key, assume SEGMENT1 is Company, or rely on response-key order. |
| accountCombinationsLOV returns zero exact retained-earnings rows | Pause Specify Ledger Options and route GL_MANAGE_ACCOUNT_COMBINATIONS in Financial Reporting Structures through Import Account Combinations FBDI owned by core.data-loader. Supply exact StructureInstanceCode and SEGMENT1 through SEGMENTn values, create an immutable preview, and use that workflow's approval gate. After terminal success, rerun the identical LOV lookup; never synthesize a CCID or continue from only the import process result. |
| Another accounting method is supplied | Preserve its exact display name only for the handoff, keep Standard Accrual in the FSCR package, and require re-export verification after the manual change. |
| Segment-vector CSV emission | Use a standards-compliant CSV writer so actual LF bytes remain inside one quoted field. Fill authoritative COA-order segments, append empty slots through the package-derived count (30 for the validated 133-column contract), and retain the terminal LF. Never write CodeCombinationId, the hyphen-delimited display, literal `\n`, or CRLF into a `*CcidSegments` field. |
| Scoped populated carrier construction | Resolve the target secondary's parent first, then use the fresh GL_SPECIFY_LEDGER_OPTIONS data export scoped by GL_PRIMARY_LEDGER and that parent's PRIMARY_LEDGER_ID as the sole carrier. Change only the exact target SECONDARY logical row in both aliases. A template-only package or project-owned secondary-create package may be historical evidence but is never the carrier. A post-import verification export is proof only and never the carrier for the already-approved import; compare semantic parity and classify service-generated differences without copying them into that immutable candidate. |
