# Specify Ledger Options Secondary-Ledger Input Validation

This context completes operational accounting policy for one exact in-process secondary ledger after Manage Secondary Ledgers. It does not ask again for the inherited secondary name, COA, calendar, currency, or conversion level, and it stops before mapping completion, Review and Submit, activation, or period opening.

## Intake Policy

| Input Class | Policy |
|---|---|
| Definitely mandatory user intake or confirmation | Exact secondary scope, First Opened Period, Number of Future Enterable Periods, and Retained Earnings Account. An exported or displayed value may be proposed but must be explicitly confirmed. |
| Conditionally mandatory user intake | Applicable SLA choices and explicitly requested option families trigger only their documented dependent fields. AccountingMethodName is not required because the new-ledger flow uses controlled Standard Accrual. Journal Description Language is not user intake for the supported baseline; blank carrier language receives the resolver-derived English default. |
| Optional user intake | Description and optional option families are not baseline questions. Ask only when the user explicitly requests the feature. |
| Resolver derived | IDs, period identity, English journal-description-language code, account combination ID, and account semantics derive from exact authoritative evidence. |
| Export derived or inherited | Ledger identity, COA, calendar, currency, conversion level, existing option values, inherited flags, and all untouched fields come from the scoped export. |
| Controlled role default | A current-release same-role baseline may fill only documented technical fields and disabled optional families; it never answers the three mandatory option choices. |
| Intentional blank | Valid blanks remain blank, including custom reversal criteria when not requested and posting-cutoff timezone/date while cutoff is disabled. |
| Service owned | IDs, short name, audit, process, status receipts, and manifest identity are preserved or generated by Fusion, never invented. |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Free-text normalization | Retain the raw decoded text exactly, including leading and trailing whitespace, internal whitespace, case, punctuation, and Unicode. Use an all-Unicode-whitespace check only to classify missing input; do not silently trim, collapse, or case-fold exact ledger, period, account, method, or LOV display values | Any free-text or business name is supplied |  |
| Exact secondary scope | Require one SECONDARY ledger under the selected PRIMARY relationship; a valid ledger in another relationship is rejected | Always | resolve_secondary_ledger_scope |
| First opened period | Require exact EnteredPeriodName membership after complete PeriodSetNameId pagination and local PeriodType filtering; preserve adjustment-period identity and ignore response order | Always | resolve_first_open_period |
| Future-enterable count | After outer-whitespace removal, accept ASCII decimal digits only, canonicalize leading zeros, and require integer 0 through 999; reject signs, decimals, exponent notation, separators, booleans, and blanks | Always |  |
| Mandatory confirmation | A resolver-derived or export-proposed FirstLedgerPeriodName, FutureEnterablePeriodsLimit, or RetEarnCcidSegments remains pending until the accountable user confirms it | Always | read_secondary_options_export |
| Retained-earnings segment shape | Split the supplied account with the resolved COA delimiter and require exactly the active SEGMENT1 through SEGMENTn values in physical order. Do not trigger a value-set or other export | Always | resolve_ledger_role_account |
| Retained-earnings CCID existence | Query accountCombinationsLOV by _CHART_OF_ACCOUNTS_ID equal to StructureInstanceNumber with no fields projection, page until hasMore is false, uniquely map every active dynamic segment key, and require exactly one full-vector exact row. Zero pauses this task for routed Manage Account Combinations FBDI creation and a mandatory post-success re-query | Always | resolve_ledger_role_account |
| Retained-earnings role | Require EnabledFlag Y or true, effective dates, AccountType O, DetailPostingAllowedFlag Y, and SummaryFlag N from the fixed accountCombinationsLOV fields. BalanceEnabledFlag is unavailable and must not be inferred. Missing or ambiguous dynamic-key mapping blocks without triggering an export | Always | resolve_ledger_role_account |
| Retained-earnings physical serialization | Do not write CodeCombinationId or the hyphen-delimited business display. Using the validated package-derived vector shape, serialize the resolved segments in authoritative secondary-COA order as one quoted field containing exactly 30 slots separated by actual LF bytes and terminated by LF; unused trailing slots are empty. Reject literal `\n`, CRLF, missing terminator, wrong slot count, reordered segments, or alias divergence | Always before preview and after re-export | resolve_ledger_role_account |
| Posting account roles | CTA, reserve encumbrance, rounding, suspense, SLA suspense, and similar posting accounts require EnabledFlag Y, effective dates, DetailPostingAllowedFlag Y, SummaryFlag N, and any family-defined AccountType | Corresponding optional family is explicitly requested | resolve_ledger_role_account |
| Net income role | Require enabled/effective, DetailPostingAllowedFlag N, SummaryFlag N, and the family-defined AccountType from the LOV; require separately authoritative evidence for balance-enabled semantics because BalanceEnabledFlag is unavailable | Average balances is explicitly requested | resolve_ledger_role_account |
| Accounting Method physical fields | Reject user-supplied method code/type or technical language code; resolve the controlled English baseline authoritatively through the method resolver's language sublookup | Any physical method field is supplied or carrier language is blank | resolve_accounting_method_evidence |
| Standard Accrual controlled options tuple | Require code STANDARD_ACCRUAL, type S, and a nonblank exact enabled resolver-derived language code on the newly FSCR-created secondary options save regardless of conversion level or omitted method input | Always for the options flow | resolve_accounting_method_evidence |
| Alternative method boundary | Preserve another exact AccountingMethodName only as desired-state handoff evidence; never author its tuple directly under open boundary GL-01 | A non-Standard-Accrual method is requested | resolve_accounting_method_evidence |
| AutoReverse dependency | AutorevAfterOpenPrdFlag Y does not require a Reversal Criteria Set; request criteria only when the user explicitly asks for custom reversal criteria | Reversal behavior is evaluated |  |
| Posting cutoff dependency | Baseline is PostingCutoffFlag N with blank timezone and date. Never author Y with blank timezone and never assume UTC; explicit cutoff intent becomes UI completion | Posting cutoff is explicitly requested |  |
| Optional-family scope | Suspense, rounding, intercompany, average balances, budgetary control or journals, automatic tax, translation, sequencing, custom reversal criteria, approval or reconciliation, posting cutoff, SLA cash basis, and USSGL are not baseline questions | User did not explicitly request the family |  |
| Unknown fields | Reject unsupported aliases, IDs, option flags, or account roles and identify the unrecognized input | User supplies a field outside this contract |  |
