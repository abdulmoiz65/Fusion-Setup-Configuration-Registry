# Assign Balancing Segment Values to Ledger Reference Lookups

All lookups are local, read-only inspections of the explicitly supplied FSM exports or scoped dependent export evidence. A missing source is a readiness blocker, never a reason to discover defaults through a failed import.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Export or metadata release differs from the target | Block and obtain matching-release evidence before deriving defaults |
| A source value is supplied as both an identifier and display name | Require both forms to resolve to the same value; conflicting evidence blocks |
| A task-scoped FSM export is about to be submitted | Validate the request before POST: one exact task code is carried at every supported request level; every criterion carries that same task code; criteria use supported business-object/attribute-set/attribute-name combinations; each scope value is the resolved technical identifier, not a display value; and the request contains no competing scope criteria. If any check fails, correct it locally and do not submit. |
| The paired direct-ledger and legal-entities exports are ready to submit | Submit the two validated read-only requests concurrently, retain separate request and ProcessId receipts, then retrieve each exact process independently. A failure in one export is not evidence about the other and blocks preview eligibility until the pair is complete. |
| A completed scoped export has an empty process-result collection | Retain its ProcessId and run the standard task-level result helper to retrieve and validate the `FileContent` ZIP by task identity, manifest, member inventory, and headers. Persist the helper receipt with ProcessId, FileContent attempt outcome, output path, and member inventory when bytes are returned. An empty result collection alone is not proof that no package exists and cannot support a statement that FileContent is unavailable. Only an evidenced unavailable or invalid FileContent attempt, followed by process-log retrieval, can be classified; do not post a replacement export while the same ProcessId is recoverable. |
| Only LedgerName is supplied for a ledger-scoped export | Use resolve_ledger_id_by_exact_name, then verify_ledger_id_exists, before building the criterion. If it resolves as SECONDARY, ask for the exact owning primary ledger name and stop; after that primary resolves and verifies, use only its numeric ID for the criterion. Do not request a UI export only to discover the numeric scope ID. |
| A primary-ledger scope is used to inspect related secondary-ledger assignments | Use the documented primary-ledger criterion only. Treat related secondary-ledger rows returned in the assignment CSV as output evidence; do not add an unsupported secondary-ledger criterion merely to obtain them. |
| An assignment row is generated | Derive `GL_LEDGER.Name` and `GL_SECONDARY_LEDGER.Name` from the one matching `GL_SECONDARY_LEDGER` parent row. Do not leave `GL_SECONDARY_LEDGER.Name` blank because an exported assignment row was blank, and do not enumerate or add unrelated secondary ledgers to the package. |
| A resolved ledger ID needs target-environment confirmation | Use verify_ledger_id_exists after the selected workflow permits a read-only GET; do not use the endpoint to infer balancing-segment assignment defaults |
| A balancing-segment value needs target-environment confirmation | Use verify_balancing_segment_value_exists with the exact resolved ValueSetCode and Value; do not query across value sets or use a partial match |
| A user supplies ledger context but no Company Value | Submit paired primary-ledger-scoped exports for GL_ASSIGN_BALANCING_SEGMENT_VALUES_TO_LEDGER and GL_ASSIGN_BALANCING_SEGMENT_VALUES_TO_LEGAL_ENTITIES, then use list_eligible_balancing_segment_values and list_current_ledger_assignments to return exactly two tables: eligible direct-ledger selections and existing or blocked values. The second table must preserve every direct-assignment effective date range and legal-entity assignment state. Do not create a package or request import approval until the user chooses one exact eligible value. |
| An approved Data Loader invocation is about to start | Run prepare_fsm_submission_recovery_anchor and persist its result before submission: use the unique immutable ZIP basename unchanged as fileName and DataSetName, bind it to the approved package SHA-256, and retain submitted-by identity, task code, environment, bounded submission start time, and exact task process baseline when available. Invoke the existing core.data-loader adapter once with an outer command budget of at least 300 seconds and continue waiting on that same invocation in intervals no longer than 60 seconds. |
| An approved Data Loader invocation ends without ContentId or RequestId | Do not retry or ask the user for server-generated identifiers. Run recover_data_loader_submission_exact, then recover_fsm_import_process_delta only when exact dataset recovery is unavailable or yields no identity. Continue only with exactly one recovered identity; zero or many candidates remain unresolved and prohibit a new upload or import. |
| A user supplies a Company Value but no ledger context | Ask for the exact LedgerName before any value-set lookup, duplicate check, package generation, or import. The applicable value set and direct-assignment evidence are ledger-dependent. |
| The export does not contain GL_LEDGER_SEG_VAL_ASSIGNMENT.csv or has no usable matching-scope evidence | Treat the result as incomplete for assignment existence/default derivation, not as an empty assignment list. Preserve the process log and manifest, diagnose scope/request shape or an explicit export size limit, and stop before package generation. |
| A UI-equivalent scoped export contains the assignment CSV | Use its header, parent-key columns, and direct assignment row as the authoritative package contract for the same task/release; do not generalize it to another task or release |
| A lookup requires live Fusion metadata | Use only the approved read-only route after its workflow prerequisites pass; failure is not treated as not found |
