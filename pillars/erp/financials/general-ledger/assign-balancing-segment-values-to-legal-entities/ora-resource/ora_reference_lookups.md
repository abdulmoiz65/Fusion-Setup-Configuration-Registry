## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Free-text matching | Retain raw input and a separate normalized-presence value; whitespace-only is missing; do not alter internal whitespace or case and do not fuzzy-match |
| Exact one result | Store resolver, source, exact filter or semantic key, requested fields, match count one, authoritative values, eligibility, validation time, and decision |
| Successful zero results | Report unknown or ineligible with the endpoint or export source and exact filter; do not broaden silently |
| Multiple results | Report ambiguity and candidate business keys; require more precise scope or identity |
| 401 or 403 | Refresh an eligible cached access token once under repository policy, then stop with authentication or authorization diagnostics; never relabel as no match |
| 429, 5xx, or timeout on GET | Use bounded backoff only for the read-only GET and retain attempt diagnostics |
| 400, malformed payload, client failure, or final auth failure | Stop without blind retry and show safe status, message, endpoint, and correlation or trace identifier when available |
| Data Loader command duration | Invoke the existing core.data-loader adapter once with an outer command budget of at least 300 seconds. If the execution host yields, continue waiting on the same invocation in intervals no longer than 60 seconds; do not terminate or start another upload merely because 60 seconds elapsed |
| Data Loader response timeout without IDs | Run recover_data_loader_submission_exact, then recover_fsm_import_process_delta when required. Continue only with one exact recovered identity; zero or many candidates remain unresolved and prohibit another upload or import |
| Ledger-scoped task export | For every create or update execution, use `core.fusion-api.rest-api-client` to POST `/fscmRestApi/resources/11.13.18.05/setupTaskCSVExports` with TaskCode GL_ASSIGN_BALANCING_SEGMENT_VALUES_TO_LEGAL_ENTITIES, one SetupTaskCSVExportCriteria row for GL_PRIMARY_LEDGER / Set1 / PRIMARY_LEDGER_ID / {LedgerId}, and one SetupTaskCSVExportProcess row. Require one positive returned ProcessId and retain the POST receipt; use the existing `shared.setup-export.task-level-export` result helper to poll and download that exact process. A missing criteria option in the high-level wrapper is not a blocker and does not authorize an unscoped export, a prior-run package, or template fallback |
| Template fallback export | Run only when classify_populated_export_fallback returns eligible. Invoke shared.setup-export.task-level-export with template-only mode, which uses setupTaskCSVTemplateExports and its template process/result resources, for the same environment, release, and task. Retain both process receipts and checksums; do not apply populated-export ledger criteria to the template endpoint or treat its empty rows as current state |
| Template fallback evidence | Require resolve_template_fallback_business_state before defaulting, preview, or import. The template supplies only the physical carrier contract; current parent, value-set role, existing legal-entity assignments, and direct-ledger assignments must come from supported current read-only Fusion evidence |
| Package lookup | Validate archive paths before extraction; read the current package in transient storage and persist only approved project artifacts without credentials or unrelated environment data |
