# Payment Terms Input Validation

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Requested mode | Offline prepare, offline review, export, validate, import, monitor, or verify, expressed in business language | Infer only the non-mutating intent supported by the request; never infer live authorization | Treat review or prepare without an environment as offline; any intended mutation still requires the routed preview and separate approval | Every request |  |
| Operation count and batch shape | One operation, or 2 through 100 distinct create/update/end-date operations with an explicit or attached business design | Stop when a requested count has no names/value pattern, exceeds 100, or targets the same Name/set more than once | Normalize one all-or-nothing operation list; consolidate compatible same-parent changes or ask about conflicts, and never build a partial subset | Mixed or batch request | find_payment_term_exact |
| Action and identity | Create with proposed Name, or update/end-date with existing Name | Ask only whether to create, update, or end-date and for the payment-term name | Compare the exact name within the intended reference data set | Every request | find_payment_term_exact |
| Update mutation scope | Exact existing Name plus reference data set as immutable selector, requested field patches, and stable child identities | Stop when the request implies rename, set move, or child deletion | Preserve every unspecified current field and child row; patch lines by SequenceNum, translations by Language, and discounts by line sequence plus DiscountPercent | Every update or end-date | find_payment_term_exact |
| Reference data set | Exact SetCode, one exact current display-to-code or business-unit mapping, or the sole current candidate | Stop before package preparation | If zero or multiple candidates remain, ask one business-first question and show current choices; never default to COMMON, ENTERPRISE, the first row, or another environment | Every create, update, end-date, or persisted-state verification | resolve_payment_term_set |
| Effective dates | StartDateActive and optional EndDateActive supported by the current template | Stop and request the missing or corrected date | Validate against current state and effective-date ordering | Create or end-date | find_payment_term_exact |
| Payment schedule | One or more complete installment lines with unique sequence and reconciled RelativeAmount | Stop and request a complete schedule | Validate each line against the current template and parent blueprint | Create or schedule update |  |
| Split-term printing and allocation | Positive whole-number Print Lead Days plus either allocate tax/freight across all installments or include it in the first installment | Stop before preview and ask one consolidated business question | Require both values whenever more than one payment line exists; never infer them from another term | Multiple installments |  |
| Discount schedule | Discount percent plus one complete supported discount-date method linked to an existing payment line | Stop and request the missing or conflicting value | Validate the child linkage and one date alternative | Discount requested |  |
| Discount calculation basis | A nonblank supported `CalcDiscountOnLinesFlag` on every header | For a create without discount rows, apply and disclose Invoice Amount (`I`); when discount rows exist, stop before preview and ask which invoice amounts should be discounted | Treat the field as entity-required. Preserve an exact current value for update; never infer a basis for requested discounts from frequency in the baseline | Every candidate header | inspect_payment_term_package |
| Tax/freight header value | A nonblank supported `FirstInstallmentCode` on every header | For a create with exactly one line, apply and disclose Include in first installment (`INCLUDE`); with multiple lines, stop before preview and ask the customer to choose | Treat the field as entity-required. A single line is also the first line, so the create default does not alter allocation; never infer the split-term choice | Every candidate header | inspect_payment_term_package |
| Partial-discount readiness | Verified Discount on partial payment Receivables system option | Stop before preview | Obtain a current read-only system-options export through the routed workflow | PartialDiscountFlag is enabled | verify_partial_discount_option |
| Balance-forward readiness | Exact supported billing cycle | Stop before preview | Resolve the cycle from current target context | Balance-forward behavior is requested | resolve_billing_cycle |
| Base language and translation | One customer-selected base language proven by current target evidence, plus a base row whose Language and SourceLang use that value | Stop before preview and ask which business language to use | Show bounded current target language choices; never omit the base row or infer the first language. For a base-description update, require exactly one current base row and synchronize its Description with the header | Every create; additional translations or base-description changes when requested | inspect_payment_term_package |
| Flexfield context and segment | Supported DFF context plus exact template `Attribute1` through `Attribute15` columns proven for that context | Stop on an unknown context, absent segment evidence, or unproven column | Validate context and segment mapping against current target evidence and the template contract; context existence alone is insufficient | DFF values are supplied | inspect_payment_term_package |
| Final local-design confirmation | Orchestration-owned design confirmation after the normalized business preview | Stop before ZIP generation | Show action, name, set, dates, ratio denominator, installments, print lead days, tax/freight allocation, discounts and basis, language, conditional flags, and all applied defaults; bind the response to the design SHA-256 | Every offline candidate generation |  |
| Current FSM evidence | Exact successful task-level template ZIP with one ASM_SETUP_CSV_METADATA.xml and current task data export when baseline state is needed; an existing ZIP is sufficient for offline review only | Stop before package preparation | In live mode, refresh task-level exports from the intended target; in offline mode, request the current local artifacts and make no external call | Every importable request or offline package review | inspect_payment_term_package |

## Dependency-Aware Validation

| Applies When | Result | Next Action | Resolver |
|---|---|---|---|
| The reference data set resolves to exactly one current candidate | Resolved | Disclose the business value and evidence source, then continue | resolve_payment_term_set |
| Any operation in a batch is invalid, unresolved, duplicate-targeted, or unsupported | Blocked | Identify its operation number/business identity and ask one consolidated question or correct invalid values; generate no partial ZIP | inspect_payment_term_package |
| The reference data set resolves to zero current candidates | Blocked | Show the supplied value and current valid choices, then ask one business-first clarification | resolve_payment_term_set |
| The reference data set resolves to multiple current candidates | Ambiguous | Show distinct display names and codes and ask the customer to choose; do not select the first or a fuzzy match | resolve_payment_term_set |
| A proposed create exactly matches an existing term in the same set | Conflict | Show the current record and ask whether the request is an update | find_payment_term_exact |
| An update or end-date does not resolve exactly one current term | Blocked | Request the exact name and reference data set | find_payment_term_exact |
| An update requests a rename, set move, child removal, or schedule contraction by omission | Blocked | Explain that this CSV package workflow cannot safely perform that mutation; offer a separately reviewed create/end-date or supported product workflow | find_payment_term_exact |
| A description update lacks exactly one current base-language translation row | Blocked | Request fresh target evidence or the correct business language; do not generate a header-only description update | inspect_payment_term_package |
| Multiple installments are supplied | Verify | Require reconciled RelativeAmount, positive whole-number PrintingLeadDays, and one explicit tax/freight installment option |  |
| A billing cycle and multiple installments are supplied | Blocked | Balance-forward billing cycles and split installments are incompatible; ask which business design is intended | resolve_billing_cycle |
| Discount rows are supplied | Verify | Require one through three unique discounts per payment line and an explicit supported discount basis | inspect_payment_term_package |
| Partial discount is requested | Verify | Continue only when the current Receivables system option is enabled | verify_partial_discount_option |
| Balance-forward behavior is requested | Lookup | Continue only with one exact supported cycle | resolve_billing_cycle |
| Source and target release or task identity conflict | Blocked | Refresh the template/export for the intended target; do not override silently | inspect_payment_term_package |
| A build template selects more than the Payment Terms task or reports an error/failed process state | Blocked | Obtain a successful task-level template; a broader package may be reviewed but not rewritten as a task-level import | inspect_payment_term_package |
| Offline mode lacks current evidence | Blocked | Request the exact local artifact; do not authenticate or call Fusion | inspect_payment_term_package |
| Create language evidence has zero or multiple candidates and no customer selection | Blocked | Show current language choices and ask which base language to use; create no ZIP | inspect_payment_term_package |
| Normalized design is complete but lacks standalone confirmation | Confirmation required | Show the complete business preview and request the orchestration-owned design confirmation; do not generate the ZIP |  |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Header identity | Require nonblank Name and SetCode that resolve to one intended payment term | Every request | resolve_payment_term_set |
| Clarification quality | Ask one consolidated question in business language, include known facts and bounded current choices, and omit FSM/CSV/API terminology unless the user asks for it | A required value is missing, ambiguous, or conflicting |  |
| Batch atomicity | Require every operation to pass and every resolved Name plus SetCode to be unique; cap one candidate at 100 operations | Mixed or batch request | inspect_payment_term_package |
| Validation ordering | Surface all known invalid values and numeric/range failures before requesting business choices that cannot make those values valid | Invalid values and missing choices coexist | inspect_payment_term_package |
| Child linkage | Copy the approved parent Name and SetCode to every line, translation, and discount row | Any child row exists |  |
| Schedule sequence | Require unique payment-line SequenceNum values and require every discount to reference an existing payment-line sequence | Schedule rows exist |  |
| Numeric shape and range | Require whole positive sequences, positive RelativeAmount, nonnegative day/month offsets, DueCutoffDay and day-of-month from 1 through 31, discount percent from 0 through 100, nonnegative single-line PrintingLeadDays, and positive whole-number split-term PrintingLeadDays | Applicable numeric field exists | inspect_payment_term_package |
| Base amount | Require the sum of line RelativeAmount values to equal header BaseAmount; do not assume a fixed denominator | Payment lines exist |  |
| Due-date alternatives | Populate exactly one supported DueDays, DueDate, or DueDayOfMonth per line; require DueMonthsForward with DueDayOfMonth and forbid it with other methods | Payment line is supplied | inspect_payment_term_package |
| Discount-date alternatives | Populate exactly one supported DiscountDays, DiscountDate, or DiscountDayOfMonth per discount; require DiscountMonthsForward with DiscountDayOfMonth and forbid it with other methods | Discount row is supplied | inspect_payment_term_package |
| Effective-date ordering | Require StartDateActive and require EndDateActive, when supplied, to be later than—not equal to—StartDateActive | Header exists |  |
| Lookup and flag values | Require Y/N for supported flags and current seeded codes for discount basis, discount basis date, and installment option | Applicable header field exists | inspect_payment_term_package |
| Entity-required header fields | Require nonblank CalcDiscountOnLinesFlag, FirstInstallmentCode, CreditCheckFlag, InUse, PartialDiscountFlag, PrepaymentFlag, and DiscountBasisDateType on every candidate header; use only the documented create defaults | Every candidate header | inspect_payment_term_package |
| Current string precisions | Enforce Name 15, Description 240, Language/SourceLang 4, header lookup/flag lengths, flexfield context 30, and flexfield segment 150 characters | Applicable field exists | inspect_payment_term_package |
| Required discount-basis header | Require a supported nonblank CalcDiscountOnLinesFlag even when no discount rows exist; create-without-discounts uses the disclosed Invoice Amount (`I`) product default | Every candidate header | inspect_payment_term_package |
| Discount uniqueness and cardinality | Require child SequenceNum to equal its referenced payment-line sequence, require unique DiscountPercent per payment line, and allow no more than three discounts per line | Discount rows exist |  |
| Unsupported field | Reject a field or code absent from the current target template; never guess a mapping | Any proposed field is unrecognized | inspect_payment_term_package |
| Service-owned audit values | Require LastUpdateDate, LastUpdatedBy, CreationDate, CreatedBy, and LastUpdateLogin to be blank in every import candidate while retaining exported values only as read-only baseline evidence | Every create, update, or end-date candidate | inspect_payment_term_package |
| Import-safe dates | Require metadata dates in generated candidates to use ISO `YYYY-MM-DD` and date-times to use ISO date-time; normalize slash-separated values copied from current exports | Every candidate | inspect_payment_term_package |
| Base translation | Require one source language across the candidate and one translation row where Language equals SourceLang | Every create | inspect_payment_term_package |
| Base-description synchronization | Require the header Description and exactly one base-language translation Description to contain the same requested value; preserve non-base translations unless explicitly patched | Description is created or updated | inspect_payment_term_package |
| Baseline-backed patch semantics | Preserve all unspecified header fields and child rows; reject duplicate or incomplete child patch identities and any candidate that does not exactly match the normalized request plus baseline | Every update or end-date; every candidate validation with baseline/blueprint | inspect_payment_term_package |
| Candidate intent | Compare every non-audit candidate row with rows independently rebuilt from the current baseline and normalized blueprint; structural validity alone is insufficient | Baseline and blueprint are available | inspect_payment_term_package |
| Persisted-state reconciliation | Compare the exact submitted candidate with a fresh successful task export by parent and child identity; allow only disclosed system-added translation languages | Verification after successful import | inspect_payment_term_package |
| Confirmation binding | Require exact preview design SHA-256 confirmation and invalidate it after any request, source, target, or resolved-value change | Every offline candidate generation |  |
| Hard delete | Refuse and offer an evidence-backed update or end-date | Delete requested |  |
| Child deletion by omission | Refuse; an omitted update child means preserve, never delete | Removal of a line, translation, or discount is requested |  |
| Offline boundary | Make no authentication, environment, export, upload, import, approval, or status call; return local evidence and SHA-256 only | Offline prepare or review |  |
