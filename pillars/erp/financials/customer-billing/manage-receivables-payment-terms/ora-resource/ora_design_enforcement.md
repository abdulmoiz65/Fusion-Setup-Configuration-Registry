# Payment Terms Design Enforcement

## Enforcement Order

| Sequence | Step | What Must Happen |
|---|---|---|
| 1 | Confirm lifecycle action and set | Resolve create, update, or end-date and one exact reference data set for every operation; permit up to 100 distinct parent targets. |
| 2 | Resolve ambiguity | Continue only when every required identity and business choice has one current evidence-backed result. |
| 3 | Reconcile patch and schedules | For update, merge stable-key child patches into the exact current four-entity state and preserve omitted values; then validate installment and discount hierarchy, sequence, date method, and allocation. |
| 4 | Verify language and conditional dependencies | For create, require one target-supported base/source language row. For a description change, synchronize the header and exactly one base-language row while preserving non-base translations. Verify billing cycle, partial-payment discount option, additional translations, and flexfield context when applicable. |
| 5 | Confirm current package contract | Require exact successful target metadata and only supported fields before a candidate archive is prepared. |
| 6 | Confirm the normalized design | Show the complete single or batch business preview and require the orchestration-owned design confirmation bound to every operation plus the source hashes before writing an offline candidate. |
| 7 | Preserve execution ownership | For an intended import, require Core Data Loader Task Hook validation and archive-bound approval; never choose a task-local import route. |

## Design Rules

| Applies When | Severity | Required Lookup | Blocking Condition | Recommendation | Fix Allowed? |
|---|---|---|---|---|---|
| Every create, update, or end-date | Error | resolve_payment_term_set | Set is missing, ambiguous, or unavailable to the intended business context | Obtain one exact current export-backed set | Yes |
| Mixed or batch request | Error | inspect_payment_term_package | An operation is invalid or unresolved, more than 100 operations are requested, names/values are not fully specified, or two operations resolve to the same parent | Resolve every operation and consolidate compatible same-parent changes; never build a partial batch | Yes |
| Every create, update, or end-date | Error | find_payment_term_exact | Lifecycle action conflicts with exact current state, including duplicate create or missing/ambiguous update target | Show the exact current match result and ask whether to create, update, or end-date | Yes |
| Every update or end-date | Error | find_payment_term_exact | Name/set identity changes, an existing child would be removed, a child patch lacks a stable key, or an unspecified current value is cleared | Preserve current values and rows; use a separate reviewed workflow for rename, set move, or removal | No |
| Every create, update, or end-date candidate | Error | inspect_payment_term_package | LastUpdateDate, LastUpdatedBy, CreationDate, CreatedBy, or LastUpdateLogin is populated in any candidate row | Clear copied service-owned audit values while retaining the current export as read-only evidence | Yes |
| Every candidate date/date-time field | Error | inspect_payment_term_package | A valid source date is emitted using an export-only representation such as `YYYY/MM/DD` | Preserve its semantic value but emit the ISO import-safe representation (`YYYY-MM-DD` for date fields) | Yes |
| Installments or discounts are supplied | Error | inspect_payment_term_package | Schedule is incomplete, parent linkage is inconsistent, sequence is invalid, or date alternatives conflict | Repair the blueprint to the current template contract | Yes |
| Payment lines are supplied | Error |  | Sum of RelativeAmount does not equal header BaseAmount | Correct header or line amounts until they reconcile | Yes |
| A header or schedule is created | Error |  | BaseAmount is missing or not positive, or no valid payment line is supplied | Supply a positive base amount and at least one complete line | Yes |
| Every candidate header | Error | inspect_payment_term_package | CalcDiscountOnLinesFlag is blank or unsupported, including when the discount collection is empty | For create without discounts apply and disclose Invoice Amount (`I`); otherwise preserve or resolve one supported basis | Yes |
| Every candidate header | Error | inspect_payment_term_package | FirstInstallmentCode, CreditCheckFlag, InUse, PartialDiscountFlag, PrepaymentFlag, or DiscountBasisDateType is blank or unsupported | For a one-line create apply and disclose `INCLUDE` plus product-backed flags/date basis; for multiple lines require the customer's tax/freight choice; otherwise preserve current values | Yes |
| Any supported text field is supplied | Error | inspect_payment_term_package | The value exceeds the current Payment Terms entity/table string precision | Shorten the business value before preview; do not truncate it silently | Yes |
| More than one payment line is supplied | Error |  | PrintingLeadDays is missing, zero, negative, or nonintegral; or FirstInstallmentCode is missing/invalid | Ask for positive whole-number print lead days and whether to allocate tax/freight or include it in the first installment | Yes |
| A balance-forward cycle and more than one payment line are supplied | Error | resolve_billing_cycle | Consolidated billing cycle conflicts with split installments | Ask whether the intended design is balance-forward with one line or a split term without a billing cycle | Yes |
| A due or discount day-of-month method is used | Error |  | The corresponding MonthsForward is absent, negative, or paired with another date method | Supply the complete day-of-month method | Yes |
| Discount rows are supplied | Error | inspect_payment_term_package | Discount basis is absent/invalid, a row is incomplete, child SequenceNum differs from the referenced line, DiscountPercent repeats on that line, a percentage is outside 0-100, or a line has more than three discounts | Ask for the discount basis and correct the affected discount rows | Yes |
| Effective dates are supplied | Error |  | Start date is missing or end date is earlier than or equal to start date | Supply a start date and a strictly later optional end date | Yes |
| Template and baseline are used together | Error | inspect_payment_term_package | Environment, Fusion release, metadata entity/field/type contract, or CSV headers differ | Refresh both task exports from the same intended target and release | No |
| Partial discount is requested | Error | verify_partial_discount_option | Corresponding target Receivables system option is not currently verified as enabled | Verify or configure the owning setup through its own routed task before returning | No |
| Balance-forward behavior is requested | Error | resolve_billing_cycle | Billing cycle is missing or unsupported | Supply one exact supported billing cycle | Yes |
| A payment term is created | Error | inspect_payment_term_package | No base translation exists, multiple base SourceLang values exist, or the selected language is not proven by current target evidence | Ask which current business language to use and generate one base row where Language equals SourceLang | Yes |
| A base description is created or updated | Error | inspect_payment_term_package | The header and base-language translation descriptions differ, the base row is missing/ambiguous, or a non-base translation changes without an explicit request | Resolve one base row and use the same requested Description in header and base row; preserve other languages | Yes |
| Additional translation or DFF values are supplied | Error | inspect_payment_term_package | Language, source language, context, or column is absent from current metadata | Use only current template-supported values | Yes |
| Any import preview is requested | Error | inspect_payment_term_package | CSV name, column, key, relationship, order, release, target, or task identity is unverified | Refresh the intended target exports and rebuild the archive | Yes |
| A task-level candidate build is requested | Error | inspect_payment_term_package | Metadata selects another task, selects multiple tasks, reports an error/failed state, lacks one of the Payment Terms entities, or contains unsafe ZIP members | Obtain a successful exact task-level template; do not rewrite broader metadata | No |
| An offline candidate is about to be written | Error |  | Standalone design confirmation is missing, stale, inferred, or bound to different normalized values or source hashes | Re-run preview, show the full business summary, and request the orchestration-owned design confirmation | No |
| A confirmed blueprint is handed to the package builder | Error |  | The internal `confirmation` envelope was removed, uses a key other than `design_sha256`, or contains approval, timestamp, user, environment, or other non-binding metadata | Preserve exactly `confirmed: true` plus the preview `design_sha256`; store execution metadata in the separate orchestration run record | Yes |
| An offline review is requested | Error | inspect_payment_term_package | The ZIP is unsafe, unreadable, encrypted, lacks exactly one metadata member, or its populated Payment Terms rows violate the current package contract | Correct or replace the local artifact; make no environment call | Yes |
| Candidate baseline and blueprint are available | Error | inspect_payment_term_package | The candidate rows do not exactly equal rows independently reconstructed from the normalized request plus preserved current state | Reject the candidate even if its archive and CSV structure are valid; rebuild from current inputs | Yes |
| Invalid values and missing business choices coexist | Error | inspect_payment_term_package | A clarification is proposed before all already-known field/range errors are disclosed | Report the invalid operation/value first, then request only decisions still relevant after correction | Yes |
| Any required value is unresolved | Error |  | Zero or multiple candidates remain, current evidence is absent/stale, or the request conflicts with evidence | Ask one consolidated business-first clarification with bounded current choices | Yes |
| Hard delete is requested | Error |  | This skill does not support destructive deletion of payment terms | Use an evidence-backed update or end-date if appropriate | No |
| Core Data Loader is about to upload | Error |  | Task Hook envelope is missing, stale, reconstructed, or not bound to the exact archive SHA-256 | Rebuild the Core Data Loader immutable preview and obtain a new standalone approval | No |
| A task-level ZIP is handed to a human uploader | Error | inspect_payment_term_package | Filename/hash/task/target handoff is not explicit, the ZIP came from a failed attempt, or the uploader is on an offering/functional-area import page | Use the current build handoff and the exact Manage Receivables Payment Terms task's Import from CSV File action | No |
| Import status is failed, timed out, or unknown | Error |  | A repeat submission is proposed without status reconciliation | Check status and diagnostics; never resubmit blindly | No |
| Successful import is being verified | Error | inspect_payment_term_package | A fresh task export is absent or bundled candidate-to-export reconciliation reports any missing, extra, or changed expected value | Preserve the mismatch report and stop; do not resubmit automatically | No |
