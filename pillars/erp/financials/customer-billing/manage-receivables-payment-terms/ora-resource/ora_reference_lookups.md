## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Current artifacts are absent | Route the required read-only export through the owning shared workflow; do not substitute an old sandbox or another task. |
| Current artifacts are absent in offline mode | Request the exact local template, export, or package and stop; do not authenticate or call Fusion. |
| A recorded absolute path does not exist | Ignore it as stale provenance and rediscover attachments or repository-relative project artifacts. |
| Task ownership or implementation lineage must be reconfirmed | Query the current accessible CodeSearch series for AR_MANAGE_RECEIVABLES_PAYMENT_TERMS; use the registered FPHDEV chain only as labeled fallback evidence. |
| Persisted-state verification is requested | Run a fresh successful read-only task export and use the bundled `reconcile` command to compare the exact submitted candidate with the PaymentTerm header, line, translation, and discount entities. Report system-added extra translation languages separately; never mutate RA_TERMS tables. |
| A lookup cannot prove one exact value | Stop and return the missing or ambiguous business fact; do not guess, normalize, or select a fallback. |
| A lookup has one exact result | Disclose the resolved display value, code, and evidence source, then continue without asking the customer to repeat it. |
| A lookup has zero or many results | Ask one consolidated question in business language, include bounded current choices, and keep the current node blocked until the customer resolves it. |
