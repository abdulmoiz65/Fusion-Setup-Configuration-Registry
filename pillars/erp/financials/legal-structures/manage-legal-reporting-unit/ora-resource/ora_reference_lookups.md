## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Declared client and environment | Use core/fusion-api/rest-api-client/scripts/fusion_rest_client.py through the routed reference_lookup step and selected environment. Send --header REST-Framework-Version=9 for addressGeographies and legalJurisdictionsLOV. Supply q, fields, onlyData, and pagination as separate --query key=value arguments for client URL encoding; do not hardcode a host, country, or language. |
| Query value escaping | Escape single quotes in string literals by doubling them. For LIKE search text, escape literal backslash, percent, underscore, asterisk, and question mark with framework-version-9 backslash escaping before adding intentional outer percent wildcards. URL encoding is separate from expression escaping. Join q predicates with and, not semicolons. |
| Country request | Use q=CountryCode='{resolved TerritoryCode}' and GeographyType='COUNTRY' and PrimaryGeographyFlag=true; fields=GeographyIdentifierId,CountryCode,GeographyValue,GeographyType,PrimaryGeographyFlag,LanguageCode,StartDate,EndDate; onlyData=true. Do not request or filter hierarchy levels2-5, their primary flags, or their languages: those joins can eliminate country rows. Do not request hidden GeographyId or GeographyUse. |
| Country candidate and language validation | Read every matching page. Require exact CountryCode, COUNTRY type, primary flag true, nonblank GeographyValue, and effective dates. If multiple candidates remain, show values and LanguageCode and ask for refinement. Do not hardcode LanguageCode US, prefer a language silently, or select by list order. |
| Country resolver | Derive all geography carriers from the same territory and primary-country receipt. GeographyValue supplies the geography name, not TerritoryShortName. Never substitute GeographyIdentifierId or a jurisdiction GeographyId for the LRU GeographyId; import resolves its internal ID from natural geography fields. Do not call geographiesLOV as a fallback. |
| Effective dates | Record one workflow as-of date. A null start or end is an open boundary; otherwise require StartDate on/before and EndDate on/after as-of. Invalid or inverted dates do not qualify. addressGeographies also applies its own current-date selection, so a historical as-of cannot recover rows excluded by the endpoint. |
| Omitted jurisdiction | Leave null, skip legalJurisdictionsLOV and address resolution, and emit no new registration row. Do not default from country, parent LE registration, another LRU, or UI list order. |
| Jurisdiction request | For exact input use q=Name='{escaped supplied name}'; for requested partial/contains search use q=Name LIKE '%{escaped supplied text}%'. Name='%text%' is not contains. Request the fields above with onlyData=true. Do not add IdentifyingFlag=true or GeographyId predicates. |
| Jurisdiction selection | After full pagination and date filtering, one candidate resolves; if multiple remain, show Name, LegislativeCategoryCode, IdentifyingFlag, registration codes, dates, and receipt-only IDs when needed, and ask which one. Reuse the selection. Use the exact returned Name, not the user's search fragment, in the CSV. |
| Jurisdiction import-name uniqueness | The importer resolves jurisdiction by case-insensitive Name and takes its first match. Before accepting a selected name, read all jurisdiction pages without identifying/date filters and compare names case-insensitively. Distinct JurisdictionId values with importer-equivalent names block, even if only one is effective or the user selected an ID. Do not invent an ID column to bypass this limitation. |
| Jurisdiction geography association | Association to the selected LRU geography is intentionally not validated in this scope. Do not require GeographyId resolution or ask an additional association confirmation. Record association as not checked; never claim it was verified from these endpoints. |
| Address selection | Search only the fresh scoped exported legal-address rows, show distinguishing details for multiple matches, and preserve the selected row's exact FormattedAddress. Do not synthesize an address or use an unrelated sample address. A suitable parent LE address may be reused; if no suitable row exists, route address setup separately and refresh the export. |
| Free-text LOV input | Outside the jurisdiction and address selection flows above, use exact code or Unicode-normalized case-insensitive exact name matching, active/effective filters, full pagination, and cardinality one |
| Function code lookup succeeds | Record the receipt but keep the function branch blocked because jurisdiction permission and authority/site coupling remain unproven |
| Export use | Use the criteria-first parent-scoped export in ../SKILL.md for current shape, unchanged parent rows, existence/collision/history checks, verification, and exact legal-address natural-key resolution. Multiple selected parents use distinct AttributeSet values and numeric parent IDs; verify the complete scope/root sets and partition child checks per parent. Reference addresses can extend beyond the selected roots. Empty LRU/registration/address data is valid when that branch does not require it. Do not depend on unrelated existing LRUs or example addresses. |
| Receipt | Record target, release, as-of, normalized inputs, method/path, requested fields, resolved q, effective framework header, full-pagination evidence, counts, selected natural keys, source-specific receipt-only IDs, dates, derivations, explicit selections, registration branch, import-name uniqueness, and fingerprint. Record jurisdiction geography association as not checked; redact sensitive values as prescribed. |
| Broader export container | A task-level export must complete successfully. A broader functional-area or offering export may have overall status Completed with errors only when its archive is available, the exact process log identifies every failed object, every object/member required by this task completed successfully with zero failed, warning, or partial rows, every failure is provably outside this task, and target, release, freshness, fingerprint, hierarchy, and headers are verified. Record and disclose the scoped exception; any required-object failure, warning, partial result, missing counter, or indeterminate status blocks. |
