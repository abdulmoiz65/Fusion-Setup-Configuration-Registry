The other four requirements have complete source-proven FSM import resolution or validation contracts in the `Lookup Operations` table. Do not call internal components directly or invent a REST path; the import-only contracts execute only through the separately governed FSM Data Loader preview/import path.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| No supported public preflight path, but a complete Confirmed FSM import contract exists | Do not call internal components or invent a REST path. Continue static planning and defer only the affected field's resolution or validation to the immutable Data Loader preview |
| Resolver contract is Partial, To collect, unsupported, or `TBD` | Block the affected field and request the missing contract evidence |
| Free-text reference | Use exact normalized matching, active/effective filters where supported, full pagination, and cardinality one; never select the first row |
| Resolver dependency | Resolve business unit, ledger/chart of accounts, and reference-data set before dependent activity, account, rule, source, or type lookups |
| Package evidence | Use only same-task export/template shape and verification evidence; do not copy physical IDs or current-data values into generated examples |
| Receipt | Record target, release, as-of time, normalized inputs, approved method/path, requested fields, match count, natural keys, receipt-only IDs, and redacted fingerprint |
