## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Certifying-agency candidate lookup | Treat collection results as read-only preview information. A parent-only PATCH supplies CertifyingAgency directly and does not run an ID lookup. A child PATCH accepts only one exact agency-name match, uses its ID for the child row and child lookup, and does not populate the parent PATCH ID. Never select a create candidate automatically. |
| An existing agency is selected for child-association maintenance | Resolve the agency by the parent ID needed for the child lookup before preparing the child Data Loader row. A parent-only PATCH is keyed by CertifyingAgency and does not require the item lookup. |
| Business-classification validation | Resolve every supplied code or name through the documented standard lookup, including code-only input. Populate BusinessClassificationCode with the validated LookupCode and omit BusinessClassification from the executable child section. Supplying a code avoids server-side name derivation, not reference validation. |
| Existing association changed by child PATCH | Retrieve the agency's current child collection through the ADF REST business object. Resolve the child row that represents the association being replaced and use its returned BusinessClassificationId in the child PATCH row; use the separately validated target LookupCode as the replacement classification code. |
