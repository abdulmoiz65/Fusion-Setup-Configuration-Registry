## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Source-backed mandatory Workstation create fields | Require nonblank `WorkstationCode`, `OrganizationCode`, `WorkstationName`, and `WorkCenterCode` when creating a Workstation. Apply the 30-character limit to `WorkstationCode` and the 120-character limit to `WorkstationName`. This rule does not assert that headers other than these four are optional. | When creating a primary Workstation record. | |
| Completed task-CSV create, restore, and update behavior | The historical completed QA result establishes that task-level Workstations CSV import can add a Workstation, restore a deleted Workstation, and apply the exported values back to an edited Workstation. Do not infer an alternate key, required file set, field set, or parser outcome from that test comment. | When documenting supported Workstations task-level CSV scenarios. | |
| Source scope for remaining documented headers | Enforce mandatory create fields only for `WorkstationCode`, `OrganizationCode`, `WorkstationName`, and `WorkCenterCode`. Do not declare another documented header required or optional without a direct source. | For all documented Workstations CSV templates. | |
| REST-confirmed primary-field length limits | Validate supplied values against the live REST limits when the same named field is used: `WorkstationCode` maximum 30; `WorkstationName` maximum 120; `WorkstationDescription` maximum 240; `WorkCenterCode` maximum 255; `SupplySubinventoryName` and `CompletionSubinventoryName` maximum 10; `SupplyLocator` and `CompletionLocator` precision 255. | As advisory validation for the corresponding named fields in the documented Workstations CSV templates. | |
| REST-confirmed primary-field types | Treat `AutomationEnabledFlag` and `SimultaneousExecutionFlag` as boolean fields, and `InactiveDate` as a date field. Do not infer a CSV literal, date-string format, or requiredness from REST metadata alone. | As advisory validation for the corresponding named fields in `ORA_WIS_WORKSTATION.csv`. | |
| REST metadata that must not be treated as FSM CSV rules | `ProductionLineCode` is read-only in the REST describe response even though it appears in the FSM CSV template. Do not reject or accept that CSV column based on REST writeability. | When assessing `ORA_WIS_WORKSTATION.csv`. | |
| Observed FSM boolean literals | The full exported primary CSV uses `Y` and `N` for both `AutomationEnabledFlag` and `SimultaneousExecutionFlag`. Accept those two observed literals as source-backed examples; do not reject other literals until an authoritative import contract defines the complete allowed set. | When assessing nonblank values in those two primary CSV columns. | |
| FSM manifest field types | Treat `InactiveDate` as the only primary Workstations manifest `date` field. Treat every other primary CSV data field as a manifest `string`; treat equipment `EquipmentInstanceCode` and `OrganizationCode`, plus all translation data fields, as manifest `string`. | When assessing the documented CSV templates. | |
| Observed FSM parent-reference shape | Equipment-instance and translation CSV rows use `ORA_WIS_WORKSTATION.WorkstationCode` plus `ORA_WIS_WORKSTATION.OrganizationCode` to reference an exported primary-row pair. Every child reference in the source export matched a primary pair. | When assessing rows in `ORA_WORKSTATION_EQUIPMENT_INSTANCE.csv` and `ORA_WIS_WORKSTATION_TRANSLATION.csv`. | |
| Equipment-instance association integrity | When an equipment association is supplied, require that `EquipmentInstanceCode` resolve to an active equipment-type resource instance in the same manufacturing organization as the Workstation. Reject an instance already associated with another Workstation. These are Workstation entity rules; they do not establish the task-CSV parent-missing behavior, CSV parser message, or terminal `ProcessLog` state. | When assessing supplied rows in `ORA_WORKSTATION_EQUIPMENT_INSTANCE.csv`. | |
| Observed blank values in a valid export | The source export contains blank values for `InactiveDate`, `ProductionLineCode`, supply/completion subinventory and locator fields, and some translation descriptions. Preserve blanks during export analysis; do not treat this observation as a universal create/update requiredness rule. | When assessing the corresponding CSV fields. | |
| Supply subinventory and locator consistency | When `SupplySubinventoryName` is supplied, require an existing subinventory in the Workstation organization. When that subinventory is locator-controlled, require `SupplyLocator`; when `SupplyLocator` is supplied, require a locator in the same organization and subinventory. Reject a supply subinventory/locator pair already assigned to another Workstation. This is a Workstation-service validation rule; the exact task-CSV `ProcessLog` message remains unknown. | When either supply field is supplied in `ORA_WIS_WORKSTATION.csv`. | |
| Completion subinventory and locator consistency | When `CompletionSubinventoryName` is supplied, require an existing subinventory in the Workstation organization. When that subinventory is locator-controlled, require `CompletionLocator`; when `CompletionLocator` is supplied, require a locator in the same organization and subinventory. This is a Workstation-service validation rule; the exact task-CSV `ProcessLog` message remains unknown. | When either completion field is supplied in `ORA_WIS_WORKSTATION.csv`. | |
| Source scope for CSV-specific values and formats | Use only source-backed examples and types: `Y` and `N` are observed Boolean examples and `InactiveDate` is a manifest date field. Do not reject Boolean, date, lookup, or coercion values using an unsupported task-local rule. | For all documented Workstations CSV templates. | |
| Source scope for translation and CSV relationships | Do not impose a task-local translation-file, missing-parent parser, or import-order rule. Enforce only the sourced entity checks in this file when their named fields are supplied. | When `ORA_WIS_WORKSTATION_TRANSLATION.csv` is supplied or when multiple documented CSV templates are imported. | |
