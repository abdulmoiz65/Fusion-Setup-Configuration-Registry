## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A configured display value is absent | The corresponding resolver is not applicable and no lookup is sent. |
| A configured display value resolves exactly once | Preserve Meaning as sanitized evidence and fill only the returned LookupCode in the documented implementation field. |
| A configured display value resolves to zero or multiple rows | Stop before Data Loader handoff and report the affected field, lookup type, and supplied display value. |
| A display value matches an excluded lookup code | Treat the value as unavailable and stop before Data Loader handoff. |
| A display value includes different case or outer whitespace | Normalize only for the exact comparison; preserve the returned system values. |
| The standard lookup request fails | Classify the failure through ora_error_handling.md; do not infer a value, use stale data, or retry a mutation. |
| REST Subinventories is selected and one locator-structure row matches | Fill `LocatorStructureMeaning` with the matched row's canonical `StructureInstanceName`, regardless of whether the supplied value matched its code or name. |
| FSM Subinventories or locators is selected and one locator-structure row matches | Fill `StructureInstanceCode` with the matched row's canonical `StructureInstanceCode`, regardless of whether the supplied value matched its code or name. |
| The supplied locator-structure value matches both fields on one row | Count that row once and retain both canonical fields. |
| The supplied locator-structure value matches multiple distinct rows | Stop as ambiguous even if more than one matching condition points to the same apparent code; do not select the first row. |
| Separate locator-structure name and code inputs resolve to different rows | Stop as conflicting input and request one consistent value or pair. |
