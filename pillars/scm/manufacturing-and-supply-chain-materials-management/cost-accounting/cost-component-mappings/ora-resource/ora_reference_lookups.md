# Cost Component Mapping Groups Reference Lookups

Oracle documentation states that cost component mapping groups are defined at the set level and can be managed only for sets to which the user has access. The mapping-group UI set selector was cross-checked against the supplied costing sets LOV: use that LOV to validate the selectable set name; Fusion remains the authority that accepts or rejects the create.

Send every live lookup through `core.fusion-api.rest-api-client` with the `REST-Framework-Version: 9` request header. The version header is part of the lookup contract, including before classifying a response as a service rejection or applying a documented fallback.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Any live lookup is required | Use core.fusion-api.rest-api-client and send REST-Framework-Version: 9. Do not classify a request without that header as a supported lookup result. |
| The lookup finds no selectable set | Stop before preview and request a valid SetName |
| The lookup returns more than one set | Stop and request an unambiguous set identity |
| DestSetName is not returned by the destination-set scope validation | Stop before preview; it must be the mapping group's set or Common Set |
| A cost-element SourceSetName is not returned by its group-set-specific source-set lookup | Stop before preview. A Common mapping group uses `q=null`; a non-Common mapping group excludes its own set. |
| A component-code Data Loader row is generated | Require explicit `ComponentSource`: `PRE_DEFINED` for predefined rows and `LANDED_COST_MANAGEMENT` for landed-cost rows. Verify that the exact value is present in the generated Data Loader row. |
| Unmapped predefined components are requested or a predefined source must be resolved | For an existing parent, use the `IntentFinder` with `bindCompGrpID` embedded in the single `finder` parameter. Page through its unfiltered result and apply `SourceCode=PRE_DEFINED`, `IsMapped=N`, and `InactiveFlag=false` locally; do not rely on a combined finder-and-`q` predicate. For a confirmed-absent master-details parent, use the generic paged component LOV and apply `SourceCode=PRE_DEFINED`, `SetId=0`, and `InactiveFlag=false` locally. |
| A destination-set `OR` predicate is rejected by `setIdSets` | Read the mapping-group set and Common Set as separate exact `SetId` queries, then combine their results before validation. |
| A cost-element type display label conflicts with its code | Use `SourceElementType` (and `CostElemType` where returned) as the canonical source type. Treat `SourceCostElementTypeMeaning` as display-only and do not fail or rewrite a mapping solely because it differs. |
| SourceSetName is Common Set | Resolve SourceCostElementCode only through the Common Set PII finder; reject a non-PII source element. |
| A selected non-Common source or destination element is not explicitly PROFIT_IN_INVENTORY | Do not invoke the PII resolver; resolve that element only through its own general set-specific LOV |
| An existing child-row type label conflicts with the exact current general LOV result | Do not silently reinterpret or update the mapping; report TYPE_CONFLICT and obtain an unambiguous current selection |
| An exact match may occur beyond the returned page | Continue pagination until the exact match is found or hasMore is false before treating the lookup as no-match |
| Fusion reports a ComponentSource-missing dataset error after a combined child package | Do not suppress the failure from the dataset result. Invoke reconcile_component_source_failure_effects only after confirming every submitted component-code DAT row has nonblank ComponentSource. Treat it as reconciled only when exact readback verifies every requested row and value; otherwise retain FAILED and stop before retry. |
