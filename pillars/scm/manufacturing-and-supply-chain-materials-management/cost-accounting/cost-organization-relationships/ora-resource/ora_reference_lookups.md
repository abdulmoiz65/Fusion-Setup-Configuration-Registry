## Lookup Execution Rules

| Rule | Requirement |
|---|---|
| Operation scope | These resolvers are read-only and may only perform the documented costOrgsLOV, eligibleInventoryOrgsLOV, costOrgItemValidationOrgsLOV, legalEntitiesLOV, setIdSets, costBooksLOV, costOrgBooksLOV, ledgersLOV, accountingCalendarsLOV, costOrgBookPeriodEndValidations, standardLookupsLOV, or referenceDataSetObjectsLOV lookup. They must not create, update, delete, upload, or initiate setup data. |
| REST framework version | Send the exact REST-Framework-Version: 9 header with every documented Fusion REST request, including every read-only lookup GET. |
| Filter syntax | For multi-condition q filters, join predicates with and, not a semicolon. Enclose every string literal, including classification values such as 'INV', in single quotes. |
| Environment identity | Join every documented relative request path to the active, approved Fusion restBaseUrl. No lookup contract may supply or override a host. Stop if restBaseUrl is absent or the environment selection is not approved. |
| Result handling | Return both CostOrgName and CostOrgCode regardless of which one was queried. Retain only the documented fields. Do not infer missing IDs, dates, status, or legal entity values. |
| Cost Organization selector | A caller may provide either CostOrgName or CostOrgCode, but must declare the field. A declared CostOrgName uses the CostOrgName query branch; a declared CostOrgCode uses the CostOrgCode query branch. Do not reinterpret a code as a name or a name as a code. |
| Item Validation Organization selector | A caller may provide either OrganizationName or OrganizationCode, but must declare the field. For example, a declared OrganizationName uses the OrganizationName query branch; a declared OrganizationCode uses the OrganizationCode query branch. Do not reinterpret a code as a name or a name as a code. |
| Accounting Calendar selector | A caller may provide either PeriodSetName or UserPeriodSetName, but must declare the field. A declared PeriodSetName uses the PeriodSetName query branch; a declared UserPeriodSetName uses the UserPeriodSetName query branch. Do not reinterpret one as the other. |
| New-record relationship key | Do not look up, derive, or populate CostOrgParameterId for a new Cost Organization Relationship. Fusion generates this primary key during creation. |
| Period-end validation PATCH key | Confirm the live registered attribute contract before every new archive. When UserKeyAttrNames is exactly CostOrgId, CostBookId, ValidationType, leave PeriodEndValSurrogateId blank and populate all three component fields. |
