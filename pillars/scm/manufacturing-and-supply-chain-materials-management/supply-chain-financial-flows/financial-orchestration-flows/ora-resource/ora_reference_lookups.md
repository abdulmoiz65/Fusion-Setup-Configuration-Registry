## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Invocation | Each lookup node evaluates its named resolver only when Runs When applies; otherwise record not applicable and follow success without a request. No create-time financial lookups for PTR deletion. |
| Request context | Use configured resource version/shared client with REST-Framework-Version: 9. Relative collection paths use /fscmRestApi/resources/latest/ unless an explicit path or configured service root is given. Escape quotes and URL-encode values. |
| Selection | Page hasMore collections before declaring absence/uniqueness. Exact full labels or verified IDs only; search substrings discover candidates but do not select them. Present identifying context for duplicates; never take the first row except the explicit first eligible BU-scoped trade-organization default for each PROCUREMENT FTR. |
| Identifiers | Preserve returned IDs as text. Supplied IDs must be verified in the same side/date/environment context as names; BU ID, LE ID, PartyId and ledger ID are not interchangeable. |
| Date scope | Default-date Agreement reads do not establish all-history absence. A noncurrent child identity needs supported dated transport; a 404 is not proof of absence. Tax lookup date is environment today unless explicitly selected for supported as-of behavior; retain route/identity dates separately. |
| Date-bound queries | Use the resolved FTR interval; when end date is omitted apply the applicable documented end-date default, not today. Keep tax lookup date separate. |
| Interval coverage | Use the selected endpoint open-end convention. A null rule end is not an expiry, but do not assume open-ended semantics when the endpoint contract is unknown; report unresolved interval coverage. |
| Status | For a requested Agreement status change, use the current-version Agreement Correction path and resolve the exact user-supplied Meaning or LookupCode through FOS_AGREEMENT_STATUS; put only the returned LookupCode in Status. Do not derive custom codes from labels. Correct/Insert are operation choices, not status LOVs. |
| Trade organization | PTR FromTradeOrganizationId/ToTradeOrganizationId differ from FTR FromTradeOrganization/ToTradeOrganization. For SHIPMENT PTR creation, omit all PTR trade-organization fields and do not run the trade-organization resolver. For new FTR chains, take the first enabled selling-BU LOV entry for an omitted first PROCUREMENT selling organization; leave an omitted first SHIPMENT or INTERNAL_TRANSFER selling organization blank. Default every omitted buying organization from its buying BU, and inherit each later omitted selling organization from the preceding buying organization. Resolve and verify every populated FTR value in its side BU. |
| Readback | Apply operation-specific absence expectations from ora_error_handling.md rather than preparation-time not-found handling. Reuse the same scoped resolvers for requested values and retained fields. Insert reads use both old/new as-of dates; PTR deletion reads the parent and route collections plus retained child impact context. |
