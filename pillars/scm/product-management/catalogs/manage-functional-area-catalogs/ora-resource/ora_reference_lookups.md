## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A new package baseline is needed | Use shared.setup-export.task-level-export for the exact task code. Immediately persist the returned TaskCode, ProcessId, submission time, source environment, and initial status in the project task run record before polling. Retain the successful process receipt and downloaded ZIP as the baseline evidence. |
| A Functional Area Name or Functional Area ID is supplied | Use the declared read-only lookupCodes child-collection GET for EGP_CATALOG_FUNCTIONAL_AREAS with limit=500, offset=0, and totalResults=true. Read all pages until hasMore is false, then resolve and validate the exact LookupCode/Meaning pair across the complete collection. Do not use a display name as the package ID without one exact lookup match. |
| Catalog content is supplied or defaulted | Normalize every non-omitted catalog row's REST/UI Boolean to `LEAF_ITEMS` or `ALL_ITEMS`. Retrieve EGP_CATALOG_CONTENT_CODE once through the declared read-only paginated lookupCodes child-collection GET, retain the complete receipt, then validate each catalog row against that cached collection. Accept only one exact enabled, effective LookupCode match per row and write that returned LookupCode to the matching EGP_CATALOG.csv.CatalogContentCode field. |
| A functional-area identity is resolved | Preserve explicit `HierarchyEnabled`, or default it to `Y` from the current `itemCatalogs/describe` `HierarchyEnabledFlag.defaultValue=true`. Require the user to provide `MultItemCatAssignFlag`; prompt once for the applicable public Oracle Functional Area Catalog Rules documentation reference and retain the supplied value or `not_provided` as validation evidence. When a default Category Code or Category Name is supplied, infer `DefaultCategoryRequired=Yes`; otherwise require the user to provide `DefaultCategoryRequired`. |
| A category or functional-area assignment references a catalog | Use an exact candidate EGP_CATALOG.csv match when available. Otherwise use the validated baseline ZIP's EGP_CATALOG.csv and require exactly one exact CatalogCode/CategorySetName match before preparing the dependent row. |
| A catalog row is omitted | Do not add a catalog data row. Retain the catalog CSV member and exact exported header. Dependent category and functional-area assignment rows remain permitted only after their catalog reference passes verify_referenced_baseline_catalog. |
| Both Category Code and Category Name are absent | Do not add category or catalog-category data rows. Retain the category CSV members and exact exported headers in the FSM package so its verified task structure remains unchanged. |
| An export is nonterminal or the client session ends | Resume polling only the persisted ProcessId. Update the project task run record with the last status and elapsed wait; do not submit another export while that process remains unresolved, unless reconciliation cannot recover the process identity and the user gives fresh explicit authorization for one replacement export. |
| An FSM import is accepted | Immediately persist the exact archive fingerprint, TaskCode, submission time, Data Loader Content ID, Request ID, and any returned FSM migration ProcessId in a sanitized project task run record. Resume status or ProcessLog retrieval only through the persisted identifier; do not re-create the import. |
| An FSM import response is missing or unusable | Treat the import outcome as indeterminate. Do not submit the archive again. Reconcile with a read-only Data Loader status query using a persisted Content ID or Request ID; when Fusion returns an FSM migration ProcessId, persist it and resume only that process. Zero or multiple matching results remain blocked. |
| A candidate package is prepared | Compare its member inventory, metadata hierarchy, and exact CSV headers with the fresh same-task baseline before preview. Preserve the verified baseline structure; do not add unrelated task members. |
| Export status is partial, failed, timed out, or unavailable | Stop and retain the process log or status evidence with the persisted ProcessId. Do not use a partial archive as a package baseline or submit a replacement export automatically. When an indeterminate export cannot be reconciled because its process identity is unavailable, a replacement requires fresh explicit user authorization and must start a new tracking receipt. |
| A cross-environment package source or target release cannot be verified | Stop before preview or import. For a same-environment baseline, verify matching source and target environment identity instead. |
