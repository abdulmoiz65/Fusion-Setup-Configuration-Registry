# Change Line DFF Input Validation

Validate intended changes from the prompt, runbook or optional spreadsheet through the existing task inputs. Existing Fusion state requires the verified baseline; field mappings and target-release length semantics must be verified before packaging.

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Stage-specific input scope | Check the supplied terminology and values relevant to the question even when a full setup definition is absent. Input-only feedback requires neither execution context nor unrelated create fields. Distinguish observed local findings from pending baseline, lookup and execution checks; do not report full task readiness or unrun nodes as passed | Questions, clarification, draft requests and supplied-value checks before formal task execution | |
| Object terminology | For incorrect, near-matching or ambiguous object wording such as context DFF segment, suggest the relevant documented choices with brief meanings and ask which is intended before assigning scope. Conflicting cues such as a Context Segment described as a new Number field require clarification. A clear canonical request needs no redundant question | Resolving requested configuration scope | |
| Disable terminology and operation | Distinguish disabling a Context from disabling its child segments or the Context Segment selector, and distinguish disable from deletion, hiding, read-only configuration or BI disablement. Ask what disable DFF or retire Context means when the intended object or operation is unclear. An explicit entire Context request needs no redundant segment-versus-Context question. Do not silently translate deletion or enable into disable | Resolving a disable or removal request | |
| Identifier terminology | Keep Name, Code, API Name, Prompt, Context Code and change type InternalName distinct. If the user says display name, internal name or API name interchangeably, show the candidate fields and confirm the intended mapping. Never copy one value into every field silently | Resolving names or identifiers | |
| Context Code shape | Require a nonempty text value for each requested Context; preserve spelling and case for the design check. Resolve a selected existing Context from the baseline; do not expand the request to unrelated preserved Contexts or apply the API Name character pattern to Context Code | Explicit code checks, requested Context definitions or requested Context Sensitive Segment associations | |
| Consistent source mapping | Apply the same stage-appropriate checks to prompt-entered, runbook-entered and spreadsheet-supplied details; identify the source message or row when reporting an issue | Intended changes come from a prompt, runbook or spreadsheet | |
| Global-only scope | Do not require Context Code or fabricate a context value | Global Segments only | |
| Names and types | Require nonempty text for required Name, Code and Prompt values and an unambiguous data type. Prompt is the user-facing label; Name and Code are internal properties. Do not apply API Name syntax to these different fields or coerce Number or Date to String | Creating Global Segments or Context Sensitive Segments, or changing these properties | |
| API Name syntax | Require ASCII letters and digits only, with a leading letter: A-Z or a-z followed by zero or more A-Z, a-z or 0-9 characters. Reject spaces, underscores, punctuation, multibyte characters and leading digits. Preserve user spelling; offer a valid alternative for approval instead of silently stripping characters | Supplying or generating an API Name | |
| Attribute-segment naming lengths | Check the documented field mappings and limits: segment Code / SEGMENT_CODE 30; API Name / SEGMENT_IDENTIFIER 30; segment Name / NAME 60; Prompt / PROMPT and Short Prompt / SHORT_PROMPT 80. Reject overlength ASCII values; never truncate. For multibyte names/labels, verify the target's length semantics before claiming acceptance; API Names prohibit multibyte characters independently. Do not transfer these attribute-segment limits to a Context Name or the Context Segment selector's Prompt without their own metadata | Supplying or generating Global Segment or Context Sensitive Segment identifiers/labels; target mapping must be verified before packaging | |
| Context Code length | The published DFF segment metadata stores CONTEXT_CODE with length 80. Check the resolved Context Code against the verified target mapping and length semantics; report any conflict with an allowed InternalName rather than truncating, rewriting or choosing another code | Creating or updating Context definitions or Context Sensitive Segment associations | |
| API Name reserved words | Check Oracle's Naming Conventions for Flexfield APIs for the target release for reserved words, including SELECT, DATE and NUMBER. Its published list is not exhaustive; retain any additional target validation. Flag case variants of listed words for review rather than assuming a casing change makes them safe | Supplying or generating an API Name | |
| Generated identifiers | Show Name, Code, API Name and Prompt separately. For requested generation, propose valid values and disclose the transformation; do not claim a guessed naming algorithm is Oracle auto-population. Resolve collisions through the baseline-backed design checks, not silent suffixing | User requests generated identifiers or the same value across identifier fields | |
| Update identity | Resolve the original segment from the verified baseline. Reject a requested change to an existing segment Code or API Name; do not implement it by delete-and-recreate. A Prompt change is a separate property change, not an identifier rename | Updating an existing segment | |
| UI experience | Apply the documented defaulting resource when Display Type is omitted; do not ask for UI experience solely to choose that authorized default. If another requested behavior depends on an unknown UI, ask the specific remaining question. An omitted UI is not evidence that the environment uses Redwood | Context Segment configuration or UI-dependent validation | |
| Selector parameter terminology | Distinguish the Product Context display label from the exact PRODUCT_CONTEXT token. Default Value and optional Derivation Value are separate properties; verify their target field mappings. Distinguish omission from an explicit alternative or request to leave blank. Do not require Derivation Value or force equality with Default Value; use ora_defaulting_rules.md for eligible omissions. Preserve existing values on unrelated partial updates; an explicitly selected Product Context parameter uses PRODUCT_CONTEXT, not its display label. Do not invent an extra archive column or apply selector derivation to child defaults | Resolving Context Segment parameter settings for either UI experience | |
| Numeric constraint shape | Maximum length and precision must be positive integers; scale must be an integer. Whole-number requests require scale 0. These input checks do not establish Oracle-supported ranges or value-set compatibility; the design rules evaluated through Task Hook own those checks | String or Number constraints are supplied | |
| Required flags and ordering | Normalize explicit Yes/No or true/false values; do not interpret missing or unrecognized text as false. Resolve requested first/second/third ordering against the baseline without resetting existing sequences; show generated sequence numbers for review | Creating segments or changing required flags or order | |
| Duplicate proposed identities | Flag repeated Name, Code or API Name identities in the same requested flexfield and applicable context namespace, even when the Prompts differ. Case-only API Name variants collide: this check follows the published unique index's UPPER expression, not permission to rewrite names. Preserve language/translation scope for names and labels; existing-state and cross-scope collisions belong to the baseline-backed design rules | Multiple input rows or sources | |
| Conflicting sources | Compare prompt, runbook and supplied spreadsheet values for the same segment; stop on differing type, name, scope, length, precision, scale, required flag, column, order or default until the user resolves the conflict. An explicit correction resolves the affected earlier intended value; revalidate affected findings and approvals, without discarding unrelated confirmed details | Multiple sources describe the same segment | |
| Default versus example value | Distinguish an explicitly requested setup default from transaction test data. If the meaning of a supplied value is ambiguous, ask. Do not turn a sample date, today's date or a blank cell into a setup default; preserve unspecified existing defaults on updates | Default or example data is supplied, omitted or withdrawn | |
| Optional artifacts | Accept complete prompt or runbook input without a spreadsheet or test plan. When a request depends on an unavailable attachment or referenced case, ask for only the missing intended details or artifact; do not claim it was read or make that artifact mandatory for unrelated requests | Prompt-only, runbook-only or artifact-assisted input | |
