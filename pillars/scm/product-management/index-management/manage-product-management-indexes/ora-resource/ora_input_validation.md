# Input Validation

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Single-index request | One environment; exactly one scalar requested index name and its own attribute additions/removals or explicit rebuild request | Stop before index-specific Fusion lookup or artifact preparation | Ask the user to select one index if multiple were supplied. Persist one `single-index-request.json` and run `index_work_item_guard.py --request` on it. | Any requested indexed-attribute change or rebuild | index_work_item_guard |
| Registered Data Loader business object | productManagementESIndexedAttributes | Stop before sample generation or import planning | Provide the registered business object named in the task skill | Always | verify_product_management_es_indexed_attributes_business_object |
| Indexed attribute change or rebuild selection | Canonicalized IndexName; requested additions and/or removals, or an explicit index rebuild request; AttributeName, GroupCode, and ObjectCode or one user-confirmed scope candidate for every requested addition | Stop before metadata lookup or payload preparation | Provide the canonicalized index name and either at least one requested addition/removal or an explicit rebuild request. Validate the index name against lookup type ORA_EGP_PM_ES_INDEXES. When GroupCode or ObjectCode is absent for a requested addition, use the available-attributes lookup to propose one scope candidate for user confirmation. | When changing indexed attributes or explicitly rebuilding an index | resolve_product_management_index_code |
| Indexed attribute removal selection | RestAction DELETE; canonicalized IndexName; AttributeName; GroupName; ObjectName; optional AttributeId | Stop before payload preparation | Provide the exact removal identity. Resolve the backend-issued AttributeId directly from the Product Management Indexed Attributes REST collection, and verify any user-supplied AttributeId against that exact record. | When removing an indexed attribute | resolve_existing_product_management_es_indexed_attribute |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Business object identity | Accept only productManagementESIndexedAttributes; reject a blank or different value | Always | verify_product_management_es_indexed_attributes_business_object |
| One-index scope | Require one scalar requested index name; reject index lists, batch work items, and attribute rows that name a different index. Multiple attributes for the same index are valid. | Before invoking this task's single-index validation nodes | index_work_item_guard |
| Canonical index readiness | Resolve the one requested name through the existing exact lookup. Run `index_work_item_guard.py --request <single-index-request.json> --mutation-ready` before any Data Loader or ESS approval, including rebuild-only work with no ZIP. | Before any Data Loader or ESS submission | resolve_product_management_index_code |
| Immutable artifact index boundary | After the exact canonical IndexName is populated, require every data row in the final immutable ZIP to use that same IndexName. Run `index_work_item_guard.py --archive <final-zip>` before Task Hook validation and approval; restart preflight if the ZIP changes. | Every nonempty Data Loader change set | index_work_item_guard |
| Index scope input | Require nonblank canonicalized IndexName and either at least one requested addition/removal or an explicit rebuild request. For POST, require AttributeName plus GroupCode and ObjectCode after scope resolution or user confirmation. For DELETE, require AttributeName, GroupName, and ObjectName. A rebuild-only request has no user attribute scope; it must calculate the seeded-attribute repair delta. If IndexName is absent, request the canonicalized index name and the scope fields required for the selected action. | When adding, removing, or explicitly rebuilding an indexed attribute index |  |
| User-provided index name | Validate the supplied name against both LookupCode and Meaning in lookup type ORA_EGP_PM_ES_INDEXES, case-insensitively and with exact equality. Require one unique matching LookupCode and use that exact returned code as IndexName for later lookups. | When adding, removing, or explicitly rebuilding an indexed attribute index | resolve_product_management_index_code |
| Indexed attribute scope resolution | After the index-name lookup returns its exact LookupCode, when IndexName and AttributeName are supplied but GroupCode or ObjectCode is blank, run the available-attributes lookup. If it yields one scope candidate, present it for user confirmation; do not populate it automatically. | RestAction is POST with partial scope | resolve_indexed_attribute_scope |
| Indexed attribute scope validation | Require nonblank IndexName, GroupCode, ObjectCode, and AttributeName after the user confirms a resolved candidate or supplies scope directly, then validate the exact attribute against Fusion. | RestAction is POST | validate_index_available_attribute |
| AttributeId for new indexed attribute | Allow AttributeId to be blank or omitted; do not synthesize a value because Fusion generates the surrogate ID | RestAction is POST |  |
| AttributeId for indexed attribute removal | Resolve one backend-issued AttributeId using the exact canonical IndexName, AttributeName, GroupName, and ObjectName. If the narrow query returns zero rows, use the resolver's complete index-only fallback and require one exact local name match. If supplied by the user, require it to equal the resolved ID. Do not synthesize, infer, or reuse an ID from another attribute. | RestAction is DELETE | resolve_existing_product_management_es_indexed_attribute |
| Attribute identity normalization | Normalize seeded, requested-addition, and existing rows only as AttributeCode#GroupCode#ObjectCode. Preserve the three exact returned codes; do not compare display names or derive missing codes. For a rebuild-only request, compare every seeded identity with existing rows and prepare POST rows only for missing seeded identities. | When calculating additions or an explicit rebuild-only repair delta | resolve_seeded_indexed_attributes |
