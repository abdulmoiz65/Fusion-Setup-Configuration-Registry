## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Registered business-object metadata is unavailable or incomplete | Stop before sample generation or import planning and report the failed metadata stage without substituting another endpoint or business object. |
| User-provided index name is supplied | Use resolve_product_management_index_code before calling indexAvailableAttributes. It may match exactly against LookupCode or Meaning, but only the resolver's unique returned LookupCode may be used as IndexName in later requests. |
| Index scope is incomplete | After IndexName is verified by resolve_product_management_index_code, use resolve_indexed_attribute_scope. Present exactly one returned GroupCode and ObjectCode pair for confirmation; do not automatically accept it. When IndexName is missing or zero or multiple pairs remain, request IndexName, GroupCode, and ObjectCode. |
| Indexed attribute is being removed | After the canonical index, seeded, and existing-index lookups, use resolve_existing_product_management_es_indexed_attribute to obtain and verify its backend-issued AttributeId from the exact IndexName, AttributeName, GroupName, and ObjectName. If the narrow query returns zero rows, use that resolver's complete index-only fallback and match those same four names locally. Do not use indexAvailableAttributes to resolve a DELETE row; it may still be used to validate a separate missing seeded POST candidate. |
| Available-attribute validation is unavailable, ambiguous, or incomplete | Stop before POST payload preparation and import planning; do not infer an attribute code or target context. |
| Seeded metadata is unavailable or malformed | Stop before addition-delta calculation and import planning; do not infer seeded attributes. |
| Existing indexed-attribute lookup is unavailable or malformed | Stop before addition-delta calculation and import planning; do not assume an attribute is absent. |
| A user-requested terminal Data Loader status is successful | Invoke `verify_loaded_index_attribute_delta`, persist `readback_verified` only after every submitted change verifies, then prepare the ESS approval payload in the same response. |
