# Manage Import Maps Dependency Readiness

## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Create-only import-map defaults | For REST create requests, default each missing, null, or whitespace-only field independently; preserve explicit create values and omitted update values |
| 2 | Missing ItemClassName resolution | Only when the REST request is a create and ItemClassName is absent, null, or whitespace-only, GET or reuse the matching cached ROOT_ICC item-class response and fill ItemClassName from ItemClass |
| 3 | Conditional import-map format lookups | Resolve each supplied or defaulted display value to one exact LookupCode or preserve an explicitly supplied LookupCode |
| 4 | Mapping-pair validation | Accept source-only mappings; reject every destination mapping without its corresponding source column and return MISSING when a REST transformation lacks a destination mapping |
| 5 | Destination attribute resolution | When a destination mapping is requested, GET and cache importMapAttributes, require one exact current item, derive all four required destination payload values from it, and copy LanguageCode when non-null |
| 6 | Transformation function validation | For each REST transformation, parse the function candidate from ExpressionCode and validate it through importMapFunctions; disclose FunctionSyntax and Examples as advisory guidance when syntax differs |
| 7 | Transformation return-attribute resolution | Build ReturnAttributeName from the exact destination item, appending LanguageCode only when non-null |
| 8 | Transformation source-column derivation | Build SourceColumns from the current source and every participating source in supplied order, including the current source again in the suffix |
| 9 | Source IgnoreFlag normalization | Set IgnoreFlag to Y for source children without destinations and N for mapped source children |
| 10 | Data Loader handoff | Continue only when required standard values, ItemClassName default, destination metadata, transformation function, ReturnAttributeName, and SourceColumns are resolved; syntax advisories do not block |
| 11 | FSM ZIP readiness | On the FSM route, continue with the same immutable ZIP only after archive validation and destination reporting complete, with no multiple-match blocker |

## Dependency Classification

| Result Category | When Used | Can Run Lookup/Create? |
|---|---|---|
| Satisfied | An explicit LookupCode is supplied, a resolver returns exactly one result, or local transformation derivation completes | No further lookup; never create |
| Advisory | A matched transformation's trimmed ExpressionCode differs from trimmed FunctionSyntax | No additional lookup; disclose FunctionSyntax and Examples and continue |
| Lookup | A required display value, destination identity, or transformation function can be resolved with a documented read-only lookup | Lookup only |
| Blocked | A required value is missing, unresolved, ambiguous, or the read-only request fails | No |
