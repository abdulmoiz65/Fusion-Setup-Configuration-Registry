# Reference Lookups

Only run a resolver when user-supplied input meets its `Runs When` condition; do not issue an unconditioned lookup. Use the declared `core.fusion-api.apps-common.lookups` capability for each required read-only lookup; on a lookup error, return its sanitized diagnostic and stop the affected record before preview or submission.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Explicit create request with Status Name only | Derive StatusCode with `derive_status_code_from_name`; traverse the item-status collection and compare returned codes case-insensitively, then query the supplied name exactly. Continue only when no code collision and no name collision are found. |
| Only Status Name is supplied | Run resolve_item_status_identity and fill StatusCode from the one exact returned record. |
| A derived Status Code collides but the supplied Status Name does not | Derive the first available numbered candidate with `derive_unique_status_code`; show that candidate and the supplied Status Name for confirmation. |
| A Status Code was derived from Status Name | Present the available derived or numbered StatusCode and StatusName to the user and wait for confirmation. On confirmation, run `reverify_confirmed_status_code_availability` before preview, payload construction, or submission. On rejection or no confirmation, stop the affected record without re-verification. |
| Only Status Code is supplied | Run resolve_item_status_identity and fill StatusName from the one exact returned record. |
| Both Status Code and Status Name are supplied | Run resolve_item_status_identity to reconcile the supplied pair; continue only if both values identify the same returned record. |
| Neither status identity field is supplied | Do not run resolve_item_status_identity; validation reports both required fields as missing. |
| Item-status identity lookup is zero-match, ambiguous, conflicting, or fails to read | Stop before preview, payload construction, or setup-data submission and report a sanitized diagnostic or request an exact existing Status Code or Status Name. |
| Confirmed derived or numbered Status Code or Status Name is no longer available, the code collection cannot be completely traversed, or either lookup is unreadable | Stop before preview, payload construction, or setup-data submission and report that availability is not confirmed. |
| StatusControl is omitted | Do not run resolve_status_control; use the documented default None. |
| StatusControl lookup succeeds | Accept the supplied exact LookupCode or Meaning as a member of EGP_STATUS_CONTROL_CODES. When a Meaning is supplied, retain that display value in StatusAttributeValue.StatusControl and record the matching LookupCode; do not replace the payload value with the code. |
| StatusControl lookup is zero-match or ambiguous | Stop before preview, payload construction, or setup-data submission. A code and a meaning that resolve to different rows are ambiguous. |
| StatusControl lookup read fails | Stop and report a sanitized transport, authorization, or Fusion API diagnostic. |
| No operational attributes are provided | Do not validate AttrDispName or run resolve_item_operational_attribute; continue without an AttrName mapping. |
| A specific operational-attribute lookup succeeds | Use the exact returned AttrName for the requested status-attribute update or lookup result; retain the supplied AttrDispName as the display-name evidence. |
| An operational-attribute list lookup succeeds | Return the available AttrDispName and AttrName pairs; do not select one automatically. |
| An operational-attribute lookup is zero-match, ambiguous, or fails to read | Stop before preview, payload construction, or setup-data submission and report a sanitized diagnostic or request an exact AttrDispName. |
