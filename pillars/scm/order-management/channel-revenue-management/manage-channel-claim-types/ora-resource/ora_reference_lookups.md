## Lookup Execution Rules

Use worksheet/header ownership from ora_input_validation.md when selecting lookup inputs. Read reference-data-set identifiers only from the associated parent SetId, SetCode or SetName. BUMappingCode is a child mapping value and is never a reference-data-set lookup input. Include the source worksheet, row, and header in lookup evidence so a failed lookup can be traced back to the correct cell.

| Situation | What Happens |
|---|---|
| Reference data set lookup | Run resolve_reference_data_set through the FSCR Run Book before preparing the channelClaimTypes Data Loader preview. |
| Business Unit lookup | Create: verify a supplied ID or resolve a supplied name; cross-check both when supplied. Retain/populate BusinessUnitId and remove intake-only names. Update: run only for a non-null requested BusinessUnit change; retain the new BusinessUnit name as the writable field and do not substitute the resolved ID into PATCH. Compare optional BusinessUnitId to the proposed BU only on create; on update it cross-checks the existing mapping in find_existing_bu_mapping. No new name means not_applicable, not a missing create field. |
| Claim-type identity lookup returns zero records | Permit creation only for explicit create intent; update blocks NOT_FOUND. |
| Claim-type identity lookup returns an exact code and set match | Create blocks DUPLICATE. Update continues to existing-child lookup (not_applicable when no children), then update validation. |
| AR-related optional value is supplied | Do not issue an AR lookup. Preserve the value for Data Loader and disclose that FSCR validation is unavailable. |
| A Data Loader-authorized write has an uncertain outcome | Reconcile through the FSCR Run Book using fresh read-only evidence; never repeat the mutation automatically. |

All lookups use core/fusion-api/rest-api-client with REST-Framework-Version: 9. Escape Fusion string literals, URL-encode queries and server-returned path keys, follow pagination and reject off-host links. Use these declared GETs for update preparation before final Data Loader preflight; Task Hook subsequently validates that exact artifact using the evidence. Source: Oracle [child collection GET](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26b/fasrp/op-channelclaimtypes-claimtypeid-child-businessunitlevelmappings-get.html). Do not construct a parent ID from a name or mapping code.

BU ID/name lookup contract: Oracle [26C Financials Business Units LOV](https://docs.oracle.com/en/cloud/saas/financials/26c/farfa/op-finbusinessunitslov-get.html) exposes both fields as queryable. An ID-only create must not require the user to supply the returned name. BUMappingCode is never a BU name or lookup identifier.

Set ID lookup source: Oracle [ADF set ID sets GET](https://docs.oracle.com/en/cloud/saas/applications-common/25c/farca/op-http-servername-fscmrestapi-resources-11.13.18.05-setidsets-get.html) documents the PrimaryKey finder and SetId/SetCode/SetName response. The equivalent 26C ADF page was unavailable at authoring; [26C set ID sets documentation](https://docs.oracle.com/en/cloud/saas/applications-common/26c/farca/op-https-servername-api-boss-data-objects-ora-commonappsinfra-objects-v1-setidsets-get.html) describes a different BOSS route, not an automatic fallback. Verify the declared ADF lookup in the selected instance during preparation; fail closed if unavailable. Never infer a set ID from a BusinessUnitId or digits in a code/name.
