| ORA_CJM_MANAGE_ADJ_TYPES | Manage Channel Adjustment Types | The reference data set lookup returns no or multiple matches | Stop the preview. For no match, create the reference data set through ERP Manage Reference Data Sets, then retry. For multiple matches, provide an exact SetName. |
| ORA_CJM_MANAGE_ADJ_TYPES | Manage Channel Adjustment Types | The adjustment-type identity lookup returns zero records | Stage parent RestAction POST and omit AdjustmentTypeId for that AdjustmentTypeCode; do not request an operation from the user. |
| ORA_CJM_MANAGE_ADJ_TYPES | Manage Channel Adjustment Types | The adjustment-type identity lookup returns exactly one record | Stage the returned AdjustmentTypeId and parent RestAction PATCH. |
| ORA_CJM_MANAGE_ADJ_TYPES | Manage Channel Adjustment Types | Source-record reconciliation produces one or more AdjustmentTypeCodes | Run find_adjustment_type_by_code once for each reconciled code; do not prepare the archive until every code has an internally generated POST or PATCH action. |

| ORA_CJM_MANAGE_ADJ_TYPES | Manage Channel Adjustment Types | An adjustmentReasons row belongs to a parent created in the same archive | Generate child RestAction POST and preserve the same-archive AdjustmentTypeCode linkage; no child lookup is possible before the new parent exists. |
| ORA_CJM_MANAGE_ADJ_TYPES | Manage Channel Adjustment Types | A REST write has an uncertain outcome | Reconcile with fresh read-only GET requests; never repeat the mutation automatically. |

Do not use direct lookup REST operations as an FSM import route. |
| ORA_CJM_MANAGE_CHANNEL_LOOKUPS | Manage Channel Lookups | Lookup values are included in an FSM package | Let core.data-loader and Fusion validate the package; do not infer a direct REST create, update, delete, or bulk operation. |
