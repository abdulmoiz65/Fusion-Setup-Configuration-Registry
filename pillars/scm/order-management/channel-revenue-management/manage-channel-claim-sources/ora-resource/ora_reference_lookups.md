## Lookup Execution Rules

For create_child, resolve_existing_claim_source uses the same exact identity GET and match rule as update. Do not run find_claim_source_duplicate: the parent must already exist. Resolve method/accounting values, then find_settlement_method_duplicate before readiness. Reuse the verified parent for post-submission child reads.

| Situation | What Happens |
|---|---|
| Request construction | GET only through the workflow-selected shared REST client; quote and escape string filters and URL-encode parameters; exact comparisons after complete pagination; no prefix or first-match selection. Follow verified server identity rather than inventing resource keys. |
| Ordering | During update preparation resolve set identity when needed, parent, then each child before changed-reference resolution. During graph evaluation RESOLVE_EXISTING owns existing targets; RESOLVE_REFERENCES owns applicable create duplicate and proposed-value resolvers. Skip inapplicable resolvers explicitly. |
| Default reference set eligibility | For both default type and reason, accept a reference when its verified SetCode equals the source SetCode OR is COMMON. A COMMON source therefore accepts COMMON references only. A specific-set source accepts its own set and COMMON, not another specific set. Missing set evidence blocks; identify COMMON by verified SetCode, not a guessed display name or assumed numeric ID. |
| Default reference ambiguity | Filter complete exact-name candidates to eligible sets before counting matches. If both the specific set and COMMON contain the name, do not infer precedence or choose the first match; request an exact ID or explicit reference-set selection. A supplied ID still must pass set eligibility and agree with any independently proposed name. Do not change the source set, blank the reference, or create a dependency to avoid a lookup failure. |
| Null or omitted update reference | Omitted is unchanged; an explicit clear does not require a new reference lookup, but must pass nullable, seeded, and loader-encoding gates. |
| Verification or stale baseline | Reuse existing-target resolvers for fresh reads and post-submission comparison. Detect drift against the trusted export baseline; do not overwrite a concurrently changed value silently. Refresh during preparation, never modify an approved artifact. |
| Missing predefined evidence | SeededFlag true identifies a predefined child. False establishes non-predefined status; null, missing, or inconsistent evidence is unknown and blocks AccountingFor changes until authoritatively resolved. Other permitted edits do not require assuming false. |

## Reference Set Sources

Oracle 26C describes the Common Set as globally shared for [Claim Type](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26c/fabsm/bo_oraScmCoreChannelSetup_ClaimType.html), [Claim Reason](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26c/fabsm/bo_oraScmCoreChannelSetup_ClaimReason.html), and [Claim Source](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26c/fabsm/bo_oraScmCoreChannelSetup_ClaimSource.html). The source-set-or-COMMON eligibility rule incorporates the user-supplied directional assignment correction; it is not permission for arbitrary cross-set assignment. Applies to create and changed references on update.
