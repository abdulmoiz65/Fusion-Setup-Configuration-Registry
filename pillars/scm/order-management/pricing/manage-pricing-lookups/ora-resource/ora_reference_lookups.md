## Live Lookups

| Resolver | Runs When | Source Values | Request Path or URL | Requested Fields | Match Rule | Values to Fill | If No Match or Many Matches |
|---|---|---|---|---|---|---|---|
| resolve_pricing_lookup_type | A request identifies a Pricing lookup type before inspection or change | User-supplied Lookup Type from the supported Standard Lookup allowlist | Routed by `core.fusion-api.apps-common` to its `lookups` child skill | LookupType and the returned lookup identity | Require an allowlisted value and exactly one returned lookup whose LookupType exactly matches it | Confirmed lookup type | Stop when the supplied type is not allowlisted, on no exact match, more than one match, or a failed read-only request. Do not infer a lookup type. |
| resolve_pricing_lookup_code | A request creates, changes, or validates a lookup code after its lookup type resolves | Confirmed allowlisted Lookup Type and user-supplied Lookup Code | Routed by `core.fusion-api.apps-common` to its `lookups` child skill | LookupCode, Meaning, Description, EnabledFlag, StartDateActive, EndDateActive, and DisplaySequence | Compare LookupCode exactly. A single matching returned code is existing; zero returned codes is available for a documented create request. | Existing lookup-code facts or an available-for-create outcome | Stop on an ambiguous result or a failed read-only request. Do not infer an existing code or overwrite it. |

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A lookup type or code must be inspected | Route the read-only lookup through `core.fusion-api.apps-common`, which selects its `lookups` child skill and returns the documented lookup facts. The request is not authorization to create, update, or delete a lookup. |
| A lookup identity is required | Accept only a lookup type from the supported Standard Lookup allowlist. Obtain the exact code and value from the approved business requirement and applicable Oracle source. |
