## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| The lookup is requested | Send a read-only GET request to the documented endpoint. Do not create, update, enable, disable, import, or infer business event trigger-point configuration. |
| The lookup response is returned | Use only returned, sanitized trigger-point detail facts for validation, planning, and verification. Do not persist credentials, tokens, opaque URLs, or protected runtime material. |
| An event activation or inactivation request is validated | Send a read-only GET request to the documented lookup-code endpoint, matching the user-supplied event meaning exactly before mapping the returned lookup code to EventCode. |
| An explicit parent-event enable request has resolved the lookup code for the requested event name | Send a read-only GET request to `/fscmRestApi/resources/11.13.18.05/omBusinessEventDetails?q=LookupCode='<resolved LookupCode>'`; match returned LookupCode exactly to the event-trigger-point LookupCode and, when present, require EventCode to match it as well. Classify EventDetailId -1 as create and leave the parent-event source EventDetailId blank; otherwise classify the parent-event action as update using the returned EventDetailId. |
| An Order Header Status Update event includes a status value | Send a read-only GET request to the documented Order Header Status Update endpoint, matching the user-supplied status value exactly to Display Name before mapping the returned Event Criteria Id to EventCriteriaId. |
| An `ORDER_ATTRIBUTE_UPDATE` request includes one or more triggering attributes | Send a read-only GET request to `/fscmRestApi/resources/11.13.18.05/omBusinessEventDetails/ORDER_ATTRIBUTE_UPDATE/child/eventOrderAttributesLOV`. For each supplied attribute, match AttributeName exactly and retain the matched EventCriteriaId; stop if any supplied attribute has zero or multiple exact matches. |
| An `ORDER_ATTRIBUTE_UPDATE` add, removal, or re-add is requested | Retrieve configured attribute rows through the authoritative detail retrieval route. Compare only EventCriteriaId values after exact attribute resolution. For add or re-add, create a new row with EventEnabledFlag true for each unambiguously missing requested attribute, set true on each matching row that is false, and report every matching row already true as a duplicate without preparing it. For removal, retain matching rows and set EventEnabledFlag false. Stop when the configured detail retrieval is incomplete or ambiguous. |
