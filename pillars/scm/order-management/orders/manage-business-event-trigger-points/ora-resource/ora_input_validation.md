# Manage Business Event Trigger Points Input Validation

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Business event trigger-point detail retrieval | No caller-supplied fields; retrieve the configured business event trigger-point details from Fusion | Stop before reporting business event trigger-point details | Use the documented live lookup | A request retrieves business event trigger-point details | get_business_event_trigger_point_details |
| Business event trigger-point configuration request | Event meaning; activate or inactivate intent only when an explicit parent-event row is requested | Stop before configuration preview or import preparation | Provide the event meaning. Provide activate or inactivate when explicitly enabling or inactivating the parent event row. | Any request that changes business event trigger-point configuration | resolve_event_code_by_meaning |
| Connector or service setup data | Connector or service value and its configuration fields | Stop before source preparation | Route the setup-data import to the registered REST Data Loader `connectors` business object | A connector or service is specified | resolve_setup_data_business_object |
| Activation action selection | `LookupCode` resolved for the requested event name | Stop before configuration preview or import preparation | Query `omBusinessEventDetails` with `q=LookupCode`, match the returned LookupCode to the resolved LookupCode, and derive ConfigurationAction from EventDetailId | An activation request has passed event-code validation | resolve_existing_business_event_detail_for_activation |
| Order Header Status Update event criteria | Status value | Stop before configuration preview or import preparation | Provide the status value to match against the returned Display Name | The event is Order Header Status Update and a status value is supplied | resolve_order_status_update_event_criteria_id |
| Order Attribute Update event criteria | One or more triggering attribute names | Stop before configuration preview or import preparation | Match every supplied attribute exactly against returned AttributeName values from `eventOrderAttributesLOV` | The event is `ORDER_ATTRIBUTE_UPDATE` and one or more triggering attributes are supplied | resolve_order_attribute_update_event_criteria |
| Existing Order Attribute Update attribute rows | Configured attribute rows and EventEnabledFlag values | Stop before add, removal, or re-add source preparation only when the configured response is incomplete or ambiguous | Retrieve configured attribute rows, compare EventCriteriaId per requested attribute, and derive create, removal, re-enable, or duplicate behavior | The event is `ORDER_ATTRIBUTE_UPDATE` and an add, removal, or re-add request is supplied | resolve_existing_order_attribute_update_attributes |
| Business event trigger-point write contract | Live `eventDetails` Data Loader metadata and the `core.data-loader` REST import contract | Stop before source preparation | Refresh the BO metadata and resolve the mismatch | Any request that changes business event trigger-point configuration | validate_data_loader_contract |

## Dependency-Aware Validation

| Applies When | Result | Next Action | Resolver |
|---|---|---|---|
| A request retrieves business event trigger-point details | The supplied endpoint is the authoritative live source for configured trigger-point details | Continue to the documented read-only lookup | get_business_event_trigger_point_details |
| A request changes business event trigger-point configuration | Validate the event meaning against the configured DOO event trigger-point lookup codes and derive EventCode from the uniquely returned lookup code | Continue to the documented live lookup | resolve_event_code_by_meaning |
| An activation request has resolved the `LookupCode` for the requested event name | Resolve one existing business event detail through `q=LookupCode`, then derive ConfigurationAction: create when EventDetailId is -1 and leave the source EventDetailId blank; otherwise update with the returned EventDetailId | Continue to configuration-action defaulting | resolve_existing_business_event_detail_for_activation |
| An Order Header Status Update request includes a status value | Validate the status value against the returned Display Name and map the corresponding Event Criteria Id | Continue to the documented live lookup | resolve_order_status_update_event_criteria_id |
| An `ORDER_ATTRIBUTE_UPDATE` request includes one or more triggering attributes | Validate every supplied attribute against the returned AttributeName values, map each matching Event Criteria Id, and prepare one implicit-enablement attribute row per match | Continue to the documented live lookup | resolve_order_attribute_update_event_criteria |
| An `ORDER_ATTRIBUTE_UPDATE` add, removal, or re-add request has resolved attribute criteria | Compare each requested EventCriteriaId with configured attribute rows. For removal retain a matching row and set its flag false. For add or re-add, create a new row when no matching configured row exists, re-enable a matching disabled row, and report each already-enabled row as a duplicate without preparing it. | Continue only when the configured rows provide an unambiguous comparison; an unambiguous missing row is a create action | resolve_existing_order_attribute_update_attributes |
| A configuration change has passed event-code validation, activation action selection when applicable, and EventEnabledFlag defaulting | The registered `eventDetails` metadata and `core.data-loader` contract provide the supported source, UCM upload, initiation, approval, and verification workflow | Route to `core.data-loader` for source validation and the immutable approval workflow | validate_data_loader_contract |
| A connector or service is specified | Use registered REST Data Loader business object `connectors` instead of `eventDetails` for the connector or service setup-data source; retain the same `core.data-loader` validation, approval, and submission workflow | Continue to Data Loader contract enforcement | resolve_setup_data_business_object |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Detail retrieval contract | Retrieve the configured business event trigger-point details through the documented read-only lookup. Do not infer missing response fields or configuration state. | A request retrieves business event trigger-point details | get_business_event_trigger_point_details |
| Event meaning | Accept an event meaning only when exactly one lookup record returns that meaning. Map its lookup code to EventCode. | Any request that changes business event trigger-point configuration | resolve_event_code_by_meaning |
| Existing business event detail | For an activation request, query omBusinessEventDetails with the `LookupCode` returned for the requested event name and accept one returned record whose LookupCode exactly matches it. When EventCode is returned, it must match the same LookupCode. Map EventDetailId -1 to ConfigurationAction create and leave the source EventDetailId blank; otherwise map it to update with the returned EventDetailId. | An activation request after LookupCode resolution | resolve_existing_business_event_detail_for_activation |
| Order Header Status Update status value | Accept a status value only when exactly one returned Order Header Status Update record has the corresponding Display Name. Map the returned Event Criteria Id to EventCriteriaId. | The event is Order Header Status Update and a status value is supplied | resolve_order_status_update_event_criteria_id |
| Order Attribute Update explicit event row | Prepare a separate parent-event row with EventCriteriaId -1 only when explicit enablement or inactivation is requested. Map its EventEnabledFlag from that explicit intent. Do not prepare or alter this row for an attribute add, removal, re-add, or duplicate-only request. | The event is `ORDER_ATTRIBUTE_UPDATE` and an explicit parent-event action is supplied | resolve_existing_business_event_detail_for_activation |
| Order Attribute Update trigger attribute | Accept a supplied trigger attribute only when exactly one returned `eventOrderAttributesLOV` record has an AttributeName exactly equal to it. Map the returned Event Criteria Id and retain the matched AttributeName in a separate attribute row. | The event is `ORDER_ATTRIBUTE_UPDATE` and one or more triggering attributes are supplied | resolve_order_attribute_update_event_criteria |
| Order Attribute Update attribute event enabled flag | Set EventEnabledFlag to true, overriding a supplied false value, on each attribute row. | The event is `ORDER_ATTRIBUTE_UPDATE` and one or more triggering attributes are supplied | resolve_order_attribute_update_event_criteria |
| Order Attribute Update attribute removal | Retain each matched attribute row and set EventEnabledFlag false. Do not use DELETE. | The event is `ORDER_ATTRIBUTE_UPDATE` and matching attributes are requested for removal | resolve_existing_order_attribute_update_attributes |
| Order Attribute Update attribute add or re-add | For each requested EventCriteriaId, create a new row with EventEnabledFlag true when no configured row exists. When a matching configured row is false, set it true. When it is already true, report that row as a duplicate and prepare no import row for it. | The event is `ORDER_ATTRIBUTE_UPDATE` and attributes are requested for add or re-add | resolve_existing_order_attribute_update_attributes |
| Fixed event criteria | Set EventCriteriaId to -1, overriding any supplied value, when EventCode is `CANCEL_BACKORDERS`, `CHANGE_COMP_COMPLETE`, `FULFILL_LINE_CLOSE`, `FLINE_STATUS_UPDATE`, `HOLD`, `RELEASE_HOLD`, or `SPLIT`. | The resolved EventCode is in the fixed-criteria list | |
| Explicit parent-event intent | Accept activate or inactivate only when an explicit parent-event row is requested. Map activate to EventEnabledFlag true and inactivate to EventEnabledFlag false. Reject another or ambiguous explicit parent-event intent. | Any request that requests an explicit event row | |
| Setup-data business object | Use `connectors` whenever a connector or service is specified; otherwise use `eventDetails` for event-detail setup data. | Before source preparation | resolve_setup_data_business_object |
| Configuration write contract | Do not call a direct business-object POST or PATCH. Prepare a validated `eventDetails` or `connectors` DAT/ZIP source selected by the setup-data business-object rule, then use the UCM upload and `initiateDataLoad` request body defined by `core.data-loader`; submit only after its task-validation and explicit approval gates pass. | Any request that changes business event trigger-point configuration | validate_data_loader_contract |
