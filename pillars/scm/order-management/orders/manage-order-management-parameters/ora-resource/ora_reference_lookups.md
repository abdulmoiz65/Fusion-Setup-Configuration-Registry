# Manage Order Management Parameters Reference Lookups

Use `qpParameters` only to retrieve and identify parameters whose `ParameterUsageCode` is `FOM`, `CMN`, or `DOO`. It is a read-only lookup resource. Use the returned `ParameterId` as `{id}` in the read-only `qpParameterValues` child-resource lookup. The task's separately approved REST Data Loader workflow continues to use `qpParameterValues` as its business object for value changes.

Oracle's [Manage Order Management Parameters — 26c](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26c/faiom/manage-order-management-parameters.html#Order-Management-Parameters) guide is the source for parameter behavior; the REST lookup contracts below are task-specific developer-provided mappings.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| The parameter definition must be identified | Send only GET /fscmRestApi/resources/11.13.18.05/qpParameters?q=ParameterUsageCode=FOM OR CMN OR DOO&limit=500. Do not broaden the filter or POST, PATCH, PUT, or DELETE through this resolver. |
| A returned parameter is outside the allowed usage scope | Stop. Do not use or prepare that parameter through this task. |
| Current values are needed after the definition is identified | Map qpParameters ParameterId to {id}, then send only GET /fscmRestApi/resources/11.13.18.05/qpParameters/{id}/child/qpParameterValues. Do not use this lookup to create or change a value. |
| A current parameter-value row is updated | Prepare the `PATCH` row with its returned `ParameterValueId` and the canonical parent `ParameterId` from `resolve_order_management_parameter`. Do not infer the parent identifier from the child identifier. |
| A source-order-system-level parameter receives All | Prepare the parameter value with source-system value All. Do not call the source-system lookup. |
