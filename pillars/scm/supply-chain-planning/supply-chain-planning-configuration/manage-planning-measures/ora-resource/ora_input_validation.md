# Manage Planning Measures Input Validation

## Create Planning Measure Validation

### Expression, units, and operation inputs

| Input | Accepted shape and validation | Submission rule |
|---|---|---|
| `name` | Required nonblank Name. Check all existing-measure pages for an exact duplicate; a rename may match only its own MeasureId. | Send only the validated `Name`. A blank or colliding Name blocks source preparation. |
| `expression` | Optional expression text. If supplied, invoke the configured `POST /fscmRestApi/resources/11.13.18.05/planningMeasureValidateExpressions` server-side validator with the exact text, target Name, and null or empty MeasureId for create or exact existing MeasureId for edit. Require a returned Fusion validation message stating `Expression is valid`; any other returned message blocks submission and is displayed verbatim. | Map the exact validated text to `Expression`. Never submit `SeededExpression`. On duplicate, validate and include copied text even when unchanged from the source. Never omit requested text because an archive or template lacks it. |
| `editLockExpression` | Optional expression text. Require Editable and Advanced Settings, then invoke the identical validator operation separately with this text in its `Expression` request field. Require a returned Fusion validation message stating `Expression is valid`; any other returned message blocks submission and is displayed verbatim. | Map the exact validated text to `EditLockExpr`. Never submit `SeededEditLockExpr`. On duplicate, validate and include copied text even when unchanged from the source. Never omit requested text because an archive or template lacks it. |
| `baseUOMCode`, `displayUOMCodes` | Resolve every supplied exact code through the UOM LOV and deduplicate display codes. A supplied base is allowed only for Number `DataTypeId`, a non-seeded and non-read-only measure, and granularity without both `PRD` and `ORG`. Display items are forbidden for Percent, Date, or Text. | Use `BaseUOMCode` for a valid base or omit/set null when inapplicable and unsupplied; reject an explicitly supplied invalid base. Create display associations as `MeasureUOM.items[].UomCode`, never display names. For an existing measure, require the confirmed parent batch child-create contract. |
| `baseCurrencyCode`, `displayCurrencyCodes` | Resolve every supplied exact code through the Currency LOV and deduplicate display codes. A supplied base is allowed only for Currency `DataTypeId`, a non-seeded and non-read-only measure, and granularity without both `PRD` and `ORG`. Display items are forbidden for Percent, Date, or Text. | Use `BaseCurrencyCode` for a valid base or omit/set null when inapplicable and unsupplied; reject an explicitly supplied invalid base. Create display associations as `MeasureCurrency.items[].CurrencyCode`, never display names. For an existing measure, require the confirmed parent batch child-create contract. |
| `priceListNames` | Resolve each supplied Price List name to exactly one live LOV row and a numeric `PriceListId`; deduplicate IDs. A missing or ambiguous name blocks submission. | Create `MeasurePriceList.items[].PricelistId` with numeric IDs only. Never send `PriceListName` or use planningMeasureSourceLists `ListId`. |
| Duplicate identity | Require `sourceMeasureName` or `sourceMeasureId`; if both, they must identify one measure. `newMeasureName` is optional and must be unused. | Create a new parent without source MeasureId or source ListId values; source-list children wait for the returned new MeasureId. |
| Delete identity | Require `measureName` or `measureId`; if both, they must identify one measure. | No delete payload is prepared until exact identity, privilege, seeded status, associations, route, and immediate approval are resolved. |
