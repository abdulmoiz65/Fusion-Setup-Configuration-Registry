# Manage Planning Measures Lookup Outcomes

## Error Situations

### Planning Measure capability failures

| Situation | Required outcome |
|---|---|
| Expression or Edit Lock validation returns a message other than `Expression is valid` | Classify as input validation, display the returned validation detail verbatim, and stop before the measure-create or update request. Do not use local syntax checks, archived payloads, or attribute LOV success as expression validity. |
| The configured Planning Measure validator operation cannot be resolved or invoked, or its result is inconclusive | Classify as a workflow contract gap and stop before submission with `Expression validation is unavailable through the configured Planning Measure validator. The expression was not submitted.` Do not remove the expression from the payload to bypass this gate. |
| A requested UOM or currency has no exact LOV match, duplicate response matches, or an unavailable LOV | Classify as catalog mismatch or workflow contract gap. Do not invent a code or silently discard the requested association. |
| Name is blank, already used by another measure, or uniqueness lookup is incomplete | Classify as input validation or catalog mismatch and stop before source preparation. Complete pagination; do not infer uniqueness from a partial or failed response. |
| BaseUOMCode or BaseCurrencyCode is explicitly supplied outside its data-type, non-seeded, non-read-only, PRD plus ORG, or exact LOV conditions | Reject the supplied base and report the failed condition. Omit or null only an unsupplied or now-inapplicable base; do not silently accept an invalid supplied value. |
| Display UOM or currency is supplied for Percent, Date, or Text, or an unresolved or duplicate code remains | Classify as input validation or catalog mismatch. Stop before measure submission; never substitute a display name for UomCode or CurrencyCode. |
| A Price List name is missing or ambiguous, its ID is nonnumeric, duplicate IDs remain, or PriceListName/Source List ListId is mapped into MeasurePriceList | Classify as input validation or catalog mismatch. Stop before submission; retain the exact selected name and lookup outcome in safe diagnostics. |
| The parent measure batch adapter or child contract is unsupported or ambiguous | Record the route gap in the project workspace and stop. Do not call an inferred child path or send an unsupported batch. |
| Duplicate source is absent/ambiguous, target name exists, or copied settings cannot be read or mapped | Classify as input validation or catalog mismatch; do not create a partial duplicate or update the source. |
| A duplicate's source granularity is dropped, changed, defaulted, or unsupported by the selected create adapter | Classify as a workflow contract gap and stop before approval. Preserve the authoritative source granularity when the live create schema and adapter support it. Otherwise require a verified equivalent level-based mapping. Never substitute the ordinary create default or report complete duplication when readback dimensionality differs from the approved source. Keep internal identifiers out of user-facing messages. |
| Duplicate parent succeeds but a later source-list child fails | Preserve the new MeasureId and the partial success in the diagnostic; do not retry a POST automatically. Reconcile before another approved child action. |
| Delete target is predefined or has blocking manual associations | Classify as predefined-measure or manual-association failure; report the exact measure and dependency evidence without issuing DELETE. |
| Delete privilege or immediate approval is missing | Classify as authorization or approval blocker. Preserve the exact environment, MeasureId, name, and proposed operation for review. |
| Delete request fails or readback still finds the exact MeasureId | Distinguish authorization, predefined-measure, manual-association, and other API errors from the returned evidence. Do not retry automatically; persist response/status and next action. |

| Situation | What Should Happen |
|---|---|
| A requested catalog, dimension, hierarchy, planning measure, planning measure group, or requested planning level has no exact match | Stop the configuration selection and report the requested identity as missing. |
| A name-based lookup returns more than one exact match | Stop the configuration selection and require an exact identifier. |
| A lookup response identity differs from the supplied path identifier | Stop the configuration selection; do not use the returned record. |
| A selected GranularityId has no returned granularity-level record | Stop the explicit existing-granularity lookup or a create request without measure levels, and report the selected GranularityId as missing, including 135 when it was defaulted. A create request with measure levels must continue with GranularityId null. |
| A required granularity lookup returns no response | Stop before source preparation. Classify the observed client timeout, connection, DNS, proxy, or service failure as transport/environment when evidence supports it; otherwise report an unresolved read-only client failure. Persist the selected environment, sanitized request path, stage, elapsed time, HTTP status if any, and client diagnostic. Do not say the GranularityId is missing: that requires a successful complete empty result. Check the declared client and route, then retry the read-only lookup only after the failure is understood. Do not switch to an undeclared `/rest/rv:.../` route merely because a returned item's self link uses it. |
| Granularity lookup returns a missing or unsupported MeasureContextId, or a supplied context conflicts with the returned value | Stop the create request and report the exact context issue. For a valid returned value use 1 Default, 2 Project, or 3 Planning Attribute without asking the user. Do not guess a context from GranDimensions or override the REST item. |
| Granularity lookup returns HTTP 400 for an unsupported parameter such as `granularityLevels_Id` | Classify as a Fusion API lookup-contract failure and stop before source preparation. Record the request path, HTTP status, and sanitized response. Correct the declared route to the documented `granularityLevels` collection with `q=GranularityId%3D{GranularityId}`; do not report the ID as missing or retry through an undeclared endpoint. |
| GranLevels or GranLevelIds is missing, their slash-separated entry counts differ, or an ordered LevelId is blank, null, zero, or non-numeric | Stop the explicit existing-granularity lookup or a create request that relies on GranularityId. For a create request with supplied levels, validate the supplied ordered LevelsList entries instead; do not construct a partial or fallback level list. |
| GranDimensions appears to have a different order from GranLevels or GranLevelIds | Continue only with the GranLevels/GranLevelIds positional pairs. GranDimensions is a participating dimension-code set, not an ordered pairing source. |
| isShared is supplied with a value other than 1 or 2 | Do not create the measure or prepare a Data Loader source; report that 1 means Shared across plans and 2 means Specific to plan. |
| Collected and Refreshed is selected but StoreResult is not 1, or Editable and Persistent is selected but Editable is not 1 | Do not create the measure or prepare a Data Loader source; report the inconsistent selected state and required payload value. |
| A supplied create LevelsList is missing, blank, zero, or non-numeric | Do not create the measure. Report the invalid level selection and do not substitute a GranularityId or infer a fallback list. |
| MeasureContextId is not 1, 2, or 3 | Do not create the measure. Report the unsupported context and require Default, Project, or Planning Attribute. |
| A selected Plan Type meaning or bit number has no declared mapping in this skill | Skip the unmapped selection and record it in internal validation evidence without treating it as an error or inventing a mapping. For duplicate, exclude unmapped source flags only from the new create projection. Require at least one mapped, live-validated Plan Type for create or duplicate; otherwise stop for a valid Plan Type selection. On update, leave existing unmapped bits unchanged and omit RelevantPlanType when all requested selections are skipped. Keep internal identifiers and flag values out of user-facing messages. |
| A mapped selected Plan Type meaning is missing or ambiguous in the live lookup | Stop before source preparation and report the selected plan-type name and lookup issue. Do not guess a mapping or silently remove a mapped selection. A LookupCode that differs from the bit number is not a mismatch. |
| A prepared Planning Measure source has a non-integer `RelevantPlanType`, including a comma-separated list of lookup codes | Reject the source during preflight. Recalculate `RelevantPlanType` as the bitwise OR of `1 << (bitNumber - 1)` for each distinct selected meaning's mapped bit number, then rebuild the source and approval preview. Do not retry the failed import unchanged. |
| A Plan Type edit would clear an existing bit for a type outside the available selection list | Stop before preview. Preserve baseline bits outside `availableMask` using `(existing & ~availableMask) OR selectedMask`, then validate the resulting integer and complete change summary. |
| No Project- or Planning Attribute-context LevelId is eligible for Default context | Set LevelsList to `1` and continue validation. Do not fail the create request solely for this condition. |
| A conditional-format rule has an empty Basis, Condition, Threshold, CompValue, and Color | Stop before the REST call and report the empty rule. |
| A conditional-format rule has both Threshold and CompValue, or neither | Stop before the REST call and show: You entered invalid conditional formatting. For each condition you must enter either compare-to measure or value, not both, and enter color. (MSC-2805364) |
| A conditional-format rule has no Color, or its Basis, Threshold, or Condition has no exact match in its validation source | Stop before the REST call; report the invalid field and do not invent a value. When Condition is valid, retain the exact caller-supplied value; never substitute its lookup code. |
| A conditional-format rule tries to fabricate the new measure ID for Basis or Threshold | Stop before the REST call. Require an exact valid existing MeasureId from the measures list. |
| SourceType is absent or not 1, 2, or 3, or source details contradict the selected mode | On create, default an absent SourceType to 1 (None) when no source-list rows are supplied. On update, an absent SourceType means unchanged. Stop before the parent action if source-list rows or level-source configuration contradict the resulting mode; do not infer List from supplied rows or discard conflicting configuration. |
| SourceType 2 has no supported planning-level source selection or its parent payload field is unconfirmed | Stop the level-source portion before submission. Confirm the live parent contract and the planning level; do not invent a source-level field. |
| SourceType 3 child management is requested on an existing Measure without evidence of an empty child set or an explicit reconciliation policy | Stop child mutation. Retain the existing Measure and Source List evidence; do not guess whether to add, replace, or update rows. |
| An update switches away from a source mode while its prior source configuration may remain | Stop until the approved runbook confirms the existing source configuration's disposition; do not silently leave or delete level or child source details. |
| A Planning Measure Source List row is missing Name, has an invalid IsDefault value, has more than one default row, or includes ListId or audit fields | Stop before submission and report every invalid source-list row. Do not remove fields or choose a default automatically. |
| The parent Planning Measure create fails or does not return MeasureId | Stop. Do not create Planning Measure Source List rows, and do not fabricate or reuse a MeasureId. |
| Planning Measure Source List creation fails after the parent succeeds | Stop without automatic retry. Report that the parent measure may already exist, retain the returned failure evidence, and require reconciliation before another request. |
| The live Data Loader template is missing, incomplete, or does not expose a registered Planning Measure Source List create contract | Stop before source preparation. Do not alter Fusion metadata, change required flags, or treat the local task declaration as proof that the object is loadable. Obtain the supported Fusion schema and create contract first. |
| The Planning Measure Source List schema requires ListId or ObjectVersionNumber for a new record, does not generate and return both fields, or does not accept exactly MeasureId, Name, and IsDefault as the create body | Stop before writing and report a schema/API contract issue. Do not create the parent measure or attempt to satisfy the server-managed fields from the client. |
| The approved SourceType 3 workflow cannot confirm a core.data-loader child import route, planningMeasureSourceLists/batch when selected by its adapter, the exact three-field child body, or the parent-response MeasureId handoff | Stop before parent submission and report the unsupported contract. Do not substitute a standalone REST write or fabricate a MeasureId. |
| A standalone Source List load has no exact existing MeasureId, blank Name, or invalid IsDefault | Stop before submission. Do not create a Source List or fabricate a MeasureId. |
| A Source List create targets a Measure whose current SourceType is 1 or 2 | Stop the child load and route a proposed SourceType 3 change through the existing approved Planning Measure update task. For SourceType 2, require a confirmed disposition of the prior level source. Resume child validation only after the parent update job succeeds and readback confirms SourceType 3. |
| The parent SourceType 3 update, its approval record, job result, or readback is unavailable or fails | Do not preview, upload, or submit a Source List child. Report the missing parent workflow step and retain the original request for a fresh check after resolution. |
| An existing Measure update has no unique exact identity, complete baseline, or supported concurrency/version evidence | Stop before preview. Report the missing identity or version contract; do not infer current values. |
| Any requested Measure update field is unsupported, read-only, server-managed, invalid, or lacks a confirmed update-template mapping | Report every field failure and stop before preparing a load. Do not silently omit a request or expand the change set. |
| The complete update summary, intended payload, validated archive digest, or Task Hook preview cannot be bound into one approval record | Stop before Data Loader upload. Require a fresh preview and explicit approval of the exact change record and archive. |
| A Data Loader update is accepted but has not reached successful terminal status | Keep the task pending with its request or ProcessId and last status; verify later through the routed workflow. Do not claim that the Measure changed or poll within the initiation request. |
| Readback differs from an approved value, or an unapproved editable parent field changed | Mark verification failed, retain baseline, approval envelope, job evidence, and readback, and report each mismatch. Do not retry or perform corrective writes automatically. |
| An enabled aggregation field has no value, WeightedBy is enabled with no value, or a disabled dependent field is supplied | Stop before submit and report every inconsistent field. Clear disabled field values only as part of the synchronized payload preparation. |
| A dependency change disables Time aggregation, Other aggregation, Weighted By, Allocation Basis, or Secondary Basis | Synchronize the affected field before validation: clear AggrMethodTime, AggrMethodOther, or WeightedBy; when Allocation Type is editable also clear the disabled allocation or secondary basis. Preserve non-editable existing or seeded allocation values unless the API requires clearing them. |
| The planningMeasures create API returns validation errors | Surface the detailed API validation errors, preserve the attempted level selections and response evidence in the run diagnostic, and stop. Do not retry with a guessed, derived, or hardcoded GranularityId. |
| Any task failure needs a run diagnostic | Persist selected environment, operation, stage, failure class, safe message, artifact references, external IDs, and recommended action under the project workspace. Redact credentials, tokens, private keys, and sensitive payload values. |
