# Content Items Reference Lookups

Original GROW-8154 V1 acceptance remains FSM-only and FSM is preferred. The separately selected [verified GOAL fallback exception](../../references/verified-fallback-contract.md) may use only its verified single-row HDL provider through Core Data Loader. It is not FSM acceptance or submission approval. Other historical HDL branches remain unreachable. Exact existing identifiers stop creation, even when supplied fields are equal.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| One fully equal fresh customer item is found | Return canonical classification exact with match source customer, actual observed identifier and route outcome exact_from_customer; stop creation and do not recommend reuse or mutate it |
| No fresh key but one seeded identity is found | Return canonical classification exact with match source seeded and route outcome exact_from_seeded; block create and do not claim full reuse/readback equality from the identity-only catalog |
| No exact key is found in either layer | Continue to design enforcement for missing approved values only |
| A source-declared Name or code collision is present | Display the collision identifiers and block creation; do not reinterpret the provider guard as a fuzzy warning |
| Multiple equally supported values or relationship endpoints remain | Stop; never select one silently |
| A create-only package passes the exact local contract | Return the immutable package evidence to Task Hook; do not upload from this task rule |
| Historical enhanced-profile HDL catalog evidence is retained | Historical regression contract only; do not execute its catalog-resolution or HDL package branch in GROW-8154 V1 |
| GOAL dual-key receipt is evaluated for the selected exception | Reopen fresh complete evidence, display every actual matching identifier and block duplicates. Historical receipts are not current readiness; FSM-only acceptance remains unproven |
| Post-load catalog child read returns one fully equal exact item | Mark readback verified; retain only sanitized exact fields and the response fingerprint |
| The package, baseline, customer evidence, seed catalogs, release, dependency evidence, or SHA-256 changes | Invalidate readiness and require a new package and Data Loader preview |
