# Content Items Dependency Readiness

Original GROW-8154 V1 acceptance remains FSM-only and FSM is preferred. The separately selected [verified GOAL fallback exception](../../references/verified-fallback-contract.md) may use only its verified single-row HDL provider through Core Data Loader. It is not FSM acceptance or submission approval. Other historical HDL branches remain unreachable. Exact existing identifiers stop creation, even when supplied fields are equal.
## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Supplied-configuration capture | Capture direct values, blank-template rows, or a readable existing file; preserve the complete set, source provenance and confirmed mappings; omit absent optional values |
| 2 | Owning content type | For technical readiness, resolve one exact content type from complete current and packaged seed evidence |
| 3 | Target profile mode | Resolve legacy or enhanced mode before selecting a live evidence or create provider |
| 4 | Evidence provider and capability | For REST, select a registry-declared API version by bounded GET before the registered child read |
| 5 | Fresh current items | For exact claims, bind a fresh complete read to the authenticated target |
| 6 | Provider-specific absence lock | Apply the selected route's exact code and name collision rules before create |
| 7 | Relationship references | Resolve every source and target item exactly when a relationship is proposed |
| 8 | Create-only provider | Require the provider-appropriate immutable package receipt and mandatory core.data-loader handoff |

## Dependency Classification

| Result Category | When Used | Can Run Lookup/Create? |
|---|---|---|
| Satisfied | The fresh exact evidence and all applicable references are exact for review, or every profile-mode-selected create-only package gate is ready | Lookup yes; create only through core.data-loader |
| Proposal-ready | Supplied object ownership is unambiguous; missing required values, uncertain field mappings, and incomplete technical or exact evidence are retained visibly | Preliminary review-only proposal; no configuration-ready, exact or create claim |
| Needs evidence | A customer export is stale, filtered, target-mismatched, or ambiguous; a seed catalog is missing or wrong-task; or a relationship endpoint is unresolved | No |
| Blocked | Evidence is incomplete, the package contract fails, or an unsupported mutation/provider is requested | No |
