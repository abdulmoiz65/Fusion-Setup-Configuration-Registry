# Profile Types and Content Section Configuration Design Enforcement

## Enforcement Order

| Sequence | Step | What Must Happen |
|---|---|---|
| 1 | Preserve business intent | Keep every inferred value in the assumption ledger and do not silently select equal patterns |
| 2 | Normalize only after review | Convert confirmed proposal values to supported technical fields and validate references |
| 3 | Separate exact duplicates from similarity | Run exact-match rules for every candidate only after technical normalization; any exact duplicate rejects the whole ZIP |
| 4 | Preserve execution separation | Require an immutable preview and separate executor approval before any write |

| HRT_MANAGE_PROFILE_TYPES | Profile Types | A current-state content-section verification is requested | Blocker | resolve_profile_content_section_verification | Any Fusion business-resource method isn't GET; a body, action endpoint, opaque runtime route, export/import operation, incomplete page set, partial-name match, or unconfirmed child GET would be used | Use only the stable GET allowlist, complete pagination, exact identifiers, and runtime capability evidence; otherwise return blocked | No write or fallback is allowed |
