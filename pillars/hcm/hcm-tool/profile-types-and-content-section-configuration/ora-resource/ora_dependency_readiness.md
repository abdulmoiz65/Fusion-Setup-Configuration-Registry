# Profile Types and Content Section Configuration Dependency Readiness

## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Business context | Capture outcome, scope, effective date, constraints, and exceptions before technical completeness validation |
| 2 | Read-only evidence | Use only declared project evidence or confirmed read-only provider contracts for discovery; current-state verification permits GET only and ends with its report |
| 3 | Technical dependencies | Resolve one exact Profiles V2 seeded target, confirm type-and-operation support, confirm a predefined template for each new Person section, resolve the corresponding active Person content section for every supported non-Person target, then resolve referenced ratings, DFF contexts, subscribers, roles, value sets, and other external references after proposal review |
| 4 | Executor boundary | Confirm immutable-preview, approval, provider, and readback contracts before a handoff for execution |
