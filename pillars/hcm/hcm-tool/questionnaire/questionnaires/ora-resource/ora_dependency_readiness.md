# Dependency Readiness

## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Live Questionnaire HDL contract | Resolve the current root, translation, child, attribute, key, operation, and content contract before rendering any DAT row. |
| 2 | Subscriber, authoritative root identity, and current state | Resolve one exact subscriber; for change, resolve one full versioned questionnaire and hierarchy with latest/update/in-use/seeded/locked/response evidence. |
| 3 | Conditional template, category, and question references | Resolve a template only when supplied or live-required, and resolve every supplied category and placed question in the same subscriber. |
| 4 | Direct Question contract | When a direct Question is requested, resolve the target Question and conditional Answer components and operations, category, response type, and template capability, then complete the approved structured normalization and executable rendering procedure before DAT generation. |
| 5 | Owner, placement response, scoring, attachments, and language | Resolve only controls and references applicable to the approved design and current live schema. |
| 6 | Mutability, lifecycle, and consumer boundary | For every update, prove exact root and per-component mutability. For in-use or response-bearing hierarchy, scoring, template-linkage, status, or lifecycle changes, require complete impact evidence and keep consumer linkage in a separate task. |

## HDL Hierarchy Order

For Questionnaire.dat, prepare the live-registered Questionnaire root before QuestionnaireAttachment and Section, Section before Question, and Question before Answer. Process QuestionnaireTranslation.dat only after its TemplateFlag N parent key resolves. File order never repairs a missing parent.

## Dependency Classification

| Result Category | When Used | Can Run Lookup/Create? |
|---|---|---|
| Satisfied | Every applicable dependency has one exact compatible match and the live HDL contract is current | Yes, artifact preparation only |
| Blocked | Metadata, identity, route-required reference, parent, current state, or operation is missing, ambiguous, stale, or incompatible | No |
| Approval required | A declared reference candidate has been proposed but no exact value has been explicitly approved and revalidated | Read-only candidate and exact-reference lookups only; no DAT preparation or upload |
| Lifecycle review | In-use, response, seeded/locked, hierarchy, scoring, template-linkage, or exact editable-operation evidence is incomplete | No mutation until complete impact and mutability review and renewed approval |
| Separate downstream task | Consumer linkage is requested | Yes for questionnaire preparation; no consumer mutation in this task |
