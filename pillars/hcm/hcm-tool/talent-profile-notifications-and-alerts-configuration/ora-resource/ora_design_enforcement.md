| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 2 | End side-effect-free modes | Return local guidance, the unchanged checked-in workbook, or the user-supplied unvalidated draft without Fusion access |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 3 | Resolve authenticated environment | On implementation only, use environment and restBaseUrl from the active FDOS authentication context |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 4 | Verify bounded REST capability | Run the declared GET through the shared client before any FSM export and retain no notification data |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 5 | Keep release optional | Record only explicit trusted quarterly-release metadata and never ask or infer it |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 6 | Require business input | Capture identity, label, or business intent and an explicit Notification Enabled value |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 7 | Partition provider scope | Treat exact ProductCode HRT rows as the dynamic eligible set before resolution |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 8 | Resolve targets | Auto-resolve exact eligible identity; require clarification for eligible case correction or every eligible semantic candidate |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 9 | Lock provider identity | Prefer unique NotifId or disclose provisional unique NotifName while retaining exact HRT scope |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 10 | Preserve selected rows | Copy eight serialized fields from selected HRT rows and change only NotifEnabled |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 11 | Stop on no change | Return exact_match_no_change when every selected value matches |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 12 | Build minimal upsert package | Retain metadata and all required CSV members; include approved changed HRT rows only |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 13 | Use one approval | Let core.data-loader own the only persistence approval |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 14 | Defer success | Persist pending_readback and verify through a new HRT-scoped export partition |
| HRT_MANAGE_TALENT_NOTIFICATIONS | Talent Notifications | 15 | Preserve alert boundary | Route explicit alert scope when available or retain it as deferred |
