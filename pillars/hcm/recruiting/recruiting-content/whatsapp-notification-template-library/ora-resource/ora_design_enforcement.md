# WhatsApp Notification Template Library Design Enforcement

Enforce request-level and batch-level business policies after input normalization and, where required, after live lookup. A natural-language proposal may be derived again to correct a name collision or content-policy failure, but it cannot advance until every blocking check passes.

The message-composition rules below are the self-contained approval-readiness standard for this task. Proposals must be expected, specific, correctly categorized, timely, accurate, safe, and easy to understand. Passing these gates improves approval readiness but does not guarantee approval.

## Enforcement Order

| Sequence | Step | What Must Happen |
|---|---|---|
| 1 | Normalize and reject duplicates inside the input | Accept any readable user-provided format, preserve source locators while normalizing it into canonical records, and compare normalized template name plus normalized supplied language so different languages for the same template remain valid; after role classification, require at most one base record per template-name group and one translation record per template and resolved language |
| 2 | Select an available natural-language name | Derive a meaningful provisional name from the prompt, check every existing template, and finalize only a zero-match name; use more specific business meaning after a collision and never an arbitrary numeric suffix |
| 3 | Classify the natural-language Meta category | Use Authentication for authentication, Marketing for job promotion, talent-pool outreach, or campaigns, and Utility for every other expected transactional message |
| 4 | Enforce Meta content standards | Validate purpose and category, front-loaded concise copy, professional tone, spam avoidance, expected timing and outreach cadence, candidate safety, factual accuracy, CTA design, and contextualized variables with nonsensitive samples before confirmation |
| 5 | Confirm natural-language proposals | Show all derived values, standards results, and realistic token sample values; require explicit confirmation before returning a base-template handoff |
| 6 | Classify structured rows or recheck natural-language names | For automatically classified structured input, route an exact existing name as translation and use session language to select the base for a zero-match name; preserve ORA_DRAFT update behavior only for explicitly base-only input. For confirmed natural-language input, recheck the name and invalidate the proposal if any match appeared after confirmation. |
| 7 | Enforce Conversation Starter tokens | A WhatsApp Conversation Starter template may contain only its documented tokens and must contain ${MessageBody} |
| 8 | Stage mixed base and translation batches | Return the base create or Draft-update phase first; defer translations until the owning workflow verifies successful completion of every base Data Loader request |

## Design Rules

| Applies When | Severity | Required Lookup | Blocking Condition | Recommendation | Fix Allowed? |
|---|---|---|---|---|---|
| A normalized structured request contains repeated records | Error |  | More than one record has the same normalized template name and normalized supplied language, or role classification produces more than one base record for a template-name group | Duplicate template-language records or multiple base candidates were found. Keep one record for each template and language and one base record for each new template-name group. | Yes — correct the duplicate records and resubmit the complete request |
| A batch contains more than one translation for the same normalized template name and resolved language | Error |  | Duplicate translation keys exist in the input | Duplicate translation records were found. Keep one record for each template and language and resubmit the complete request. | Yes — correct the duplicate records and resubmit the complete request |
| A provisional natural-language template name matches one or more existing WabaTemplateName values case-insensitively | Error | find_available_whatsapp_template_name | The collided name is finalized or shown for confirmation | Derive a more specific meaningful candidate from the notification purpose, recheck all pages, and finalize only a zero-match name. Do not append an arbitrary number. | No — the availability lookup must select the final name |
| A meaningful zero-match natural-language template name cannot be derived | Error | find_available_whatsapp_template_name | The workflow invents a name or advances to category and content derivation | Show the collided candidates and ask the user for one distinguishing business concept. | Yes — use the added business context to derive and recheck a candidate |
| An automatically classified normalized template-name group from any readable input format returns exactly one existing Fusion template | Error | find_existing_whatsapp_base_template_for_upsert | Any record in the group is routed as a base create or Draft update, or the translation handoff does not use the matched WaTemplateId and recruitingWhatsappLangTemplates | Classify every record in the existing-name group as a translation, preserve the matched WaTemplateId as templateId, resolve each language, and use recruitingWhatsappLangTemplates. | No — Fusion existence determines the structured record role |
| An automatically classified normalized template-name group from any readable input format has no existing Fusion template | Error | resolve_user_session_language_for_base_selection | No resolved LanguageCode or Description matches the active user session language uniquely, a different-language record is routed as the base, or more than one record is routed to recruitingWhatsappBaseTemplates | Select exactly one record whose resolved language matches the active session language as the base, use recruitingWhatsappBaseTemplates for it, and defer all remaining records in the group as translations. If the session language cannot be obtained or matched uniquely, stop and request the preferred base language. | No — base selection must use the active session language or explicit user preference after the documented prompt |
| An explicitly base-only structured existing-template lookup returns exactly one template whose WabaTemplateStatus is ORA_DRAFT | Error | find_existing_whatsapp_base_template_for_upsert | The requested operation remains create instead of being converted to a content update | Treat the row as an update and preserve the existing template identifier; update only the validated content and other documented updateable fields. | No — operation classification is mandatory |
| An explicitly base-only structured existing-template lookup returns exactly one template whose WabaTemplateStatus is blank or is not ORA_DRAFT | Error | find_existing_whatsapp_base_template_for_upsert | The request would overwrite a template that is not eligible for Draft update | The existing template isn't in ORA_DRAFT status and can't be updated by this request. Use a different template name or manage the existing template separately. | Yes — rename the new template or remove the conflicting row |
| A confirmed natural-language template name has any existing WabaTemplateName match during the pre-handoff recheck | Error | find_existing_whatsapp_base_template_for_upsert | The stale confirmed proposal advances to handoff | Invalidate the confirmation, derive and availability-check a more meaningful name, update the display name, rerun the proposal rules, and obtain a new confirmation. | No — stale confirmation cannot authorize the renamed proposal |
| A natural-language requirement describes authentication or recipient verification | Error |  | The proposed Meta category is not Authentication | Classify the proposal as Authentication and revalidate the content for that designated purpose. | No — category selection must match the purpose |
| A natural-language requirement describes job promotion, talent-pool outreach, or a campaign | Error |  | The proposed Meta category is not Marketing, including when promotional content is presented as Utility | Classify the proposal as Marketing and keep the message within that designated purpose. | No — marketing cannot be disguised as Utility |
| A natural-language requirement describes an expected transactional update such as application receipt, interview confirmation, schedule change, or a requested status update | Error |  | The proposed Meta category is not Utility | Classify the proposal as Utility and keep the message tied to the expected transaction. | No — category selection must match the purpose |
| A natural-language message is composed | Error |  | The intended recipients are not documented as opted in, the real business is not identifiable in the message or surrounding sender context, the message type is unexpected, or no clear opt-out path is provided | State the real business, use the template only for recipients who opted in to this message type, make the expected purpose clear, and include a clear opt-out instruction or supported opt-out action. | Yes — revise the proposal and recipient-use conditions before confirmation |
| A natural-language message is composed | Error |  | The purpose or most important information is buried, sentences are unnecessarily long, the message is not focused, or essential content is unnecessarily placed after the first five lines where it can be truncated | Put the purpose and essential details first, use short sentences, and keep the key content within the first five lines whenever practical. | Yes — shorten, reorder, and revalidate the content |
| A natural-language message is composed | Error |  | The tone is not warm, professional, grammatical, and informative; personalization is irrelevant; or the content contains typos, excessive capitalization, excessive punctuation, or pushy language | Use a natural professional tone and personalize only when the detail adds relevant value. | Yes — revise and revalidate the content |
| A natural-language message or its recipient-use conditions are composed | Error |  | The proposal contains a long dense block, multiple promotions, excessive emoji, repeated or irrelevant outreach, or outreach from multiple numbers that could confuse recipients | Keep one clear purpose, remove spam-like elements, and use a consistent recognizable sender identity and number. | Yes — revise the content or recipient-use conditions and revalidate |
| A natural-language message or its recipient-use conditions are composed | Error |  | The proposed send time is unrelated to the recruiting event, frequency is excessive, non-engaging recipients receive no cooldown period, or overlapping campaigns can produce disjointed messages | Tie the send to the relevant recruiting event, limit frequency, apply a cooldown for non-engaging recipients, and coordinate overlapping candidate outreach. | Yes — revise the recipient-use conditions before confirmation |
| A natural-language message includes a destination link | Error |  | The URL is embedded in body text when the template design supports a CTA button, or the proposal contains more than one competing CTA | Use one clear CTA button for the destination where supported and keep body content focused on the notification. | Yes — move the destination to the CTA and revalidate the proposal |
| A natural-language message uses Recruiting tokens or review samples | Error | resolve_natural_language_content_tokens | A dynamic value is not valid for the selected Recruiting category, lacks enough fixed surrounding text to make its meaning clear, constitutes the entire message, or lacks a realistic nonsensitive sample; media lacks a review sample; or an appeal is prepared without its required sample | Use only exact category-valid Recruiting tokens, contextualize every token with fixed text, keep variables from constituting the whole message, and provide realistic nonsensitive samples for every dynamic value; include media and appeal samples when applicable. | Yes — correct tokens, context, and samples before confirmation or appeal |
| A natural-language message is composed | Error |  | Content includes discriminatory language or a decision based on a protected characteristic; requests identification, financial information, background-check documents, or other sensitive material through a WhatsApp reply; or contains prohibited, regulated, fraudulent, exploitative, offensive, or deceptive material | Remove unsafe content. When sensitive information is required, direct the candidate to an approved secure portal without asking them to send it in a WhatsApp reply. | Yes — revise and revalidate the content |
| A natural-language message is composed | Error |  | Content implies selection, rejection, an offer, or another hiring decision that is not final and factually correct, or it uses false urgency, exaggerated promises, misleading claims, or pressure tactics | State only verified final decisions and use accurate, neutral wording without artificial urgency or pressure. | Yes — revise and revalidate the content |
| A natural-language proposal is otherwise complete | Error | derive_recruiting_category_from_requirement | The user has not explicitly confirmed the unique template name, display name, Meta category, Recruiting category, compliant content, tokens, and realistic samples | Present the complete proposal and standards result, then wait for explicit confirmation. | Yes — the user may confirm or provide corrections; corrections require a new proposal |
| A request creates a WhatsApp Conversation Starter template | Error |  | Content contains a token outside ${CandidateDisplayName}, ${LoggedInUserOrganization}, ${LoggedInUserName}, ${LoggedInUserTitle}, and ${MessageBody} | The WhatsApp Conversation Starter template contains an unsupported token. Use only the supported Conversation Starter tokens. | Yes — remove every unsupported token and resubmit |
| A request creates a WhatsApp Conversation Starter template | Error |  | Content does not contain ${MessageBody} | The WhatsApp Conversation Starter template must contain the ${MessageBody} token. | Yes — add ${MessageBody} and resubmit |
| An automatically classified batch contains a selected base row and one or more deferred translation rows | Error |  | A translation is handed off before every corresponding recruitingWhatsappBaseTemplates request is verified as completed successfully, or a deferred translation is sent through a business object other than recruitingWhatsappLangTemplates | Submit the session-language base phase through recruitingWhatsappBaseTemplates first, wait for verified completion through the owning Data Loader workflow, then submit the deferred rows through recruitingWhatsappLangTemplates as a new translation-only phase. | No — base-first staging and business-object routing are mandatory |

## Design Lookup Requirements

| Resolver | When Required | Values Needed | Source File |
|---|---|---|---|
| find_available_whatsapp_template_name | Every natural-language base-template request before the proposal name is finalized | Every WabaTemplateName; the chosen meaningful candidate must have zero case-insensitive matches | ora_reference_lookups.md |
| find_existing_whatsapp_base_template_for_upsert | Every structured template-name group and every confirmed natural-language base-template request | WabaTemplateName, WaTemplateId, and WabaTemplateStatus; an automatically classified structured exact match becomes translation, a zero match requires session-language base selection, explicitly base-only update eligibility requires ORA_DRAFT, and any confirmed natural-language match invalidates the proposal | ora_reference_lookups.md |
| resolve_structured_template_languages | Every automatically classified normalized record from any readable input format | Supported LanguageCode and Description for each supplied Language before record-role classification | ora_reference_lookups.md |
| resolve_user_session_language_for_base_selection | Every automatically classified structured request after language resolution | Active user session language or explicitly confirmed preferred base language after the documented prompt, resolved LanguageCode and Description values, selected base row for every zero-match name group, existing-name translation rows, deferred translation rows, and target Data Loader business object for each role | ora_reference_lookups.md |
| derive_recruiting_category_from_requirement | A natural-language requirement does not supply an exact Recruiting category | Proposed recruitingCategoryCode and Meaning | ora_reference_lookups.md |
| resolve_natural_language_content_tokens | Every natural-language proposal | Exact category-valid token Names used in content and realistic nonsensitive sample values for review | ora_reference_lookups.md |
