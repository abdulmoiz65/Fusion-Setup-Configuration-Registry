# WhatsApp Notification Template Library Input Validation

Accept, normalize, and validate any readable user-provided document, data, image, or natural-language request before any dependency lookup or Data Loader handoff. Do not reject an input solely because of its file extension. Use a safe parser, text extraction, or OCR capability available in the active runtime, preserve source locations, and normalize the extracted content into canonical template-language rows or one natural-language proposal. Validation is atomic: unreadable content, an ambiguous extraction, or one invalid row or derived field rejects the complete request. These rules prepare validated field mappings and staged handoffs only; they do not construct a payload or perform a Fusion change.

## Supported Input Modes

| Input Mode | Accepted Input | How Rows Are Processed | Result |
|---|---|---|---|
| Universal structured batch | Any readable format containing one or more template-language records, including XLS, XLSX, CSV, DOC, DOCX, PDF, TXT, Markdown, JSON, YAML, XML, pasted tables or text, and images or screenshots when OCR is available | Safely extract text, tables, or records; preserve the source file and page, section, table, or record locator; normalize documented aliases and semantic labels into canonical rows; validate every row; group rows by normalized template name; and derive base or translation routing only after the documented Fusion existence and session-language lookups | One atomic validated batch with source-traceable canonical rows and derived base and translation phases |
| Natural language | A user requirement describing the notification purpose and intended recipient outcome | Derive a meaningful provisional template name or code from the requirement, confirm that the name is not already in use, derive a consistent display name, classify the Meta category, resolve the Recruiting category and supported tokens, and enforce the Meta content standards before showing the complete proposal for confirmation | One unique and policy-compliant proposed base-template request; no handoff until confirmed |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Template name is required | Reject a missing value with: Enter the template name or template code. | A base-template creation is requested |  |
| Template name length | Reject a value longer than 100 characters with: The template name must not exceed 100 characters. | A template name is supplied |  |
| Template name format | Require ^[a-z][a-z0-9_]*$; reject any other value with: The template name must start with a lowercase letter and can contain only lowercase letters, numbers, and underscores. | A template name is supplied |  |
| Template display name is required | Reject a missing or blank value with: Enter the template display name. | A base-template creation or translation-only update is requested |  |
| Template display name length | Reject a value longer than 3,000 characters with: The template display name must not exceed 3,000 characters. | A template display name is supplied |  |
| Meta WhatsApp template category is required | Reject a missing value with: Enter the Meta WhatsApp template category. For a natural-language request, derive Authentication for authentication messages, Marketing for job promotion, talent-pool outreach, or campaigns, and Utility for all other expected transactional messages. | A base-template creation is requested |  |
| Recruiting content category is required | Reject a missing value with: Enter the Recruiting content category. | A base-template creation is requested |  |
| Base-template system defaults are not user inputs | Do not request or accept productContext or recruitingSource from the user; always set them to HCM_RECRUITING and ORA_FSM_UI respectively | A base-template creation is requested |  |
| Translation Recruiting content category is required | Reject a missing value with: Enter the Recruiting content category. Resolve the supplied code or meaning and use its LookupCode only for mandatory token validation; do not include it in the translation Data Loader handoff | A translation-only update is requested | resolve_translation_recruiting_content_category |
| Content is required | Reject missing or blank content with: Enter the WhatsApp template content. | A base-template creation or translation-only update is requested |  |
| Content length | Reject content longer than 1,024 characters, including token names, with: The template content must not exceed 1,024 characters, including token names. | Content is supplied |  |
| Content contains a token | Require at least one token; otherwise return: The template content must contain at least one valid token in the ${TokenName} format. | Content is supplied |  |
| Content unique-token count | Reject more than 15 unique tokens with: The template content can contain no more than 15 unique tokens. | Content is supplied |  |
| Content token format | Require every token to match \$\{[A-Za-z]+\}; for each invalid token return: <token> doesn't use the required ${TokenName} format. | Content is supplied |  |
| Base-template content token authority | Always require every extracted ${TokenName} token to have exactly one case-sensitive Name match in the token LOV for the resolved Recruiting content category; use the documented invalid-token error for no match or casing difference and block the complete request | Base-template content passes the documented shape checks | resolve_create_content_tokens_by_category |
| Translation content token authority | Always require every extracted ${TokenName} token to have exactly one case-sensitive Name match in the token LOV for the resolved translation Recruiting content category; use the documented invalid-token error for no match or casing difference and block the complete request | Translation content passes the documented shape checks | resolve_translation_content_tokens_by_category |
| Translation language is required | Reject a missing or blank language with: Enter the translation language. | A translation-only update is requested |  |
| Format-neutral intake | Do not reject readable content solely because of its filename or format; safely extract supported content and normalize it to structured rows or a natural-language proposal | Any user-provided document, data, image, pasted content, or attachment |  |
| Safe content extraction | Reject inaccessible, encrypted-without-access, corrupt, empty, executable-only, or unreadable input; never run macros, scripts, embedded programs, or active content | Any file or attachment is provided |  |
| Extraction traceability and ambiguity | Preserve a source locator for every normalized field; when row boundaries, labels, values, or mappings are ambiguous, show the proposed normalization and require correction or explicit confirmation before any lookup or handoff | Content is extracted from a non-canonical, unstructured, scanned, image-based, or semantically labeled source |  |
| Structured language is required for automatic classification | Reject a missing or blank Language and identify the source locator and normalized record unless the complete request is explicitly declared base-only | A normalized structured request is being automatically classified |  |
| Translation base-template identifier is required | Require a base template name, template code, or existing template display name | A translation-only update is requested |  |
| Structured batch is atomic | Validate all normalized records and collect all extraction and field errors before returning; if any record fails, reject the entire request and perform no duplicate lookup or handoff | Any normalized structured request |  |
| Structured aliases and semantic labels | Match Template Name and Template Code to templateName; Template Display Name to templateDisplayName; Meta Category to wabaTemplateCategory; Template Content and Content to content; Recruiting Category to recruitingCategoryCode; and Language Details and Language to language; accept semantically equivalent labels only when the mapping is unambiguous | Any normalized structured request |  |
| Natural-language derivation boundary | Derive the provisional identity and content only from the user requirement and values returned by the documented name, category, and token resolvers; classify the Meta category as Authentication for authentication messages, Marketing for job promotion, talent-pool outreach, or campaigns, and Utility for all other expected transactional messages | Natural-language input | derive_recruiting_category_from_requirement |
| Natural-language confirmation | Do not request confirmation or return a Data Loader handoff until the selected template name has zero existing matches and the Meta content standards pass; after the user confirms, recheck the name before handoff; any correction or new collision invalidates the proposal and requires revalidation and a new confirmation | A complete natural-language proposal is ready |  |
| Base-template Data Loader handoff | Preserve validated templateName, templateDisplayName, wabaTemplateCategory, recruitingCategoryCode, content, productContext, and recruitingSource field mappings for the recruitingWhatsappBaseTemplates handoff; for an automatically classified file, permit this mapping only for the unique non-existing-name row whose language matches the active user session language; do not construct a payload here | Base-template validation, existence and session-language classification, required lookups, mandatory token-authority validation, fixed defaults, and design enforcement succeed |  |
| Translation Data Loader handoff | Preserve resolved templateId and language plus validated templateDisplayName and content field mappings for the recruitingWhatsappLangTemplates handoff; an exact existing template-name match classifies the structured row as a translation, while translations for a newly selected base remain deferred until that base load completes; recruitingCategoryCode is required lookup context for token validation and is not part of this handoff; do not construct a payload here | Translation validation, language and base-template resolution, Recruiting-category resolution, and mandatory token-authority validation succeed |  |
