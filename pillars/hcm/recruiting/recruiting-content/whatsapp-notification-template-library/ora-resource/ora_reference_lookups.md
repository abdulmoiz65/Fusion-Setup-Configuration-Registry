# WhatsApp Notification Template Library Reference Lookups

Resolvers are read-only. The active user session is the local authority for session language; all other resolvers use the documented live Fusion sources. No lookup authorizes a Data Loader submission or retry. Token validation is mandatory for natural-language proposals, structured base-template requests, and translation-only requests.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Structured category lookup | Resolve every row independently but reject the complete request if any row has no unique match |
| Natural-language name availability | Derive a meaningful provisional name from the requirement, read every existing-template page, and finalize only the first candidate with zero case-insensitive WabaTemplateName matches; use additional business meaning for a collided candidate and never an arbitrary numeric suffix |
| Natural-language proposal | After selecting a unique name and purpose-based Meta category, select one returned Recruiting category, use only exact token Names returned for that category, enforce the Meta content standards, and show the complete proposal with realistic token sample values for confirmation |
| Structured name-existence classification | Read every template page before routing normalized records. For automatically classified structured input from any readable format, one exact existing name routes the group to recruitingWhatsappLangTemplates; zero matches requires session-language base selection; multiple matches block. Preserve ORA_DRAFT update behavior only for an explicitly base-only structured request. |
| Structured language resolution | Resolve every supplied structured Language to a Fusion LanguageCode and Description before comparing it with the active user session language or preparing a translation handoff. |
| Session-language base selection | For every automatically classified zero-match name group, use the active user session language as the named local authority and require one matching resolved LanguageCode or Description row. Route that row to recruitingWhatsappBaseTemplates and defer the remaining rows to recruitingWhatsappLangTemplates. If the session language is unavailable or no row matches uniquely, stop and request confirmation to create the base plus the user's preferred base language. |
| Confirmed natural-language name recheck | Recheck every confirmed natural-language name and treat any match as a stale-proposal collision that requires a new meaningful name and confirmation. |
| Structured or translation token validation | Always resolve the applicable Recruiting content category, call the category token LOV, and require every extracted token to match exactly one case-sensitive Name before handoff |
| Any live lookup unavailable or unauthorized | Stop the complete request without retry or inferred fallback |
