# Enterprise Recruiting and Candidate Experience Information Reference Lookups

## Section Configuration Source

Use a valid matching target-environment `ORA_IRC_SETTING.csv` export as the only
source for supported section configuration reporting. Map fields through
`ora_input_validation.md`, report missing rows as unavailable, and never use an
exported integration value as proof of secure credential-store state or
successful validation.

Microsoft Graph, Google Workspace, and Zoom have no live prerequisite lookup or
CSV mutation route in this skill. Their modification result is always
`FSM_REQUIRED`.

## Export Evidence Run-Record Contract

After every successful fresh task export used by this skill, append a sanitized
`skill_run_record` under `project/{project_id}/state/runs/`. Do not modify
`shared.setup-export.task-level-export` or duplicate its export mechanics.

| Field | Required value |
|---|---|
| `skill_id` | This task skill ID |
| `status` | `completed` |
| `stage` | `section_export_ready`, `section_configuration_report`, or the current Interview Intelligence mutation stage |
| `environment` | Normalized target environment identity used for the export |
| `task_code` | `ORA_IRC_MANAGE_ENTERPRISE_RECRUITING_AND_CANDIDATE_EXPERIENCE_INFORMATION` |
| `fusion_release` | Target Fusion release when known; omit when the target context does not provide it |
| `source_export_process_id` | ProcessId returned by the successful export |
| `source_export_completed_at` | Recorded successful completion timestamp in UTC |
| `source_export_path` | Project-relative downloaded ZIP path |
| `source_export_csv_path` | Project-relative extracted `ORA_IRC_SETTING.csv` path |
| `source_export_sha256` | SHA-256 computed from the downloaded ZIP |

The local lookup does not call Fusion. It computes the current ZIP SHA-256 and
compares it with the run record before reuse. A later successful import for the
same environment and task, or a user-declared later FSM/UI change, supersedes
the receipt. When the lookup returns `refresh_required`, hand off to
`shared.setup-export.task-level-export`, wait for successful completion, record
the fields above, and then resume section reporting from that fresh artifact.
Reuse a fresh export already produced within the same current mutation workflow
rather than repeating it.

## Interview Intelligence Booster Lookup

Resolve Recruiting Booster readiness from the selected Fusion environment
before preparing any Interview Intelligence setting change. Delegate OAuth,
the local gitignored token cache, request execution, and the one permitted
401/403 token refresh to `core.fusion-api.rest-api-client`. Do not use direct
curl, BOSS, caller-provided booleans, UI-only observations, repository catalogs,
or another environment as prerequisite proof.

### REST API Version Resolution

The endpoint contract uses `{version}` as a documentation placeholder. Resolve
it before execution to an explicit caller-supplied supported REST API version,
or to `latest` when none is supplied. Do not send the literal `{version}` token
or braces to Fusion. Record the resolved value as `ResolvedRestApiVersion` in
the sanitized lookup result.

Execute the resolved GET with the approved standard Fusion client. From the
repository root, the default-version invocation is:

```bash
python3 core/fusion-api/rest-api-client/scripts/fusion_rest_client.py \
  /fscmRestApi/resources/latest/features/ORA_IRC_ADVANCED_RECRUITING \
  --token-cache auto
```

When the caller explicitly supplies a supported REST API version, replace
`latest` in that command with the supplied version. The generic REST client
executes the path it receives and does not substitute `{version}` itself.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| REQUISITION_NUMBER_GENERATION_METHOD remains eligible | Read ORA_IRC_REQ_GEN_METHOD through the exact Applications Common Lookup path and compare the supplied value only with LookupCode. Continue with the verified code only when exactly one accepted code matches. |
| The supplied generation method has no exact accepted LookupCode match | Return no_match_warning, skip only REQUISITION_NUMBER_GENERATION_METHOD, disclose both accepted codes, and preserve other independently valid Recruiting Management settings. |
| The supplied generation method has more than one exact returned match | Return many_matches_warning, skip only REQUISITION_NUMBER_GENERATION_METHOD, disclose the ambiguity and both accepted codes, and preserve other independently valid settings. |
| The supplied generation method is not one of the two accepted codes | Return invalid_setting_skipped, skip only REQUISITION_NUMBER_GENERATION_METHOD, and do not match by Meaning or infer a code. |
| The generation-method lookup is unauthorized or authentication fails | Stop the affected lookup as an authentication or authorization failure and skip only REQUISITION_NUMBER_GENERATION_METHOD; do not relabel the failure as no match. |
| The generation-method lookup has a transport, timeout, HTTP, or response-shape failure | Report the concrete failure category and skip only REQUISITION_NUMBER_GENERATION_METHOD; do not guess from Meaning, cached data, or another environment. |
| An ordinary section read has a valid matching completed export receipt | Recompute and verify the ZIP SHA-256, use the latest matching artifact, label the report as cached evidence, and show environment, task code, ProcessId, completion timestamp, and path or checksum. |
| The user asks for current, live, fresh, refreshed, re-exported, or latest values | Return `refresh_required` and obtain a new task export before reporting. |
| A candidate export is missing provenance, unreadable, for another environment/task/release, or superseded by known activity | Reject it and obtain a fresh task export before reporting. |
| The exact versioned item GET returns HTTP 200 with the expected FeatureCode and EnabledFlag Y | Record the sanitized result and continue to the remaining dependency checks. |
| No REST API version is supplied | Resolve `{version}` to `latest` before invoking the core REST client. |
| An explicit supported REST API version is supplied | Use that exact version in the request path and record it as `ResolvedRestApiVersion`. |
| The request path still contains `{version}` or braces | Stop locally before authentication or network execution and report an unresolved endpoint template. |

| The item GET remains 401 or 403 after the core client's one token refresh | Stop as auth/authz; verify the standard scope, OAuth client assignment, target identity, and read privilege. |
| The response FeatureCode differs, the origin differs from target restBaseUrl, or the payload lacks EnabledFlag | Reject the response as invalid prerequisite evidence. |
| Only caller-provided, UI, BOSS, or repository-catalog evidence is available | Run the exact same-target item GET; do not continue package preparation. |
