# Existing-Site Operations — Discovery, Languages, Status, Link, Filters, Settings, and Talent Community

## Supported operations

| Operation | Side effect | Required live contract | Result |
| --- | --- | --- | --- |
| List languages | None | Existing parent and installed-language LOV | Return site-enabled languages, active installed languages, and the current default. |
| Show site summary | None | Existing parent and expanded supported child collections | Return parent identity/status, Events state, enabled/default languages, effective Filters, Cookie Consent state, Settings summary, Talent Community state, and the Site Editor Copy Link when the UI base URL is configured. |
| Show Events state | None | Existing parent with `EventsEnabledFlag` | Return whether Events are configured for this site from `EventsEnabledFlag`. A global Events capability may be returned separately as environment context, never as the site-state source. |
| Show effective Filters | None | Existing parent and expanded `filters` collection | Return persisted restrictions by type and state **No restriction — All** for each type without a row. |
| Show Cookie Consent | None | Existing parent and expanded `cookieConsent` collection | Return the one child’s effective flags/text as Persisted or Fusion-initialized default; report missing or multiple rows as Data inconsistency. |
| Show Talent Community state | None | Existing parent and expanded `talentCommunitySignUp` collection | Return the singleton visibility/text state as Persisted or Fusion-initialized default; this read does not require the global opt-in capability to be enabled. |
| Site Editor Copy Link | None | Existing parent, configured Fusion UI base URL, and the selected/default enabled language's `LanguageTag` | Return the exact Site Editor Copy Link and its active-site availability. |
| Add language | One child POST | Main `languages` contract, current child template, and parent routing | Add exactly one active installed language that is not already site-enabled. |
| Add filter | One child POST | Main `filters` contract, current child template, parent routing, and fresh type-specific LOVs | Add one or more validated standard Filters without changing the parent or other children. |
| Show available settings | None | Existing parent, current `settings` collection, controlled client-derived catalog, and read-only global capabilities | Return friendly setting groups, current persisted/default state, choices, dependencies, and availability. |
| Update settings | One child POST or PATCH per requested key | Main `settings` contract, current template, and parent routing | Apply only catalog-backed Settings choices without changing the parent or unrelated children. |
| Update Talent Community Sign-Up | One singleton child PATCH | Main `talentCommunitySignUp` contract, current template, and parent routing | Update the default child created during initial site creation without changing the parent or unrelated children. |
| Change default language | One parent PATCH | Published parent PATCH URL, updateable `DefaultLang`, and current parent template | Set `DefaultLang` only to an already site-enabled active installed language. |
| Activate | One parent PATCH | Published parent PATCH URL, updateable `StatusCode`, and current parent template | Set `StatusCode=ORA_ACTIVE`. |
| Inactivate | One parent PATCH | Published parent PATCH URL, updateable `StatusCode`, and current parent template | Set `StatusCode=ORA_INACTIVE`. |

Do not create a site, create Cookie Consent, add an unrelated child, alter an unrequested parent attribute, delete a Setting, rename a Setting key, or update Talent Community translations in these operations.

## Preconditions

Resolve the exact existing parent by Site Code, then retain its opaque String `SiteNumber`, current `DefaultLang`, current `StatusCode`, current `EventsEnabledFlag`, and every child collection required by the selected operation. A site summary expands `languages`, `filters`, `cookieConsent`, `settings`, and `talentCommunitySignUp`; a focused discovery expands only its required collection. Resolve the installed language LOV separately when language labels/tags or a Site Editor Copy Link are needed. Stop on zero or multiple parent matches or an absent `SiteNumber`. Registration/template capability is required only for a mutating operation, never for these read-only discoveries.

For add language, reject a duplicate active site language. For add filter, apply the exact type/value validation and duplicate check in [ora_filters.md](ora_filters.md). For default-language change, reject a language not already in the enabled site-language collection; the user must add it successfully first. For activate/inactivate, treat a request for the already-current status as an idempotent no-op: return the verified current status and do not create an archive.

## Archive rules

For every mutating operation, resolve the current published registration and template through `core/data-loader` immediately before source generation. Build the source from the live header as a field-name-to-value map. Derive exactly one value list by iterating that sanitized header, then serialize that list once after `MERGE|<section>|`; never append a delimiter or value afterward. Reopen the final DAT member and require every `MERGE` line to have exactly the same pipe-cell count as its matching `METADATA` line, including trailing blanks. On any mismatch, reconstruct the row from its field map and stop before preview. Only then generate an immutable preview and obtain the Data Loader approval immediately before submission.

- **Add language:** Include only metadata required by the current Data Loader hierarchy and exactly one `languages` child POST row. Populate the requested language field and only technical parent-routing fields required by the live template. Exclude routing/technical fields from the REST body. Do not include a parent data row or Cookie Consent row. Use the [main Languages child contract](ora_main_registration_contract.md#languages-child-contract): `SiteLanguage` is the child surrogate, `SiteNumber` is the String parent identity, and cleared custom URL overrides are not a blocker.
- **Add filter:** Follow [ora_filters.md](ora_filters.md#existing-site-filter-post) and the [main Filters child contract](ora_main_registration_contract.md#filters-child-contract). Include only top-level and `filters` metadata required by the live hierarchy and one `filters` POST row per approved Filter. Populate `SiteCode`, `DimensionTypeCode`, the one matching normalized business value, and `RestAction=POST`; leave `ObjectCtxId`, `ObjectId`, and `SiteNumber` blank. Do not include a parent, Language, or Cookie Consent data row.
- **Update settings:** Follow [ora_settings.md](ora_settings.md#validation-and-archive-rules) and the [main Settings child contract](ora_main_registration_contract.md#settings-child-contract). Include only top-level and `settings` metadata required by the live hierarchy and one child row per requested key, using POST for an absent key or PATCH for an existing key. Populate `SettingKey`, normalized string `SettingValue`, `SiteCode`, and `RestAction`; leave `SettingId` and `SiteNumber` blank when present. Do not include a parent, Language, Cookie Consent, or Filters data row.
- **Update Talent Community Sign-Up:** Follow [ora_talent_community.md](ora_talent_community.md) and the [main Talent Community child contract](ora_main_registration_contract.md#talent-community-sign-up-child-contract). Include only top-level and `talentCommunitySignUp` metadata plus exactly one child PATCH row. Populate the exact singleton read-back `Id`, requested writable fields, `SiteCode`, and `RestAction=PATCH`; leave `SiteId`, `SiteNumber`, `Language`, and every unrequested field blank. A missing/blank default-child `Id` or a missing default child is a historical/partial-create blocker, not a reason to add a second initialization route. Do not include a parent, Language, Cookie Consent, Filters, or Settings row.
- **Default-language change / activate / inactivate:** Include only the parent section. Populate the current registration's required technical routing fields plus exactly one requested business field: `DefaultLang`, or `StatusCode=ORA_ACTIVE`, or `StatusCode=ORA_INACTIVE`. Set `RestAction=PATCH` only when the published parent PATCH contract requires it. Do not include a language or Cookie Consent row.

After a final successful load, run the corresponding read-only verifier in `ora_reference_lookups.md`. A verification mismatch is a failed operation; do not retry without a new immutable archive and approval.

## Read-only discovery rules

Do not generate a DAT file, consult the Data Loader registration, request an approval, or make a Fusion write for a summary or focused discovery. Return the effective behavior using [defaulting rules](ora_defaulting_rules.md): empty supported Filters mean **No restriction — All**; a normal default Cookie Consent or Talent Community singleton is **Fusion-initialized default** until patched; and absent Settings use their documented **Using editor default** behavior.

For a summary, clearly separate persisted values from effective defaults and include the parent status, Events state from `EventsEnabledFlag`, default language, enabled languages, every Filter category, Cookie Consent, Settings summary, and Talent Community state. If the UI base URL and default language tag can be resolved, include the Site Editor Copy Link result; otherwise list it as unavailable with the reason, without treating the rest of the summary as failed. Do not state that Events are enabled for the site merely because the global Events capability is available.

## Site-link behavior

Only return the verified Site Editor **Copy Link** route. It is a read-only result, not an archive or Data Loader action. Use a requested site-enabled language; otherwise use the verified current default language. Resolve its exact `LanguageTag` and the persisted String `SiteNumber`. Bind this read-only result to the same selected target environment used by the current login, site-creation, or Data Loader workflow. Derive the Fusion UI base URL from that environment's standard `restBaseUrl`, owned by the existing authentication/client configuration: remove only its trailing slash and append `/hcmUI`. Preserve its scheme, host, and explicit port. Do not select a different environment or ask the user for a base URL when the active environment's `restBaseUrl` is configured.

```text
{configured Fusion UI base URL}/CandidateExperience/{LanguageTag}/sites/{SiteNumber}
```

For example, a Korean site with `SiteNumber=CX_44037` has `https://cptcpuwqy.fusionapps.ocs.oc-test.com/hcmUI/CandidateExperience/ko/sites/CX_44037` when that environment's `restBaseUrl` is `https://cptcpuwqy.fusionapps.ocs.oc-test.com`. Do not use `SiteCode` or `SiteURLName`, do not put `sites` before the language segment, and never return a `CandExpSecured` route. An unqualified request for a site link returns this Site Editor Copy Link route. Return the link even when the site is inactive, with: **"The site is inactive. This Site Editor Copy Link will work after the site is activated."** For an active site, state that the public Site Editor Copy Link is available. Ask for a base URL only if the active target environment has no valid standard `restBaseUrl`; never ask merely because the skill repository has no separate `/hcmUI` setting.
