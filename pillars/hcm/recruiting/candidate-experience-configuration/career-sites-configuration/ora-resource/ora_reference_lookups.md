# Reference Lookups — Parent, Cookie Consent, Languages, Filters, Status, and Link

## Live Lookups

Run these requests only through `core.fusion-api.rest-api-client` after the user is authenticated to the configured Fusion environment. They are strictly read-only; no request in this table may create or update a Career Site.

| Resolver | Request | Required response handling |
| --- | --- | --- |
| `find_career_site_by_code` | `GET /hcmRestApi/resources/latest/recruitingCESites?fields=SiteCode&onlyData=true&limit=1000` | Page until `hasMore=false`; compare `items[*].SiteCode` to the requested code using exact case-sensitive equality. Zero matches permits create; one or more matches blocks it. |
| `resolve_active_career_site_language` | `GET /hcmRestApi/resources/latest/recruitingCELanguages?onlyData=true&limit=1000` | Match exact `items[*].LanguageCode`; require `ActivationStatus=ACTIVE`. Persist the matched `LanguageCode` and `Description` in preflight evidence. |
| `resolve_next_career_site_sequence` | `GET /hcmRestApi/resources/latest/recruitingCESites?fields=SequenceNumber&orderBy=SequenceNumber:desc&limit=1&onlyData=true` | Require exactly one numeric `items[0].SequenceNumber`; derive the next value as current maximum plus one. If no current value is returned, stop rather than inventing a seed value. |
| `resolve_career_site_parent_attribute_schema` | Fresh `recruitingCESites_attribute-details.xlsx` obtained by the core Data Loader metadata resolver immediately before the current preflight/archive | Require one parent worksheet with selectable `SiteName`, `SiteCode`, `DefaultLang`, `SequenceNumber`, `StatusCode`, and `TemplateNumber`. Use its ordered attributes to construct the parent source header; a skeletal sample DAT does not replace this schema. Persist the result for the current run only; never reuse a project copy from an earlier run. |
| `resolve_created_career_site` | `GET /hcmRestApi/resources/latest/recruitingCESites?fields=SiteCode,SiteNumber,SiteName,DefaultLang,StatusCode,SequenceNumber&onlyData=true&limit=1000` | Page until `hasMore=false`; require exactly one exact SiteCode match, exact approved parent values, and a nonblank String `SiteNumber`. Retain its exact value without numeric conversion. |
| `read_cookie_consent_collection` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=cookieConsent` | Require the exact parent and count `cookieConsent.items`. Exactly one is required for a Cookie Consent update; zero or more than one is an inconsistent historical state that blocks the operation. |
| `verify_initialized_career_site` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=languages,cookieConsent,filters` | Require exact approved parent values, every approved `SiteLanguage` exactly once including `DefaultLang`, no unexpected language rows, exactly one Cookie Consent row, and every requested Filter type/value pair after the combined load succeeds. |
| `resolve_cookie_consent_for_patch` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=cookieConsent` | Require one exact parent, a nonblank String `SiteNumber`, and exactly one child with a nonblank `CookieId`. Cross-check `CookieId` against the registration's SiteCode Object User Key before preparing PATCH. |
| `verify_cookie_consent_patch` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=cookieConsent` | Require the unchanged approved parent, exactly one child, and equality of every approved changed child field to its requested value. |
| `resolve_existing_career_site_operation_target` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true` after exact SiteCode resolution; expand only the child collections required by the selected operation | Require exactly one parent with nonblank String `SiteNumber`; retain `SiteCode`, `DefaultLang`, and `StatusCode` plus every requested child collection. |
| `read_career_site_summary` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=languages,filters,cookieConsent,settings,talentCommunitySignUp` after exact SiteCode resolution | Require one exact parent and retain all supported child collections. Report effective behavior using `ora_defaulting_rules.md`; an unavailable optional Site Editor Copy Link must not invalidate the rest of the summary. |
| `read_site_filter_state` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=filters` after exact SiteCode resolution | Retain the full collection and report each supported type. Empty collection, or a missing type, means **No restriction — All** for that type. |
| `read_site_cookie_consent_state` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=cookieConsent` after exact SiteCode resolution | Require exactly one child for normal state reporting. Zero or more than one is Data inconsistency; never call it unconfigured. |
| `read_site_talent_community_state` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=talentCommunitySignUp` after exact SiteCode resolution | Require exactly one child for normal state reporting. Report the returned state or Fusion-initialized default; zero or more than one is Data inconsistency. |
| `list_installed_career_site_languages` | `GET /hcmRestApi/resources/latest/recruitingCELanguages?onlyData=true&limit=1000` | Page until `hasMore=false`. Retain `LanguageCode`, `Description`, `LanguageTag`, and `ActivationStatus`; distinguish installed active languages from site-enabled languages. |
| `verify_site_language_add` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=languages` | Require the requested language exactly once, retain the unchanged parent `DefaultLang` and `StatusCode`, and verify Cookie Consent was not changed. |
| `verify_parent_lifecycle_patch` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=languages,cookieConsent` | Require the requested `DefaultLang` or `StatusCode`, unchanged unrequested parent values, unchanged language collection unless this was a language operation, and exactly one unchanged Cookie Consent child. |
| `resolve_existing_filter_target` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=filters` after exact SiteCode resolution | Require exactly one parent with nonblank String `SiteNumber` and its current `filters.items`. Retain the current collection for idempotency validation and a child-only POST; do not require `SiteId` as a Data Loader routing input. |
| `verify_filter_add` | `GET /hcmRestApi/resources/latest/recruitingCESites/{siteNumber}?onlyData=true&expand=languages,cookieConsent,filters` | Require each approved Filter type/value pair, unchanged parent fields, language collection, and Cookie Consent collection. |
| `search_filter_geography` | `GET /hcmRestApi/resources/latest/recruitingGeographyHierarchyLocationsLOV` with query `finder=findByWord;SearchTerms={search},FilterAttributes=GeographyName`, `onlyData=true`, `limit=100`; then `GET /hcmRestApi/resources/latest/recruitingHierarchyLocations` with query `finder=findByGeographyIds;Ids={geographyId}`. Send headers `Ora-Irc-Language: en`, `Accept-Language: en`. | Treat `GeographyId` as the only persisted value. Require the selected ID in the by-ID result; a name search must resolve to one exact display-name match or require the user to choose. |
| `search_filter_organization` | `GET /hcmRestApi/resources/latest/recruitingOrganizationsLOV` with query `finder=findByWord;SearchTerms={search},FilterAttributes=Name,StartsWithFlag=true`, `onlyData=true`, `limit=100`; then `GET /hcmRestApi/resources/latest/recruitingOrganizationsLOV/{organizationId}` with `onlyData=true`. Send headers `Ora-Irc-Language: en`, `Accept-Language: en`. | Treat `OrganizationId` as the only persisted value. Require the selected ID in the item result; never infer one from an ambiguous name search. |
| `list_filter_job_categories` | `GET /hcmRestApi/resources/latest/jobFamiliesLov` with query `limit=499`, `offset=0`, `orderBy=JobFamilyCode`, `onlyData=true`; send headers `Ora-Irc-Language: en`, `Accept-Language: en`. | Filter results to `ActiveStatus='A'`; then require exact returned `JobFamilyId` or one exact display-name match. Retain the returned ID unchanged. |
| `list_filter_job_functions` | `GET /hcmRestApi/resources/latest/recruitingCEDictionaries/1/lov/genericHcmLookups`, with query parameters `finder=findByLookupType;LookupType=JOB_FUNCTION_CODE`, `onlyData=true`, `limit=1000`; headers `Ora-Irc-Language: en`, `Accept-Language: en` | Read raw `LookupCode`/`Meaning` (or client-normalized `lookupCode`/`meaning`) case-insensitively by field name. Require exact code or one exact display-meaning match, then retain the returned code unchanged. The complete finder expression is one `finder` parameter, not separate `finder` and `LookupType` parameters. |
| `list_filter_recruiting_types` | `GET /hcmRestApi/resources/latest/recruitingCEDictionaries/1/lov/genericHcmLookups`, with query parameters `finder=findByLookupType;LookupType=ORA_IRC_RECRUITING_TYPE`, `onlyData=true`, `limit=1000`; headers `Ora-Irc-Language: en`, `Accept-Language: en` | Read raw `LookupCode`/`Meaning` (or client-normalized `lookupCode`/`meaning`) case-insensitively by field name. Require exact code or one exact display-meaning match, then retain the returned code unchanged. The complete finder expression is one `finder` parameter, not separate `finder` and `LookupType` parameters. |
| `resolve_career_site_ui_base_url` | The same active target environment's standard `restBaseUrl` used by login, site creation, and Data Loader | Require a nonblank valid HTTPS `restBaseUrl`; preserve its scheme, host, and port, remove only a trailing slash, then append `/hcmUI`. This is not obtained from `SiteURLName` or `SiteNumber`, and the user is not asked for it while the active environment's `restBaseUrl` is configured. |

Use exact matching. Retain the generated String `SiteNumber` as the opaque REST parent identity for read-back and verification; do not convert it to a number or invent it in DAT. Filter requests additionally use the live Filter LOVs above; settings, talent, and targeting remain outside this phase.
