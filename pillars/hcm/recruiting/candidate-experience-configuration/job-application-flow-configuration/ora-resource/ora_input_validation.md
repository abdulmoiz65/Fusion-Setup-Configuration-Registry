# Input Validation

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Operation | Retrieve, DesignNew, CreateFromTemplate, CreateVersion, or an unambiguous natural-language equivalent | MISSING or UNSUPPORTED | Normalize create apply flow, create applyflow and createapply flow to DesignNew when no template or existing-parent version intent is supplied; creation scope is owned by AF.ROUTE_OPERATION. Preserve explicit prohibited intent even if mixed with supported intent; route to matching refusal node before export | AF.VALIDATE_REQUEST | |
| Environment | One selected target environment | MISSING | Select the intended environment; no authentication during authoring | AF.VALIDATE_REQUEST; all supported operations | |
| New flow | Target AfCode, Target ApplyFlowName, Application Flow Type | MISSING | Supply nonblank new code/name and supported type | AF.VALIDATE_REQUEST; DesignNew | |
| Template | Exact Source AfCode, Target AfCode, Target ApplyFlowName | MISSING | Supply one source and a new target identity; exact source name/version are optional cross-check/selection inputs | AF.VALIDATE_REQUEST; CreateFromTemplate | |
| Parent | Exact Parent AfCode | MISSING | Supply an existing parent code; type and all version names are resolved before defaults | AF.VALIDATE_REQUEST; CreateVersion | |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Supported input scope | Retrieve: environment and optional exact supported AfTypeCode filter only. DesignNew: required identity/type plus optional Description, VersionName, applicable options, External Recruiting Type Meaning, blocks/order and translations. Template: optional exact source name/version, target VersionName, applicable options, additional External Recruiting Type Meaning, block changes and translations. Version: optional VersionName, applicable options, blocks/order and section/page/page-block translations only | AF.VALIDATE_REQUEST | |
| Unknown or mixed prohibited input | Reject every unlisted field or operation, including generic View, Change or standalone Validate. Dispatch known prohibited input to its dedicated refusal node; report all supplied issues and select the first applicable refusal by task sequence. Never silently discard intent or export first | AF.VALIDATE_REQUEST | |
| Retrieve filter | Without a filter return all ORA_IRC_JA_APPLY_FLOW.csv root rows, including historical internal types. With a filter require exact supported AfTypeCode equality. Return zero rows as success when valid evidence has no matches | AF.FILTER_RETRIEVE | resolve_apply_flow_type |
| New target conflicts | Reject if either target AfCode or ApplyFlowName exists in complete target root evidence. CreateVersion parent identity is not subject to this new-root check | AF.VALIDATE_TARGET_IDENTITY; AF.VALIDATE_TEMPLATE_CONFLICTS | resolve_apply_flow_identity |
| Type and selected-branch readiness | AF.VALIDATE_FLOW_TYPE requires AF.ROUTE_OPERATION plus the selected successful predecessor: DesignNew AF.VALIDATE_TARGET_IDENTITY; CreateFromTemplate AF.COPY_SUPPORTED_TEMPLATE_HIERARCHY; CreateVersion AF.RESOLVE_PARENT_FLOW. Evaluate only that alternative, never an AND join of mutually exclusive branches. Validate supplied/inherited type against the static local authority | AF.VALIDATE_FLOW_TYPE | resolve_apply_flow_type |
| Inherited type and parent fields | Template/version inherit type; reject replacement AfTypeCode. CreateVersion rejects root name, root Description/status/translations and availability changes. Template Description is copied; only supported explicit language/field translations may change translated Description | AF.VALIDATE_REQUEST and AF.VALIDATE_FLOW_TYPE after source/parent resolution | |
| Version conflict | Final VersionName must be absent under exact target AfCode, including inactive names. Existing CreateVersion parent is required and is not itself a conflict | AF.VALIDATE_VERSION_CONFLICT | resolve_apply_flow_version_conflict |
| Text limits | AfCode <=30, ApplyFlowName <=240, Description <=1000, VersionName <=240 characters, including final copied/translated values where applicable. Never truncate. Required identity text and an explicitly supplied VersionName cannot be blank | AF.VALIDATE_REQUEST for supplied text; AF.VALIDATE_FIELD_LENGTHS for resolved candidate | |
| Option input | Explicit applicable options accept only uppercase Y or N. Reject lower-case, true/false, yes/no, 1/0, blank or inapplicable values; defaulting uses the resolved type, never an assumed type | AF.VALIDATE_REQUEST for supplied shape; AF.RESOLVE_VERSION_OPTIONS for resolved applicability | |
| Recruiting Type input | Only a business Meaning on External DesignNew/CreateFromTemplate is accepted; CreateVersion and every other type reject it before lookup | AF.RESOLVE_RECRUITING_TYPE after type validation | |
| Translation shape | Each explicit value identifies one supported field, exact target entity and Language code. Reject duplicate/contradictory assignments. Supported fields are ApplyFlowName, Description, SectionName, PageName, PageBlockTitle, PageBlockInstructions within operation scope | AF.VALIDATE_REQUEST; AF.RESOLVE_TRANSLATIONS | |
| Sequences | Factory section/page sequences remain fixed; copied template section/page sequences remain unchanged even when non-factory. Per-page PageBlockSeqNum is a unique contiguous integer sequence from 1; identify the parent and offending values on failure | AF.VALIDATE_SEQUENCES | |
| Block fields | Accept BlockCode, one existing fixed target page, intended order, PageBlockTitle and PageBlockInstructions including supported translations. Reject unsupported fields through the refusal table | AF.VALIDATE_REQUEST; AF.VALIDATE_PROHIBITED_FIELDS | |
| Input presence | Preserve whether block information and each supported checkbox were supplied or omitted, including explicit N and explicit empty/invalid input. Do not coerce supplied values to missing or lose the original selection before applying the owning default/design rules | AF.VALIDATE_REQUEST | |
| Required block titles | Reject explicit null, empty or whitespace-only PageBlockTitle, including any language override. Omitted titles use ora_defaulting_rules.md. Require a nonblank title in every final ORA_IRC_JOB_AF_PAGE_BLOCK.csv row and every ORA_IRC_JOB_AF_PAGE_BLOCK_TL.csv row; verify base/US agreement and resolved default/copy/override evidence. Name the offending block key and Language before preview; a populated BlockCode alone does not satisfy title validation | AF.VALIDATE_REQUEST for supplied values; AF.VALIDATE_NEW_FLOW_PACKAGE, AF.VALIDATE_TEMPLATE_PACKAGE, AF.VALIDATE_VERSION_PACKAGE for final bytes | |
| Final prohibited-field scan | Reject property-child values, visibility/requiredness/conditional/hidden overrides and unsupported dates; property input routes to AF.REFUSE_PROPERTIES, dates to AF.REFUSE_DATES, other invalid fields to AF.HANDLE_ISSUES. Empty property children are valid for Draft blocks, including bare Questionnaire for PADC | AF.VALIDATE_PROHIBITED_FIELDS | |
| CSV encoding and headers | Inspect raw bytes of every CSV in the final ZIP, including header-only members. Reject a leading UTF-8 BOM (EF BB BF), then decode with strict UTF-8 and compare parsed header names and order exactly with the carrier. Do not use utf-8-sig, strip U+FEFF, normalize headers or replace decoding errors during validation. Reject any added ApplyFlowId column. Record per-member results; any failure blocks preview and import | AF.VALIDATE_NEW_FLOW_PACKAGE; AF.VALIDATE_TEMPLATE_PACKAGE; AF.VALIDATE_VERSION_PACKAGE | |
| Package result | Evaluate final immutable byte-validation evidence, including per-member CSV encoding and headers results, against Operation Row Scope, Package Members, Verified Headers and Package Invariants in ora_design_enforcement.md. Missing evidence or mismatch is failure, not permission to generate a substitute archive or claim success | AF.VALIDATE_NEW_FLOW_PACKAGE; AF.VALIDATE_TEMPLATE_PACKAGE; AF.VALIDATE_VERSION_PACKAGE | |
| Explicit-input reconciliation | Apply the owning Explicit Block Selection and supplied-values package invariant to final CSVs for every supported AfTypeCode. Validate the retained selection and per-option input-presence evidence against actual block/TL rows and checkbox values, not just factory row counts | AF.VALIDATE_NEW_FLOW_PACKAGE; AF.VALIDATE_TEMPLATE_PACKAGE; AF.VALIDATE_VERSION_PACKAGE | |
| Final block support | Reapply AF.VALIDATE_BLOCK_APPLICABILITY to every reopened ORA_IRC_JOB_AF_PAGE_BLOCK.csv row. An unsupported block blocks preview and import even if copied from a template or retained from an older prepared package. Report the block code and parent/sequence key; do not silently remove it | AF.VALIDATE_NEW_FLOW_PACKAGE; AF.VALIDATE_TEMPLATE_PACKAGE; AF.VALIDATE_VERSION_PACKAGE | resolve_apply_flow_block |
| Package branch | New flow: exactly one new Draft root plus one initial Draft version in the same package, even if the user only asked to create a flow. Template: one new Draft root plus one initial Draft version from the selected source hierarchy with preserved valid layout/translations plus supported defaults/overrides. Reject a missing or header-only ORA_IRC_JOB_AF_VERSION.csv, more than one version, a wrong parent AfCode or missing required descendants. Version: exactly one new version, root/root-TL/availability members header-only and parent unchanged | Operation-specific package validation | |
| Preview reconciliation | Require final package evidence sufficient for the Business-first Preview Contract in ora_error_handling.md: names, every section/page/block instance, totals, options and translations agree with exact final CSVs. Missing or inconsistent evidence fails before presenting approval; do not substitute intended inputs for package values | All three package-validation nodes | |

## Dependency-Aware Validation

| Applies When | Result | Next Action | Resolver |
|---|---|---|---|
| Source or parent evidence required | Lookup | Resolve exact selected identity before defaults or dependent validation | resolve_apply_flow_identity |
| Template source version or parent name set required | Lookup | Resolve exact eligible source version, or all parent version names, without assuming latest | resolve_apply_flow_version |
| Final VersionName selected | Lookup | Validate exact parent/version uniqueness before package construction | resolve_apply_flow_version_conflict |

## Unsupported Input Refusals

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Block-property configuration | Reject block-specific property-child input, including questionnaire selection/version, profile section, EFF context, document category and visibility/requiredness settings; use the Unsupported operation manual handoff in ora_error_handling.md. Supported block code/page/order/title/instructions apply only to new-flow/new-version construction, not edits to an existing version | AF.REFUSE_PROPERTIES | |
| Flow activation/deactivation | Refuse the requested operation without mutation; use the Unsupported operation manual handoff in ora_error_handling.md | AF.REFUSE_FLOW_LIFECYCLE | |
| Flow deletion | Refuse the requested operation without mutation; use the Unsupported operation manual handoff in ora_error_handling.md | AF.REFUSE_FLOW_DELETE | |
| Existing-flow editing | Refuse the requested operation without mutation; use the Unsupported operation manual handoff in ora_error_handling.md | AF.REFUSE_FLOW_EDIT | |
| Existing-version block changes | Refuse adding, editing or removing blocks in an existing apply flow/version; use the Unsupported operation manual handoff in ora_error_handling.md. Do not substitute a new flow or version for the requested edit | AF.REFUSE_EXISTING_BLOCK_EDIT | |
| Version activation | Refuse the requested operation without mutation; use the Unsupported operation manual handoff in ora_error_handling.md | AF.REFUSE_VERSION_ACTIVATE | |
| Version deletion | Refuse the requested operation without mutation; use the Unsupported operation manual handoff in ora_error_handling.md | AF.REFUSE_VERSION_DELETE | |
| Existing-version editing | Refuse editing an existing version, including a Draft version; use the Unsupported operation manual handoff in ora_error_handling.md. Do not substitute version creation | AF.REFUSE_VERSION_EDIT | |
| Unsupported creation type | Show supplied/inherited value and the four supported meanings/codes; refuse ORA_INTERNAL, ORA_PADC_INTERNAL and unlisted types | AF.REFUSE_UNSUPPORTED_TYPE | resolve_apply_flow_type |
| Version dates | Reject Version Start Date and Start on Activation; neither is serialized | AF.REFUSE_DATES | |
| Direct REST mutation | Refuse direct writes; only later eligible approved FSM submission through core.data-loader is supported | AF.REFUSE_DIRECT_MUTATION | |

Refusal nodes are entered by a failed check, so their successful-prerequisite
list is none. Their incoming transitions and Applies When retain the exact
refusal origin. They never provide an alternate successful creation path.
