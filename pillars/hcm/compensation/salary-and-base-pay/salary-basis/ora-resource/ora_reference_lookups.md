### Resolver Evidence Contract

For every Salary Basis resolver, generate an internal evidence record before a
preview is built. It must include `resolver`, `status`, `requested`,
`matchedRecords`, and `classification`; the task orchestrator derives the
Data Loader rule result, issues, and pass/block state from these records. Do
not ask users to provide these internal values. A missing record, non-exact
identity match, ambiguous result, or `query-contract failure` blocks the
create preview.

For `resolve_salary_basis_input_value_id`, the successful record also carries
`requested.elementName`, `requested.inputValueName`, and `values` containing
the exact `ElementName`, `InputValueName`, and `InputValueId`. The separate
Salary Basis payload-preparation runbook consumes this record and must reject
any mismatch rather than infer or hand-enter the ID.

## Read-Only Element Validation Boundary

The element resolver validates only the supplied element identity, LDG, and effective dates returned by payrollElementDefinitionsLOV. It does not validate category, primary classification, processing type, calculation rule, or automatic eligibility. It is a read-only prerequisite check and does not authorize a Data Loader payload, upload, import, create, update, delete, or any other mutation.
