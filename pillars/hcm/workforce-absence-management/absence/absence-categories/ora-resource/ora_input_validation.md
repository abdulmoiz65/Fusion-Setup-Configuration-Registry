# Absence Categories Input Validation

Source guidance: [Absence Categories - REST API Details](https://confluence.oraclecorp.com/confluence/display/FUSIONANC/Absence+Categories+-+REST+API+Details?src=contextnavpagetreemode) and [Absence Categories - Fields REST Mapping - 310826](https://confluence.oraclecorp.com/confluence/display/FUSIONANC/Absence+Categories+-+Fields+REST+Mapping+-+310826?src=contextnavpagetreemode).

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Operation and target | Requested operation; selected effective-dated category identity for non-create operations | Stop before preparation | Select create, update, correction, end-date, delete-changes, or ZAP; resolve exactly one category in the selected effective context | Every date-effective request | find_absence_category_by_exact_name |
| Category view filters | Optional Name, effective date, Status, and Legislation | Default the view context to active and current system date | Apply only supplied filters; never treat a browse result as a selected maintenance target | View or filter request | find_absence_categories |
| Policy grouping | Policy scope, leave inventory, jurisdiction, reporting purpose, separation rules, and effective date | Flag each missing or ambiguous decision in the proposal | Collect the missing decision; do not infer statutory, pay, eligibility, or reporting rules | Taxonomy or reporting-design request |  |
| Category name or resolved maintenance identity | Name for create; exact Name or previously resolved AbsenceCategoryId for maintenance | Request the name only when no usable identity was provided or resolved | Validate a supplied nonblank Name up to 240 characters; for maintenance resolve the selected dated row and retain its observed name | Every request | find_absence_category_by_exact_name |
| Removal intent | End date, Delete changes, or ZAP | Stop and request the exact operation | Recommend End date to stop future use while retaining history; never infer Delete changes or ZAP from “delete” | End-date or delete request |  |
| Category effective start | EffectiveStartDate or RangeStartDate | Stop and request an explicit date or confirmation of the displayed system date | Use the user-supplied ISO date in YYYY-MM-DD format; otherwise, only for a create with the live mandatory flag and explicit consultant confirmation, apply the current system date in the same format for the parent effective-of RangeStartDate contract | Every create request |  |
| Date-effective control | EffectiveStartDate, EffectiveEndDate, and derived effectiveOf | Stop if the selected operation has no applicable explicit date or its effectiveOf value cannot be derived exactly | Create may default EffectiveStartDate; update, correction, delete-changes, and end-date require the applicable explicit date; ZAP requires explicit destructive intent | Every date-effective request | normalize_absence_category_effective_of |
| Category status | Status code or status display meaning | Stop and request a category status | Supply one ANC_SETUP_OBJ_STATUS code or meaning and resolve it to LookupCode | Every create request | resolve_absence_category_status |
| Legislation | LegislationCode or legislation display name | Stop when an associated type is supplied; otherwise legislation may remain omitted | Supply a territory code or display name and resolve it to TerritoryCode | An associated absence type is supplied, or legislation is explicitly supplied | resolve_absence_category_legislation |
| Associated absence type | AbsenceTypeId or absence type Name | Stop and request one associated absence type identity | Supply an existing type ID or exact type name that is effective on the resolved association start date and matches LegislationCode | An absenceCategoryTypes item is supplied | resolve_associated_absence_type |
| Associated type status | absenceCategoryTypes.Status code or display meaning | Stop and request the association status | Supply one ANC_SETUP_OBJ_STATUS code or meaning and resolve it to LookupCode | An absenceCategoryTypes item is supplied | resolve_absence_category_status |
| Associated type effective start | absenceCategoryTypes.EffectiveStartDate | Default to the resolved category parent EffectiveStartDate | Supply a child date in YYYY-MM-DD format to override the inherited parent date; otherwise copy the resolved parent EffectiveStartDate to the child | An absenceCategoryTypes item is supplied |  |
| Association evidence | Selected category export/history, resolved type, Type, Status, and Effective Start Date | Stop before preparation | Confirm no duplicate or overlapping effective-dated association and that the association date is not before the category or type effective date | Association create or maintenance | resolve_associated_absence_type |

## Dependency-Aware Validation

| Applies When | Result | Next Action | Resolver |
|---|---|---|---|
| A category or associated-type status code or meaning is supplied | Require exactly one ANC_SETUP_OBJ_STATUS row and populate the applicable Status from LookupCode | Continue only with the resolved code | resolve_absence_category_status |
| A date-effective create, update, correction, end-date, delete-changes, or ZAP operation is requested | Require one exact operation-to-effectiveOf mapping and, for non-create operations, one resolved selected effective-dated category | Continue only with the derived effectiveOf on every included row | normalize_absence_category_effective_of |
| A legislation code or display name is supplied | Require exactly one territory row and populate LegislationCode from TerritoryCode | Continue only with the resolved code | resolve_absence_category_legislation |
| An associated absence type is supplied | Require exactly one matching absence type that has the resolved legislation and is effective on the resolved absenceCategoryTypes.EffectiveStartDate | Populate absenceCategoryTypes.AbsenceTypeId and continue only after the dependency is ready | resolve_associated_absence_type |
| General or legislative flexfield data is supplied | Require current absenceCategories describe metadata before validating contexts or segments | Refresh describe and validate only fields present in the target-environment response | refresh_absence_categories_describe |
| Any date-effective source is supplied | Require the registered Data Loader template to expose effectiveOf on the parent and every included child/DFF section | Refresh the UCM template and stop when a selected section lacks effectiveOf | refresh_absence_categories_dataloader_template |
| A correction or update supplies an AbsenceCategoriesDDFFlex or AbsenceCategoriesFlex value | Require the registered AbsenceCategoryId, resolved child effective range, and current segment/context metadata | Populate identity and date-key fields from the resolver; accept the registered shared surrogate without requiring a separate child ID | resolve_absence_category_flex_dataloader_contract |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Parent end-date source preserves resolved parent fields | Require AbsenceCategoryId, EffectiveStartDate, EffectiveEndDate, Name, LegislationCode, Status, effectiveOf, and RestAction in the parent source. Copy ID, selected slice start, Name, LegislationCode, and Status from the resolved row; change only the requested end date and derive the END_DATE control. Retain a returned blank legislation without inventing one. Reject missing columns, unresolved identity, or unrelated business-value changes before preview. | Parent-category end-date request | find_absence_category_by_exact_name |
| Name is nonblank and no longer than 240 characters | Accept the value; otherwise stop with the exact field issue | Name is supplied |  |
| Non-create category identity resolves exactly once | Require one category in the selected effective-date context; retain its registered ID, name and dates. For historical correction, accept the selected prior slice tied to the resolved ID even when its name differs from today's name. | Update, correction, end-date, delete-changes, or ZAP | find_absence_category_by_exact_name |
| Category EffectiveStartDate is an ISO date | Accept YYYY-MM-DD for the parent effective-of RangeStartDate value; otherwise stop before preparation | EffectiveStartDate or RangeStartDate is supplied |  |
| Category EffectiveStartDate uses the current system date only after explicit confirmation | Display the date and apply it in YYYY-MM-DD format only after consultant confirmation | Create; EffectiveStartDate and RangeStartDate are both absent; current live parent metadata marks EffectiveStartDate mandatory for new records |  |
| effectiveOf matches the selected operation | Create: `RangeStartDate=<EffectiveStartDate>`; update: `RangeMode=UPDATE;RangeStartDate=<EffectiveStartDate>`; correction: `RangeMode=CORRECTION;RangeStartDate=<EffectiveStartDate>`; end-date: `RangeMode=END_DATE;RangeEndDate=<EffectiveEndDate>`; delete-changes: `RangeMode=DELETE_CHANGES;RangeStartDate=<EffectiveStartDate>`; ZAP: `RangeMode=ZAP` | Every date-effective source row | normalize_absence_category_effective_of |
| Each row uses its operation-specific effectiveOf | Validate each row against ora_defaulting_rules.md. Existing flex rows participating in a parent update share that update range; new association POST rows use the create range, not a parent UPDATE or CORRECTION mode. Do not add a row solely to carry effectiveOf. | An AbsenceCategoriesDDFFlex, AbsenceCategoriesFlex, or absenceCategoryTypes row is included | normalize_absence_category_effective_of |
| Association parent identity differs from association identity | Retain resolved AbsenceCategoryId as ParentId. For a new association omit generated AbsenceTypeCateId; for maintenance resolve the existing AbsenceTypeCateId and dated row. Never substitute AbsenceTypeId or AbsenceCategoryId for AbsenceTypeCateId. ParentUserKeys LegislationCode,Name are an alternative registered parent lookup, not the child's ObjectUserKeys. | An absenceCategoryTypes row is included | find_absence_category_by_exact_name |
| Final immutable DAT contains derived effectiveOf | Inspect the exact DAT member inside the final upload archive. Require the effectiveOf header and derived value in every included parent or child MERGE row. A flex-only correction may omit the parent section; its resolved parent identity is still required. Caller-provided Task Hook `ruleResults` is not validation evidence. | Every date-effective source before preview or approval | normalize_absence_category_effective_of |
| Flexfield correction or update includes the complete registered identity | Require a nonblank resolved AbsenceCategoryId and valid EffectiveStartDate and EffectiveEndDate on every changed DDF/DFF row. AbsenceCategoryId is the registered surrogate and parent ID; do not put a comma-separated or opaque REST key in it. Dates must match the selected correction slice or the planned update slice under ora_defaulting_rules.md. | A correction or update source includes a DDF or DFF child row | resolve_absence_category_flex_dataloader_contract |
| Non-create date inputs are explicit | Reject defaulted dates, an unspecified deletion scope, or a ZAP without destructive intent | Update, correction, end-date, delete-changes, or ZAP | normalize_absence_category_effective_of |
| Associated type EffectiveStartDate is an ISO date | Accept YYYY-MM-DD; otherwise stop before preparation | absenceCategoryTypes.EffectiveStartDate is supplied |  |
| Associated type EffectiveStartDate defaults from the parent when absent | Copy the resolved category parent EffectiveStartDate to each absenceCategoryTypes row without overriding an explicitly supplied child date | An absenceCategoryTypes row omits EffectiveStartDate |  |
| EffectiveEndDate is an ISO date from explicit input or resolved flex identity | Preserve an explicit YYYY-MM-DD value. For DDF/DFF maintenance, retain the resolved existing child end date required by its registration, without treating it as a newly requested end date; otherwise omit the field and do not create a client default. | EffectiveEndDate is supplied or carried as a DDF/DFF date-key field |  |
| Description is no longer than 2000 characters | Accept the value; otherwise stop | Description is supplied |  |
| Description and technical rationale have separate destinations | Keep an employee-safe supplied description in the category; retain policy citations, technical logic, report mapping, and unresolved decisions only in the project summary | Create or taxonomy-design request |  |
| Status values resolve through ANC_SETUP_OBJ_STATUS | Use the resolved LookupCode for the parent or association; otherwise stop | A Status value is supplied | resolve_absence_category_status |
| LegislationCode is no longer than 30 characters and resolves to one territory | Use the resolved TerritoryCode; otherwise stop | Legislation is supplied or required by an associated type | resolve_absence_category_legislation |
| Associated type matches the category context | Require one type with matching LegislationCode whose effective range includes the resolved absenceCategoryTypes.EffectiveStartDate | An associated absence type is supplied | resolve_associated_absence_type |
| Association is unique and effective | Compare the resolved category export/history with the selected type and association date; reject duplicate or overlapping associations and dates before the category or type becomes effective | Association create or maintenance | resolve_associated_absence_type |
| Language is absent from client input | Remove Language from preparation because Fusion derives it from the authenticated login context; never default it | Language appears in supplied input |  |
| Audit and response-only meaning fields are absent | Reject CreatedBy, CreationDate, LastUpdatedBy, LastUpdateDate, LegislationMeaning, ManagementTypeCdMeaning, StatusMeaning, AbsenceTypeName, and flex display-context values as write fields | Any source row contains one of these fields |  |
| Generated identifiers and values are omitted for ordinary create | Reject AbsenceCategoryId, AncAbsCategoryFAltcd, BaseName, AbsenceTypeCateId, and child parent keys unless a separately documented operation explicitly requires them | Ordinary create request |  |
| Flexfield attributes exist in current metadata | Reject deployment-specific contexts or segments absent from refreshed describe metadata | General or legislative flexfield data is supplied | refresh_absence_categories_describe |
| Flexfield actions and fields conform to the registered template | Use a MERGE DAT directive with RestAction=PATCH for a correction or update. Require the derived effectiveOf plus ID/start/end fields on the final changed child row. Preserve unrelated segments by omitting them; never serialize display-context values, an undocumented ParentIdentifier, or a blank POST/PATCH URL as data. | A correction or update source sets any AbsenceCategoriesDDFFlex or AbsenceCategoriesFlex value | refresh_absence_categories_dataloader_template |
