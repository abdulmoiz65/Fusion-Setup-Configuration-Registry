# Absence Plans Input Validation

Source guidance: [Absence Plan Setup - REST API Details](https://confluence.oraclecorp.com/confluence/display/FUSIONANC/Absence+Plan+Setup+-+REST+API+Details), [Absence Plans Minimal + LOVs](https://confluence.oraclecorp.com/confluence/pages/viewpage.action?pageId=21792518140), and the developer-provided sanitized Fusion UI HAR captured on 2026-09-01.

## Evidence Boundary

The REST details page supplies the current resource contract. The minimal-plan page records values posted by six successful client captures. Treat captured values as conditional preparation candidates only: they are not evidence of server-side defaulting, user-override policy, or portable tenant data.

The registered `absencePlans` Data Loader object currently contains exactly eight sections: parent `absencePlans`; direct children `absencePlanDDFs`, `absencePlanDFFs`, `accrualBands`, `eligibilityProfiles`, `entitlementBands`, and `events`; and nested child `entitlementBandDetails` under `entitlementBands`. Refresh the registered template before every preparation and stop if that inventory changes. A REST child action is read/metadata evidence only; mutation remains routed through `core.data-loader`.
