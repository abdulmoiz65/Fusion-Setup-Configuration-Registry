# Absence Plans Design Enforcement

## Execution Boundary

This resource package validates data and stops at a handoff. Every Absence Plans mutation must use core.data-loader in REST mode with BusinessObject absencePlans. The Data Loader workflow owns source review, immutable preview, explicit approval, submission, status handling, and diagnostics. This resource package does not supply or authorize a direct REST write route.

## Lifecycle Impact Evidence Boundary

For AC8, a definitive application-reported result means supported evidence of the selected operation's impact or dependency, not an invented assertion that every dependency count is zero. Preserve and disclose the scope of the evidence. The source-backed Delete Plan and End Date dialogs report setup cascade behavior; a generic cascade warning does not establish target-specific enrollment, pending-absence counts, or final server permission. An enabled menu entry is not proof that Fusion permits the final action. Before end date, assess participation and pending absences as required by the story; when the necessary supported read contract is unavailable, retain that specific blocker. Do not require an invented comprehensive dependency-count API for every operation, and do not treat unknown impact as no impact.

The [Absence Plans VB UI Analysis, version 2](https://confluence.oraclecorp.com/confluence/pages/viewpage.action?pageId=21810192649) places `isPlanEnrolled` in the manage-page editability flow. Its name, action availability, or string return alone does not establish a complete lifecycle preflight or pending-absence check. The [REST API Details](https://confluence.oraclecorp.com/confluence/pages/viewpage.action?pageId=21792512110) also leaves runtime delete restrictions unresolved. Do not call that action as an undeclared substitute for the required check, infer clearance from Pending status, or trial-submit a deletion. These evidence boundaries do not add a new execution route: every mutation remains in the approved Data Loader workflow, and unresolved operation-relevant checks remain blocked.
