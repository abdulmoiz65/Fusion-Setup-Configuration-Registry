# Absence Plans Error Handling

## Error Situations

| Situation | What Should Happen |
|---|---|
| A required or policy-relevant value is absent, ambiguous, or supported only by a captured profile | Report the missing business decision and ask for the named setting and value. Do not treat general permission to use defaults as policy confirmation. Omit optional fields without a policy requirement; stop if applicability is uncertain. Retain decisions and unresolved items in the policy-to-configuration summary. |
| A required plan name or current-loader-required target value is missing | Identify the exact field and stop before Data Loader preparation |
| EffectiveStartDate and RangeStartDate are both omitted for a create | Ask: No effective start date was supplied. Should I use today, <YYYY-MM-DD>? Stop before date normalization or DAT preparation until the user confirms that exact date or supplies another date. Then derive effectiveOf and disclose the confirmed date in the Data Loader handoff. |
| An operation-required effective date is missing for a date-scoped non-create operation | Classify as input validation and request the exact operation-specific business date; do not default it. ZAP instead requires explicit complete-deletion scope for the selected logical target and a verified dated identity at its recorded lookup as-of date, not an invented range date. |
| A prepared create source synthesizes EffectiveEndDate or emits it as a physical DAT column | Do not ask for or default a create end date. Preserve a supplied valid ISO end date as business intent and follow the governed supplied-create-end-date rule in ora_input_validation.md. Block unsupported handling; never emit the physical field or silently discard the requested end date. |
| Fusion reports that a data line exceeds 4000 characters | Classify as source-shape validation. Rebuild the affected section with a compact METADATA header containing only populated user values, applied documented defaults, and required nonblank loader control or relationship values; do not retry the complete-template header. |
| A final immutable DAT member has a METADATA line of 4,000 characters or longer, a blank header field, physical effective-date attribute, or an effectiveOf form different from the normalized operation/date | Classify as source-shape validation. Do not preview or upload. Rebuild the exact member compactly, derive `RangeStartDate=<YYYY-MM-DD>` for a create and `RangeMode=CORRECTION;RangeStartDate=<YYYY-MM-DD>` for a correction, recreate the ZIP, and revalidate it. |
| A parent formula-based accrual definition readback shows Matrix or no parent accrual formula | Classify as controller-default mapping failure for the requested absencePlans.AccrualFormulaId definition. Do not accept that parent load as configured. Correct the compact parent row to include `AccrualDefinitionType=F` and the independently resolved parent accrual formula ID, then require a new immutable preview and approval. A formula on accrualBands.AccrualFormulaId does not select the parent Formula definition; do not treat its Matrix parent as this failure or add a parent MERGE row for that reason. |
| Requested Elective Disbursements read back blank or disabled | Classify as enable-controller mapping failure. Do not infer Disburse remaining balance. Correct the plan through a separately approved same-date correction with `CashOutFlag=Y`, election date, payment percentage, and evaluation formula; then verify each value by readback. |
| Elective values remain blank after the separately approved correction while Formula is selected for Discretionary Disbursements | Classify as a target compatibility conflict. Preserve the observed readback and stop. Require the requester to choose whether to retain Formula-based Discretionary Disbursements or switch that separate rule to Flat amount to pursue the target's retained elective pattern; never change either policy silently. |
| A requested payroll element reads back null | Classify as enable-controller mapping failure. Correct the plan through a separately approved same-date correction with `PayrollImpactFlag=Y` and the resolved payroll mapping ID; then verify both values by readback. |
| A final-disbursement formula is discarded after a rate definition is loaded, or both are requested | Classify as a controller conflict. Formula or Rate definition is mutually exclusive for the same target. Stop and ask the requester to choose Formula (`F` plus formula ID) or Rate definition (`D` plus rate ID); do not trial-load both. |
| Fusion rejects physical EffectiveStartDate as a date-effective update attribute | Classify as Data Loader source-shape validation. Remove EffectiveStartDate from the parent and every included supported child/DFF section, derive effectiveOf from the business effective date using the selected operation mapping, revalidate the changed archive, and require new approval before resubmission. |
| Fusion rejects the business effective date or derived effectiveOf format | Classify as input validation. Use the supplied or explicitly confirmed YYYY-MM-DD start date for a create and the explicit operation-specific date when required for maintenance. Derive the Date-Effective Operation Mapping for each section: END_DATE uses RangeEndDate and ZAP has no range date. Do not retry a YYYY/MM/DD, partial, locale-formatted, or caller-authored effectiveOf value. |
| A plan type is omitted and the policy description maps to exactly one Plan-Type Intent Matrix entry | Present the proposed type and ask The description maps to [Plan Type]. Should I create a [Plan Type] plan? For unpaid tracking, do this only after the policy states that it tracks time with no entitlement or qualification assessment and no accrual balance. Do not set AbsencePlanTypeCode, apply a profile, or prepare a DAT until the user explicitly confirms. |
| An unpaid-tracking request could be Qualification or No Entitlement and no entitlement-policy direction is supplied | Ask: No entitlement policy was provided. Is this a Qualification plan or a No Entitlement plan? Reply Qualification if the plan determines entitlement or qualification; otherwise reply No Entitlement only if it tracks time with no entitlement and no accrual balance. Do not set ProposedAbsencePlanTypeCode or ResolvedAbsencePlanTypeCode, apply a Q or N plan-type profile, or prepare a DAT until the user explicitly selects one. |
| Supplied Q conflicts with tracking-only/no-balance policy, or supplied N conflicts with an expressly required entitlement or qualification assessment | Explain the conflict, remove the resolved type, and ask whether the policy requires Qualification or only tracking with No Entitlement. Do not recommend or configure a Qualification combination, or apply either profile, until the user supplies a compatible policy direction and selection. |
| A plan type is omitted and no policy description is supplied, or the policy description has zero, multiple, or conflicting Plan-Type Intent Matrix matches outside the Qualification or No Entitlement decision | Ask the user to choose Accrual, Qualification, No Entitlement, Agreement, Compensatory, or Donation. Treat one exact listed name as an explicit selection and map it to the matrix code. Never use a plan name, capture, or current describe default. |
| A plan type needed for a captured profile is missing or unsupported by a captured profile | Require an explicit user-selected type or explicit confirmation of one proposed matrix type. For an unprofiled type, require explicit current-contract-valid values and do not infer a profile. |
| CalendarStartDay or CalendarStartMonth is missing for an Accrual or No Entitlement plan with Calendar period type | Classify as input validation. Require both explicit values when AbsencePlanTypeCode is `A` or `N` and AbsencePlanPeriodType is `C`; do not default either value. |
| A repeating monthly request has zero or multiple `Monthly*` candidates, no exact selected Repeating Period, or no current mapping to Repeating period | Classify as lookup resolution or metadata validation. Return the candidates when relevant and require the requester to select one exact existing period. Do not substitute Person primary frequency, a captured `PM` value, payroll frequency, or a plan-term calendar; do not create a repeating period. |
| A captured default conflicts with a user-supplied value | Preserve the user value and validate it; never overwrite it |
| A supplied or defaulted legislation does not resolve exactly once | Classify as lookup resolution and request one precise territory code or display name; do not select an arbitrary territory. |
| A supplied LDG ID or name does not resolve exactly once within the resolved legislation | Classify as lookup resolution. Read every legislation-filtered LDG lookup page, then request one precise LDG ID or exact name; do not select an arbitrary LDG or reuse captured ID 202. |
| Fusion reports that LegislativeDataGroupId must be entered during a create | Classify as source-shape validation. Rebuild the compact parent DAT with the resolved numeric `LegislativeDataGroupId` field and matching value; remove `LegislativeDataGroup` when it was used as a substitute. Revalidate the changed archive and obtain a new immutable approval before resubmission. |
| A captured code is rejected during current Data Loader source review | Show the field and supplied value when safe, then request one precise current value or correct the profile selection |
| An explicit Accrual Method is emitted as `I` when the requester selected a non-Incremental method | Classify as input validation. `I` is capture-proven only for Incremental. Remove the substituted value, resolve the requested method against the current target contract, preserve its code in the compact DAT, revalidate the archive, and obtain new approval before submission. |
| Fusion reports that `RoundingPrecision` must be entered | Classify as conditional input/default validation. Confirm the selected Rounding Rule. Preserve an explicitly supplied precision; when Always round down, Always round up, or Standard rounding was selected without one, add `RoundingPrecision=0` for whole plan-UOM units. Record and disclose the default, revalidate the changed archive, and obtain a new immutable approval before resubmission. Do not retry the failed archive unchanged. |
| A Termination Rules request is represented by `EnrollmentPositiveBalanceFlag` or `EnrollmentNegativeBalanceFlag` | Classify as input validation. Map Disburse positive balance to `EmployeeEnrollmentPositiveBalanceFlag`, Forfeit positive balance to `TerminationForfeitBalanceFlag`, and Recover negative balance to `EmployeeEnrollmentNegativeBalanceFlag`. Revalidate the changed archive and obtain new approval before submission. |
| A Loss of plan eligibility Disburse or Recover request renders disabled after the load | Classify as mapping validation. Map Disburse positive balance to `EnrollmentPositiveBalanceFlag` and Recover negative balance to `EnrollmentNegativeBalanceFlag`; do not use GTEnrollmentPositiveBalanceFlag or GTEnrollmentNegativeBalanceFlag as substitutes. Preserve any other supplied Loss of plan eligibility selections through their observed dedicated fields, revalidate the changed archive, and obtain new approval before submission. |
| A parent create archive gives an accrual band or eligibility profile a date different from the parent create date | Classify as source-shape validation. The UI validation shows Fusion coerces that child date to the parent date in a single create archive. Stop; do not submit a silently coerced configuration. Use a separately designed and approved effective-dated follow-on operation after the parent and child identities are read back. |
| Enable concurrent entitlement is mapped to `DisableEntitlementOverrideFlag` | Classify as input validation. Correct the DAT field mapping to `StatutoryFlag`; current REST metadata titles that field Enable concurrent entitlement, while `DisableEntitlementOverrideFlag` controls payment-percentage override. |
| A Discretionary Disbursements role is mapped to Donation, compensatory-expiry, or another unrelated access field | Classify as input validation. Map Enable for administrator to `CashOutFlag`, Enable for manager to `ManagerManualAdjustmentFlag`, and Enable for worker to `EmployeeManualAdjustmentFlag`. Preserve the supplied Boolean for each role, omit an unspecified role, and revalidate the changed archive before preview. |
| The type-specific frequency value fails its period-type captured rule or current Data Loader validation | Identify the selected period type and the excluded frequency code; require a permitted current value |
| A parent or child field is not in current describe or the Data Loader sample | Classify a metadata validation gap and stop; do not infer support from a HAR capture |
| A requested parent or child operation is not representable by the refreshed section contract | Classify as metadata validation. Name the exact target section and requested create, update, correction, end-date, delete-changes, or ZAP operation. Stop without converting it to another operation, cascading it to another section, or trial-submitting it. |
| An operation-relevant LOV value has no current binding, zero or multiple matches, is inactive or ineffective, or conflicts with its controller | Classify as lookup resolution or metadata validation as applicable. Name the component and field, discard stale dependent results, and rerun only a returned describe binding or existing named resolver. Stop the affected operation; do not accept explicit text as proof, invent a generic LOV endpoint, or report complete LOV coverage. |
| A requester-supplied LOV name resolves to zero or multiple rows | Classify as lookup resolution. Return the field and requested name plus safe candidate names when available. Do not write the name into a code/ID field, choose the first result, or submit a trial load. |
| A LOV description is supplied instead of its name | Classify as unsupported input contract and request the selected LOV name. Description matching is not enabled; do not use exact, contains, or fuzzy Description matching. |
| Conversion Formula resolves to an incompatible formula type, date, or LDG | Classify as lookup resolution. Require one effective Global Absence Plan Duration FormulaName compatible with the selected LDG or global scope, and write only its FormulaId to AbsenceDurationFormulaId. Do not reuse the result for another formula field. |
| A Rate Definition name is supplied while its Rate Rule is unresolved or not Rate definition | Classify as controller mismatch. Resolve the corresponding Rate Rule first; run the rate-definition resolver only for returned code D. Do not write a rate ID under Formula or Unpaid. |
| A payrollGenericLOV response has unexpected ResultKey1 or ResultKey2 values | Classify as Fusion API contract failure and stop. Do not guess whether ResultValue1 or ResultValue2 is the name or ID. |
| A controller such as legislation, LDG, plan type, flex context, or parent band changes after dependent LOV validation | Invalidate every dependent LOV result. Rebuild the relevant set and re-resolve each dependent value retained in the update or correction payload before preview. Preserve unrelated unspecified values. |
| A destructive payload is padded with untouched business LOV values so they can be called validated | Remove the untouched values. Validate only exact identity, legislation when it is part of the user key, operation scope/date, and any LOV-backed field genuinely written or required to resolve the target; record all other business LOVs as not applicable. Revalidate the compact payload and obtain a new immutable approval if the artifact changed. |
| A DDF or DFF context or segment is stale, missing, or ambiguous | Stop and require current target-environment flex metadata |
| An exact plan-name lookup returns zero or multiple rows | Classify as lookup resolution. Show the resolved legislation and lookup as-of date, then request a more precise name, legislation, or date; do not select a row. |
| A keyword plan-name lookup returns zero or multiple rows | Return the empty or complete candidate result set with the resolved legislation and lookup as-of date. Do not treat multiple candidates as an exact identity or select the first row. |
| A non-create identity is absent or ambiguous | Stop before preparation and request the exact AbsencePlanId and effective dates, or an exact plan name with legislation and lookup as-of date followed by primary-key validation using the explicit operation-specific date for date-scoped actions or the recorded lookup as-of date for ZAP with explicit complete-deletion scope for the selected logical target. |
| A non-create child identity is absent or ambiguous | Stop before preparation and request the exact returned child identity and effective dates; do not use the parent identity as a substitute |
| A proposed child omits required dates, sequence, or source-described key values | Identify the child section and required field; remove or correct the section before a new validation |
| A same-archive parent-and-child create reports an orphan REST child because a PARENT key value is required | Classify as Data Loader source-shape validation. Include the normalized `AbsencePlanName` and resolved `LegislationCode`, preserve derived effectiveOf and required child values, revalidate the changed archive, and obtain new approval before resubmission. |
| A child-only create against an existing plan fails REST surrogate-ID resolution for AbsencePlanId with ORA-00904 | Classify as Data Loader source-shape validation. Re-resolve the exact existing parent by primary key, replace the alternate `AbsencePlanName` plus `LegislationCode` relationship with the returned parent AbsencePlanId, keep the generated local child identifier absent, revalidate the changed archive, and obtain new approval before resubmission. Do not retry the failed archive unchanged. |
| A standalone `entitlementBandDetails` create with an exact EntitlementBandId returns `Not Found` | Classify as Data Loader source-shape validation. Re-read the exact existing band and empty detail collection. Prepare one disclosed retry with the band as an identity-only CORRECTION carrier—exact AbsencePlanId, EntitlementBandId, correction effectiveOf at the existing band start, and PATCH only—followed by the detail POST. Do not copy band business values or reuse approval for the failed archive. Stop on another failure. |
| A standalone `entitlementBandDetails` non-create with exact returned identities returns `Not Found` | Classify as Data Loader source-shape validation. Re-read the exact detail and its parent band at the explicit operation date for a date-scoped action or the recorded lookup as-of date for ZAP and confirm the failed mutation made no change. Prepare one disclosed retry with the selected band slice as an identity-only CORRECTION carrier—exact AbsencePlanId, EntitlementBandId, correction effectiveOf at that returned band slice start, and PATCH only—followed by the unchanged requested detail operation and controls. Do not copy band business values, do not replay successful rows, obtain a new immutable approval, and stop on another failure. |
| A mixed parent-and-direct-child UPDATE partially succeeds and direct DFF or child rows return `Not Found` | Classify as Data Loader sequencing/source-shape validation. Wait for terminal status, preserve every successful row, then read back the parent and each failed child at the target date. For an auto-provisioned DFF row now starting on that date, retry only the failed DFF values as CORRECTION. For a failed child with no target-date row, retry only that child as UPDATE after the parent is committed. Revalidate and obtain new approval; never replay successful rows. |
| An `absencePlanDFFs` update or correction with an exact parent ID returns `PARENT key value is required for orphan REST child` | Classify as Data Loader source-shape validation. Re-read the exact parent slice and DFF child at the requested operation date and confirm the failed mutation made no change. Prepare one disclosed retry with the existing `absencePlans` row as an identity-only CORRECTION carrier—exact AbsencePlanId, correction effectiveOf at that parent slice start, and PATCH only—followed by the unchanged requested DFF PATCH for the same plan and date. Do not copy parent business values, do not create a new parent effective row, do not replay successful sibling rows, and obtain a new immutable approval. Stop on another failure. |
| `absencePlanDFFs` DELETE_CHANGES returns `DELETE date range operation cannot be performed on non-date effective resource` | Classify as unsupported operation for the child resource. Reconcile the parent carriers and DFF readback, record any partial carrier success separately, and do not retry the DFF DELETE_CHANGES row. If the business request is to remove the parent plan's future slice, prepare only the exact parent `absencePlans` DELETE_CHANGES payload through a new immutable approval and let Fusion manage its flex child; verify both parent and DFF readback. |
| AC8 operation, target, date, scope, or application-reported impact is unresolved | Classify as input validation, unsupported impact check, or Fusion action constraint and stop before preparation. Require the exact AbsencePlanId and dated identity, an explicit end date, latest-row deletion, or complete-deletion choice, the operation-specific date or whole-plan intent, and a definitive application result. Report an explicit no-impact result only when Fusion returns it. Unknown impact is not no impact; without a supported read or preflight contract, disclose the capability gap and do not trial-submit. Do not substitute another destructive action or add a child delete. |
| AC9 cannot resolve one exact seed slice | Classify as lookup resolution. Require one exact plan ID or exact plan name with legislation and lookup as-of date; do not default a mutation date or select an arbitrary plan. |
| AC9 boundary traversal repeats, overlaps, returns multiple exact-ID rows, or does not advance | Classify as Fusion read-contract failure and stop. Report that history is incomplete; do not return the collected subset as complete or probe arbitrary dates. |
| AC9 cannot retrieve one complete expanded plan record for every discovered composite key | Classify as Fusion read-contract failure and stop without displaying partial history. Preserve only the failed dated identity in diagnostics; do not expose the full payload. |
| AC8 parent DELETE_CHANGES completes but the latest slice, earlier parent slice, or earlier DFF state is not verified | Classify as process failed or verification failed as applicable. Preserve the request identifier and readback evidence, do not claim AC8 success, and do not retry the mutation automatically. |
| AC8 parent END_DATE or ZAP completes but its operation-specific parent or Fusion-managed DFF outcome is not verified | Classify as process failed or verification failed as applicable. Preserve the request identifier and readback evidence, do not claim AC8 success, and do not retry or add a standalone child lifecycle mutation automatically. |
| A parent-only end date or ZAP succeeds but the flex-child outcome is not yet known | Do not add or replay a standalone DFF mutation. Re-read the exact parent and DFF child. Treat the operation as successful only when the parent has the requested end date and the DFF end matches, or, for ZAP, when both parent and DFF endpoints are absent. |
| Data Loader rejects a child-only archive because it has no registered top-level business object | Classify as Data Loader source-shape validation. Add a metadata row for business object absencePlans with RestAction before the child section, with no parent MERGE row; retain the child relationship keys, revalidate the changed archive, and obtain new approval before resubmission. |
| A direct REST-client mutation is requested | Refuse the route and hand off only to core.data-loader in REST mode with BusinessObject absencePlans |
| A read-only lookup returns HTTP 401 or 403 | Classify authentication or authorization failure; refresh a rejected cached token at most once for that read operation |
| A returned `FlexFnd*` context or segment LOV is sent to hcmRestApi and returns 403 | Classify the request as a REST-family routing error. Retry the read-only lookup once under /fscmRestApi/resources/11.13.18.05 using the unchanged returned resource name, filter, and attribute map; do not treat the 403 as an empty result and do not retry a mutation. |
| A read-only lookup times out or the environment is unavailable | Classify transport or environment failure and stop with the failed resolver and target environment |
| Fusion returns a read-contract or business-rule response | Preserve redacted detail, classify the failed stage, and stop |
| A Data Loader preview, approval, upload, initiation, or process fails | Preserve the Data Loader status or diagnostics through its workflow; do not replay a mutation automatically |
| A required diagnostic or validation artifact cannot be persisted | Classify artifact persistence failure and stop without claiming readiness |

## Error Classifications

| Result Category | When Used | Next Action |
|---|---|---|
| Input validation | Required business fields, formats, type conditions, child keys, or read-only-field checks fail | Correct the identified values and rerun validation |
| Lookup resolution | An exact current plan, child, profile, or flex context does not resolve exactly once | Provide a precise value or current target context; return keyword plan matches without selecting one |
| Metadata validation | Current describe or Data Loader template omits a required field, section, or context | Refresh the current target contract and revise the source |
| Catalog mismatch | A captured profile code or value is no longer accepted during current Data Loader source review | Select a current code or obtain current product guidance |
| Authentication or authorization | A read-only lookup returns HTTP 401 or 403 | Correct access or refresh an eligible cached token once; never retry a mutation from this package |
| Transport or environment | A safe read cannot reach the target environment | Verify the environment and retry only the read when safe |
| Fusion API | Fusion rejects a documented read contract or returns incomplete required metadata | Preserve redacted evidence and correct the contract before retrying |
| Approval blocker | A mutation lacks a validated immutable Data Loader preview or explicit approval | Stop and complete the core.data-loader approval workflow |
| Process timeout or failed | A routed Data Loader request times out or fails | Report the environment, operation, request identifier, last status, elapsed wait when available, and safe next check |
| Artifact persistence | A required validation or diagnostic artifact cannot be safely written | Report the intended path and stop without claiming completion |
| Route violation | A mutation attempts to bypass core.data-loader | Refuse the direct route and return the Data Loader handoff |

## Disclosure Rules

| Gate | What Must Be Shown |
|---|---|
| Policy-to-configuration handoff (AC10) | Plain-language policy source, plan name/type, legislation, LDG, effective date, status, included/excluded population, each supplied/confirmed decision and its configuration mapping, separately routed dependencies, unresolved decisions and omitted optional settings. Retain the sanitized summary using the existing project artifact workflow before approval; never put technical rationale in an employee-facing description. |
| Completion or resumed run (AC10) | Distinguish prepared, submitted, pending, failed and verified success. Preserve the decision-summary reference and unresolved items on failure as well as success. Resume from recorded state, refresh changed evidence and invalidate approval if the target or payload changed. Report final plan identity/date only from returned evidence; a successful upload alone is not a verified plan. |
| History-only disclosure (AC9) | Show only Effective Period, Changes, Last Updated Date, and Last Updated By, newest first. Show start date - end date for a bounded row and only the start date when EffectiveEndDate is 4712-12-31; never add an assumed open-ended label. Leave Changes blank when no change evidence exists; never invent Initial record. Keep complete fetched records, IDs, child payloads, status, actions, other audit/who data, links, pagination, and ordinary current-plan details out of the response. Preserve plan type, legislation, LDG, and composite dated identity internally for row selection. |
| Unsupported impact check | Identify the missing supported read contract and affected operation. No fabricated empty-impact assertion, substitute execution route, or unapproved trial mutation. Keep unrelated supported operations available. |
| Validation failure | Field or section, supplied value when safe, violated rule, and one corrective action |
| Lookup failure | Resolver, requested identity, zero or multiple match classification, and required correction |
| Metadata failure | Target environment, absencePlans resource or Data Loader template, failed metadata stage, and safe next action |
| Profile-default decision | Resolved plan type, conditional values considered, values applied, any user overrides preserved, and values left explicit |
| Data Loader handoff | Exact task, REST mode, BusinessObject absencePlans, validated values, defaults applied, unresolved items, target environment, and approval state |
| Process timeout or failure | Environment, operation, request identifier, last status, elapsed wait when available, diagnostic reference, and safe next action |

## Refusal Rules

| Situation | What Must Not Happen |
|---|---|
| A direct REST client write is requested | Do not execute or author a direct POST, PATCH, DELETE, or upsert route; use core.data-loader only |
| A type-specific value is not covered by a resolved profile | Do not borrow values from another plan type |
| A resource identity or flex context is ambiguous | Do not choose the first row or infer a code |
| A plan type is omitted | Do not silently select AbsencePlanTypeCode from a policy description, plan name, capture, or current describe default. A description-derived matrix result is a proposal only and requires explicit user confirmation; an exact user-selected matrix Plan Type Name is an explicit selection. For unpaid tracking without entitlement-policy direction, do not infer Q or N; require the two-way Qualification or No Entitlement clarification. |
| Qualification or No Entitlement is unclear or conflicts with stated policy | Do not set ProposedAbsencePlanTypeCode or ResolvedAbsencePlanTypeCode, apply a Q or N plan-type profile, prepare a DAT, or create a combined plan type before the user supplies compatible policy direction and explicitly selects one type. |
| A current template or describe response conflicts with a capture | Do not treat the capture as authoritative for the target environment |
| CalendarStartDay or CalendarStartMonth is omitted for an Accrual or No Entitlement plan with Calendar period type | Do not infer either value; stop and request both explicit calendar-anchor values |
| A requester says repeating or repeating monthly | Do not reinterpret it as Person primary frequency or a captured `PM` default, create a repeating period, or guess the target relationship field. Resolve one current existing Repeating Period and its target mapping first. |
| EffectiveEndDate is omitted on create | Do not synthesize it; let Fusion derive it server-side. This does not waive the explicit business end date required for END_DATE |
| A date-effective Data Loader source is prepared | Do not emit physical EffectiveStartDate, accept caller-authored effectiveOf, or use REST describe as authority for DAT effectiveOf support. Refresh the registered UCM template and derive effectiveOf from the business date. |
| A complete UCM template is available | Do not copy every template attribute into a source header or emit blank placeholder columns; build only compact populated sections |
| A DDF or DFF context is missing or stale | Do not reuse captured tenant context values |
| A prior mutation result is uncertain | Do not retry automatically or claim success |
| Condition Builder is requested during 27A plan creation | Do not offer, invoke, route to, or emulate Condition Builder, and do not silently substitute another configuration object |
| The durable AC10 policy-to-configuration artifact is missing or cannot be written | Do not show creation readiness, request creation approval, or claim a completed outcome |
| Credentials, tokens, session headers, or sensitive payloads appear in evidence | Do not persist or disclose them |
