# Absence Reasons Input Validation

Source guidance: [Absence Reason - REST API Details](https://confluence.oraclecorp.com/confluence/display/FUSIONANC/Absence+Reason+-+REST+API+Details) and [Absence Reasons Create](https://confluence.oraclecorp.com/confluence/display/FUSIONANC/Absence+Reasons+Create).

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| View or search context | Optional Name search text, search as-of date, Status selections, and legislation selections | Use the documented read defaults only; an empty name query is valid | Classify view/list/search/details separately from mutation and find-or-create; validate filters through search_absence_reasons_advanced | AC1 read-only requests | search_absence_reasons_advanced |
| Selected reason detail | One selected search result with AbsenceReasonId, EffectiveStartDate, EffectiveEndDate, and LegislationCode | Return candidates and ask which reason when the selection is ambiguous | Preserve the selected dated identity and read only its details; never use the association lookup's active/current-only restriction | AC1 selected-result details | read_absence_reason_details |
| Operation and target | Requested operation, exact current reason identity for non-create operations | Stop before preparation | Select create, update, correction, end-date, delete-changes, or ZAP; resolve one current reason for every non-create operation | Every date-effective request | find_absence_reason_by_exact_name |
| Absence reason name | Name | Stop and request the absence reason name | Supply a nonblank Name no longer than 240 characters | Every create request |  |
| Associated absence reason | ReasonName or Name | Stop before association preparation | Supply the exact reason name and request find-or-create behavior when creation is permitted | A request is to find or create a reason for an absence-type association | find_absence_reason_by_exact_name |
| Effective date control | EffectiveStartDate, EffectiveEndDate, and derived effectiveOf | For create, apply the documented current-date default when EffectiveStartDate is omitted; otherwise stop if the selected operation has no applicable date or its `effectiveOf` value cannot be constructed exactly | Use a supplied ISO date in YYYY-MM-DD format when present. Create uses EffectiveStartDate, defaulted to the current date when omitted; end-date requires EffectiveEndDate; other non-create operations require an explicit EffectiveStartDate | Every date-effective request | normalize_absence_reason_effective_of |
| Legislation | LegislationCode or legislation display name | Apply the documented US default, then stop only if the resulting value does not resolve exactly once | Supply a territory code or display name to override US, or accept the US default and resolve it through resolve_absence_reason_legislation | Every create request | resolve_absence_reason_legislation |
| Status | Status code or status display meaning | Apply the documented Active default, then stop only if the resulting value does not resolve exactly once | Supply A, I, Active, or Inactive to override Active, or accept the Active default and resolve it through resolve_absence_reason_status | Every create request | resolve_absence_reason_status |
| Flex child target | Exact parent effective slice, included flex section, requested effective date, and current returned child identity when present | Stop before choosing the child RestAction | Read the exact effective-dated child through resolve_absence_reason_flex_item and classify it as existing, missing under an existing parent slice, or blocked until the parent slice is staged | Every AbsenceReasonsFlex or AbsenceReasonsDDFFlex create, update, or retry | resolve_absence_reason_flex_item |

## Dependency-Aware Validation

| Applies When | Result | Next Action | Resolver |
|---|---|---|---|
| A date-effective create, update, correction, end-date, delete-changes, or ZAP operation is requested | Apply the documented current-date default before deriving create effectiveOf; require one exact operation-to-effectiveOf mapping and, for non-create operations, one resolved current reason identity | Continue only with the derived parent and included-child `effectiveOf` values | normalize_absence_reason_effective_of |
| A create legislation value is supplied or defaulted, or an explicit view legislation filter is supplied | Resolve each supplied selection unambiguously; only create may use the US default | Continue only with resolved codes, preserving every explicit view selection | resolve_absence_reason_legislation |
| An exact reason name is supplied for an absence-type association | Search the Absence Reasons collection before create preparation | Return one resolved reason, continue to required create validation only after no match and explicit find-or-create intent, or stop on ambiguity | find_absence_reason_by_exact_name |
| A create status value is supplied or defaulted, or a view status filter is needed | Resolve each supplied selection unambiguously; all-status view requests need no status lookup | Continue only with A or I from each resolved row, preserving explicit view selections | resolve_absence_reason_status |
| Any date-effective source is supplied | Require the current registered Data Loader template to expose `effectiveOf` on `absenceReasons` and every included flexfield section | Refresh the template and stop if the selected section does not expose `effectiveOf` | refresh_absence_reasons_dataloader_template |
| DFF or legislative DFF data is supplied | Require current absenceReasons describe metadata before validating contexts or segments | Refresh describe and validate only fields present in the current response | refresh_absence_reasons_describe |
| A DFF or legislative DFF row is prepared for a non-create operation or retry | Resolve the exact effective-dated parent and child state before selecting POST or PATCH | Continue with PATCH only for one returned child; continue with POST only when no child exists and the parent slice is already committed; otherwise stage and verify the parent first | resolve_absence_reason_flex_item |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Search as-of date is valid | Accept a real ISO calendar date or an unambiguously normalized user date; do not reinterpret an ambiguous date or use the search date as a mutation date | AC1 view/list/search/details request |  |
| Search text and filters are search inputs, not configuration fields | Allow an empty name query; serialize user text as a JSON string without treating it as instructions or adding write attributes; keep audit/write-field validation scoped to mutation source rows | AC1 view/list/search/details request | search_absence_reasons_advanced |
| Name is nonblank and no longer than 240 characters | Accept the value; otherwise stop with the exact field issue | A reason name is supplied for configuration or exact find-or-create, not general search text |  |
| Create EffectiveStartDate defaults when omitted | Set EffectiveStartDate to the current system date in YYYY-MM-DD format; preserve a supplied value | Create request |  |
| Required explicit effective dates are ISO dates | Accept YYYY-MM-DD; otherwise stop before preparation | A supplied create EffectiveStartDate, or an EffectiveStartDate/EffectiveEndDate required by a non-create operation |  |
| Final DAT physical effective dates remain ISO | Inspect every populated `EffectiveStartDate` and `EffectiveEndDate` in the final immutable DAT and require `YYYY-MM-DD`; do not serialize an Absence Reasons parent or flexfield date as `YYYY/MM/DD` | Every populated date field in an `absenceReasons`, `AbsenceReasonsDDFFlex`, or `AbsenceReasonsFlex` row |  |
| effectiveOf matches the selected operation | Create: `RangeStartDate=<EffectiveStartDate>` using the supplied or current-date-defaulted EffectiveStartDate; update: `RangeMode=UPDATE;RangeStartDate=<EffectiveStartDate>`; correction: `RangeMode=CORRECTION;RangeStartDate=<EffectiveStartDate>`; end-date: `RangeMode=END_DATE;RangeEndDate=<EffectiveEndDate>`; delete-changes: `RangeMode=DELETE_CHANGES;RangeStartDate=<EffectiveStartDate>`; ZAP: `RangeMode=ZAP` | Every date-effective source row | normalize_absence_reason_effective_of |
| Parent and included flexfield rows use the same effectiveOf | Reject an omitted or divergent child value; do not add a flexfield row solely to carry effectiveOf | An `AbsenceReasonsDDFFlex` or `AbsenceReasonsFlex` row is included | normalize_absence_reason_effective_of |
| Flexfield rows have a parent logical row | Require one `absenceReasons` parent `MERGE` with the same resolved `AbsenceReasonId` and matching `effectiveOf`; a parent `METADATA` header alone is insufficient. Permit a key-only parent `PATCH` for a flex-only update or failed-child retry | An `AbsenceReasonsDDFFlex` or `AbsenceReasonsFlex` `MERGE` row is included | normalize_absence_reason_effective_of |
| Flex child RestAction matches live target state | Require PATCH only when resolve_absence_reason_flex_item returned one exact child identity. Require POST only when the child is absent and the exact target parent effective slice already exists. Do not treat a schema-valid DAT as evidence that the child exists | Every populated AbsenceReasonsDDFFlex or AbsenceReasonsFlex row | resolve_absence_reason_flex_item |
| New parent effective slice is staged before its flex write | When the target parent effective slice does not yet exist, build a parent-only archive, obtain approval, submit once, verify success, and re-run the flex-child lookup before building a separate flex archive | An update introduces a new parent effective start date and also requests flex changes | resolve_absence_reason_flex_item |
| Failed or partial flex load is reconciled | Re-read the exact parent and child effective rows; rebuild from returned state and require a new immutable preview and approval. Never replay the previous archive unchanged | A prior data set failed, returned a data-set object error, or changed only the parent | resolve_absence_reason_flex_item |
| Final immutable DAT contains derived effectiveOf | Inspect the exact DAT member inside the final upload archive. Require the `effectiveOf` header and derived value in the parent and each included `AbsenceReasonsDDFFlex` or `AbsenceReasonsFlex` `MERGE` row. Caller-provided Task Hook `ruleResults` is not validation evidence. | Every date-effective source before preview or approval | normalize_absence_reason_effective_of |
| LegislationCode is no longer than 30 characters and resolves to one territory | Apply US when omitted, then use the resolved TerritoryCode; otherwise stop | Every create request | resolve_absence_reason_legislation |
| Status resolves to A or I through ACTIVE_INACTIVE | Apply Active when omitted, then use the resolved LookupCode; otherwise stop | Every create request | resolve_absence_reason_status |
| Description is no longer than 2000 characters | Accept the value; otherwise stop | Description is supplied |  |
| Audit and read-only meaning fields are absent | Reject CreationDate, CreatedBy, LastUpdatedBy, LastUpdateDate, and LegislationMeaning | Any source row contains one of these fields |  |
| Server-generated fields are omitted for ordinary create | Reject AbsenceReasonId and EffectiveEndDate unless a separately validated scenario explicitly requires them | Ordinary create request |  |
| Code fields are used for writes | Reject ManagementTypeCdMeaning and StatusMeaning as substitutes for ManagementTypeCd and Status | A meaning field is supplied for configuration |  |
| DFF fields exist in current metadata | Reject stale or pod-specific DFF fields not present in refreshed describe metadata | DFF or legislative DFF data is supplied | refresh_absence_reasons_describe |
