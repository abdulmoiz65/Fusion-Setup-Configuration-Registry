# Absence Reasons Reference Lookups

All calls in this file are read-only. They do not authorize create, update, upsert, or delete operations.

Source guidance: the user-supplied Absence Reasons search-page request and response
captured on 10 September 2026, and [Absence Reason - REST API Details](https://confluence.oraclecorp.com/confluence/pages/viewpage.action?pageId=21451523631),
sections 4-8, 11-13, and 18.3-18.5. The capture establishes the Reasons-specific
filter grammar and a single-page result envelope. It does not establish every
filter combination, multi-page behavior, Description in search results, or the
object syntax of the detail finder's optional SysEffectiveDate parameter.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Advanced search endpoint and access | Before sending credentials, require HTTPS and the same origin as the routed target environment, the exact absenceReasons/action/findByAdvancedSearchQuery action suffix, and a current supplied/captured or describe-returned action URL. A runtime rv: path is environment/version-specific, not a portable constant. Do not guess another runtime version or a /resources equivalent when the chosen URL fails. Use the shared REST client, not browser automation, a Data Loader load, arbitrary POST, batch, or upsert. Successful read access does not prove create/update/delete privileges. |
| Advanced search request body | Only limit, offset, displayFields, searchFields, query, sort, and filters are permitted body keys. Set limit to 25 and initial offset to 0; displayFields to [Name, LegislationCode, Status, StatusMeaning, EffectiveStartDate, EffectiveEndDate, LegislationMeaning]; searchFields to [Name]; query to supplied name text or an empty string; sort to [{name: Name, direction: Asc}]. Serialize JSON; do not hand-interpolate user text or append write fields, effectiveOf, Upsert-Mode, arbitrary actions, or batch parts. |
| Advanced search filters | Use the read defaults in ora_defaulting_rules.md only when the corresponding value is omitted. Encode the search date as {name: [SysEffectiveDate], value: [YYYY-MM-DD]}, status as {name: [Status], terms: [resolved codes]}, and legislation as {name: [LegislationCode], value: [resolved codes]}. Do not substitute EffectiveDate, values, or a status value member from another resource's grammar. Resolve explicit labels with the documented status and legislation resolvers. An explicit all-status request omits Status; unspecified legislation omits LegislationCode. Preserve explicit selections as arrays. The captured A/US case is evidence for that case only; verify other combinations during live QA. |
| Advanced search response pagination | Require result.items to be an array and result.summary to be an object, not a one-element array. Require integer offset, limit and count with offset and count nonnegative, limit positive, and hasMore a Boolean; do not treat a nonempty string false as true. Require response offset to match the requested offset and count to equal this page's item count. While hasMore is true, advance offset by count and keep query, filters, sort, and display fields unchanged. Stop and label results partial for an empty page with more pages, repeated dated identities, inconsistent counts/offsets, malformed envelopes, or a failed next page; never report partial rows as the complete set. A page count is not the total count of reasons in the system. |
| Advanced search business display | Show one fixed-column table: Name from Name, Legislation from LegislationMeaning, Status from StatusMeaning, Effective Start Date from EffectiveStartDate, and Effective End Date from EffectiveEndDate. Preserve explicit nulls as blank cells and escape pipes and line breaks in text so columns cannot shift. Keep actual returned dates without labels such as open ended. If a display meaning is missing, disclose it rather than inventing a meaning. Retain technical IDs internally and keep hasMore, offsets and other transport fields out of the business response. Report totals only for fully retrieved requested scope, disclosing date, status and legislation filters; never call the default Active search a system-wide total. |
| Advanced search selects a detail row | A search result is a candidate, not a mutable item address. Require an explicit selection or one exact name/ID and legislation match when the requester already identified a reason; do not treat a sole substring match as exact identity. Only then call read_absence_reason_details. Missing AbsenceReasonId prevents detail lookup but does not erase otherwise usable list results. Neither this selection nor its search date supplies a later change approval or operation date. |
| Selected detail collection pagination and links | For finder GET responses, use the collection's top-level items, offset, count and hasMore, not the action's result envelope. Read until complete with the same count/progress checks and exact selected-row matching. Only follow returned same-environment absenceReasons self/canonical links over HTTPS. Preserve Language and both effective dates; never synthesize an opaque key from AbsenceReasonId. |
| Description is requested | Search does not return Description in the supplied capture. Use read_absence_reason_details for a selected row. An explicitly returned null remains blank; an absent field is reported as not returned. If a historical/future search row has no usable returned item link and the documented finder cannot retrieve the same dated row, report the specific detail gap; do not copy the search filter grammar into the finder's undocumented SysEffectiveDate object. This does not block displaying already retrieved search columns. |
| A lookup returns an authentication or authorization failure | Stop and classify the failure; a rejected cached token may be refreshed once for a read operation only |
| A single-value identity or LOV lookup returns zero or multiple acceptable rows | Stop and request a more precise value; never select an arbitrary row. This rule does not apply to AC1 candidate search, where zero and many matches are normal |
| An exact reason lookup returns zero rows | Classify the result as not found. Continue to reason creation only when the request explicitly selected find-or-create; otherwise return the not-found result without a mutation. |
| An exact reason lookup returns one row | Return the resolved reason identity for the Absence Types handoff. Do not create a duplicate reason. |
| An exact reason name contains a quote or reserved URL character | Escape the Fusion string literal and URL-encode the complete q parameter before the read-only request; never interpolate raw user input into the query. |
| A lookup response does not contain the documented fields | Classify the affected query/detail contract failure; do not substitute another endpoint or infer mappings. Preserve already verified AC1 columns with the affected field or detail explicitly marked unavailable; never claim full AC1 completion from partial evidence |
| A registered Data Loader template omits effectiveOf for the parent or an included section | Stop before DAT preparation; do not substitute REST describe metadata or synthesize an unsupported column |
| DFF metadata differs from the captured documentation | Use the current target-environment describe response as authoritative and reject fields absent from it |
| A flex child action must be selected | Run resolve_absence_reason_flex_item after the describe contract is current. Never choose PATCH from the user's word "update" alone: PATCH is an item action and requires one exact returned child. Never choose POST when an exact child already exists. |
| A new parent effective slice and flex change are requested together | Return parent_stage_required and prepare only the parent archive. After its approved load succeeds, re-read the returned parent and child links and enter the flex preparation as a new immutable archive. Do not assume parent propagation makes the child available inside the original load transaction. |
| A prior flex load partially succeeded | Treat the data-set terminal status and object errors as authoritative even when row counts show a loaded parent. Reconcile through live parent and child reads before selecting a new action; do not replay the failed archive. |
| A lookup succeeds | Record only the resolver name, matched identity, and mapped values needed by downstream validation; never persist credentials or bearer tokens |
