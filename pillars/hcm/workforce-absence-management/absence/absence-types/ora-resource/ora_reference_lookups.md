# Absence Types Reference Lookups

All calls in this file are read-only. They do not authorize create, update, upsert, or delete operations.

Source guidance: [Absence Types - Fields REST Mapping - 280826](https://confluence.oraclecorp.com/confluence/display/FUSIONANC/Absence+Types+-+Fields+REST+Mapping+-+280826) for LOV ownership and endpoints, and [Absence Types - REST API Details](https://confluence.oraclecorp.com/confluence/display/FUSIONANC/Absence+Types+-+REST+API+Details) for the absenceTypes describe contract. Default values are not sourced from the REST API Details page.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A common-lookup-backed LOV is resolved | Use only /fscmRestApi/resources/11.13.18.05/commonLookupsLOV with finder=LookupTypeFinder and the documented lookup type; use LookupCode as the stored REST value and Meaning as the display value |
| LegislationCode is resolved | Use only /fscmRestApi/resources/11.13.18.05/territoriesLOV and map TerritoryCode to LegislationCode |
| A Legislative Data Group lookup has more pages | Continue the same legislation-filtered request until hasMore is false, increasing offset by the number of rows returned on each page. Do not classify an initial-page miss as a catalog mismatch. |
| A stored code is supplied | Restrict the lookup with an exact q=LookupCode='<stored code>' filter when supported; never accept an unverified code |
| A Display Feature or Rules value is supplied in human language | Resolve the target field first, then use only its exact returned or UI-documented lookup type. Accept a unique exact, normalized, or semantic match; otherwise stop and ask the user to choose from the returned Meanings. Never translate a word such as `enabled` to one global code. |
| Absence Types are viewed or filtered | Use `list_absence_types`, retrieve every page, and render a table—not a names-only list. The table columns, in order, are **Absence Type Name**, **Effective Start Date**, **Effective End Date**, **Status**, **Pattern**, **Entry Display Priority**, **Legislation**, and **Legislative Data Group**. Map `DisplaySequence` to the business label Entry Display Priority; render a null value as `—`. Use `StatusMeaning`, `AbsencePatternMeaning`, and `LegislativeDataGroupName` when returned; otherwise stop rather than exposing an unverified display value. |
| An absence type is searched by exact name | Use the `absenceTypes` GET collection with the exact name and resolved legislation filter. Read every page, then exact-match Name locally and validate its effective range against the lookup as-of date. |
| An absence type event is attached | Resolve its condition through `resolve_absence_type_event` and its response through `resolve_absence_type_event_response`. The Absence Type response is from `ORA_ANC_EVT_ABS_ACTIONS`; do not use the similarly named Absence Plan response lookup. |
| A pattern must be selected | Interpret the business intent first, recommend II for illness or injury, MAP for childbirth or placement, and GENERIC for other leave; if the intent is ambiguous, ask the user instead of silently accepting GENERIC |
| MAP is selected | Resolve MapEventTypeCode from every current event-type LOV page. Infer a candidate from the absence-type name or stated business intent and, when one Meaning matches, recommend that Meaning and offer a change option. Show available Meanings only for no unique match or a requested change. Keep LookupCode internal. |
| An optional LOV or checkbox attribute is omitted | Leave LinkageUOMCode, LinkageReasonCode, EligibilityProfileId, LinkageStartRuleCode, LegGroupCode, EmployeeMeasures, ManagerMeasures, ActionId, ActionReasonId, and AssignmentStatusTypeId absent; do not query or default it. |
| An ActionId is supplied | Resolve ActionId and AssignmentStatusTypeId before resolving ActionReasonId. An action reason lookup must use the resolved action and EffectiveStartDate. |
| A lookup endpoint is TBD | Do not substitute another endpoint, infer local authority, or accept an unresolved name-to-ID mapping; request a supported ID or stop until the endpoint is documented |
| A lookup returns an authentication or authorization failure | Stop and classify the failure; a rejected cached token may be refreshed once for a read operation only |
| A lookup returns zero or multiple acceptable rows | Stop and request a more precise value; never select the first row |
| A lookup response omits documented fields | Stop as a lookup-contract failure; do not infer the mapping |
| A lookup succeeds | Record only the resolver name, matched business identity, and mapped values needed downstream; never persist credentials, bearer tokens, or the full response |
| An expanded parent response contains nested child arrays | Treat an `onlyData=true` expansion as a convenience value snapshot only; it strips the links needed for collection discovery, and the outer `hasMore=false` proves only the parent collection. Issue an exact parent link-discovery read without `onlyData=true` and without a fields projection. Follow the exact returned `rel=child` links from parent to regions, region to usages, and usage to rules; never synthesize a child URL. Page each linked collection by its returned next link or its own `limit`/`offset` until its own `hasMore=false`, retaining hrefs, page/row counts, IDs, and hashes. If a required child link or completion receipt is absent, stop rather than classify the hierarchy as complete. |
| A date-effective DAT is prepared | Refresh the registered UCM template first. Use REST describe only for DFF contexts and segments, never as authority for DAT columns or date-effective support. |
| A plans child row is prepared | Refresh the registered `absenceTypes` template and use only the current plans header. Verify plan handoff values for every child field that the current metadata requires; never invent AbsenceTypePlanId, display values, or date-effective controls. |
