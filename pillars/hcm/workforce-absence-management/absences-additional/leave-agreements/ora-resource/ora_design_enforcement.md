# Leave Agreements Design Enforcement

## Enforcement Order

| Sequence | Step | What Must Happen |
|---|---|---|
| 0 | Establish UI scope and adapter capability | View/Create/Edit/Delete current are supported. Retired dated/history requests are unavailable, with supported choices; never prepare obsolete dated sources. Current metadata gates execution of a selected available action only |
| 1 | Normalize operation context | Create uses its disclosed Start Date. Edit derives internal RangeStartDate from verified stored Start Date; whole-object Delete derives date-free RangeMode=ZAP. Neither accepts a new operation date or changes stored dates |
| 2 | Confirm pattern | Resolve Agreement or Conversion before applying conditional fields or coded defaults |
| 3 | Confirm legislation- and date-scoped values | Resolve Legislative Grouping in the selected legislation, require every Certification to be effective on the leave agreement Effective Start Date, and clear stale Certification values after legislation or that date changes |
| 4 | Confirm conditional selections | Enforce Agreement-only Event Type, eligibility formula/profile exclusivity, complete reason lists, and payment-formula dependency for Override Allowed |
| 5 | Confirm pattern-specific plans | On Create require complete pattern-specific mappings. On Edit validate changed/new children in stored parent context and review retained children; parent-only changes do not require new plan selections |
| 6 | Confirm source contract | Use only fields and sections in the current absenceLeaveAgreementTemplates UCM template and validate physical EffectiveStartDate behavior |
| 7 | Confirm requester presentation | Use business-facing labels and display meanings in ordinary interaction while retaining technical attributes, codes, identifiers, lookup types, resolvers, and endpoints internally |
| 8 | Confirm mutation route | Hand every mutation to core.data-loader in REST mode with BusinessObject absenceLeaveAgreementTemplates |

## Design Rules

| Current Delete is requested | Blocker | find_leave_agreement_template | Whole-agreement destructive intent, exact current parent, complete before state, or selected parent-only source is missing; a known protection constraint is bypassed; or immutable Data Loader approval is missing at submission | Show the exact target and whole-agreement scope, including known child counts and any unknown downstream references. Fusion enforces dependency restrictions during the approved Data Loader operation; no separate dependency-validation API is declared. Any matching row blocks Create without upsert/overwrite. Zero matches proves only this queried scope, not global historical uniqueness; no existing new-row identity is needed | No |

| An unsupported contract or ambiguous target blocks readiness | Blocker |  | A validation waiver or requester confirmation is used to bypass absent operation/impact support, unknown metadata, unsafe scope or ambiguous identity | Apply repository fail-closed requirements; preserve the draft and named blocker. | A create or name change is requested | Blocker |  | The name is not meaningful or uses an environment marker prefix/suffix DEV, TEST, UAT or PROD | Use a stable business name and recommend a useful Description | Yes |
| A formula, plan, certification or flexfield is selected | Blocker | resolve_agreement_legislation | Current selected-country applicability is missing, contradicted or stale after country/pattern/date changes | Re-resolve affected dependencies in the original scope and report missing prerequisites; documented UK examples are not global defaults | Yes |
| Agreement pattern is selected | Blocker | resolve_agreement_pattern_code | The pattern is missing, ambiguous, or unsupported | Select Agreement or Conversion or provide one exact supported code | Yes |
| Agreement pattern is used | Blocker | resolve_target_absence_plan | Create has no required target mapping, or a changed/new child lacks its applicable plan dependency or includes conversion-only source fields | Supply target mappings for Create or resolve only the new/changed Edit rows; inspect retained mappings in the full before state | Yes |
| Conversion pattern is used | Blocker | resolve_source_absence_type | Create lacks its compatible source type/complete plan mappings, or changed/new Edit rows conflict with stored source context | Resolve Create source and plans, or use stored parent source context for current child maintenance; do not require new source selection for a parent-only Edit | Yes |

| SourcePlanName and SourcePlanId are both supplied | Blocker | resolve_source_absence_plan | The AbsencePlanId resolved from the name differs from the supplied SourcePlanId | Correct the Source Plan name or identifier so both identify the same plan | Yes |
| A Conversion plan child is prepared | Blocker | resolve_source_absence_plan | SourcePlanName is copied into SourcePlanId, retained as an unregistered loader attribute, resolved by partial or first-result matching, or resolved through a child URL constructed from numeric SourceAbsenceTypeId | Map only the exact-match AbsencePlanId returned through the Source Absence Type's plans child link into absenceAgreementPlans.SourcePlanId | Yes |
| TargetPlanName is supplied | Blocker | resolve_target_absence_plan | The name resolves to zero or multiple active Agreement absencePlans rows in the resolved agreement legislation on the normalized business date | Supply one exact active Agreement Target Plan name or its TargetPlanId | Yes |
| TargetPlanName and TargetPlanId are both supplied | Blocker | resolve_target_absence_plan | The AbsencePlanId resolved from the name differs from the supplied TargetPlanId | Correct the name or identifier so both identify the same plan | Yes |
| A target-plan child is prepared | Blocker | resolve_target_absence_plan | TargetPlanName is copied into TargetPlanId, retained as an unregistered loader attribute, resolved by choosing the first or a partial-name result, or selected after removing the Agreement plan type, active status, legislation, or date filter | Map only the exact-match active Agreement plan's AbsencePlanId into absenceAgreementPlans.TargetPlanId | Yes |
| A requester is asked for a target plan | Blocker | resolve_target_absence_plan | The interaction asks for TargetPlanId before offering exact Target Plan name resolution, or exposes the resolved plan identifier without an explicit technical-details request | Ask for the exact Target Plan name, resolve its identifier internally, and present the plan name and display values | Yes |
| Any common default is proposed | Blocker | resolve_agreement_management_type | A captured value is applied without matching pattern scope and current lookup verification | Resolve the code and show the proposed default before source preparation | Yes |
| United States is proposed as legislation | Blocker | resolve_agreement_legislation | US is inferred without explicit business context or confirmed project policy | Collect or confirm the legislation, then resolve TerritoryCode | Yes |
| Legislative Grouping is supplied | Blocker | resolve_agreement_legislative_grouping | It does not resolve exactly once within the resolved legislation, or a prior grouping remains after legislation changes | Supply one exact grouping valid for the selected Legislation and re-resolve it | Yes |
| Validation Formula is supplied | Blocker | resolve_agreement_validation_formula | The exact name does not resolve once under the documented validation formula type | Supply one exact Validation Formula | Yes |
| Denial Reasons or Withdrawal Reasons are supplied | Blocker | resolve_agreement_denial_reasons | Any item is unresolved or ambiguous, a duplicate is selected, order is lost, or a partial list is serialized | Correct the complete ordered reason list and resolve every item before comma serialization | Yes |
| Event Type is supplied | Blocker | resolve_agreement_event_type | The pattern is Conversion or the event type does not resolve exactly once | Remove Event Type for Conversion or select one exact Event Type for Agreement | Yes |
| Eligibility Formula or Eligibility Profile is supplied | Blocker | resolve_agreement_eligibility_formula | The value is incompatible with Eligibility Rule, both are populated, or a stale dependency remains after the rule changes | Keep only the exact Formula or Profile selected by Eligibility Rule | Yes |
| Payment Percentage Display Formula is supplied | Blocker | resolve_agreement_payment_percentage_formula | The exact formula does not resolve once or its identifier is placed in a different plan item | Resolve and map the formula independently in the same plan item | Yes |
| Override Allowed is supplied | Blocker | resolve_agreement_override_allowed | The same plan item has no resolved Payment Percentage Display Formula, the value is not Yes or No, or it is not converted to Boolean | Select the payment formula first, then resolve and convert Yes or No | Yes |
| Certification Name or identifier is supplied | Blocker | resolve_agreement_certification | It does not resolve exactly once as active documentation in the selected legislation, its Effective Start Date is after the leave agreement Effective Start Date, its nonblank Effective End Date is before that date, or a prior certification remains after legislation or the agreement start date changes | Supply one exact Certification valid for the selected Legislation on the leave agreement Effective Start Date and re-resolve every child | Yes |
| A create omits EffectiveStartDate and RangeStartDate | Blocker |  | The workflow does not default the normalized business date to the current system date in YYYY-MM-DD format or fails to disclose the applied default | Apply and disclose the create-only current-date default before deriving effectiveOf | Yes |
| Current Edit is requested | Blocker | read_leave_agreement_configuration | Full before state is incomplete, a requested field is read-only in current UI, or a new operation date/dated RangeMode is invented | Stage only allowed fields and current child changes. In observed parent Edit preserve Start Date, Legislation, Management and Pattern; Name, Status, Grouping and Description are editable | Yes |
| New row or maintenance date context is prepared | Blocker | refresh_leave_agreement_dataloader_contract | Caller-authored effectiveOf or a control inconsistent with the selected Create, Edit, or Delete action is used | Derive Create from new Start Date, Edit from verified stored Start Date, and whole-object Delete from date-free RangeMode=ZAP | Yes |
| EffectiveStartDate appears in Data Loader METADATA | Blocker | refresh_leave_agreement_dataloader_contract | Header presence alone is treated as a populated value or as evidence that dual population is supported | Allow the template header, but validate the physical record value separately | Yes |
| Physical EffectiveStartDate is populated | Blocker | refresh_leave_agreement_dataloader_contract | An existing Edit/Delete attempts to change stored dates, or new-row dual date population lacks equal dates and explicit operation-specific support | Leave physical date values blank by default. Header presence proves no writable date or history capability | Yes |
| A create omits EffectiveEndDate | Blocker | refresh_leave_agreement_dataloader_contract | The client adds 4712-12-31 solely because it appeared in an observed response, or discards a template-required field | Follow the current loader template and never convert server behavior into an unsupported client default | Yes |
| A non-create target is selected | Blocker | find_leave_agreement_template | Exact current parent or affected current child keys are unresolved | Resolve current identities and full before state; no dated-slice selection or new effective date is required | Yes |
| A search result or ordinary requester interaction is presented | Blocker |  | The response exposes raw REST or Data Loader attribute names, stored lookup codes, surrogate identifiers, resolver names, lookup types, or endpoints without an explicit technical-details request | Use Agreement Name, Agreement Type, Target Plan, Source Plan, Source Absence Type, Management Type, Status, Partner Rule, Eligibility Rule, Legislation, Effective Start Date, Effective End Date, and As-of Date with display values | Yes |
| Any source is prepared | Blocker | refresh_leave_agreement_dataloader_contract | The source uses stale metadata, a direct REST payload, a REST request header, an unregistered section, or an unknown field | Rebuild from the current Data Loader template | Yes |
| Any mutation is requested | Blocker |  | The operation attempts direct REST POST, PATCH, DELETE, upsert, child write, action, or batch execution, or bypasses core.data-loader | Route the operation exclusively through core.data-loader in REST mode using BusinessObject absenceLeaveAgreementTemplates | No |
| Delete is requested | Blocker | find_leave_agreement_template | Explicit whole-agreement deletion scope, exact target, full before state, known child inventory or known protection constraint review is missing before preview | Complete the preflight and prepare the concrete parent-only source. Disclose that downstream references are unknown and Fusion enforces restrictions at load; core.data-loader then presents its immutable preview and requests the single final approval before submission | No |
