# Leave Agreements Input Validation

Source guidance: [Absence Agreement Templates - REST API Details](https://confluence.oraclecorp.com/confluence/display/FUSIONANC/Absence+Agreement+Templates+-+REST+API+Details?src=contextnavpagetreemode) and [Absence Agreement Templates Create Payload - Minimal Details](https://confluence.oraclecorp.com/confluence/pages/viewpage.action?pageId=21882862289).

The REST documentation is evidence for fields, finders, and observed create behavior. The registered `absenceLeaveAgreementTemplates` Data Loader template remains authoritative for loader sections, attributes, and effective-dating controls.

For an AC1 read-only list, an Agreement Name is optional. Accept one or more
exact Legislation selections and an ISO As-of Date; "today" uses the requester's
local date. Zero or multiple matching current templates are valid list results.
Do not apply Create requirements, defaults, or exact-one target selection to a
list. A full-information request follows each matching parent and child link
through the declared read contract.

Requester-facing interactions use business labels and display meanings. Ask for Agreement Name, Agreement Type, Target Plan, Source Plan, Source Absence Type, Management Type, Status, Partner Rule, Eligibility Rule, Legislation, Legislative Grouping, Validation Formula, Denial Reasons, Withdrawal Reasons, Event Type, Eligibility Formula, Eligibility Profile, Payment Percentage Display Formula, Override Allowed, Certification Name, Effective Start Date, Effective End Date, or As-of Date as applicable. Keep raw Data Loader and REST attribute names, stored codes, and surrogate identifiers internal unless the requester explicitly asks for technical details.
