# Absence Certification Design Enforcement

Apply the [Redwood conversation contract](../references/redwood-workflow.md)
and [lifecycle preflight](../../references/absence-additional-lifecycle.md)
inside the existing ANC_CERT.ENFORCE_DESIGN node. Missing operation contracts or known-protection evidence required
by the selected maintenance/destructive operation fail closed at runtime with
operation_capability_status=unverified; generic mappings, registry readiness,
template fields, a validation waiver, and user confirmation cannot establish
support. These gates apply before source preparation as well as preview.

Functional scope is the current target Redwood form, followed by WFM-82961.
Block backend-only fields even when describe/template metadata contains them.
Both Correct and Update keep identity, Management, stored dates and disabled
Absence Record Update Rule unchanged. Their inspected forms hide creation,
due-date, expiration and entitlement payment configuration; validate any
configuration-specific Confirmation Absence Record Update control against
fresh UI evidence. Apply the portable `uiContext` checks during preparation
and final source verification, without treating a local claim as live evidence.
Upsert/replacement is not supported. Delete Record is exposed in the fresh
multi-row review for a selected non-first physical row. Validate the exact selected stored range from complete contiguous History and
full configuration with User-defined protection and the physical-row adapter
contract. No runtime UI read, browser route or enabled-action flag is required.

## Enforcement Order

| Sequence | Step | What Must Happen |
|---|---|---|
| 1 | Select certification type | Select only Documentation or Entitlement, the two choices exposed by Redwood Add. |
| 2 | Normalize effective dating | Apply the current-date default only to an eligible create, derive effectiveOf, and validate it against the current Data Loader template. |
| 3 | Validate target contracts | Resolve supplied coded values and applicable conditional default candidates through their documented read-only target LOVs. Resolve Certification Type before selecting its Trigger lookup type. A Trigger suggestion is not a default and remains uncommitted until requester confirmation. Refresh DFF metadata only when DFF values are supplied. |
| 4 | Apply conditional defaults | Commit only the corresponding captured defaults that resolved successfully, preserve validated user overrides, and omit inapplicable fields, including hidden managed-by-entitlement-formula groups. |
| 5 | Enforce lifecycle capability and impact | Require environment identity, authorized access, validated fields/date semantics, dependencies and current registered create contract for Create; no existing new-record identity or destructive impact resolver is required. For maintenance of an existing object additionally require exact selected rows, allowed-field evidence, verified operation semantics and only its applicable protection/reference impact before source preparation. |
| 6 | Hand off source readiness | Return source_ready_for_preview after applicable source checks. Route the validated artifact exclusively to core.data-loader in REST mode for business object absenceCertifications to build its immutable preview and obtain its single final approval; reconcile the exact saved record after a successful load. |

All six resolvers below participate in ANC_CERT.VALIDATE_LOOKUPS before defaulting and ANC_CERT.ENFORCE_DESIGN before preview. Missing matches, ambiguous results, identifier conflicts, duplicate reasons, and incomplete multi-select resolution are blockers. Do not replace a failed supplied selection with null or silently retain unvalidated names in loader fields.
