# Absence Certification Reference Lookups

Resolve only controls and choices exposed in the current Redwood branch.
Filter backend LOV results to the reviewed UI choices before accepting an
intake value: Classification Documentation/Entitlement, Status Active/Inactive,
and the classification-specific Trigger list in redwood-workflow.md. A match
to another backend choice is not a supported requester selection. Return the
exact matched code/meaning pair as portable `uiContext.meanings` evidence;
mapped visible event/flex fields also require current UI evidence. Saved
before-state values stay outside immutable mutation fields. Do not impose
create choices on a full read of an existing predefined certification.

All calls in this file are read-only. They validate supplied and conditionally defaulted values in the target environment; they do not authorize a create, update, upsert, or delete operation.

## Lookup Execution Rules

Use the mandated `REST-Framework-Version: 9` and its rowmatch query syntax.
Combine Name and Legislation equality predicates with `and`, not the
framework-1 semicolon separator. Keep user values as quoted literals and
pass the complete q value through the core client query encoder; a literal
plus in a name must remain a plus after decoding. This repairs expression
syntax without broadening the lookup scope. Source: Oracle
[ADF REST query syntax](https://docs.oracle.com/middleware/12213/adf/develop/consuming-adf-restful-web-services.htm)
and [current Fusion framework versions](https://docs.oracle.com/en/cloud/saas/applications-common/26d/farca/Setting_the_REST_Framework_Version.html).

The existing exact-name finder has separate internal modes. Create preflight
reuses its declared paginated GET with the final proposed Name, resolved
Legislation, and normalized Create Start Date. A complete zero-match result is
`collision_clear` only within that query's scope; it does not prove global
historical uniqueness. Any matching row stops Create without upsert or overwrite.
Read failures, incomplete pages, or missing/ambiguous evidence never count as
zero matches. Ordinary search and non-create selection still require exactly
one effective record. A material change to the proposed name, legislation,
date or environment invalidates the collision evidence and requires a new read.
