# Areas of Responsibility Templates Input Validation

## Purpose

Defines required inputs, conditional requirements, field checks, and validation routing for Areas of Responsibility Templates.

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|

## Dependency-Aware Validation

| Applies When | Result | Next Action | Resolver |
|---|---|---|---|
| An existing template does not resolve exactly once | Missing | Provide one exact template selector | find_areas_of_responsibility_templates |
| A create TemplateCode matches an existing active or inactive template | Invalid | Stop before other resolution and return `PER-1532084 — You need to enter a different code. There's already a responsibility template with this code.` An existing TemplateName alone is permitted. | find_areas_of_responsibility_templates |
| A lookup-backed type, usage, status, attribute, criterion, category, or object-backed scope value has zero, multiple, disabled, or ineffective exact matches | Invalid | Correct the lookup-backed value | resolve_aor_common_lookup |
| A Job criterion is inactive, ineffective, unresolved, or ambiguous | Invalid | Correct the Job | resolve_aor_job |
| A Location criterion is inactive, ineffective, unresolved, or ambiguous | Invalid | Correct the Location | resolve_aor_location |
| A System Person Type criterion has zero, multiple, disabled, or ineffective exact Common Lookup matches | Invalid | Correct the System Person Type | resolve_aor_system_person_type |
| A Job Function criterion has zero or multiple enabled exact matches | Invalid | Correct the Job Function code or meaning | resolve_aor_job_function |
| A Country scope or criterion has zero, multiple, obsolete, or nonexact matches | Invalid | Correct the Country code or name | resolve_aor_country |
| A worker-assignment pair is ineligible, unresolved, or ambiguous | Invalid | Correct the representative | resolve_aor_worker_assignment |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Date normalization and range | Before AOR validation, normalize unambiguous `DD Month YYYY`, `D Mon YYYY`, `YYYY-MM-DD`, `YYYY/MM/DD`, `today`, and `one year from today` to `YYYY/MM/DD`; ask for clarification rather than guessing an ambiguous numeric date such as `01/02/2027`; reject impossible calendar dates. For create, require StartDate; reject EndDate earlier than StartDate and an active template EndDate before the validation date with `PER-1532765`. State normalized StartDate and EndDate with the failed business rule. DAT content always uses `YYYY/MM/DD`. | A date is supplied or a template is created | Apply during live-template source authoring, then run generic Core Data Loader validation |
| Inactive provisioning | Reject a new `MERGE` AORTemplate with blank TemplateId and Status `I`; create it active, then use an identified update if an inactive status is required | A new template is prepared | Apply during live-template source authoring, then run generic Core Data Loader validation |
| Past end-date provisioning | Reject a new active `MERGE` AORTemplate with blank TemplateId and an EndDate before the validation date | A new active template is prepared | Apply during live-template source authoring, then run generic Core Data Loader validation |
| Registered source contract | Reject unsupported columns, types, cardinalities, writable values, or child shapes | A mutation source is prepared |  |
| DAT row alignment | Build every AOR source from the current live AORTemplate workbook/template. Require every `MERGE` row to have the same pipe-delimited field count and attribute order as its business object's `METADATA` row, and apply the same rule to `DELETE` and every other operation row. Preserve only required trailing empty fields; reject extra or missing delimiters. For a multi-template archive, emit one union METADATA header per component. Re-run the check on every final DAT extracted from the immutable ZIP and report the business object, line, expected and actual counts, and row content. Validate populated values against their registered HDL attributes and resolved stored keys separately because matching counts do not prove semantic alignment. | A DAT is generated, imported, previewed, or submitted | Generic `core/data-loader/scripts/validate_data_load_file.py` after authoring |
| Archive filename | Name each outer artifact `AORTemplate-<operation>-<primary-template-code-or-batch-label>.zip` with a supported lowercase operation and sanitized tokens. Keep the single root DAT member exactly `AORTemplate.dat`; include the selected archive name in the preview and artifact manifest. | An AOR ZIP is generated | Apply during live-template source authoring; validate with generic Core Data Loader validation |
| Prohibited supplied values | Reject response-only IDs, audit values, links, generated values, read-only meanings, partial keys, and unknown multi-value encodings | Any such value is supplied |  |
| Direct assignment identity | Require one resolved worker-assignment pair and one supplied ResponsibilityName | A representative is directly assigned | resolve_aor_worker_assignment |
| Criteria value shape | Require the exact registry columns for the selected criterion. Resolve display values to canonical codes before serialization and emit only the supported CriteriaAttributeName header. Support Business Unit, Department, Job, Location, Position, Job Family, User Role, and the existing Country, Legal Employer, System Person Type, and Job Function mappings; reject missing values or populated fields belonging to another criterion. | TemplateCriteria is supplied | resolve_aor_criteria_value |
| Criteria child identity | Emit one TemplateCriteria MERGE row for every selected value. Assign CriteriaAttributeId sequentially from `1` across every TemplateCriteria MERGE or DELETE in the complete DAT, including criteria for different templates and repeated values of one criterion. Reject blanks, gaps, duplicate IDs, and aggregated comma-separated values. | TemplateCriteria is supplied | resolve_aor_criteria_value |
| Scope value shape | Resolve display scope values to canonical codes before serialization and emit only the supported AttributeName header. Apply the AttributeName-to-columns registry, require every selected scope's required target columns, reject unrelated populated columns and unknown attributes, and use a SetCode only when that scope's resolver contract explicitly returns one; never force COMMON. | TemplateScope is supplied | resolve_aor_scope_value |
| Dynamic scope mode | Allow `DynamicValueFlag=Y` only for AOR_BUSINESS_UNIT, AOR_DEPARTMENT, AOR_LEGAL_EMPLOYER, or AOR_LOCATION. Do not resolve a LOV or serialize any static mapping field for a dynamic scope; it counts as populated for final-state validation. Reject a nonblank flag other than Y, an unsupported attribute, duplicate TemplateCode plus AttributeName rows, or any static field on a dynamic row. | TemplateScope is supplied |  |
| Position criterion resolver | Require PositionId. Serialize PositionCode only when returned. Keep PositionBusinessUnitShortCode optional and blank when no supported live endpoint returns it; never derive it from a Business Unit name or ID. If Fusion explicitly rejects the blank field after load, preserve that loader message as a resolver-contract gap. | Position criterion is supplied | resolve_aor_criteria_value |
| Hierarchy exclusivity | Permit at most one hierarchy type per template. Department, Organization, Position, and Supervisor hierarchy paths remain blocked until each has a complete active loader-proven resolver contract. | A hierarchy scope is supplied |  |
| Lookup Tag isolation | Do not compare an Assignment Category or System Person Type Lookup Tag with Country, Legal Employer, LDG, or any other sibling AOR scope or criterion unless the registered AOR Data Loader contract explicitly defines that dependency. | Assignment Category or System Person Type is supplied | resolve_aor_common_lookup |
| Approval mapping completeness | Require one evidence row for every Scope and Criteria source row showing requested value, resolver, exact match, stored key, and target source field. | An approval preview is prepared |  |
| Parent-child completeness | Validate the template parent and every supplied child row together. For an existing template with any TemplateScope, TemplateCriteria, or DirectlyAssigned MERGE or DELETE, require one preceding AORTemplate MERGE identity row in the same archive with the resolved TemplateId and TemplateCode, even when no parent field changes. Do not invent parent values in that row. A parent DELETE remains the cascading delete operation. | A mutation includes child rows |  |
| Task Hook upload envelope | Require the approved inner `taskValidationEnvelope` returned by archive verification; reject the outer verification wrapper | A task-routed upload is prepared |  |
| Verification boundary | Do not treat transport or process acceptance as proof of the approved business state | Every mutation |  |
