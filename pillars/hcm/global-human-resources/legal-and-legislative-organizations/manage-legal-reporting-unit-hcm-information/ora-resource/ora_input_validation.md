# Legal Reporting Unit HCM Information Input Validation

## Purpose

Defines required inputs, conditional requirements, field checks, and validation
routing for Manage Legal Reporting Unit HCM Information. Loader templates and
DAT construction remain owned by the task skill and Core Data Loader.

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Search identity | Trim whitespace and require one exact normalized Name match across all pages | Every request | find_lru_by_exact_name |
| Classification readiness | Treat A as active and I, null, or an absent supported indicator as inactive. For an explicit classification change require both business-facing Yes/No answers. When both branches are inactive for a Get or Edit, require both answers and at least one Yes; both No remains blocked and must not invoke the classification loader. When both questions are pending, `Both` or `Yes to both` is explicit Yes/Yes: do not ask again and immediately continue through classification identity resolution, live loader-contract validation, immutable preview, and the Core Data Loader approval gate. Map eligible answers internally to the classification loader fields. If classification is an approved prerequisite for the pending Get or Edit, poll its accepted load to terminal status as this task's continuation step, refresh, require both properties to match the approved answers, and resume that pending operation; otherwise return the accepted standalone classification initiation response | Get, Edit, DE Delete, or classification change | find_lru_by_exact_name |
| Classification identity provenance | Before roots exist, use only the one distinct OrganizationId returned by organizationsLOV for exact Name and ClassificationCode=HCM_LRU; an inactive status is valid. Reject user-invented, stale, or substituted values | Classification identity is required | resolve_lru_classification_organization |
| Active-branch identity provenance | After classification is active, use only each fresh branch-root OrganizationId returned by q=EstablishmentId={EstablishmentId}. Reject user-invented, stale, or substituted values | A branch, context, or history identity is required | resolve_active_lru_branch_identity |
| Read effective date | Use today's system date when omitted. When supplied, require an unambiguous YYYY-MM-DD value and append it as effectiveDate only to the top-level Tax Reporting Unit or Reporting Establishment GET | Get |  |

| EffectiveStartDate | Resolve the current top-level organization's EffectiveStartDate for every affected branch, reject a requested operation date earlier than any affected organization start, and classify each branch independently | Edit | resolve_lru_loader_contract |
| EFF root controls and locators | Require FLEX:PER_ORGANIZATION_INFORMATION_EFF, EFF_CATEGORY_CODE, and every locator exposed by the exact selected object's current live template. | Dated update | When the requested operation EffectiveStartDate is later than an affected top-level organization's current EffectiveStartDate, existing rows require `effectiveOf=RangeMode=UPDATE;RangeStartDate=YYYY-MM-DD`; a new POST child requires `effectiveOf=RangeStartDate=YYYY-MM-DD` without RangeMode. Include SplitOrganizationUnitForEFFUpdate with the affected EFF branch, including when its EFF child row is new; do not construct a direct REST split action | Edit | resolve_lru_loader_contract |
| LRU DAT date normalization | Normalize every populated date-only DAT value to ISO `YYYY-MM-DD` during task payload preparation, including action dates and `effectiveOf` RangeStartDate. Reject a source containing a date-only `YYYY/MM/DD` value; do not transform timestamps or datetimes | Every Data Loader upload | resolve_lru_loader_contract |
| Existing and new EFF children | An existing child copies its current OrgInformationId, EffectiveStartDate, and EffectiveEndDate exactly from the fresh selected effective row and uses `RestAction=PATCH`; never replace those child key values with the requested operation date. | Current-row date independence | Validate the top-level organization, parent locator set, and existing child row independently against fresh state and the exact live-template contract. | New-child parent locator integrity | Before preview, require every available parent locator field to match its fresh parent row.
