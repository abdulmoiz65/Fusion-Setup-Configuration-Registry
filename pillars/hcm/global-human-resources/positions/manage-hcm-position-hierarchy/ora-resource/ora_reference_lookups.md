# Reference Lookups

## Purpose

Defines deterministic, read-only reference resolution for Manage HCM Position
Hierarchy.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| An existing date-effective target or reference is resolved as of a requested date | Accept the row when EffectiveStartDate ≤ requested date ≤ EffectiveEndDate; do not require equal start dates. |
| A supplied hyperlink names a host or pod | Ignore that host for environment selection; use the authenticated environment and only the safe Position selector. |
| positionsLov returns more than one row | Show only the first five with business-facing fields and require an explicit selection. |
| A mutation supplies a parent reference | Resolve it through positionsLov, then use positionsV2 for effective details and current relationships. |
| A hierarchy descendant search runs | First resolve one positionsLov row, then pass only its PositionCode in the AncestorPositionCode terms and the same date as the EffectiveDate value. |
| positionSearches omits the selected ancestor | Create the root from the selected ancestor row. |
| A positionSearches graph read is required | Invoke the declared POST directly; never call /positionSearches/describe. |
| A direct child is below the four-level display cap | Retain it in the full graph and use it in cycle and row-set checks. |
| A lookup or relationship changed after preview | Invalidate approval, regenerate the workbook, and preview again. |
