## Purpose

Defines deterministic, read-only reference resolution for this task.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A lookup requires authentication | Use core.auth.fusion-oauth-authentication. |
| A read or mutation precheck runs | Execute applicable reference_lookup nodes through core.fusion-api.rest-api-client before source preparation; do not use core.data-loader, core.data-loader.task-rest, or ora_rest_execution.md for the read. |
| An existing date-effective target or reference is resolved as of a requested date | Accept the row when EffectiveStartDate ≤ requested date ≤ EffectiveEndDate; do not require equal start dates. |
| A Position Extra or Legislative EFF context or segment is requested | Read the exact parent and requested POS_EIT or POS_LEG envelope without `onlyData=true`, resolve the context from current polymorphic describe, and follow the matching returned child link from `links` or `@context.links`. |
| A Position section read is requested | Default to the Position parent when no section is named; otherwise expand only the requested first-level child on the exact parent read, expand positionsEFFContainer.positionsEFF for PositionExtraInfo, and follow returned context child links for EFF values. |
| A supplied field has a lookup name but no dedicated resolver | Take the exact Lookup Name from current operation-specific Position Data Loader attribute metadata when REST describe exposes only a childRef. Resolve an exact code or one exact meaning through GET /fscmRestApi/resources/{version}/commonLookupsLOV with finder=LookupTypeFinder;LookupType={lookup_name},ActiveDate={target_date_iso}; paginate all results and require one exact match. Store LookupCode, not Meaning. Do not use /hcmRestApi for commonLookupsLOV or treat a childRef as a top-level resource. |
| A supplied field is a foreign reference | Use its current declared source-to-target mapping or complete business-key alternative; never invent or carry a surrogate identifier from another environment. |
| A Position is copied with child objects | Page every declared child collection as of the source date, record section row counts, and separately resolve every target-environment dependency as of the target date. Source reads are not dependency evidence. |
| A dependency is resolved for a final create/copy artifact | Record the dependency type, section and one-based row, `status: resolved`, `matchCount: 1`, exact payload values, and effective range when date-effective. Reject evidence that does not match the final payload. |
| A final edit artifact is prepared | Re-read every included existing row and applicable dependency, then compare evidence with the serialized DAT or ZIP by METADATA header name. Require exact existing-row keys, numeric values in ID columns, display values only in name columns, matching FLEX:FLEX_CODE declarations and context cells, and valid nonoverlapping ranges. Any source or serialized byte change invalidates this review. |
| A manager payload is prepared or verified after load | For a non-null manager change, before preview inspect the final Position DAT row by header name and require SupervisorPersonNumber and SupervisorAssignmentNumber to equal the same resolved pair; reject stale included supervisor IDs. For explicit removal, instead require the metadata-supported #NULL actions to clear both underlying supervisor references, with no retained or nonblank supervisor values; after load require both manager references absent. Omitted manager fields require no new manager evidence and must preserve the current manager. For a non-null manager change, after approved load read the exact Position as of the same effective date and compare its current ManagerId or ManagerPersonNumber through current describe mappings to the resolved manager identity; also confirm the retained correction range and unrelated attributes are unchanged. A mismatch is process failed, not success, and must not be retried automatically. |
| A Position delete is requested | Resolve the logical Position first. For effective-split delete, run resolve_position_delete_history and show only the Position business identity, selected effective period, and resulting retained range; keep FirstSplitFlag and PositionId internal. For zap, disclose that the complete logical Position will be purged and do not run the split-range derivation. |
| An exact target or reference is required | Accept exactly one eligible result; stop on zero or multiple results. |
| A collection is requested | Use bounded limit and offset pagination and follow hasMore or the next page only to the declared bound. |
