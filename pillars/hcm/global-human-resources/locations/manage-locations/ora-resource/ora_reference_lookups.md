# Manage Locations Reference Lookups

## Purpose

Defines deterministic, read-only reference resolution for this task.

## Lookup Operations

| Resolver | Runs When | Source Values | Request Path or URL | Requested Fields | Match Rule | Values to Fill | If No Match or Many Matches |
|---|---|---|---|---|---|---|---|

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A lookup requires authentication | Use core.auth.fusion-oauth-authentication. |
| A read or mutation precheck runs | Execute applicable reference_lookup nodes through core.fusion-api.rest-api-client before source preparation; do not use core.data-loader, core.data-loader.task-rest, or ora_rest_execution.md for the read. |
| An existing date-effective target or reference is resolved as of a requested date | Accept the row when EffectiveStartDate ≤ requested date ≤ EffectiveEndDate; do not require equal start dates. |
| Address style resolution is required | Resolve exactly one SUPP_TAX_AND_RPTNG_ADDR layout for the selected Country; do not substitute another style. |
| Address layout mapping is required | Map Address1 to AddressLine1, Address2 to AddressLine2, Address3 to AddressLine3, Address4 to AddressLine4, City to TownOrCity, PostalCode to PostalCode, County to Region1, and State to Region2. Use only a returned AttributeName and a current loader field; never derive Region mapping from label, geography level, or layout order. |
| A Location Extra or Legislative EFF context or segment is requested | Read the exact parent and requested HCM_LOC or HCM_LOC_LEG envelope without `onlyData=true`, resolve the context from current polymorphic describe, and follow the matching returned child link from `links` or `@context.links`. |
| An exact target or reference is required | Accept exactly one eligible result; stop on zero or multiple results. |
| A collection is requested | Use bounded limit and offset pagination and follow hasMore or the next page only to the declared bound. |
