## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A time-device-mapping collection or supported child collection is paginated | Retrieve every page before determining the candidate set; do not treat a partial collection as complete |
| A time-attribute field or dependent ValuesList search runs | Keep discovery bounded to at most 25 eligible records. Prefer an endpoint-supported display-field contains filter; otherwise apply normalized case-insensitive contains matching locally to that bounded candidate page. |
| A supplied parent or child criterion is absent from a collection item | Retrieve that candidate's item detail or follow its supported child-resource link; evaluate the candidate only after every supplied criterion is available |
| Multiple search or update candidates satisfy all criteria | Show all matching candidates with sanitized selection details and ask the user to select one; do not select automatically |
| A create duplicate-search phase finds one or more candidates | Stop the ordered search at that phase, show all candidates from the phase, and ask whether to use a selected existing record or create a new record |
| A parent LOV value changes | Clear every documented dependent selection before refreshing its provider |
| A LOV request has no exact match but returns candidates | Show up to five closest eligible business display values and require the user to select one; do not substitute or auto-select a value. |
| A LOV request returns no eligible candidate | Stop and request refined search text; do not substitute a value. |
| A common lookup supplies a mapping field | Delegate through hcm.workforce-time-management.time-and-labor-common.manage-common-lookups and pass the resolver's exact lookupType unchanged; do not call commonLookupsLOV directly or substitute an inferred lookup type. |
