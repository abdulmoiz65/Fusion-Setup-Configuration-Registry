## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| One or more fully compatible verified templates | Display every matching template and its characteristic-by-characteristic match; ask whether the user still wants a new template |
| The user confirms a new template after exact-match disclosure | Proceed to the proposal gate using normalized requested intent; do not select or copy a source row |
| Exactly one exact update target | Display its current configuration and complete proposed change set, then return update requested so the proposal and Data Loader import path can run |
| More than one fully compatible template | Display all verified candidates and require user selection |
| One or more partial candidates and no fully compatible template | Display every material difference; do not silently reuse a partial candidate |
| No fully compatible template | Return no match so the complete proposal and approval gate can run |
| Export read, join, or normalization fails | Return lookup failure and stop without preparing an import |
