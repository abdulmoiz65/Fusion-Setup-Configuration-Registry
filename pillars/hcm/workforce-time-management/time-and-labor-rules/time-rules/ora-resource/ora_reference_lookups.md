## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Exactly one exact Time Rule match | Reuse the verified existing Time Rule and show its normalized evidence |
| More than one exact Time Rule match | Do not select a rule; show the verified candidates and require user selection |
| One derivable same-family Time Rule match | Use it internally to propose complete business values and defaults. Default to **Create new** and invite the user to change any value or explicitly request **Update existing**. Show source provenance only on request or for a material ambiguity. Then verify its supporting template before resolving fields, preparing and validating the immutable archive, and seeking approval immediately before Fusion import. |
| One or more compatible-only Time Rule matches that are not derivable same-family matches | Use the candidates as source-backed evidence. Verify a supporting template before package preparation. Resolve common and request-derived values without a whole-rule selection; present only unresolved meaningful business inputs or outputs as focused user choices |
| No suitable Time Rule match | Run the prerequisite Time Rule Template compatibility lookup before proposing or creating a Time Rule |
| Exactly one fully compatible Time Rule Template | Display the selected template, explain the characteristic-by-characteristic match, and reuse it in the Time Rule proposal |
| Multiple fully compatible or partial-only template candidates | Do not select or create automatically; display every candidate and material difference and require user direction |
| No fully compatible Time Rule Template | Return no match so the joint template-and-rule proposal gate can run |
| Export read, join, or normalization fails | Return lookup failure and stop without creating or preparing dependent objects |
