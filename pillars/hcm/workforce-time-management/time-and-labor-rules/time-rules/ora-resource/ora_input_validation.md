# Time Rules Input Validation

Source: User-provided Time Rules authoring requirements, the supplied Time Rules template reports, the supplied Time Rule Templates ASM_SETUP_CSV_METADATA.xml and CSV template reports, developer-provided failed-import evidence for BOM-prefixed headers and short CSV input rows, and developer-provided FSM row-cloning requirements.

## Dependency-Aware Validation

| Applies When | Result | Next Action | Resolver |
|---|---|---|---|
| A child input, output, or conditional-member row does not resolve to exactly one parent row | Invalid | Stop and correct the parent identity or grouping key | |
| Any CSV starts with hexadecimal bytes EF BB BF or its parsed first header differs from the file-specific expected header | Invalid package encoding | Stop before import; create a new BOM-free package and repeat full package validation | |
| The current Time Rules export cannot be read completely | Lookup failure | Stop without preparing or creating a Time Rule | find_behaviorally_equivalent_time_rule |
| A plain-language creation request states a condition and outcome but omits RuleName or RuleType | Draft identity ready | Derive and display a proposed RuleName and provisional RuleType, then continue to the baseline lookup. Confirmation is required before package preparation. | find_behaviorally_equivalent_time_rule |
| One behaviorally exact Time Rule is found | Exact match | Reuse and verify the existing Time Rule | find_behaviorally_equivalent_time_rule |
| Exactly one verified same-family predecessor is found and its differences are limited to the requested name or explicitly supplied requirement values | Derivable family match | Propose complete business values and defaults, default to Create new, invite value changes, verify the supporting template, then prepare and validate the immutable archive. An update still requires an explicit user request. | find_behaviorally_equivalent_time_rule |
| More than one exact match is found | User selection required | Disclose candidates and differences; do not choose automatically | find_behaviorally_equivalent_time_rule |
| One or more compatible-only matches that are not an exact same-family predecessor are found | Field resolution required | Use the candidates as evidence; disclose only unresolved meaningful business input or output values and obtain a focused decision when needed | find_behaviorally_equivalent_time_rule |
| No suitable Time Rule match is found and the current Time Rule Templates export cannot be read completely | Template lookup failure | Stop without proposing or creating either object | find_compatible_time_rule_template |
| Exactly one fully compatible Time Rule Template is found | Template reuse ready | Display the selected template and the characteristic-by-characteristic match evidence, then reuse it in the Time Rule proposal | find_compatible_time_rule_template |
| More than one fully compatible template or any partial-only candidate is found | Template selection required | Display every candidate and material difference; do not select or create automatically | find_compatible_time_rule_template |
| No fully compatible Time Rule Template is found | Joint proposal required | Display the complete proposed Time Rule Template and Time Rule, then wait for explicit approval before either task is handed off for import | find_compatible_time_rule_template |
| Selected Time Rule Template effective-date compatibility cannot be established from authorized source data | Blocked | Stop preparation until the template's compatible dates are verified | |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| RuleName is not used as the sole behavioral match | Compare the normalized parent, inputs, outputs, conditions, categories, formula, execution behavior, and context | During lookup | find_behaviorally_equivalent_time_rule |
| Intent-derived identity lifecycle | Label an intent-derived RuleName and RuleType as proposed during lookup; allow user override and require a resolved, confirmed identity before package creation | From plain-language intake through package preparation | find_behaviorally_equivalent_time_rule |
| Exact-match semantics | Every populated and applicable normalized characteristic must agree | During lookup | find_behaviorally_equivalent_time_rule |
| Compatible-match semantics | Treat a verified same-family predecessor whose differences are limited to the requested name or explicitly supplied requirement values as derivable. Use it internally to propose values and defaults, default to Create new, and retain source provenance unless requested or needed to resolve a material ambiguity; treat every other non-exact behaviorally similar candidate as compatible-only evidence for field-level resolution, not as a whole-rule selection | During lookup | find_behaviorally_equivalent_time_rule |
| TemplateName is not used as the sole compatibility match | Compare RuleType and formula, calculation condition, required inputs and outputs, summation and reporting levels, Time Category support, result or payroll time-type behavior, parameters, and effective context | During prerequisite template lookup | find_compatible_time_rule_template |
| Fully compatible template semantics | Every requested behavior characteristic must be supported without an undisclosed functional gap; compare ordered template inputs and usages as part of the parent | During prerequisite template lookup | find_compatible_time_rule_template |
| Partial template semantics | A candidate with any missing, conflicting, or unverified applicable characteristic is not automatically reusable | During prerequisite template lookup | find_compatible_time_rule_template |
| Proposal completeness | The displayed proposal contains the complete template details and explains how the proposed Time Rule uses the template | Before requesting approval | |
| Approval freshness | Approval is valid only for the exact displayed proposal fingerprint and target Fusion environment; any material change requires a new display and approval | Before either import handoff | |
| ProcessingOrder and DisplaySequence values are positive integers and unique in their applicable parent scope | Reject invalid or duplicate ordering | For ordered child rows | |
| Template effective-date values use a source-supported date format and number values are numeric | Reject values that cannot be represented by the attached CSV contract | When a Time Rule Template is proposed | |
| UTF-8 BOM exclusion | Read the first three bytes of every CSV and reject EF BB BF; a visual header check alone does not pass because text readers may hide the BOM | Every Time Rules CSV package | |
| File-specific first-header identity | Parse the first header after the byte check and require the exact documented header for that file | Every Time Rules CSV package | |
| CSV row width | Parse every Time Rules CSV with the same CSV parser used for package validation; require each data row to contain exactly the number of fields in that file's header, including trailing empty fields | Before any Time Rules package is previewed, approved, or submitted | |
| Field states and preservation | Treat unspecified, literal values including `0`, intentionally blank values, and intentionally null values using the supported FSM null representation as distinct states. Never use truthiness; do not drop, normalize, or substitute any state, including trailing blank fields | When resolving or serializing a Time Rule | find_behaviorally_equivalent_time_rule |
| Generated-row completeness | Generate every required parent and child row from the complete resolved configuration; preserve metadata-defined ordering, parent-child references, headers, exact column counts, and trailing blank fields | Before any Time Rules package is previewed, approved, or submitted | |
| A newly created rule is verified by a refreshed authoritative export before reuse | Block any unverified reference | After approved conditional creation | find_behaviorally_equivalent_time_rule |
| A catalog result has the same task name but a task code other than ORA_HWM_MANAGE_RULES | Invalid task routing | Stop and correct the task code from the selected Time and Labor task skill before any export, import, or execution | |
