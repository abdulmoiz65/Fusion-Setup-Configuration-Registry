# Time Rule Sets Dependency Readiness

Source: Existing ASM_SETUP_CSV_METADATA.xml behavior, requested rule, child Rule Set, category, parent, and execution dependencies, observed committed-parent and member-verification results, and the developer-requested new-Time-Rule preview and approval gate.

## Dependency Order

| Sequence | Dependency | What Must Happen |
|---:|---|---|
| 1 | Read-only baselines | Use shared.setup-export.task-level-export to export the current Time Rule Sets and Time Rules before any create or update preparation |
| 2 | Fresh stage package contract | Export the current Time Rule Sets to obtain the exact staged-object CSV headers and `ASM_SETUP_CSV_METADATA.xml`; prepare new parent and member rows from normalized request intent, not from a selected existing Rule Set |
| 3 | Existing Time Rule resolution | Search the exported Time Rules baseline and resolve each requested condition to exactly one verified compatible existing Time Rule |
| 3 | New Time Rule preparation | When no verified existing match exists and the request specifies its name, type, threshold, period, and intended result, hand the normalized requirement to the supported Time Rules workflow so it derives a compatible rule from an exact verified sibling or a documented template, then prepares and validates the immutable Time Rules archive |
| 4 | New Time Rule import approval | Obtain explicit approval only for the exact immutable Time Rules archive immediately before its Fusion import; do not request a second design confirmation when the user request already supplies the requirement |
| 5 | New Time Rule verification continuation | After the approved import is accepted, start the task-authorized final-completion flow. It issues status requests until a documented terminal result, then refreshes and verifies the named Time Rules before Rule Set member preparation. Do not ask the user to request status separately and do not retry the import |
| 6 | Referenced child Time Rule Sets | Every nested member must reference exactly one ready, acyclic child Rule Set |
| 7 | Member Time Categories | Every supplied or behavior-required category must resolve exactly once |
| 8 | Committed parent Time Rule Set | For a new parent, state that the approved workflow has parent and member imports, import ORA_HWM_RULE_SET without members, verify its terminal result, then refresh the authoritative Time Rule Sets export and resolve its committed RuleSetUnqId |
| 9 | Ordered Rule Set members | When approved members exist and the parent succeeds, continue automatically by preparing ORA_HWM_RULE_SET_MBR rows with the committed exported RuleSetUnqId and derived GroupingKey, then present the member preview in ProcessingOrder sequence without waiting for a new association request |
| 10 | FSM CSV import and verification | Prepare a minimal immutable Time Rule Sets CSV ZIP, validate it through core.data-loader, obtain approval for each import stage, and refresh the authoritative export after the member import |

## Dependency Classification

| Result Category | When Used | Can Run Lookup/Create? |
|---|---|---|
| Ready | All conditional references resolve exactly once, dates and types are compatible, the graph is acyclic, and every member uses the committed exported parent RuleSetUnqId | Preparation may continue |
| Selection required | A Time Rule has multiple exact or compatible candidates | No automatic selection or preparation |
| Rule requirement incomplete | No verified existing Time Rule matches and the request lacks the rule type, threshold, period, or intended result | No Time Rule preparation until the missing requirement is supplied |
| Import approval required | A validated immutable Time Rules archive is ready for Fusion import | Stop only before the import until the exact archive is approved |
| Final completion monitoring | An approved asynchronous request is In progress or not available | Preserve the approved intent and continue task-authorized status requests until a documented terminal result; do not request separate user status authorization or submit again |
| Lookup blocked | A rule, child Rule Set, or category is missing, ambiguous, or unverified | No dependent preparation |
| Cycle detected | A child points to itself or reaches the parent through nested membership | No dependent preparation |
| Import blocked | A required CSV package, approval preview, import approval, or verification is missing | No live create or update |
| Parent import failed | The parent import reaches a failed terminal state | Stop the logical request; do not prepare or upload members |
| Member approval required | Parent verification succeeded and the immutable member preview is ready | Present the preview automatically; no member upload is allowed before the separate exact `approve` |
| Verification failed | An import reports success but the refreshed authoritative export does not contain the exact member relationship | No retry until the committed parent identity is re-resolved and a new approved member preview is produced |
