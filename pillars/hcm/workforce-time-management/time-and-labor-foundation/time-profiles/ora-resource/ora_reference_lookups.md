# Time Profiles Reference Lookups

## Purpose

Defines deterministic, read-only Fusion resolution for existing Worker Time
Profile state, selectable values, and server validation. `{BASE}` means
`{FA_HOST}/hcmRestApi/resources/11.13.18.05`; reusable guidance never hardcodes
the evidence tenant.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A lookup requires authentication | Use core.auth.fusion-oauth-authentication through the active implementation workflow |
| A Time Profiles request starts | Before any profile search, validation, preview, approval, or provider handoff, delegate ProfileOptionName ORA_HXT_ENABLE_TIME_PROFILE to /workforce-time-management/time-and-labor-common/manage-profile-options through hcm.workforce-time-management.time-and-labor-common.manage-profile-options. | A create or duplicate is prepared | After all other preflight validation and before the Complete Summary, Data Loader DAT preview, or approval, invoke resolve_next_time_profile_priority. Show its exact result in the Complete Summary. Do not use a priority supplied by the caller or retained from the duplicated profile. |
| A user asks to browse all Time Profiles | Use search_time_profiles with GET {BASE}/timeProfiles, fixed profile type Time represented by ProductArea TIME_PROFILE, limit=25, and offset=0. Continue by offset 25 only while hasMore is true, then display all returned business records. Do not silently choose a profile. |
| A user searches Time Profiles by name | Use search_time_profiles to retrieve every 25-record page. Compare ProfileName using case-insensitive contains matching. Fetch the one matching profile when exactly one is found; when multiple profiles match, display all matches and require selection. |
| A create request has no exact profile-name match | Run find_similar_time_profiles_for_reuse before presenting approval or creating a profile. Retrieve every Time-profile collection page, read every candidate at the applicable effective date, and compare the derived name, description, effective-date applicability, Layout Set, Time Card Period, Consumer Set, groups, and all other applicable configuration values. A differently named profile remains a candidate when its description or configuration matches. Display suitable and unsuitable candidates with business reasons, then ask whether to use an existing profile or create a new profile. |
| A live lookup runs | Use core.fusion-api.rest-api-client; keep reference lookups read-only even when a POST custom action performs search or validation |
| An existing profile is identified for update, correction, duplication, history selection, or Delete Changes by name | Use search_time_profiles to retrieve every GET collection page with required profile type Time represented by fixed ProductArea TIME_PROFILE. Compare ProfileName using case-insensitive contains matching regardless of capitalization; fetch the item when exactly one profile matches, otherwise display all matches and require selection. A verified TimeProfileId may still resolve directly. |
| An update or correction is prepared | Run read_worker_time_profile and read_time_profile_history. Display the current group assignments and effective-dated history as update impact information before the Complete Summary. If the history read is unavailable, state that it could not be retrieved and continue with the verified current profile state. |
| A text value is supplied to the Time Card Period selector | Use GET {BASE}/repeatingTimePeriodsLOV?fields=Name,RepeatingTmPeriodId&q=Name LIKE '%{search text}%'&limit=25&offset=0; select an exact returned Name and retain its RepeatingTmPeriodId; do not infer a period. |

| A custom action reports batchEnabled=false | Invoke it independently; do not place it in an ADF batch request |

| Provider monitoring returns failure, timeout, partial, uncertain, or unavailable result | Preserve the last known sanitized status and stop before retry; do not begin or resume a dependent workflow |
| The host is needed | Resolve the target Fusion environment at runtime and retain {FA_HOST}; never hardcode the evidence tenant |
