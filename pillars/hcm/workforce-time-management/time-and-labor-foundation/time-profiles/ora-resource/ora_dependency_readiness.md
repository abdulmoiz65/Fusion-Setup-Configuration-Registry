# Time Profiles Dependency Readiness

## Purpose

Defines the related Time and Labor setup that a Worker Time Profile references.
Dependencies are resolved read-only and are never created implicitly by this
task.

## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Time Profiles availability | Before any profile search or configuration activity, verify that Enable Time Profile is effective as Enabled for the current user. When that effective value is unavailable, accept the exact site-level value Y through the Time and Labor Common Manage Profile Options task. Do not change the option in this task. |
| 2 | Existing profile identity, current state, and update impact | For existing-record operations, resolve a verified TimeProfileId directly or search ProfileName with case-insensitive contains matching, then load fresh state through the documented item route. For update or correction, also retrieve effective-dated history and display it with current group assignments; an unavailable history read is informational and does not block the update. |
| 3 | Core time-card setup | Resolve Time Card Period and Layout Set before dependent Consumer Set |
| 4 | Payroll and calendar setup | Resolve any supplied time category, payroll selection, calendar category, and Yes/No value |
| 5 | Rule sets | Resolve each supplied rule set using its exact rule type and effective-date filter |
| 6 | Selected feature setup | For every optional feature selected by the user, resolve all documented required and conditional prerequisites through their owning providers before preview |
| 7 | Group assignments | Resolve every group, then run server-side assignment validation |
| 8 | Data Loader metadata preflight | Before DAT creation, review the selected task guidance and fresh live timeProfiles sample headers and attribute details to determine required fields, keys, dates, and effectiveOf format |
| 9 | Data Loader provider handoff | For a mutation, require core.data-loader with dataloader_import_mode REST and businessObject timeProfiles |
| 10 | Final completion | After the approved asynchronous submission is accepted, use the task-authorized core.data-loader monitoring flow and then the documented Time Profiles read-back before reporting final success |

## Dependency Classification

| Result Category | When Used | Can Run Lookup/Create? |
|---|---|---|
| Satisfied | Every applicable dependency resolved exactly and required validation returned no messages | No |
| Lookup | A documented resolver can fill a selected reference | Read-only lookup only |
| Verify | A documented validation action must confirm the proposed values | Read-only validation only |
| Not Applicable | The optional guided section or field is not selected | No |
| Needs Input | A required business selector is absent | No |
| Unresolved | A resolver cannot return or the user cannot select an eligible available or closest result | No |
| Blocked | A required resolver contract is unresolved or Assignment Validation returns messages | No |
