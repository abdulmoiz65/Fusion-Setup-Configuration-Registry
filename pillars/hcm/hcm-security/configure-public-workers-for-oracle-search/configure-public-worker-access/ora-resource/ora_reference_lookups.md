Run every documented PWA read-only Fusion GET through `core/fusion-api/rest-api-client/scripts/fusion_rest_client.py`. The resolver rows below are the task's callable lookup contract; a task-specific PWA lookup adapter is not required. The Data Loader remains the only mutation route.

## Batch Preflight

| Stage | What Happens | User-Facing Result |
|---|---|---|
| 1 | When requested, verify and present the profile option | Current effective and site mode when available. Explain the supported design and route a requested change to Manage Profile Options; do not block package preparation when no effective value is available |
| 2 | When the user needs help choosing a role, run the active-role candidate finder before exact role selection | A paged Role candidates result showing active business-visible roles only; selection is not yet assignee resolution |
| 3 | When the user needs help choosing a job, Business Unit, or Legal Employer criterion, run its documented current-page candidate browse before exact selection | A paged business-visible candidate result with a Next page action when available; selection is not yet identifier resolution |
| 4 | Run independent exact role and criterion resolvers together after their required selections are known, then verify the selected role remains unassigned | One consolidated Ready, Needs selection, No match, Inactive role, or Role unavailable result for the requested configuration; retain each resolved value and identify only unresolved values and their next action |
| 5 | Re-run only unresolved or ambiguous resolvers after the user supplies the requested discriminator | Updated consolidated result that retains successful values and does not repeat their lookups unless their inputs changed |

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A documented read-only REST GET lookup is needed | It is pre-authorized for this task and does not require separate user approval. Route it through `core/fusion-api/rest-api-client/scripts/fusion_rest_client.py`, using only the documented path, source values, match rule, and fields; do not require or create a task-specific PWA adapter, and do not issue raw HTTP directly. |
| A criterion is selected in the UI | Treat the value control as the rendered criterion-specific field, such as Grade or Job. Do not refer to it as a fixed Label field. |
| A lookup endpoint or contract is not documented | Do not infer an endpoint |
| A query-filter value contains a single quote | Escape it by doubling the quote before the request |
| An exact resolver response hasMore is true | Paginate before deciding that an exact match is unique or absent |
| A candidate discovery response hasMore is true | Keep the current page result and offer an explicit Next page action using the next offset. Do not prefetch later candidate pages or treat page results as identifier resolution |
| A user asks for roles like a keyword | Run discover_active_roles_by_keyword only when the keyword has at least three non-space characters. Return paged active candidates with business-visible role details and require an explicit user selection before exact-role validation |
| A user asks for Business Units or Legal Employers like a keyword | Run discover_active_business_units_by_keyword or discover_active_legal_employers_by_keyword with the user-confirmed keyword. Return the current page of business-visible candidates and require an explicit selection before exact validation |
| An exact Business Unit or Legal Employer lookup returns zero rows | Automatically run its documented keyword candidate browse with the original requested value and offset=0. Return the current page of business-visible candidates and require an explicit selection before exact validation |
| A user asks to browse suspended assignment statuses | Run discover_active_and_suspended_assignment_statuses. Return paged suspended candidates and require an explicit selection before exact AssignmentStatusCode validation |
| A role candidate is selected | Run resolve_assignee_by_exact_role_name. Do not treat a discovery result as an assignee or expose RoleId in the candidate list |
| An active role is resolved for a PWA package | Run verify_role_unassigned_for_pwa before package generation. Do not continue with a role that is assigned to another PWA configuration |
| A suspended assignment-status candidate is selected | Run resolve_assignment_status_by_user_status with the selected AssignmentStatusCode and locally verify the selected business-visible UserStatus label and dates. Do not treat a discovery result as a resolved AssignmentStatusTypeId |
| A Data Loader create or update has completed | Show the completed import status. Offer verify_public_worker_access_configuration as an optional expanded readback; do not report the configuration as verified unless the user selects it and its exact parent and expected child entries match |
| A Data Loader import status reports Succeeded | Automatically offer the optional verify_public_worker_access_configuration action. Do not run the expanded read unless the user selects that offered verification |
| A user asks to browse jobs | Run discover_active_jobs. When a keyword is supplied, use its uppercase form in upper(JobName) like '%<UPPER_KEYWORD>%'. Return a paged result of active, current candidates. Do not expose JobId or SetId, and do not populate the package until the user selects a candidate and one-key resolution succeeds |
| A jobsLov query parser rejects a combined predicate | Do not retry the same combined q expression. For a selected candidate, query q=JobCode='<job-code>' only and compare the returned active status, Name, SetName, SetCode when shown, and effective dates locally |
| A hcmBusinessUnitsLOV query parser rejects a combined predicate | Do not retry the same combined q expression. Query q=Name='<name>' only, retain active rows locally, and offer discover_active_business_units_by_keyword after a zero match |
| The generic Business Unit or Legal Employer LOV path rejects its documented q contract with HTTP 400 | When no route has already succeeded in this session, use the same-environment verified versioned route for that LOV and retain it for both candidate browsing and exact resolution. Do not ask the user to provide a raw REST URL, hard-code another tenant's route, add a predicate, or apply this route fallback to jobsLov |
| A job candidate is selected | Run resolve_job_by_exact_name_and_set with the selected JobCode and locally verify its business-visible Name, SetName, and current active state. Do not treat a discovery result as a resolved JobId |
| A resolver returns zero or several valid rows | Return the preflight result as No match or Needs selection, request the documented discriminator, and never request an internal numeric identifier |
| A multi-value preflight has both resolved and unresolved values | Return one consolidated result that retains each resolved business-visible value and identifies only the unresolved value, its result, and its next action. Do not rerun successful lookups unless their inputs changed |
| A role lookup returns an inactive row | Return Inactive role with the business-visible role Name and RoleCode. Do not populate AssigneeId or continue package preparation |
| The site profile value is available but the effective-session value is unavailable | Return Effective value unavailable and name the verified site value. Continue package preparation using the requested design and its applicable validations; do not infer the effective value from the site value |
| A dated lookup returns a result outside the requested effective date | Return the effective date and business-visible candidate values. Do not populate the package field until the date context is corrected |
| Multiple values satisfy policy | Require implementation-owner approval of the intended values |
| An associated role is already assigned | Stop and select an unassigned role |
