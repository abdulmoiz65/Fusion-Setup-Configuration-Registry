# Organization Security Profile Input Validation

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Profile definition | Name, ViewAllFlag, EnabledFlag, IncludeTopOrganizationFlag, IncludeFutureOrganizationsFlag, SecureByOrganizationHierarchyFlag, SecureByOrganizationClassificationFlag, SecureByOrganizationListFlag, and intended organization-access scope | Stop | Provide the required values and selected criteria | Creating or changing a profile | verify_organization_security_profile_name_unique |
| Existing profile identity | Current Name and OrganizationSecurityProfileId; proposed new Name for a rename | Stop | Resolve the old exact Name to one profile and require its returned ID to equal the supplied current ID before checking the proposed new Name | Updating or renaming an existing profile | find_organization_security_profile_by_exact_name |
| Security-criterion selection | An explicit selected or not-selected state for each applicable criterion: organization hierarchy, organization classification, and organization list | Stop before any criterion-specific lookup when the requested criteria are unclear | Confirm which criteria are selected, then resolve only the values needed for every selected criterion | Creating or changing a profile | |
| Change scope | Profile-only, or profile plus explicitly authorized reference-data changes | Stop before any reference-data creation or modification | Request the change scope. Profile-only permits using existing reference data but does not authorize creation or modification of organizations, Departments, or trees. | Creating or changing a profile | |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Profile Name availability | For a create or genuine rename, require zero exact matches for the proposed Name. An exact match blocks; multiple matches are ambiguous. If proposed Name equals current Name, use the unchanged-name update route. | A profile is created or a genuine rename is requested | verify_organization_security_profile_name_unique |
| Rename CSV identity mapping | Block with `rename CSV identity mapping unverified` before CSV preview or import; never infer update keys from REST IDs or name-based GroupingKey fallbacks | A genuine rename passes name availability |  |
| Security-criterion gate | Collect the selected or not-selected state for each applicable criterion before its REST lookup. Organization hierarchy, organization classification, and organization list can be selected together; resolve only the inputs required by each selected criterion. Treat a Department Tree and Department as hierarchy inputs, not as a competing security model. | A profile is being planned, created, or changed | |
| FSM export metadata | Require exactly one ASM_SETUP_CSV_METADATA.xml member from the FSM task CSV export and validate its reusable task and package contract before using the export as a CSV baseline. Do not carry environment, submitter, timestamps, ESS request IDs, or process IDs into package guidance or generated rows. | An FSM task CSV export is validated or used as an import baseline | verify_fsm_task_csv_metadata |
| Template-derived CSV layout | Require the current template-only export to resolve parent and child members, exact header arrays and order, field mappings, parent-child linkage, ViewInstanceName values, GroupingKey patterns, and metadata node order. A missing ViewInstanceName or GroupingKey pattern uses the documented member-specific fallback. Generate rows only from that output and retain ASM_SETUP_CSV_METADATA.xml byte-for-byte unchanged. | A CSV package is generated or imported | resolve_organization_security_profile_csv_context |
| Change-scope gate | Collect the change scope before resolving reference values. Profile-only uses existing values only and cannot create or change reference data. | A profile is being planned, created, or changed | |
| Organization Tree structure code | Accept PER_ORG_TREE_STRUCTURE only. If PER_ORG_TREE_STRUCTURES is supplied, stop and request the singular code rather than treating it as a matching structure. | An Organization Tree structure code is supplied | |
| Organization Tree browsing | After the organization-hierarchy criterion is selected, accept a recognizable OrganizationTreeSearchTerm or a browse-only request. A browse-only request uses the bounded Organization seed and returns at most five candidates; empty or wildcard-only supplied terms cannot browse hcmTreesLOV. | A user requests Organization Tree candidates | browse_organization_trees_from_hcm_trees_lov |
| Department Tree browsing | After the organization-hierarchy criterion is selected and the hierarchy uses a Department Tree, accept a recognizable DepartmentTreeSearchTerm or a browse-only request. A browse-only request uses the bounded Department seed and returns at most five candidates; empty or wildcard-only supplied terms cannot browse hcmTreesLOV. | A user requests Department Tree candidates | browse_department_trees_from_hcm_trees_lov |
| Organization Tree | For a supplied code, resolve through hcmTreesLOV PrimaryKey. For a supplied name, use the structure-aware, comma-delimited word finder. Do not send fields; map the supported response locally. Require one active tree with TreeStructureCode=PER_ORG_TREE_STRUCTURE before accepting it. | OrganizationTreeCode or OrganizationTreeName is supplied | resolve_organization_tree_from_hcm_trees_lov |
| Department Tree | For a supplied code, resolve through hcmTreesLOV PrimaryKey. For a supplied name, use the structure-aware, comma-delimited word finder. Do not send fields; map the supported response locally. Require PER_DEPT_TREE_STRUCTURE, active status, and an effective version before accepting the tree. | DepartmentTreeCode or DepartmentTreeName is supplied | resolve_department_tree_from_hcm_trees_lov |
| Department Tree parent CSV fields | For a Department Tree hierarchy, set TreeName from the resolved TreeName, OrgHierTreeStructCode=PER_DEPT_TREE_STRUCTURE, and OrgHierTreeCode from the same resolved TreeCode. Tree display name is not a substitute for its code. | An organization-hierarchy profile CSV uses a Department Tree | resolve_department_tree_from_hcm_trees_lov |
| Organization LOV browsing | Require OrganizationSearchTerm and return no more than five Name-matching organization candidates for user browsing only; do not automatically select a record | A user requests organization LOV values | browse_organizations_lov |
| Organization Classification LOV browsing | Retrieve the documented classification fields through organizationClassificationsLOV without a supplied filter for user browsing only; do not automatically select a record | A user requests organization-classification LOV values | browse_organization_classifications_lov |
| Organization Tree node browsing | Return effective, distinct node candidates from the selected TreeVersionId before a user selects a top organization; do not automatically select a node. | A user requests top-organization candidates | browse_organization_tree_nodes_from_lov |
| Top Organization | Require TopOrganizationName and scan the selected organization-tree version to resolve one exact, effective-dated distinct logical node. Deduplicate repeated raw rows by OrganizationId and OrganizationName; if TopOrganizationId is supplied, require it to match the resolved node ID. | Organization-hierarchy security is selected | resolve_top_organization_in_tree_nodes_lov |
| Top Organization classification | Resolve the selected hierarchy node through organizationsLOV using exact name, active status, requested effective date, and the hierarchy-node ID; fill its classification values for the CSV. | A hierarchy profile CSV requires a top-organization classification | resolve_top_organization_classification_from_lov |
| Department from the user's assignment | Set TopOrgSelection=U to derive the hierarchy top organization from the user's assignment department. This is distinct from IncludeTopOrganizationFlag: that flag independently controls whether the resolved top organization itself is included in secured access. Do not substitute a named-top selection simply because the requested department is known. | The requested top organization is the department on the user's assignment | |
| Department Tree Node | Require DepartmentName and resolve it in the selected Department Tree at the requested effective date with a server-side DepartmentName search and full page traversal; if OrganizationId is supplied, require it to match the resolved node ID. For an organization-hierarchy criterion using a Department Tree, fill nonblank TopOrganizationName and TopOrganizationId from the resolved node. | A selected department-tree node is required | resolve_department_tree_nodes_from_lov |
| Department Tree hierarchy CSV handoff | Require the Department Tree resolver output to contain TreeCode and TreeName, and the Department-node resolver output to contain DepartmentName, OrganizationId, TopOrganizationName, and TopOrganizationId. Set OrgHierTreeCode exactly to the resolved TreeCode; stop package preview if it is blank or differs from that TreeCode. Stop if either TopOrganization value is blank or no longer equals the resolved Department identity. The resolved Department Tree and node are the hierarchy evidence; do not require a separate profile-contract lookup. | An organization-hierarchy profile CSV uses a Department Tree | resolve_department_tree_nodes_from_lov |
| Organization Tree Node | Require OrganizationName and scan the selected Organization Tree version at the requested effective date for one exact distinct logical node. Deduplicate repeated raw rows by OrganizationId and OrganizationName; if OrganizationId is supplied, require it to match the resolved node ID | A selected organization-tree node is required | resolve_organization_tree_nodes_from_lov |
| Combined criteria | Every selected hierarchy, classification, and organization-list criterion applies to the secured set | More than one criterion is selected | |
| Future organization access | Select Include future organizations when future-dated access is required | Future-dated access is required | |
