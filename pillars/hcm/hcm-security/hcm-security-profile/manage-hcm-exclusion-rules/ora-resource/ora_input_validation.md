# HCM Exclusion Rules Input Validation

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Exclusion rule type | Exclusion Type | Stop before preparing the rule | Resolve the value through `hcm.hcm-security.hcm-security-common.manage-common-lookups` using the designated common lookup | Creating or updating an exclusion rule | resolve_exclusion_type_from_common_lookup |
| Exclusion rule name | Name with 1–30 characters, or a functional definition from which Name can be derived | Stop before preparing the rule | Provide a Name with 1–30 characters or the functional definition needed to derive one | Creating an exclusion rule | |
| Existing exclusion-rule reconciliation | Exact parent Name, ExclusionType, selected child collection, and child identifiers when present | Stop before preview or import | Resolve the parent through exclusionRules with the type-specific child collection expanded | Creating or updating an exclusion rule | resolve_exclusion_rule_by_name_with_children |
| Existing exclusion-rule parent mapping | Returned ExclusionRuleId in the parent CSV row | Stop before preview or import | Populate ExclusionRuleId when resolve_exclusion_rule_by_name_with_children returns an exact parent | Updating an existing exclusion rule | resolve_exclusion_rule_by_name_with_children |
| Exclusion criterion | Selected list or hierarchy type and its supplied display value | Stop before preparing the rule | Supply the display value required by the selected exclusion type | A list or hierarchy exclusion criterion is configured | |
| Resolved exclusion value | Source display value and its resolved ID, code, or territory value in the required CSV detail field | Stop before preview or import | Resolve the source value with the individual LOV resolver and place it in the CSV detail field required for the selected exclusion type | A list or hierarchy exclusion criterion is configured | resolve_hcm_exclusion_rule_csv_layout |
| Attribute exclusion criterion | Attribute exclusion type, attribute display name, and operator type | Stop before preparing the rule | Select a supported attribute exclusion type; resolve the attribute and operator through their documented resolvers | An attribute-based exclusion criterion is configured | resolve_exclusion_rule_attribute_from_lov |
| Resolved attribute exclusion criterion | Flexfield context, column name, table name, operator lookup value, and comparison value in their required CSV detail fields | Stop before preview or import | Resolve attribute metadata through its task LOV and the operator through `hcm.hcm-security.hcm-security-common.manage-common-lookups`; retain the literal comparison value unchanged unless ColumnName is SET_ID, in which case resolve the supplied SetName or SetCode to SetId and SetCode; use Global Segment as FlexContext for global-segment attributes | An attribute-based exclusion criterion is configured | resolve_hcm_exclusion_rule_csv_layout |
| Set-backed attribute exclusion criterion | SetName or SetCode and returned SetId and SetCode | Stop before preview or import | When resolved attribute metadata maps to ColumnName SET_ID, resolve the supplied SetName or SetCode through setIdSets; use the returned SetCode as AttributeSetCode and returned SetId as AttributeValue | An attribute-based exclusion criterion is configured for a set-backed attribute | resolve_set_id_from_set_id_sets |
| Attribute comparison value | Supplied nonempty comparison text, or SetName or SetCode for a set-backed attribute | Stop before preparing the rule | Provide literal comparison text unless the resolved attribute maps to ColumnName SET_ID; for a set-backed attribute, provide SetName or SetCode | An attribute-based exclusion criterion is configured | |
| Verified CSV baseline | Fresh HCM Exclusion Rules export package with unchanged ASM_SETUP_CSV_METADATA.xml | Stop before package preparation | Validate the package structure and linkage against the documented local CSV-layout resolver | A CSV import package is prepared | resolve_hcm_exclusion_rule_csv_layout |

## Dependency-Aware Validation

| Applies When | Result | Next Action | Resolver |
|---|---|---|---|
| A selected exclusion type uses a non-country list criterion | The supplied display value must resolve to one identifier placed in IdValue | Run the individual LOV resolver documented for the selected list type and stop on no match, an unresolved duplicate, or any CSV field other than IdValue | resolve_hcm_exclusion_rule_csv_layout |
| A selected exclusion type uses a country-list criterion | The supplied country must resolve to one TerritoryCode placed in Value | Run the country LOV resolver and stop on no match, an unresolved duplicate, or use of IdValue | resolve_hcm_exclusion_rule_csv_layout |
| A selected exclusion type uses a Department Hierarchy or Department Tree criterion | The tree and top department must resolve to TreeCode and TopNodeValue | Run the documented tree and top-department resolvers and stop on no match, an unresolved duplicate, or use of IdValue | resolve_hcm_exclusion_rule_csv_layout |
| A selected exclusion type uses a Position Hierarchy or Supervisor Hierarchy criterion | The top position or manager must resolve to TopNodeValue | Run the documented top-node resolver and stop on no match, an unresolved duplicate, or use of IdValue | resolve_hcm_exclusion_rule_csv_layout |
| A list exclusion has a matching existing child row | The matching child must not be emitted as a new detail row | Compare the resolved list identifier with the documented child identity from resolve_exclusion_rule_by_name_with_children | resolve_exclusion_rule_by_name_with_children |
| An attribute or hierarchy exclusion has an existing child row | The existing child identifier must populate ExclusionRuleDtlId so the CSV updates that row | Compare the resolved attribute or hierarchy identity with the documented child identity from resolve_exclusion_rule_by_name_with_children | resolve_exclusion_rule_by_name_with_children |
| An attribute-based exclusion criterion is configured | The supplied attribute must resolve to exactly one documented FlexfieldContextCode, ColumnName, and TableName mapping; the supplied operator must resolve through `hcm.hcm-security.hcm-security-common.manage-common-lookups` using lookupType ORA_PER_EXCLUSION_OPERATORS; the supplied comparison value is retained as literal free text unless ColumnName is SET_ID; the detail row must use FlexContext, ColumnName, TableName, Operator, and AttributeValue, with Global Segment as FlexContext for global-segment attributes | Resolve the attribute and operator before preparing the rule; require a nonempty comparison value, but do not perform value-set or LOV validation unless the resolved attribute maps to ColumnName SET_ID | resolve_hcm_exclusion_rule_csv_layout |
| An attribute-based exclusion criterion maps to ColumnName SET_ID | The supplied SetName or SetCode must resolve to exactly one SetId and SetCode; populate AttributeValue with SetId and AttributeSetCode with SetCode | Resolve the selected reference-data set through setIdSets before preparing the rule; stop on no match, ambiguity, conflicting supplied SetName and SetCode, or either required resolved output | resolve_set_id_from_set_id_sets |
| Exclusion Type is supplied | The code must resolve through `hcm.hcm-security.hcm-security-common.manage-common-lookups` using lookupType ORA_PER_EXCLUSION_TYPE | Resolve the common lookup value before preparing the rule | resolve_exclusion_type_from_common_lookup |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Enabled flag | Enabled Flag defaults to Y when omitted | A new exclusion-rule row is prepared | |
| Exclusion Type | Verify the supplied code through `hcm.hcm-security.hcm-security-common.manage-common-lookups` using lookupType ORA_PER_EXCLUSION_TYPE | Exclusion Type is supplied | resolve_exclusion_type_from_common_lookup |
| Business Unit List | Match Name exactly and map BusinessUnitId to idValue | Business Unit List is selected | resolve_business_unit_id_from_hcm_business_units_lov |
| Department List | Match Name exactly and map OrganizationId to idValue | Department List is selected | resolve_department_id_from_departments_lov |
| Grade List | Match Name exactly; if multiple matches are returned, require Grade Code and Set Name; map GradeId to idValue | Grade List is selected | resolve_grade_id_from_grades_lov |
| Job Family List | Match JobFamilyName exactly; if multiple matches are returned, require Job Family Code; map JobFamilyId to idValue | Job Family List is selected | resolve_job_family_id_from_job_families_lov |
| Job List | Match JobName exactly; if multiple matches are returned, require Job Code and Set Name; map JobId to idValue | Job List is selected | resolve_job_id_from_jobs_lov |
| Legal Employer List | Match Name exactly and map OrganizationId to idValue | Legal Employer List is selected | resolve_legal_employer_id_from_legal_employers_lov |
| Work Location List | Match LocationName exactly; if multiple matches are returned, require Location Code and Set Name; map LocationId to idValue | Work Location List is selected | resolve_location_id_from_locations_lov |
| Person List | Search DisplayName using the documented workersLov finder; if multiple matches are returned, require Person Number; map PersonId to idValue | Person List is selected | resolve_person_id_from_workers_lov |
| Position List | Match PositionName exactly; if multiple matches are returned, require Position Code; map PositionId to idValue | Position List is selected | resolve_position_id_from_positions_lov |
| Country List | Match CountryName exactly and map TerritoryCode to Value | Country List is selected | resolve_country_territory_code_from_hcm_countries_lov |
| Department hierarchy tree | Match Tree Name exactly using the documented department tree structure finder and map TreeCode to TreeCode | Department Hierarchy or Department Tree is selected | resolve_department_tree_code_from_hcm_trees_lov |
| Top Department | Match Name exactly and map OrganizationId to TopNodeValue | Department Hierarchy or Department Tree top department is selected | resolve_top_department_id_from_departments_lov |
| HCM Position Hierarchy top position | Match PositionName exactly; if multiple matches are returned, require PositionCode; map PositionId to TopNodeValue | HCM Position Hierarchy is selected | resolve_hierarchy_top_position_id_from_positions_lov |
| Supervisor Hierarchy top manager | Search DisplayName using the documented workersLov finder; if multiple matches are returned, require Person Number; map PersonId to TopNodeValue | Supervisor Hierarchy is selected | resolve_top_manager_person_id_from_workers_lov |
| Attribute exclusion type | Accept only ORA_EXCL_DEPT_ATTR, ORA_EXCL_GRD_ATTR, ORA_EXCL_JOB_ATTR, ORA_EXCL_LOC_ATTR, ORA_EXCL_PER_ATTR, or ORA_EXCL_POS_ATTR | An attribute-based exclusion criterion is selected | |
| Attribute | Search AttributeDisplayName using exclusionRuleAttributesLOV for the selected attribute exclusion type; if multiple results are returned, require an exact attribute | An attribute-based exclusion criterion is selected | resolve_exclusion_rule_attribute_from_lov |
| Operator Type | Verify the supplied code through `hcm.hcm-security.hcm-security-common.manage-common-lookups` using lookupType ORA_PER_EXCLUSION_OPERATORS | An attribute-based exclusion criterion is selected | resolve_attribute_operator_from_common_lookup |
| Attribute comparison value | Require supplied nonempty text and place it unchanged in AttributeValue with FlexContext, ColumnName, TableName, and Operator; use Global Segment as FlexContext for global-segment attributes; do not resolve, normalize, or validate the comparison value against a value set or LOV | An attribute-based exclusion criterion is selected and its resolved ColumnName is not SET_ID | resolve_hcm_exclusion_rule_csv_layout |
| Set-backed attribute comparison value | Match supplied SetName or SetCode exactly; map returned SetCode to AttributeSetCode and returned SetId to AttributeValue | The resolved attribute ColumnName is SET_ID | resolve_set_id_from_set_id_sets |
| CSV resolver layout | Require every generated CSV member, header order, row relationship, required criterion mapping, and metadata node order to match the current template-only export and documented task CSV criterion mappings. Use template ViewInstanceName and GroupingKey values when available; otherwise apply the documented member-specific ViewInstanceName fallback and distinct new-row GUID GroupingKey fallback. | A CSV import package is supplied | resolve_hcm_exclusion_rule_csv_layout |
