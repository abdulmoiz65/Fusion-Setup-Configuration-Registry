## Verified Read Lookup Sources

The stored-grade lookup uses Oracle's current [Get all grades REST contract](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-gradeslov-get.html), verified on 2026-09-24. It documents GradeId as queryable and the requested response fields, including active/inactive status and effective dates. Omitting the active-only filter avoids imposing create eligibility; it does not guarantee that every historical or inaccessible grade is returned. Missing or ambiguous labels remain partial read results.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Read-details request | Invoke find_candidate_security_profile_details on the fresh verified export. The configuration classification, defaults, capacity, View All rejection, package preparation, and approval path do not apply |
| Stored read-details criteria | Resolve every populated value in the five supported dimensions with the corresponding resolve_stored_*_label resolver, including values whose dimension flag is N. Do not erase exported duplicates or mutate source rows |
| Read-details lookup authority | Use current-request authenticated Fusion results for display labels. Do not reuse conversation memory or prior-run mappings. Within this read operation, reuse a result only for the same environment, resolver, and exact stored identity |
| Read-details evidence coverage | Derive the expected environment, resolver, and exact stored identity set from every populated supported criterion in the verified current-request export, independently of dimension flags. Keep all source rows, including duplicates. For each expected identity retain current-request resolver evidence: whether execution occurred, match count when available, outcome, verified label or specific unresolved reason. Code formatting, memory, local file searches, and export completion do not supply label evidence |
| Read-details completion evaluation | Evaluate coverage locally using only the verified current-request export and current-request resolver results. Complete requires a verified label for every expected identity; an empty expected set needs no calls. Partial requires every identity to have either a verified label or an actual unresolved lookup outcome. Any unexecuted lookup or missing evidence is execution_gap, never resolved or no match. Finish permitted outstanding lookups before leaving resolution; if execution remains blocked, disclose the gap and safe resume step without claiming completion |
| Read-details lookup failure | Preserve verified profile facts and all raw values. Record label unresolved with a per-value reason and continue independently resolvable dimensions when execution is permitted. Never report complete label resolution after a failure; do not bypass an authoring readiness blocker |
| The current-environment export baseline is not verified | Stop before create-or-update classification; do not substitute the authoring reference files or an older export |
| One or more profile Names are supplied | Evaluate each distinct exact Name independently and require the user's applicable fields and setting values for every supplied profile |
| No exported header row matches a supplied profile Name under the confirmed match contract | Classify as create and apply create defaults only after CSP.CHECK_CHANGE_INTENT allows the operation. If update wording implied an existing profile, disclose that this would create a new profile and obtain clarification before proceeding |
| One exported header row matches a supplied profile Name under the confirmed match contract | Classify as existing-profile updates; compare all associated detail rows. Preserve omitted settings and all existing criteria, and check requested change intent before defaults or lookups |
| Multiple detail rows have the same ORA_IRC_CAND_SEARCH_SECURITY_PROFILE_VALUES.Name | Group all rows under the matching profile; each row is one setting value and the repeated profile Name is not ambiguous |
| A requested detail tuple already exists | Report it as unchanged and do not generate a duplicate row |
| Duplicate criteria in existing-profile additions | Resolve supplied labels and codes first. Compare each canonical tuple against all associated exported detail rows and the pending additions for that exact profile and dimension. Existing tuples are no-ops; repeated new tuples produce one addition only. Do not skip the baseline duplicate check because the user called the request an addition |
| A requested detail tuple is missing | After canonical resolution, generate an addition only for an allowed additive request. Never reinterpret an explicit replacement as an addition |
| Enabled creates or N-to-Y updates are requested | Run count_active_candidate_security_profiles for the complete merged batch and pass its counts to CSP.ENFORCE_DESIGN before approval; no silent subset selection |
| Every requested profile is an update | Run count_active_candidate_security_profiles for changed batches; existing N-to-Y activations increase the projected count just as enabled creates do |
| ORA_IRC_CAND_LIST_NOT_DEFINED is selected where applicable | Treat it as the delivered Not Defined option; do not treat it as a country returned from hcmCountriesLov |
| A selected value is unresolved | Do not guess an ID or create a profile |
| Resolving Person Type or Recruiting Type choices | Follow all pages, combine the declared lookup sources, deduplicate by code, and sort by Meaning; Not Defined is a real NOT_DEFINED value, not a blank |
| A lookup definition is disabled | Apply only the owning resolver eligibility rule; do not modify lookup definitions or substitute a common enabled-only policy |
| A fresh run is requested | Discard earlier conversational inputs and approvals; do not discard current environment data established by this run's fresh export |
