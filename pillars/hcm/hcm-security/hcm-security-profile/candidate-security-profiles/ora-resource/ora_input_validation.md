## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Replacement input | Retain source, target, dimension, and explicit replacement intent for CSP.CHECK_CHANGE_INTENT; do not convert it into an additive criterion | A criterion replacement is requested | |
| Security dimension flags | Accept only Y or N when supplied; preserve the distinction between omitted and explicit values for dimension-flag enforcement | A SecureBy flag is supplied | |
| Profile name | Reject a missing, blank, or whitespace-only identity name; for updates accept old name instead of Name. Reject a supplied blank new name or conflicting Name and old name; do not discard explicit update intent | Always | |
| Description | Preserve omission; do not invent a description | Description is omitted | |
| EnabledFlag | Accept only Y or N when supplied; omission is valid for creates and updates | Explicitly supplied | |
| ViewAllFlag | Validate an explicitly supplied value as Y or N; omission is valid on both creates and updates. Never prompt for this field, including on invalid input; report the validation finding. Y is subject to the separate design-policy rejection, not silently normalized to N | Explicitly supplied | |
| Header CSV shape | Require the documented 14-column header schema and one row per Candidate Security Profile; reject duplicate exact Name headers anywhere in the baseline instead of silently deduplicating them. Header EnabledFlag must be Y or N | Validating the current-environment export baseline | verify_candidate_security_profile_export_baseline |
| Detail CSV relationship | Require ORA_IRC_CAND_SEARCH_SECURITY_PROFILE_VALUES.Name on every detail row and associate every row with its exact header row Name; allow multiple detail rows for the same profile | Validating the current-environment export baseline or generated detail rows | verify_candidate_security_profile_export_baseline |
| Detail CSV row cardinality | Require exactly one populated value field per detail row: SecureByRecruitingTypeVal, SecureByPersonTypeVal, SecureByCandCountryVal, SecureByGradeLevelVal, SecureByBusinessUnitVal, SecureByJobFamilyVal, SecureByJobFuncVal, or SecureByLegalEmployerVal | Validating exported or generated detail rows | |
| Multi-profile request | Group by exact Name. Merge compatible flag updates and additive requests; identical supplied settings are compatible. Report different explicit values, differing new names, or incompatible operation intents; do not silently choose first or last. Resolve aliases before deduplicating canonical additions. Keep unsupported change intent visible rather than dropping it | Multiple entries address one or more profiles | |
| Supported dimensions | Reject Job Family, Job Function, and Legal Employer unless a separately verified product contract is provided | Those dimensions are requested | |
| Selected dimension values | Require supplied values or baseline entries for selected dimensions. Validate input shape before resolution; resolve canonical values at CSP.RESOLVE_VALUES before delta classification | A supported security dimension is selected on create or enabled from N to Y, including flag-only updates and activation derived from supplied criteria; criteria are supplied or preserved | |
| Partial-request intake | Require only nonblank Name for an eligible create; export and classify first, then default omitted flags without prompting. Existing profiles support allowed flag updates and criterion additions; preserve omitted settings. Keep explicit change intent for the policy gate | Partial input | |
| Outgoing Grade and Business Unit IDs | Use the final immutable upload artifact as authoritative local input. Every populated SecureByGradeLevelVal and SecureByBusinessUnitVal must be a complete ASCII digit string with at least one nonzero digit. Reject scientific notation, decimals, signs, whitespace, separators, non-ASCII digits, and all other malformed representations. Blank unused fields remain valid. Preserve all digits without floating-point conversion, rounding, exponent expansion, trimming, or guessing. Apply this to every outgoing row, including copied criteria. Require complete authoritative IDs via the existing resolve_grade or resolve_business_unit contract; never silently replace existing criteria | Every final create or update artifact before approval/upload | |
| Flag-only criterion preservation | A flag-only update must send no criterion rows and must not silently repair or resend existing criteria. Malformed baseline-only IDs are disclosed separately, not transformed into outgoing data | Final flag-only update artifact | |
