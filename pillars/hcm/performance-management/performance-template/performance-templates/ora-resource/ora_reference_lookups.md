## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A caller supplies a create-only request | Use the describe lookup. At PT.READ_EXISTING_TEMPLATE record not_required without making a singleton request, then continue to dependency resolution. No template ID is required for a new root. |
| A caller supplies an update, delete, or child request | Read the existing template before evaluating lifecycle locks or dependent child state. |
| A caller asks which existing templates are suitable starting points or requests a comparison | Use the task-declared template list and exact-item read routes. For every shortlisted template, report its exact `DateFrom` and `DateTo`, status, template type, `InUseFlag`, `DocumentExistsFlag`, and `PeriodExistsFlag`, plus the material configuration differences actually read. State which requested child areas were not inspected; never replace exact dates or status with only a year, “current,” or another inference. |
| A comparison is requested before the user chooses a reference value | Report the resolved candidates and material differences, but keep the business choice unresolved. A target's current value, a comparator value, or an assistant recommendation is not user confirmation. In every later blueprint or preview, show the pending choice until the user explicitly selects a candidate; never silently promote evidence or a recommendation into a confirmed decision. |
| A supplied field has a documented resolver in this table | Run the resolver using its listed source values, request path, and exact match rule before treating the field as resolved. |
| A process flow or process-flow step is supplied | Always run `resolve_active_process_flow` before planning, preparing a CSV, or creating a payload. Do not use an FSM export, prior artifact, or display label as a substitute for the live result. |
| A lookup produces no match or more than one match | Stop and require a valid, unambiguous supplied value. |
| A related reference object is resolved for live execution | Use only the allowlisted route in `related_fixture_routes.json`; fetch all pages and validate exact identity, status, fixed eligibility values, and effectivity before reuse. Persist page bindings and response digests. |
| A related reference object is absent | Route Performance Template Sections and Performance Roles setup to their registered provider skills using fresh target Describe metadata. Treat all declared LOV resources as read-only and route other setup to its owning skill; never invent writable fields or an endpoint. Continue independent requests. |
