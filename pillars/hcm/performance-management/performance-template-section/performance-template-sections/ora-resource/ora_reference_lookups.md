## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A caller supplies derived meanings, in-use flags, or a less-common attribute | Resolve describe metadata before accepting the field in a request |
| A caller proposes update or delete | Resolve the exact section before a mutation path; do not infer target state from client input |
| A lookup result is unavailable or inconclusive | Stop and return the lookup failure to the task error handler; do not submit a mutation |
| A code, rating model, rating level, profile type section, or profile is supplied | Resolve it with its documented LOV route; never accept a display meaning in place of the required identifier or code |
| The rating-model lookup uses `{today-date}` | Replace the placeholder with the actual execution date in `YYYY-MM-DD` format, retaining the single quotes; for example, on 2026-08-21 use `q=DateFrom <= '2026-08-21'`. Never submit the literal words `today date`. |
| The synchronized-goals profile option is needed | Use core.fusion-api.apps-common.profile-options and its /fscmRestApi profileValues route to read the effective value. Do not substitute the configured profileOptions resource or a profile-value ID. |
| Person profile competencies are selected | Use core.fusion-api.apps-common.profile-options and its /fscmRestApi profileValues route; require the returned effective ProfileOptionValue to be Y. |
