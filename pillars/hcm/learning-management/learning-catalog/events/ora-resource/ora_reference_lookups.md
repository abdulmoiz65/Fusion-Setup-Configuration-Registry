# Events Reference Lookups

Use `{version}` for the target's current supported HCM REST version. All GET
calls in this file are read-only. `validateProviderUser` is a documented
validation-only POST action and never authorizes mutation of an instructor or
provider account. Follow server-returned links; never construct an opaque
event, activity, or provider-account hash.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Only a Draft is requested and activation-only details are omitted | Do not call unrelated instructor, classroom, supplier, or provider resolvers; record activation gaps |
| A Draft supplies a resource reference | Resolve and validate the supplied reference, but do not require schedule availability until an exact schedule window exists |
| A lifecycle mutation is requested | Run resolve_event_identity and resolve_event_lifecycle_values before preview; writable fields alone do not establish eligibility |
| A create or update mutation is requested | Run resolve_event_loader_registration before preview and execute the supported mutation through core.data-loader; do not substitute Direct REST automatically |
| Instructor returns hasFutureBookings as affirmative | Treat it as informational and use schedule-aware instructorAvailability for the exact requested window |
| Classroom returns a capacity | Compare it with planned demand in addition to requiring schedule-aware affirmative availability |
| Fixed meeting URL is selected | Validate the URL against the Event schema and do not invoke the provider-account resolver unless provider-backed delivery is selected |
| validateProviderUser payload or success shape is not supplied by an approved provider contract | Stop only the affected provider-backed row; do not invent object members or infer success from HTTP status alone |
| An ad hoc resource is requested | Stop only that row because current approved sources do not expose a global identity, inventory, or schedule-availability provider |
| One mixed-input row lookup fails | Preserve its blocker and continue read-only lookup work for unrelated rows |
| Lookup evidence changes after preview | Invalidate only affected approvals and rebuild those row previews |
