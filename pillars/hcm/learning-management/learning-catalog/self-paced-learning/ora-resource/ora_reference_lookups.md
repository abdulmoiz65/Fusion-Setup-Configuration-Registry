## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Mutation route selection | Require the exact Data Loader registration and selected operation before artifact preparation; absence never authorizes Direct REST fallback |
| Exact learning item number is known | Use findByLearningItemNumber and require exactly one returned item for an existing-item operation |
| Technical learning item ID is known | Use findByLearningItemId and require exactly one returned item |
| Item or child navigation | Follow the returned link; never manufacture the opaque item hash or child key |
| Create collision check | Exact number is authoritative duplicate evidence; exact title is advisory collision evidence only |
| Current-state fingerprint | Include normalized identity, last-modified value, lifecycle, visibility, profile, content, metrics, usage, action hints, and change-request state without claiming ETag or If-Match protection |
| Owner lookup | Use Worker or PublicWorker only for read-only identity resolution; identity does not prove business authorization |
| Language label | Resolve one installed active code at runtime and confirm payload serialization before preview |
| Objective or Ideal Learner | No lookup or REST mapping exists in the confirmed contract; keep generated values as preview-only metadata and capture omission acceptance |
| HCM list association write | Stop as unsupported when the association is absent from the learningSelfPacedItems schema |
| Evidence changes after preview | Mark the row stale, invalidate approval, and rebuild the preview |
