# Topics Dependency Readiness

## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Target, profile-option, and security readiness | Confirm the selected environment, shared REST root, every applicable profile option, conditional external CAP prerequisite, caller privilege and HCM data-role access, and exact operation capability |
| 2 | Topic identity and runtime values | Resolve Topic identity when existing and exact subtype, Active status, visibility, DFF, and lookup-backed values |
| 3 | Relationship and reference readiness | Resolve Categories, learning, people, criteria, skills, qualifications, media, related materials, and current child state |
| 4 | Graph, impact, and approval readiness | Preserve manager safety, prevent duplicate or cyclic edges, refresh impacts, and bind approval to the exact proposal |

## Dependency Classification

| Result Category | When Used | Can Run Lookup/Create? |
|---|---|---|
| Ready | Every applicable dependency is exact; already-correct options are recorded without dialog; approved profile changes and prerequisite readbacks are complete | Read-only lookups may run; mutation still requires exact approval |
| Child Blocked | A dependency applies to only one Category, learning, membership, skill, media, or moderation row | No for that row; unaffected valid parent and child rows may continue |
| Operation Blocked | A required parent, security, subtype, route, manager-safety, graph, or approval condition is unresolved | No for that operation |
| Not Required | A conditional dependency does not apply | No lookup is needed |
