# Topics Reference Lookups

Every call in this file is read-only. A lookup proves current identity,
availability, access, or capability; it never authorizes or performs a Topic
mutation. Follow returned item links rather than constructing opaque item keys.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A collection returns an item | Follow its returned item link and preserve the technical ID and number |
| A create or update mutation is requested | Run resolve_topic_loader_registration before preview and execute the supported mutation through core.data-loader; do not substitute Direct REST automatically |
| A title returns multiple accessible objects | Require explicit selection; do not treat title as unique |
| A requested route is not registered | Mark only that operation runtime-blocked; do not construct a payload from a similar child |
| A Category is supplied as catalog learning | Reject it; Category relationships use the Category/Topic flow |
| A Topic resolves to the parent itself | Reject the child row as self-reference |
| Lookup or relationship evidence changes after preview | Invalidate the affected approval and rebuild its proposal |
| A read succeeds but an operation-specific privilege is absent | Preserve read results and block the mutation |
| An applicable profile option is already correctly populated | Record it as satisfied and omit it from the user dialog |
| An applicable profile option needs a change | Show the exact code, trigger, Site scope, current/effective value, proposed value, and prerequisite evidence in the immutable approval payload; route only that approved change through the foundation capability and read it back |
| ORA_WLF_SINGLE_CATALOG_LISTING_REDWOOD needs Site Y | Block until applicable Catalog Administration Profiles are created or validated through their separate excluded scope; do not invent a CAP skill ID or perform CAP setup here |
| ORA_WLF_SS_CATALOG_SEARCH_MODE is applicable | Ask for broader recall, balanced matching, or tighter precision; preserve the current value without exact approval and test representative searches after an approved change |
