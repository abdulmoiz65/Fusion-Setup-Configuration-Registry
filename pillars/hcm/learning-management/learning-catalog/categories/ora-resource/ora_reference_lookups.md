# Categories Reference Lookups

All calls in this file are read-only. Follow returned links, use the current
target version, and never construct opaque item or child keys. A successful
lookup proves identity or capability only; it does not authorize a mutation.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A create or update mutation is requested | Run verify_category_dataloader_registration before preview and execute the supported mutation through core.data-loader; do not substitute Direct REST automatically |
| A collection returns an item | Follow its returned item and child links; never construct an opaque key |
| Title search finds similar Categories | Warn and show create-versus-update review; do not treat similarity as a uniqueness failure unless the service does |
| A title matches multiple accessible Categories or Topics | Require selection by number or ID; never choose the first result |
| A shared-endpoint result has a different subtype | Reject it for the requested Category or Topic role even if its title matches |
| A Topic already belongs to another Category | Allow the requested parent relationship if it does not already exist under this Category |
| A generic child advertises POST, PATCH, DELETE, or upsert | Treat the method as capability evidence only; require exact Category applicability, request schema, route registration, approval, and verification |
| An applicable profile option is already correctly populated | Record it as satisfied and omit it from the user dialog |
| An applicable profile option needs a change | Include its exact code, level, current and proposed values, trigger, prerequisite evidence, and business effect in the immutable approval payload; route through the governed profile-option provider and read back afterward |
| ORA_WLF_SINGLE_CATALOG_LISTING_REDWOOD is relevant | Require applicable CAPs first and verify intended category/catalog administrator access after Site Y; never implement CAP setup in this task |
| ORA_WLF_SS_CATALOG_SEARCH_MODE is relevant | Ask broader recall, balanced matching, or tighter precision; preserve current unless change is approved; test representative searches after readback |
| Membership criteria or groups are submitted | Report asynchronous and row-level state; never claim every person succeeded from the criteria/group row alone |
| Lookup or state evidence changes after preview | Invalidate only affected approvals and produce a new proposal version and fingerprint |
