# Common provider-backed reference lookups

Source: the selected Apps Common provider references and current Learning guidance
listed in ../references/taxonomy-and-sources.md. Fusion is the authority; no user
file or synthetic value establishes live state. appsCommonResourceRoot must be
resolved by the selected core provider, including its supported API version and
target identity. It is not a user-supplied URL or a new version default.
levelChildCollection is exactly siteProfileOptionValues, productProfileOptionValues
or userProfileOptionValues as selected by the profile provider. Validate and encode
identifiers through that provider. Read its SKILL.md and references first.
Requested Fields describes evidence to inspect in the provider response, not a
literal fields query. Confirm actual field names in provider metadata; never
serialize a prose label or guess an absent field. Missing required evidence
stops the affected lookup even when this static rule graph is complete.

Each lookup uses the declared provider only, after routed read preflight. No
mutation, login shortcut, export or browser action is authorized by these nodes.
The DFF local resolver assesses an approved provider artifact using
../references/dff-verification.md; export preparation is a separate handoff,
not a GET. Other unbound contracts remain blocking gaps.
