# Common input contract

Source: PM FDD GB-01–GB-09 and the existing Learning setup validation guidance.
These checks assess supplied request shape, not local authority for tenant data.
Only provider evidence from ora_reference_lookups.md can validate actual identity,
allowed values or current state. Missing business input prompts a focused question;
optional unknown decisions are Deferred and create no write.

Read-only review asks what exists; mutation asks to create or change it. Select
intent before applying Required Groups. Review needs only the target scope or
identity, never a proposed value, new lookup meaning or segment design. A broad
Learning inventory uses the documented candidate inventory rather than asking
the user to enumerate every code. Provider-resolved definitions and baseline
evidence are lookup outputs, not mandatory user inputs before the read.

Release/build is optional for every task. Omitted or unknown release does not
block intake, reads or proposals; validate feature support from authoritative
capability evidence. Do not infer the application release from the core REST
API version. Other identity, security and provider gates still apply.
