# Learning Audience Design Enforcement

Scope comes from the supplied Learning taxonomy, baseline and
learningOrganizations /describe response. Contract and execution boundaries
below apply the repository's workflow rules to those sources. No source
establishes local enforcement authority; any unresolved evaluation contract is
retained as TBD and blocks planning.

## Enforcement Order

| Task Code | Task Name | Sequence | Step | What Must Happen |
|---|---|---|---|---|
| CUSTOM_MANAGE_LEARNING_AUDIENCE_CRITERIA | Manage Learning Audience Criteria | 1 | Confirm product scope | Keep criteria setup in Learning Audience and shared filtered-list capability with HCM Tool |
| CUSTOM_MANAGE_LEARNING_AUDIENCE_CRITERIA | Manage Learning Audience Criteria | 2 | Confirm contract coverage | Require documented criteria-definition semantics; extracted-item storage is insufficient |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | 1 | Confirm product scope | Keep user-group setup in Learning Audience; access-group catalog setup belongs to Learning Catalog |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | 2 | Resolve operation identity | For existing-record work, resolve the exact parent and requested child. For new root POST, omit generated identifiers and do not demand an existing-parent lookup |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | 3 | Preserve relationship roles | Keep managerCriteria linked through ManagerRelationId and participantCriteria linked through ParticipantRelationId; never substitute the sibling relationship |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | 4 | Enforce the mutation route | Use a validated core.data-loader artifact by default. Permit only the documented, explicitly requested existing-parent criteria-create fallback after the Data Loader registration mismatch is proven; bind one separately approved collection POST to the exact composite parent key |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | 5 | Prevent duplicate criteria | Check resolved proposed rows within each parent and role; for existing parents also compare with live criteria. An update excludes its own criteriaId, not other matching rows |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | 6 | Confirm remaining contract coverage | Apply the conditional provider check from ora_dependency_readiness.md; direct-person criteria do not require filtered-list evidence. Keep applicable LOV codes, loader-specific effective-date semantics, privileges and reconciliation verification gates |

## Design Rules

| Task Code | Task Name | Applies When | Severity | Required Lookup | Blocking Condition | Recommendation | Fix Allowed? |
|---|---|---|---|---|---|---|---|
| CUSTOM_MANAGE_LEARNING_AUDIENCE_CRITERIA | Manage Learning Audience Criteria | Learning-item list creation is proposed | Error | resolve_learning_audience_criteria | Supplied request shape is known, but identity, create-conflict behavior, filter semantics or relationship to the shared provider is undocumented | Complete the semantic and identity contracts; retain creation intent rather than silently updating or upserting a matching list | No automatic correction |
| CUSTOM_MANAGE_LEARNING_AUDIENCE_CRITERIA | Manage Learning Audience Criteria | Cross-product policy is evaluated | Error | TBD | Authority and evaluation method for provider-specific filtering restrictions are unresolved | Obtain provider-owned policy and documented evaluation evidence | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | Creating a user group | Error |  | The create artifact supplies generated root identifiers or status, requires a pre-create identity lookup, or silently selects upsert | Omit learningOrganizationId, learningOrganizationNumber and status. Do not assert title uniqueness without a documented business-key contract; validate criteria within the request and capture server-returned parent identity after creation. Resolve uncertain previous submissions before considering a new POST | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | Updating, deleting, reconciling or reading children of a user group | Error | resolve_learning_user_group | The requested identifier does not resolve exactly one user group | Stop and require an unambiguous learningOrganizationId or learningOrganizationNumber | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | Creating or updating learningOrganizations, managerCriteria or participantCriteria | Error |  | A direct REST mutation is proposed outside the narrowly documented existing-parent criteria-create fallback, or the fallback lacks evidence of both Data Loader `Not Found` failures, exact composite parent resolution, duplicate validation, an exact payload preview or separate approval | Route ordinary mutations through core.data-loader. For the established registration-mismatch fallback, allow only a user-requested managerCriteria or participantCriteria collection POST through the core Fusion REST client after all fallback gates pass; PATCH requires an existing criteriaId and is not a create substitute | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | Manager criteria are supplied | Error |  | The criteria are placed under participantCriteria or mapped through ParticipantRelationId | Keep the row under managerCriteria and preserve the /describe relationship ManagerRelationId to RelationId | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | Participant criteria are supplied | Error |  | The criteria are placed under managerCriteria or mapped through ManagerRelationId | Keep the row under participantCriteria and preserve the /describe relationship ParticipantRelationId to RelationId | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | A participant person's supplied or selected input is Fusion Username | Error | resolve_participant_person_by_username | Username does not resolve exactly once to a non-null PersonId or the returned Username is not an exact case-insensitive match | Use the user-selected input branch, with no precedence or separate Username-versus-PersonId conflict checking. If both were independently supplied and the branch is unspecified, ask which to use. Show the resolved PersonId and ORA_PERSON in preview. If resolution fails, ask for corrected Username or an ID-only reference and resume | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | Creating or updating either criteria role under an existing parent | Error | check_duplicate_learning_user_group_criteria | Another criterion in the same exact parent and role has the final proposed sourceType/sourceId, or the duplicate read is incomplete; PATCH excludes only its own resolved criteriaId | Show existing criterion evidence and ask whether to skip/correct the proposed row. Do not silently create, update or upsert a duplicate; preserve independent work and revalidate after correction | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | Creating managerCriteria or participantCriteria under an existing effective-dated user group | Error | resolve_learning_user_group | The Data Loader registration mismatch has been demonstrated but another loader retry is proposed, or the direct-child fallback uses the numeric parent key, PATCH without criteriaId, a sibling child role, or an unapproved payload | Stop loader retries. If the user explicitly requests the fallback, retain the exact returned composite parent key and requested child role, re-run duplicate validation, preview one collection POST, and require separate approval | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | Updating or deleting an existing criterion | Error | resolve_learning_user_group_criteria | criteriaId does not resolve exactly once under the requested parent and exact child role | Resolve the criterion under managerCriteria or participantCriteria as requested; never fall back to the sibling collection | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | A request attempts to create managerPersonList or participantPersonList rows | Error |  | The /describe contract advertises collection GET but no collection create for either person-list resource | Keep criteria input in managerCriteria or participantCriteria; use person-list resources only through a separately documented workflow | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | Reconcile action is proposed | Error | resolve_learning_user_group | The group is unresolved, or the action request, ESS status mapping, timeout and verification contract remain TBD | Obtain the reconcile action request and monitoring contract before previewing an action call; do not infer it from the action name | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | Seeded-group or tenancy policy is evaluated | Error | TBD | Permitted modifications, authority and evaluation method are unresolved | Obtain service-owned policy; the storage columns alone do not specify allowed mutations | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | A person ID is the supplied or user-selected input | Error | validate_criteria_person_id | Malformed ID, returned identity mismatch or person identity cannot be verified | Notify the user and ask for a corrected ID, exact Username or missing authoritative evidence; never guess a replacement or equate access denial with nonexistence | No automatic correction |
| CUSTOM_MANAGE_USER_GROUPS | Manage User Groups | Multiple criteria rows are proposed for one parent | Error |  | Repeated create tuples in the same role, colliding final proposed source identities or conflicting changes to the same criteriaId | Ask which rows to skip/correct; preserve role boundaries and lossless sourceId values. New parents use this in-request check without requiring a nonexistent server key | No automatic correction |
