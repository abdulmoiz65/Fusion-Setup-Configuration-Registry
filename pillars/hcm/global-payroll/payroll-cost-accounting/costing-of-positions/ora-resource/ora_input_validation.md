## Dependency-Aware Validation

| Applies When | Result | Next Action | Resolver |
|---|---|---|---|
| Either Position Business Unit stage has multiple distinct or conflicting rows after identical projected repeats are coalesced | Blocked | Report the actual failing resolver and unresolved Position-bound Business Unit; stop HDL preparation without choosing by row order or asking for a second Position choice. | resolve_position_business_unit |
| The same positive PositionId repeats with conflicting requested fields | Blocked | Treat the positionsLov response as malformed and stop stage 1; do not present conflicting occurrences as selectable Positions. | resolve_position_business_unit |
| LDG LIKE discovery has multiple terminal candidates | Selection required | List the returned LegislativeDataGroupName values and request user selection; do not render a package until the selected Name is exactly confirmed. | resolve_legislative_data_group |
| A valid selected Position has no costing association | Continue | Preserve source identity and confirmed LDG context. Check date-specific absence before Create; do not reject empty allocation fields or manufacture an association. | query_position_costing |

Follow the sealed two-stage contract; do not report position absence, change the source/date, substitute caller values or use an alternate lookup. | resolve_position_business_unit |
| A list Query is complete | Continue without HDL dependencies | Skip Business Unit, templates, account metadata and history fan-out unless the requested Query actually needs them. | search_position_costing_records |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| End Date DAT shape | In the final CostAllocationV3.dat, require one parent METADATA and one matching MERGE, with ReplaceLastEffectiveEndDate exactly once as a METADATA attribute and Y in the corresponding MERGE column. Require equal column counts, the selected parent keys and dates, and the requested calendar EffectiveEndDate; reject #RETAIN, #ALL, and #NULL for that end date. Do not render account members. | End Date source validation before preview and handoff | |
| HDL SET instructions | Inspect every instruction in every final DAT member, not only METADATA headers. Reject every SET line for End Date. For other operations, accept only the exact SET command and arguments expressly required by this task's ora_defaulting_rules.md and ora_design_enforcement.md; reject unknown commands, aliases, unsupported arguments, and directives belonging to another operation before loading. | Every HDL source validation before preview and handoff | |
| Finder-safe input | Reject unsupported embedded finder delimiters such as double pipes, comma or semicolon rather than inventing grammar escaping. Preserve ordinary spaces, accents, apostrophes and leading zeros; encode parameters exactly once. | Position search criteria | search_position_costing_by_criteria |
| Source effective date | Before preparing HDL require the selected Position to exist by the explicit or defaulted search/as-of date; do not replace an explicit date with a captured or current date to obtain a result. | Every mutation | resolve_position_source |
| Position Business Unit binding | Require the final sealed context from both BU stages to agree with Main Search Position identity, selected date and environment, and the BusinessUnitId to agree between stages. Require nonblank BusinessUnitName. Keep Main Search Status; ActiveStatus is supplementary, HiringStatus and costing presence are distinct. Use the resolved name in existing HDL keys; reject BusinessUnitId or PositionId as alternative HDL keys. | Every HDL operation | resolve_position_business_unit |
| Complete GET state | Validate parent identity and each nested account/KFF collection. An HTTP error, missing collection or truncated response is never proof of absence. | Account Query, preflight or verification | query_position_costing |
| Segment code validation | Validate every supplied code against the complete runtime-declared LOV; preserve leading zeros and do not declare absence from the first page. | Account input or display | resolve_cost_account_segment_meanings |
| HDL account proportion | Accept a decimal fraction from 0 through 1 after one percentage conversion; total must not exceed 1. | Create or Update | |
| HDL account row arity | Require the same number of row values as METADATA columns. | Every account DAT member | |
| Account SourceType | Reject a supplied SourceType other than POS; never silently overwrite it. | Create or Update account row | |
| Account segment clear | Reject #NULL in Create, Update, Correct, and physical DELETE account segments. Correct also rejects blank and null target clear intent until a current template-validated HDL clear contract is documented. | Create, Update, Correct, or physical DELETE | |
| Required HDL key/text token | Reject literal #NULL in PositionCode, LegislativeDataGroupName, BusinessUnitName, SourceSubType, and every other required HDL text field. | Every parent or account DAT row | |
| HDL delimiters | Reject pipe characters and CR/LF in PositionCode, LDG, BusinessUnitName, SourceSubType, and every populated segment value. | Every account or parent DAT row | |
| Create loader initiation | Require the exact submitted Create archive to have a Content ID and Request ID. Return pending immediately; evaluate status only when the user explicitly requests it. | Create | |
| Update loader initiation | Require the exact submitted Update archive to have a Content ID and Request ID. Return pending immediately; evaluate status only when the user explicitly requests it. | Update | |
| Correct loader initiation | Require the exact submitted one-action Correct MERGE or child DELETE archive to have a Content ID and Request ID. Return pending immediately; evaluate status only when the user explicitly requests it. | Correct | |
| End Date loader initiation | Require the exact submitted End Date archive to have a Content ID and Request ID. Return pending immediately; evaluate status only when the user explicitly requests it. | End Date | |
| Zap loader initiation | Require the exact submitted Zap archive to have a Content ID and Request ID. Return pending immediately; evaluate status only when the user explicitly requests it. | Zap | |
| Mutation route | Reject POST, PATCH, PUT, DELETE, raw UCM, FSM, CX, and browser mutation attempts. | Every supported mutation | |
