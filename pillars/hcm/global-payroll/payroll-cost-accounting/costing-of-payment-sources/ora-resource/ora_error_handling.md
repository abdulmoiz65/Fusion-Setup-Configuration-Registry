# Costing of Payment Sources Search and HDL Error Handling

## Error Situations

| Situation | What Should Happen |
|---|---|
| Search needs a filter or selection | Return the applicable CPS.SEARCH terminal with the retained filters and one concise question for LDG, source-name text, date clarification or candidate selection. Do not request HDL keys, accounts or upload approval to run a search |
| Search returns no rows | Report no matches under the exact as-of/filter context. An empty Search is a valid result; an operation still has unresolved identity. Do not remove filters or infer permission to create |
| Incomplete, malformed or contradictory search response | Preserve sanitized resolver and field/count evidence. A payment-source hasMore=true result needs refinement; invalid envelopes or contradictory mapped data are catalog mismatch. Stop before choosing an HDL target |
| Organization method or source-parent association remains unresolved | Classify missing joined parent data, zero/multiple effective same-name LOV matches or incomplete evidence as catalog mismatch and stop through CPS.HDL.HANDLE_ERROR. Retain source/LDG/date and the sanitized resolver result. Do not ask the user to confirm or select a parent to substitute for relationship evidence; correct the data/lookup issue and rerun the declared reads |
| Organization method conflicts with an explicit selector | Classify as catalog mismatch or input validation as appropriate. Preserve the conflicting field names and sanitized evidence; never overwrite an explicit code/ID, cross LDGs, change the as-of date or reinterpret ResultValue14 to force a match |
| Latest resource endpoint fails or the target environment is invalid | Classify the sanitized response as transport/environment, auth/authz or Fusion API as appropriate and name the affected resource. Use only the declared /hcmRestApi/resources/latest/ path against the active restBaseUrl; never fall back to an rv route or request a browser route identifier |
| Search transport/authentication failure | Use the core client's declared authentication handling and active session controls. Stop after its allowed recovery; never replay captured browser credentials, suppress TLS verification, or turn this into a loader retry |
| Input validation failure | Classify as input validation, identify the missing payment-source identity, date, CostInfoV3 value, account value, or operation, and stop before archive creation. |
| Account role/subtype or proportion violates fixed defaults | Classify as input validation and identify the account role, offending field and required value from ora_defaulting_rules.md. Stop before archive preparation; do not silently replace the input, convert its proportion, request approval for an exception or make a Fusion call to resolve a fixed literal. Omitted defaultable fields alone are not an error |
| Required payment account is missing or Payroll reports PAY_COSDF_NO_CLRNG_ACCT / PAY_COSDF_PYMNT_AC_DEF | Apply Required payment accounts in ora_input_validation.md and identify the affected role and flag context. A missing planned account is input validation; an actual loader rejection retains its sanitized process-failed diagnostic and partial outcomes. Do not mislabel these account-presence checks as a GL/Cash Management mismatch or retry an import automatically |
| Full Flexfield structure or lookup contract is missing, mismatched or incomplete | Classify as catalog mismatch, auth/authz or transport/environment as applicable. Identify the LDG structure, descriptor or declared LOV stage without exposing credentials. Stop account preparation; do not invent segment order/delimiter/binds, use a different route, or ask the user to certify the missing evidence |
| Full Flexfield account has an unknown/missing component, invalid value, non-unique LOV match or conflicting concatenation | Classify as input validation when the supplied value is invalid, otherwise catalog mismatch for an unusable lookup contract. Report the account role and runtime segment title with a concise correction. Keep valid inputs; request only the missing/corrected business value and rerun the affected validation before a new preview |
| Full Flexfield HDL row populates Segment columns or lacks a validated complete ConcatenatedSegment | Classify as input validation and stop archive preparation. Re-render from validated_full_kff_accounts under Full Flexfield Contract; do not submit a partial account, change requested values, or replace validation with approval |
| CostInfoV3 flag value, alias or coverage is invalid | Classify as input validation, identify the business checkbox and mapped attribute from ora_input_validation.md, and stop before archive preparation. Ask only for a conflicting or missing required choice; do not ask the user to supply a mapping or metadata attachment |
| A runtime need exceeds the packaged lookup or HDL contract | Report the precise unsupported field/operation as an authoring maintenance gap and stop that operation. Preserve any valid search results. Do not ask the runtime user for reference captures or metadata exports, guess a mapping, or bypass the governed route |
| Update state or delta conflict | Stop before preview on a missing/ambiguous containing interval, duplicate account role, misaligned CostInfo, invalid old-value precondition, malformed Account or incomplete history/detail. Classify bad supplied data as input validation and broken/mismatched live contracts as catalog mismatch. Do not ask the user to certify the missing evidence or silently turn Update into Create, Correct or Zap |
| Update freshness or verification mismatch | Changed preapproval state invalidates preparation. After submission, report the exact changed account, flag or period plus component outcomes; preserve partial successes and stop without replay. Terminal loader success with mismatched read-back is not verified Update success |
| Update pending or approval resume | Accepted initiation returns pending without automatic polling. An explicit status request resumes CPS.UPDATE.RESULT for the saved run, not the upload gate. Contextual approval resumes CPS.HDL.GATE_UPDATE with the same preflight, Task Hook preview and immutable archive; use approve-data-load-preview and verify-approved-data-load-archive, retain the returned taskValidationEnvelope unchanged and submit once through core.data-loader |
| End Date missing/invalid dates or non-last target | Classify as input validation; ask only for a missing business date/selector or identify the conflicting interval. The target start is not an end-date default. Stop rather than extend history, select another period or turn this into Update/Zap |
| End Date component capability or shared-validator rejection | Classify as catalog mismatch and report the exact sanitized component error. Retain the combined archive contract; missing special-attribute template membership alone does not establish unsupported Oracle behavior. Missing capability evidence for either component blocks automated handoff. Do not modify the shared loader, remove ReplaceLastEffectiveEndDate, substitute SET or claim a rejected validation passed |
| End Date partial result, freshness or verification failure | Report CostInfoV3 and CostAllocationV3 outcomes from the same accepted run separately. Success of only one object is partial failure, not completed End Date or authorization for a second import. Preserve the original baseline, artifact and per-object results. Reconcile the existing run through core.data-loader and stop with sanitized diagnostics; do not automatically replay the archive, resend successful objects, split the operation or roll back. A new attempt requires resolved failure, proven scope and fresh approval |
| End Date pending or approval resume | Accepted initiation returns pending without polling. Explicit status resumes CPS.END_DATE.RESULT for the same combined run. Contextual approval resumes CPS.END_DATE.GATE with the matching persisted preflight, combined archive and Task Hook preview; invoke approve/verify and submit exact bytes once through core.data-loader. Status-only cannot prepare or submit another import |
| Correct requested | Classify as input validation because Correct is unsupported by this source-backed HDL contract. Stop before archive creation; do not invoke or require a REST write, REST failure, reconciled-failure flag, or fallback approval. |
| Current template rejects the discriminator, metadata header, or identity | Classify as catalog mismatch and stop. Do not infer a replacement header, GUID, source key, segment, or execution route. |
| Archive validation or Task Hook validation fails | Classify as artifact persistence or process failed as appropriate; preserve only sanitized diagnostic facts and stop. |
| Approval is absent, stale, or mismatched | Classify as approval blocker and request approval for the exact immutable archive. |
| Authentication, authorization, transport, or Fusion failure | Classify the failure, retain redacted evidence, and stop. Do not retry an import automatically. |
| Import timeout or ambiguous initiation | Classify as process timeout or transport or environment; do not resubmit until the declared status workflow establishes a safe next action. |
| Zap history/detail mismatch | Classify as catalog mismatch for dates, IDs, missing expansions, incomplete pages or unselected shared CostInfo. Stop before preparing an incomplete deletion; do not turn missing evidence into an empty account set |
| Zap contract validation failure | Classify as catalog mismatch or approval blocker as appropriate. Use the authored, execution-validated CostInfoId plus child PaymentMethodId DELETE contract; current metadata or identity mismatch still blocks. Do not fall back to the old CostInfoId-only header, hidden SourceId, alternate live deletion keys or suppressed validation |
| Zap freshness change | Invalidate the immutable archive and approval. Refresh the complete baseline and repeat preparation before requesting a new loader approval; do not patch approved bytes silently |
| Zap accepted or pending | Return the accepted Content ID/Request ID or safe resume reference and explain that submission is not completion. Do not automatically poll, verify or resubmit; on an explicit follow-up resume CPS.ZAP.RESULT for that run |
| Zap partial or uncertain result | Report component-level outcomes and sanitized diagnostics; preserve successful portions. Stop without replaying the archive. For the known PM resolver failure, follow PM CostInfo-Only Recovery and the published PaymentMethodId mapping, not a hidden SourceId column. A retry requires read-only reconciliation and explicit approval for a new remaining-target artifact |
| Zap verification fails | Distinguish an API error, retained costing, missing source and unsupported independent orphan checking. None is verified success; retain the saved scope and one safe next action |

## PM CostInfo Resolver Failure

| Situation | What Should Happen |
|---|---|
| PM CostInfo DELETE fails with voAttrDef null / getName | The source-backed failure mechanism is missing internal SourceId triggering name resolution even with CostInfoId. The PM name resolver supplies ParentOrgPayMethodId to a helper VO that does not expose it. Do not conclude that CostInfoId is invalid |
| Supported indirect identity | Published PaymentMethodId supplies the child OrgPaymentMethodId inside the PM SourceId helper and bypasses that name-resolution branch. The loader still enters the helper because internal SourceId is initially null. Do not add hidden SourceId to HDL or substitute the parent's OrganizationPaymentMethodId |
| Recovery boundary | The CostInfoId plus child PaymentMethodId PM DELETE has succeeded through core.data-loader, with the targeted CostInfo no longer returned, allocation history/detail absent and the source preserved. This confirms the packaged mapping, not a guarantee for other targets or releases. Still require current template and governed child-identity checks, preserved partial successes, reconciliation and fresh approval of only the remaining targets |

## PM End Date Loader Failure

| Situation | What Should Happen |
|---|---|
| CostInfo says a costing flag is required on an existing PM record | The non-DELETE validation checks the logical row, not a reliable fallback to persisted flags. The word create does not prove insertion. The CostInfoV3 member must carry all four unchanged live flags as Y/N; CostableType stays omitted |
| CostAllocation fails with Map.get returning null before toString | The reported failure involves the proposed-date CostInfo lookup and a staging fallback with incompatible legacy/V3 attribute mappings. Preserve this diagnostic and the exact sanitized component result. Including the preserved flags is required but does not prove the fallback defect is fixed. Keep the requested combined-load contract; stop for diagnosis if it fails instead of imposing a prior CostInfo-only load, changing physical IDs or asserting success |
| Shared loader rejects ReplaceLastEffectiveEndDate as unknown | Distinguish the local template allowlist from Oracle special-attribute support. If core.data-loader accepts only ordinary template attributes, confirmed component capability alone cannot pass its validator. Stop automated submission and report the shared-loader limitation without modifying core, editing templates, removing the attribute or suppressing validation. If the user explicitly requests only a ZIP for manual testing, disclose local structural checks separately from the unmet loader validation; artifact delivery is not permission to upload or proof of success |

## Error Classifications

| Result Category | When Used | Next Action |
|---|---|---|
| input validation | Required operation, identity, date, or account data is invalid or absent. | Correct the supplied source and repeat validation. |
| catalog mismatch | The current loader template conflicts with the authored discriminator contract. | Reconcile against the current approved template. |
| approval blocker | The immutable archive lacks current approval. | Present the exact preview and obtain approval. |
| auth or authz | Authentication or privilege validation fails. | Resolve access without retrying the import. |
| transport or environment | Connectivity or environment identity fails. | Correct the environment issue and revalidate. |
| Fusion API or process failed | The shared loader rejects or fails the approved import. | Preserve sanitized diagnostics and follow the status workflow. |
| process timeout | The initiated import has no final status within the declared wait. | Stop and use the approved status-check path. |
| artifact persistence | The immutable source or validation artifact cannot be safely prepared. | Stop before handoff. |

## Disclosure Rules

| Gate | What Must Be Shown |
|---|---|
| Search result | As-of date, applied business filters, candidate names and the distinguishing LDG/type/parent. Distinguish a complete result, no matches, and an incomplete list; include missing HDL mappings only when relevant to a requested operation |
| Search selected but HDL input is incomplete | State which display fields and identifiers were resolved, then identify only missing business codes, account detail, required flag choices or write dates. The four checkbox mappings are already embedded; do not list them as missing or request authoring attachments. Distinguish an unsupported automatic lookup from missing user data; do not claim the source is load-ready |
| Organization method code resolved | Report the documented method code and context when requested, with joined_parent_name_plus_unique_lov provenance. Distinguish automatic relationship resolution from reading a numeric parent ID on the source: that ID was resolved by the LOV. State when PaymentSourceCode is still absent; do not request confirmation of the resolved association |
| Archive preview | Target environment, Create, Update, End Date or Zap operation, source identity summary, immutable archive fingerprint, expected effect, and approval requirement. |
| Update preview | Show the new start and observed end, old/new account components or flags, unchanged carry-forward accounts/options, prior-period preservation and any later periods left intact. Include all DAT members and counts, loader preflight and exact-byte Task Hook preview before asking once for approval. A prepare/validate-only request receives validation output without an approval prompt or upload |
| Update completion | Distinguish prepared, awaiting approval, initiated, pending, failed, no change and verified. Claim completed Update only after terminal success of every submitted row plus the saved-baseline split and unchanged-scope checks |
| End Date preview | Show environment, source/LDG, selected start S, observed end E and inclusive requested end F. List CostInfoV3.dat and CostAllocationV3.dat together, one MERGE each, retained CostInfo flags and unchanged accounts/prior history. Show the combined immutable artifact and one loader approval. Do not request separate object approvals or imply atomic processing from a single ZIP |
| End Date completion | Distinguish prepared, awaiting approval, initiated/pending, failed/partial, verified no change and verified closure. Completion requires both objects in the same accepted load to succeed and aligned read-back at S/F, next-day absence and preserved prior scope. A valid ZIP, expected success or one object's success is not completed End Date |
| Full Flexfield validation | Report the verified LDG structure, runtime segment mapping and component-value results. State the failing account role and segment title when correction is needed. Respect the task validation scope in ora_design_enforcement.md; do not claim completed configuration or guaranteed later accounting from a successful LOV lookup |
| Unsupported Correct | State that this task lacks a source-backed HDL Correct contract and that no REST fallback or prior REST failure is permitted. |
| Failure | Failure class, stage, sanitized message, safe artifact reference when available, and one next action. |
| Handoff | That core.data-loader received the approved archive; do not claim completed configuration before the loader reports it. |
| Zap preview | Only after load-request preparation is complete: exact environment, selected source/LDG, full historical interval scope, counts for each component, immutable archive fingerprint and explicit destructive effect on costing only. A validation-only request instead receives the loader validation report without an approval prompt |
| Zap completed | All included loader components succeeded; saved-scope history/detail checks and source-preservation search passed. State that CostInfo confirmation combines its explicit loader result with nested read-back, not an independent orphan query |

## Refusal Rules

| Situation | What Must Not Happen |
|---|---|
| Search replay | Do not execute telemetry POST /trace, replay browser headers, use Code or @context.key as a unique payment-source key, or perform an HDL upload for Search |
| Execution route | Do not use direct REST, Generic Costing, ADF REST Business Objects, browser replay, a direct Business Objects route, or a raw upload/import call to mutate. A documented task-local REST GET remains read-only evidence only. |
| Unsupported Correct | Do not satisfy Correct with a REST write, a required REST failure, a reconciled-failure flag, or fallback approval. |
| Identity and template | Do not invent a header, GUID, source key, account subtype, account segment, percentage, or a sequence outside the documented consecutive default. |
| Mutation | Do not submit an archive without current validation and fresh approval. |
| Failure | Do not replay an uncertain loader submission or make an undocumented substitute call. |
| Zap replay | Never rely on cascade, delete the payment source or parent method, convert to a REST DELETE, replay an uncertain import, or treat metadata alone as certified DELETE capability |
