# Costing of Payment Sources Search Lookups

Use the search contracts, response mappings and Payment Source Identity rules
below with `<host>/hcmRestApi/resources/latest/<rest>`. The Full Flexfield runtime
descriptor uses the explicit applcoreApi path below; segment LOVs use only its
declared service contracts through the governed client. Browser `rv` routes are
not supported. Search resolves candidates; Create/Update preparation additionally
requires source and parent codes, write dates and account data. Zap uses its
identity-only contracts; CostInfo-only recovery does not require those codes.
End Date submits CostInfoV3 and CostAllocationV3 together in one HDL archive and
one load request. It accepts no account edits and preserves flags from live evidence.

Public resource documentation:
[Organization Payment Methods LOV GET](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-organizationpaymentmethodslov-get.html)
and [Payroll Generic LOV GET](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-payrollgenericlov-get.html).
Use the task-specific finder parameters and mappings defined here.

## Full Flexfield Contract

CASH, CLRNG and LBLTY are Full Flexfield accounts. This contract validates their
component values and HDL representation; it does not add a Partial Key Flexfield
account branch, a GL combination-existence check, or a costing-hierarchy check.

| Situation | What Happens |
|---|---|
| Applicability | Run the three Full Flexfield resolvers for Create account values and every account carried into an effective-dated Update snapshot, including a flags-only Update. If Update has a proven empty resulting account set and effective flags permit it, record skipped at these nodes without GETs. End Date preserves accounts without rendering or revalidating their components and skips these nodes. Plain Search and identity-only Zap, including CostInfo-only recovery, never enter these nodes |
| LDG structure | Resolve CostAllocationIdFlexNumber from the exact LDG. Preserve it as a string and bind the descriptor to that LDG/environment. Search ResultValue19 alone is not sufficient metadata and is never CostAllocationId |
| Runtime descriptor | Keep the presented API field, title, sequence, segmentColumnName and complete declared LOV contract for each presented segment. Require unique API fields, segment columns and sequence positions; titles used to resolve labels must be unambiguous. Preserve the returned delimiter and discriminator; do not hardcode six segments, Segment1 order, titles, value sets or a hyphen delimiter |
| Technical descriptor versus account type | CostAllocationAccountsVO#CostPartialKff is the runtime describe selector for obtaining segment metadata. It does not authorize partial account values or populated Segment columns in a CASH, CLRNG or LBLTY HDL row |
| Component input | Match a supplied business label to one runtime title, or an explicit field to its exact runtime API field/segmentColumnName. Unknown, duplicate or conflicting assignments block. Keep codes as strings, including leading zeroes. Do not substitute a LOV display description for its value field |
| Complete account input | Decompose a supplied ConcatenatedSegment using the runtime delimiter and sequence. Require one nonblank value for every presented segment, no missing or extra components, and an unambiguous representation. When components and ConcatenatedSegment are both supplied, require exact agreement after descriptor-based mapping; never silently choose one |
| Partial business change in Update | Decompose each stored Account from update_existing_accounts with the bound runtime delimiter and sequence. Null Segment columns or an empty CostPartialKff display do not make a nonblank full Account absent. Map requested component labels to runtime titles, compare any supplied old value exactly, then overlay only the requested new values. Retain every other component and account. A whole-account replacement must agree with any simultaneously supplied components. This produces a complete full account, never a Partial Key Flexfield row |
| Segment validation | For every component, apply the descriptor's declared constraints and, when a LOV is declared, call its exact serviceRef with its declared finder/binds, value field and display fields. Resolve contextual/dependent binds only from this descriptor and the bound account/LDG inputs; missing bindings block, never guess. A segment with no declared LOV uses only its declared constraints; do not invent a lookup or claim LOV validation for it |
| LOV completeness | Consume a complete returned collection, following only the declared continuation/paging contract. Require exactly one item whose value field equals the selected code. No match, multiple exact matches, a missing value field, unknown continuation or a partial response blocks. A contains/display-name match is not an exact code match |
| Governed transport | Use core.fusion-api.rest-api-client GET only for the descriptor and each LOV, with REST-Framework-Version: 9 and Accept-Language: en. Resolve serviceRef only on the configured Fusion HTTPS host via the governed client; reject browser rv paths, unexpected hosts or an incomplete service contract. Do not copy credentials or replay browser headers |
| HDL representation | After validation, join each account's exact component codes in runtime sequence with runtime_delimiter into one complete ConcatenatedSegment. Omit runtime Segment columns from the account METADATA where permitted; if present in the validated template/header, leave every Segment value empty. Verify column/value alignment and ConcatenatedSegment against the live CostAllocationAccountV3 template. Preserve the task's role, Proportion and SubTypeSequence defaults |
| HDL field encoding | Keep the validated full account unescaped in task state. For DAT serialization, escape literal backslashes and prefix each literal HDL pipe inside ConcatenatedSegment with a backslash, exactly once; do not escape the actual HDL column separators. Validate METADATA/value counts with HDL-aware parsing, not a raw pipe split. Decode for comparison with REST Account. An unsupported or rejected encoding blocks archive preparation; never change the runtime delimiter or account values to bypass it |
| Evidence and reuse | Retain the resolved LDG/structure, descriptor and LOV outcomes with the normalized account values for the current preapproval artifact. A later approval of an intact persisted artifact follows core.data-loader integrity checks, not new GETs |
| Validation boundary | A passed Full Flexfield check establishes the LDG structure binding, presented segment mapping and component validity under the declared metadata/LOVs. It does not establish a GL combination or guarantee later accounting results. Apply the task validation scope in ora_design_enforcement.md; these evidence limits are not additional lookup requirements |

## Payment-Source Finder Contract

The following is decoded query text, not an HTTP body. Substitute data values,
then pass each query parameter separately to the core client for one URL-encoding
pass. Double pipes separate finder slots; single pipes separate LDG IDs.

```text
findByWord;AdditionalViewCriteria={criteria},ParameterKeys={keys},ParameterValues={values},PayRestName=PaymentSourcesSearchVO,DisplayAttributes=PaymentTypeId||PaymentTypeName||PartyName||Name||CostEffectiveStartDates||CostEffectiveEndDate||CostedFlagValue||CostClearedPaymentValue||TransferToGlFlagValue||CostManualPaymentValue||CostingExists||OrgPaymentMethodName||LegislativeDataGroupId||OrgPaymentMethodId||PaymentMethodEffectiveStartDate||PaymentMethodEffectiveEndDate||CostInfoId||ParentOrganizationName||CostAllocationIdFlexNum
```

| Position | Parameter key | Value | User-facing meaning / evidence |
|---|---|---|---|
| 1 | pCostClearedPayment | all | Neutral search control; not the requested HDL flag |
| 2 | pCostedFlag | all | Neutral search control; distinct from existence of costing |
| 3 | pCostingFilter | all, with_costing, or without_costing | Both states / With Costing / Without Costing |
| 4 | pCostManualPayment | all | Neutral search control |
| 5 | pEffectiveDate | {search_as_of_date} | Effective As Of Date, YYYY-MM-DD; not a write effective date |
| 6 | pLegislativeDataGroup | % | Retain this wildcard even when the LDG ID criterion is present |
| 7 | pPaymentTypeName | % or {payment_type_name} | No type restriction, or exact supplied display name |
| 8 | pSearchStr | {search_text} | Payment Source Name search text; the search also matches LDG names, so treat it as candidate discovery rather than exact identity |
| 9 | pTransferToGLFlag | all | Neutral search control; not the requested HDL flag |
| 10 | Empty when no LDG is selected; otherwise pLegislativeDataGroupIds | Empty when no LDG is selected; otherwise {id1}&#124;{id2}&#124; | One or more explicitly selected LDGs. Preserve the trailing single pipe after the last ID |

| Reserved characters | The finder contract does not support a supplied pipe, comma, semicolon, equals sign, control character, or percent-encoded delimiter. ## Response Mapping

Map from the requested DisplayAttributes order, never from JSON property order
or from the lexicographically ordered fields parameter. Keep all IDs as exact
strings and preserve empty values, including absent costing details. The table
below applies only to the full 19-attribute projection above. Request the matching
ResultKey1 through ResultKey19 as well as ResultValue1 through ResultValue19 and
require ResultKeyN to equal the requested DisplayAttributes name at position N.
Fail closed on missing, duplicated or mismatched keys; never assume position 14
identifies the child when a different projection is used. JSON integer IDs must
be converted losslessly to decimal strings, never through floating point.

## Organization Payment Method Code Contract

PaymentSourcesSearchVO joins the child source to its parent using
child.PARENT_ORG_PAY_METHOD_ID = parent.ORG_PAYMENT_METHOD_ID and projects the
parent's ORG_PAYMENT_METHOD_NAME as ParentOrganizationName. This is relationship
evidence, not a guessed name. The public LOV resolves that joined name to one
effective parent code/ID in the same LDG. Together these reads establish the
association without asking the user to confirm it. The source search does not
expose ParentOrgPayMethodId; never claim to have read that column through REST.
Neither read supplies the child's BaseOrgPayMethodName; keep Payment Source
Identity separate from the parent's code resolution.

|---|---|---|
| effectiveDate | {search_as_of_date} | Use the same YYYY-MM-DD date as the selected source, not a hard-coded example date or today's date when the search used a historical date |

If the name cannot be safely represented, use the complete LDG-only result and compare the exact name in memory under Literal safety. Do not add supplied code/ID/type predicates that could hide another effective parent with the same name; check those constraints only after proving uniqueness. Never substitute the child name or ID |
