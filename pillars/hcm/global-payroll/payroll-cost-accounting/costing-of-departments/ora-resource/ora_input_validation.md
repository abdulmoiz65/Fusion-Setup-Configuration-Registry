# Department Costing Input Validation

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Department Costing search | Effective date; literal search text or percent wildcard; optional LDG IDs, Department Set IDs, LocationName, costing filter, and Active control | Blocked | Use the documented DepartmentCostSearchVO finder. Keep criteria in captured order and resolve names to IDs before LDG or Set filters. | Department list, source resolution, or Create pre-check | search_department_costing |
| Department filter options | Filter paging context and, where applicable, typed filter text | Blocked | Retrieve LDG, Department Set, or status options from their documented read-only LOVs. Preserve returned identifiers; never derive an ID from a display value. | A user opens or changes a Department search filter | list_department_search_ldgs |
| Department identity | DepartmentName and enough Department Set or Location context to select one result | Blocked | Resolve one exact DepartmentCostSearchVO row. | Create, Update, End Date, Zap, or verification | resolve_department_source |
| Legislative Data Group | LegislativeDataGroupName text or LegislativeDataGroupId | Blocked | Use user text for LIKE discovery, exactly confirm the selected returned Name, and retain only that canonical Name for HDL. | Create, Update, End Date, Zap, or verification | resolve_legislative_data_group |
| Effective date | EffectiveStartDate in YYYY-MM-DD or YYYY/MM/DD | Blocked | Normalize once and render HDL dates as YYYY/MM/DD. | Create, Update, End Date, or Zap | |
| End Date request | Department selector, LDG selector, explicit target EffectiveStartDate, and a separate requested EffectiveEndDate | Blocked | Before authentication or live lookups, request only missing business values. | Zap request | Zap or Delete Record And History; Department selector, LDG selector, and target EffectiveStartDate | Blocked | Normalize Delete Record And History to Zap. | Account distribution | At least one account with SourceSubType and Proportion; each COST account with populated individual runtime Segment values and an empty ConcatenatedSegment; each SUSP or DFLT account with one complete ConcatenatedSegment and empty runtime Segment columns | Blocked | Validate the current KFF descriptor. Ignore a supplied SubTypeSequence, assign 1 to the first supplied account row, and increase by 1 for each following row. | Create or effective-dated Update | resolve_runtime_costing_kff |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Department search finder | Require the documented DepartmentCostSearchVO parameters and captured criteria order. pCostingFilter is all, with_costing, or without_costing. | Any Department search | search_department_costing |
| Active control | When Active is requested, retain only the documented ResultValue8 = A control. Do not infer status from allocation data. | Active Department list | search_department_costing |
| Search continuation | Do not make an exact source decision from a page with hasMore=true. Continue through the documented route or narrow the search and stop. | Department source resolution | search_department_costing |
| Create absence | Require zero matching Generic Costing parents for the resolved Department, LDG, and effective date. | Create | query_department_costing |
| Update state | Require one exact current allocation and validate the requested effective start date against its current history. | Update | query_department_costing |
| Department HDL keys | Render only ORG, DepartmentName, LegislativeDataGroupName, EffectiveDate, SourceSubType, Proportion, SubTypeSequence, ConcatenatedSegment, and runtime Segment columns in the official order. Do not use OrganizationId, SourceId, DepartmentCode, DepartmentSetCode, or LocationId as HDL keys. | Create or Update | resolve_department_source |
| Account rendering by subtype | Render each COST row using only individual runtime Segment1 through SegmentN values and leave ConcatenatedSegment empty. Render each SUSP and DFLT row using only one complete validated ConcatenatedSegment in runtime segment order with the runtime delimiter and leave every runtime Segment column empty. Block HDL rows that violate this subtype-specific representation. | Create or Update | resolve_runtime_costing_kff |
| Account totals | Each source subtype must have a fractional total from 0 through 1. SUSP and DFLT each allow one row only and must use Proportion 1. | Create or Update | |
| End Date DAT shape | Require exactly one CostAllocationV3.dat member, one METADATA and one MERGE row with equal column counts. Columns after CostAllocationV3 are EffectiveEndDate, EffectiveStartDate, SourceType, DepartmentName, LegislativeDataGroupName, ReplaceLastEffectiveEndDate, in that order. Bind the MERGE to the selected parent start, requested inclusive end date, ORG, and resolved Department/LDG names; ReplaceLastEffectiveEndDate must occur exactly once with value Y. Reject blank end dates and #RETAIN, #ALL, or #NULL tokens. Exclude account members, DELETE rows, and every SET instruction, including SET PURGE_FUTURE_CHANGES N and SET REPLACE_LAST_EFFECTIVE_END_DATE. | End Date source validation before preview and handoff | |
| Zap parent DAT shape | CostAllocationV3.dat contains one METADATA and exactly one DELETE row, with columns EffectiveEndDate, EffectiveStartDate, SourceType, DepartmentName, LegislativeDataGroupName in that order. Use the latest end and earliest start of the selected logical history, ORG, and the resolved names. Both dates are required for this user-key DELETE; do not default an end-dated record to 4712/12/31. | Zap source validation | |
| Zap account DAT shape | Include CostAllocationAccountV3.dat only when zap_history_accounts is nonempty. Require one METADATA and one DELETE per distinct resolved physical account, using CostAllocAccountId, CostAllocationRecordId, EffectiveDate, SourceType, DepartmentName, LegislativeDataGroupName, SourceSubType in that order and the bound read values. Confirm these columns against the current Data Loader template. Identity-only DELETE rows omit Proportion, SubTypeSequence, ConcatenatedSegment, and all Segment columns; never generate account values or a replacement sequence. Parent-only requires zap_no_children_proven. | Zap source validation | query_department_costing_history_accounts |
| Zap archive shape | Require only the parent DAT and the conditional account DAT, matching METADATA/DELETE column counts, unique headers, and dates in YYYY/MM/DD. Reject MERGE, SET instructions, ReplaceLastEffectiveEndDate, and date tokens. Account DELETE targets must exactly cover the resolved child set. | Zap source validation before preview and handoff | |
| Create loader result | Require the exact submitted Create archive to have a Content ID, Request ID, and terminal successful core.data-loader result before verification GET. | Create | |
| Update loader result | Require the exact submitted Update archive to have a Content ID, Request ID, and terminal successful core.data-loader result before verification GET. | Update | |
| End Date or Zap loader result | Require the exact submitted archive's Content ID and Request ID. Return pending on accepted initiation; only an explicit user status/verification request resumes that same handoff, with terminal success required for every included business object before verification GETs. | End Date or Zap | |
| REST write request | Reject POST, PATCH, PUT, and DELETE as task mutation routes. | Any mutation request | |
