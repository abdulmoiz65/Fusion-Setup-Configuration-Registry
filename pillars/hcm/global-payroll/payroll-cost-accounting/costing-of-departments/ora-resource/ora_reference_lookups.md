## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| REST transport | Use core.fusion-api.rest-api-client with GET only. REST POST, PATCH, PUT, DELETE, ADF REST business-object mutation, browser replay, and raw import routes are not task routes. |
| Department finder | Build the literal DepartmentCostSearchVO finder before percent encoding. Join criteria, parameter keys, and parameter values with double pipes; join multi-select LDG and Department Set values with a single pipe inside their parameter. |
| Derived SourceId | Before a Generic Costing or history GET, require the selected Department result to have Code equal to ResultValue1. SourceId equals OrganizationId equals ResultValue1; related ResultValue4 LocationId is never the Department Costing source. |
| Allocation presence | Department search CostAllocationId, status, and costing filters are discovery fields only. Resolve exact source and LDG, then use Generic Costing GET to establish parent allocation and account state. |
| Generic Costing Proportion | For Create and effective-dated Update comparison or terminal verification only, require a returned numeric percent from 0 through 100 and divide it by 100 once before comparing it with the fractional HDL `Proportion`. Do not apply this normalization to another operation. |
| Pagination | Use returned paging facts for Department search, LDG, and Set continuations. Exact source resolution requires a terminal complete result set; otherwise narrow the supported filters and stop. |
| Verification | Compare the loaded Department identity, effective date, source subtype, account count, and proportions through the matching read-only GET only after the terminal successful Data Loader result. |
| End Date verification | On an explicit status or verification request after terminal loader success, use query_department_costing_history to confirm that only the selected last parent's end date changed and prior intervals remain intact. Use query_department_costing at the requested end date to confirm the same start date and unchanged COST, SUSP, and DFLT account values/counts, then at the next calendar day to require absence. Compare returned proportions directly; End Date does not render or normalize accounts. |
| Zap verification | On an explicit status/verification request after terminal loader success, reuse the saved Department/LDG context and pre-load history keys. Repeat query_department_costing_history and require the targeted CostAllocationId to be absent from every page. Repeat query_department_costing at each captured historical start and require zero parents and no account expansion. Do not require the deleted record to resolve again before verification. Missing or failed reads are not proof of absence. |
