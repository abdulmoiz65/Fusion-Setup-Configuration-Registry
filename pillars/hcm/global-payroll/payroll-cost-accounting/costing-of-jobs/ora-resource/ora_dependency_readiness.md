# Job Costing Dependency Readiness

## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Job and Set source | Resolve one JobCostSearchVO JobId with JSON boolean hasMore=false, then one matching effective-dated jobsLov SetCode with JSON boolean hasMore=false. |
| 2 | Legislative Data Group | Run one bounded server-side Name LIKE LDG candidate request at offset 0/limit 11; select the exact Name immediately or apply the bounded candidate rules. Seal the selected row's LegislativeDataGroupId, Name, and positive CostAllocationIdFlexNumber before runtime KFF. |
| 3 | Runtime Costing KFF for non-Create account work | For Update and Correct MERGE with account values, retain the existing order: resolve_runtime_costing_kff, resolve_costing_job_segment_qualifiers, and validate_costing_segment_value. Create follows the separate Create Dependency Order below. |
| 4 | Non-Create current allocation state | Resolve exact Update state. For Correct, End Date, and Zap, bind the exact Job, jobsLov, and LDG outputs into sealed context, aggregate PayCostSearchVO from offset 0 through JSON boolean hasMore=false with matching requested/returned paging, and seal one expanded, identity-bound Generic Costing item for every unique CostAllocationId and EffectiveStartDate split. Create follows the separate Create Dependency Order below and never uses genericCosting collection paging for absence. |
| 5 | Current HDL template | Complete core.data-loader source/schema review for the selected DAT members. |
| 6 | Approval and handoff | Bind Task Hook validation and fresh approval to the immutable archive and target environment. |
| 7 | Loader handoff | Record the accepted core.data-loader Content ID, Request ID, or redacted resume reference; do not wait or poll. |
| 8 | Optional status and verification | Only on an explicit user request, read the handoff status once. Use matching read-only Generic Costing GET only after terminal success. |

## Create Dependency Order

| Sequence | Create Step | Actions in Order | Gate Before Next Step |
|---|---|---|---|
| 1 | Parse the unambiguous user effective date before date-dependent GETs; resolve exact Job through JobCostSearchVO and effective-dated jobsLov; seal matching JobId, JobCode, and authoritative jobsLov.SetCode. | Input date validation; resolve_job_source; resolve_job_hdl_identity | Stop on ambiguous date, identity, or like-typed SetCode mismatch; a supplied SetName is a selector, not the HDL code. |
| 2 | Resolve exact LDG and retain the normalized YYYY-MM-DD date for REST. | resolve_legislative_data_group | Seal LDG ID, Name, positive CostAllocationIdFlexNumber, and the same normalized date; no KFF request yet. |
| 3 | Call check_active_job_costing_record with the sealed JobId, LDG ID, and date. | check_active_job_costing_record | JSON boolean true blocks immediately; only exact false permits the future action. No KFF, qualifier, Value Set, or HDL work on a blocked branch. |
| 4 | Call check_future_job_costing_record with the same sealed JobId, LDG ID, and date. | check_future_job_costing_record | A valid result date blocks and is retained; only HTTP 200 exact {"result":null} permits KFF. Empty body and malformed results fail closed. |
| 5 | Resolve runtime KFF, then Job-applicable qualifiers, then validate each supplied account value through its runtime Value Set. | resolve_runtime_costing_kff;resolve_costing_job_segment_qualifiers;validate_costing_segment_value | Seal canonical Segment<N> mappings and exact values before account validation. |
| 6 | Validate COST-only account distribution and build both Create HDL DAT members with YYYY/MM/DD dates. | Local account validation; HDL render | Use jobsLov.SetCode, SourceType JOB, SourceSubType COST, and fractional proportion; require overall total 1. |
| 7 | Validate current template and final source, create the immutable ZIP, run Task Hook preview, obtain fresh approval, then hand off through core.data-loader. | Existing source/template validation; immutable ZIP; Task Hook preview; fresh approval; core.data-loader handoff | Preserve the existing archive, approval, and Data Loader gates. |

## Dependency Classification

| Result Category | When Used | Can Run Lookup/Create? |
|---|---|---|
| Satisfied | Exact input or resolved evidence is already present. | Yes |
| Lookup | A documented read-only resolver can resolve the value, including either specifically governed Create decision POST action. | Yes |
| Verify | Template, approval, accepted loader handoff, or user-requested loader status evidence must be checked. | Yes |
| Blocked | Identity, KFF, template, approval, accepted-handoff, or required status evidence is absent or ambiguous. | No |
