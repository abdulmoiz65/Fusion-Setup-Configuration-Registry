## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| End Date DAT shape | In the final CostAllocationV3.dat, require one parent METADATA and one matching MERGE, with ReplaceLastEffectiveEndDate exactly once as a METADATA attribute and Y in the corresponding MERGE column. Require equal column counts, the selected parent keys and dates, and the requested calendar EffectiveEndDate; reject #RETAIN, #ALL, and #NULL for that end date. Do not render account members. | End Date source validation before preview and handoff | |
| HDL SET instructions | Inspect every instruction in every final DAT member, not only METADATA headers. Reject every SET line for End Date. For other operations, accept only the exact SET command and arguments expressly required by this task's ora_defaulting_rules.md and ora_design_enforcement.md; reject unknown commands, aliases, unsupported arguments, and directives belonging to another operation before loading. | Every HDL source validation before preview and handoff | |
| Applicable mandatory attributes | For each component and selected HDL operation, compare the final DAT with the current UCM template and live component attributes, including mandatory, required-for-create, and key metadata. Every attribute mandatory for that operation must appear in that component's METADATA and have a nonblank supported value in every applicable MERGE or DELETE row. A system-generated attribute or an alternative user key may be omitted only when the current component contract explicitly supports that choice and the complete chosen key is present; otherwise stop for contract clarification. A generic source/schema pass or a valid archive digest does not prove operation-specific completeness. | Every HDL source validation before preview and handoff | |
| Job parent MERGE key | In the exact final CostAllocationV3.dat, require each MERGE to contain EffectiveEndDate, EffectiveStartDate, SourceType, JobCode, SetCode, and LegislativeDataGroupName in the current template-supported order, plus any operation-specific required attribute. Require nonblank values in the corresponding positions: the Create EffectiveEndDate default 4712/12/31 or the validated end date for another operation, the selected start date, JOB, the sealed JobCode, the nonblank jobsLov-derived SetCode, and the confirmed LDG Name. Reject a header or row that omits SetCode or leaves a required date blank. Do not treat a displayed SetName or SetId as SetCode. | Every parent MERGE source validation before preview and handoff | resolve_job_hdl_identity |
| Job account MERGE key | In the exact final CostAllocationAccountV3.dat, require every MERGE row to contain SourceType, JobCode, SetCode, LegislativeDataGroupName, EffectiveDate, SourceSubType, Proportion, and SubTypeSequence, plus every required canonical `Segment<N>` attribute derived from the runtime segment index, in the current template-supported order. Never render uppercase runtime column spelling in METADATA. Require nonblank values in the corresponding positions and bind JobCode, jobsLov-derived SetCode, and LDG Name to the parent and sealed lookup evidence. Use the operation's validated subtype and sequence rules. Reject SetCode omission from either the header or a row even when the generic Data Loader validator accepts the remaining columns. | Every account MERGE source validation before preview and handoff | resolve_job_hdl_identity |
| Create HDL dates | Parse the final Create DAT members by METADATA position. Require every actual date attribute, including EffectiveStartDate, EffectiveEndDate, and EffectiveDate, to contain a calendar-valid YYYY/MM/DD value; retain parent EffectiveEndDate default 4712/12/31. The two existence-action requests use the same normalized date in YYYY-MM-DD. | Create source validation before preview and handoff | |
| Create account subtype | Require SourceType JOB and SourceSubType COST in every rendered Create account MERGE row. Omitted user subtype defaults to COST; explicit COST is valid; explicit SUSP, DFLT, or any other subtype is input_validation and blocks before HDL. | Create input and source validation | |
| Final archive member completeness | Inspect the exact immutable ZIP that will be approved and uploaded, not only an earlier DAT or planning record. For every DAT member, parse METADATA and all instructions; require each METADATA-bound MERGE or DELETE row to have the same column count as its METADATA, map its values by METADATA position, and run the operation-applicable mandatory-attribute and Job-key checks on those bytes. Validate SET lines separately under HDL SET instructions. When both members are present, require matching parent and account JobCode, SetCode, and LDG Name. If a correction changes any DAT or the ZIP, repeat source/schema and Task Hook validation and obtain approval for the new digest. | Every Job Costing HDL archive validation before approval and handoff | |
| Job search finder | Require a validated criterion and profile from the JobCostSearchVO Request Contract in ora_reference_lookups.md. Preserve its positional bind order; do not manufacture a wildcard or an unvalidated combined finder. | Any Job search | search_job_costing_by_criteria |
| Search continuation | Do not make an exact Job source decision unless JobCostSearchVO returns JSON boolean hasMore=false; narrow the supported search and stop on hasMore=true, a string flag, or a missing paging flag. | Job source resolution | search_job_costing_by_criteria |
| History continuation and binding | Start PayCostSearchVO at offset 0 and aggregate each contiguous page through JSON boolean hasMore=false before producing sealed evidence. Require a sealed normalized environment, request/approval scope fingerprints, fresh observation timestamps, and matching requested/returned offset and limit. Require exactly one terminal Generic Costing detail at requested/returned offset 0 and limit 1 for every sealed history split, and require its CostAllocationId, EffectiveStartDate, EffectiveEndDate, sealed LDG, sealed JobId-derived SourceId, JOB, CostAllocationRecordId, and complete CostAllocationAccounts expansion to match. | Correct, End Date, or Zap | query_job_costing_history_accounts |
| Job Set technical key | Require a one-row jobsLov response filtered by the resolved JobId and requested effective date with JSON boolean hasMore=false. Require matching JobId and JobCode, a covering effective range, and nonblank SetCode. Compare a search SetCode only with jobsLov.SetCode and a separately returned SetName only with jobsLov.SetName when present; a technical SetCode/display SetName difference is not a mismatch. Only jobsLov.SetCode populates HDL; the user need not supply it. | Create, Update, Correct, End Date, Zap, or verification | resolve_job_hdl_identity |
| Create active absence | Require findExistingRecord result JSON boolean false for sealed JobId, LDG ID, and date. | Create | check_active_job_costing_record |
| Create future absence | After active absence, require futureRecordExists HTTP 200 exact {"result":null} for the same sealed inputs before any Create KFF, qualifier, or Value Set lookup. Empty body, missing result, or string "null" fails closed. | Create | check_future_job_costing_record |
| Update state | Require one exact current allocation and validate requested effective start date against current history. | Update | query_job_costing |
| Correct state | Require one exact parent and complete history-split child evidence, including physical IDs, CostAllocationRecordId, SourceSubType, and effective identity for any existing child or DELETE. For MERGE, use a positive REST-resolved SubTypeSequence when present or request it explicitly from the user. | Correct | resolve_job_correct_sequence |
| End Date state | Require the exact last effective parent, no later split, a requested end date on or after its start and no later than its resolved end, bound children resolved for every history split, and component support for ReplaceLastEffectiveEndDate. | End Date | query_job_costing_history_accounts |
| Zap state | Require the exact logical parent, every sealed history split, every resolved account child with its physical account ID, allocation-record ID, effective date, current proportion, SourceSubType, and populated segments, plus fresh destructive confirmation as JSON boolean true. Do not manufacture a SubTypeSequence. | Zap | query_job_costing_history_accounts |
| Job HDL keys | Render only JOB, JobCode, jobsLov-derived SetCode, LegislativeDataGroupName, EffectiveDate, SourceSubType, Proportion, SubTypeSequence, ConcatenatedSegment, and canonical `Segment<N>` columns for every supplied validated segment in official order. Correct child rows also include only resolved physical account identifiers supported by the current template. Do not use JobId, SourceId, LegislativeDataGroupId, CostAllocationId, SetId, ResultValue3, or SetName as HDL keys. | Create, Update, or Correct | resolve_job_hdl_identity |
| Segment clear request | Reject #NULL, JSON null, and an empty value when it is presented as a request to clear an existing segment. Do not render a clearing directive until an official explicit-clear HDL contract exists. | Create, Update, or Correct | |
| Account totals | For Create, all account rows use COST, every fractional Proportion is within 0 through 1, and the overall COST allocation totals exactly 1. For Update, retain the established overall and per-subtype fractional total checks without adding supported subtype choices or changing Update behavior. | Create or Update | |
| Loader handoff | Require the exact submitted archive to return a Content ID and Request ID or other core.data-loader resume reference. Do not wait for a terminal result at initial handoff. | Create, Update, Correct, End Date, or Zap | |
| Loader status or verification | Only after the user explicitly asks, read the exact prior handoff status once. A pending state is informative; only terminal success permits the matching verification GET. | Check status or verify a prior handoff | |
| End Date post-load state | Require the selected parent to end on the requested date and no allocation on the following calendar day. | End Date | query_job_costing |
| Zap post-load state | Require no remaining parent for the complete pre-request logical history. | Zap | query_job_costing_history |
| REST write request | Reject arbitrary POST, PATCH, PUT, and DELETE as task mutation routes; allow only the two governed read-only Create existence POST actions. | Any mutation request | |
