# Job Costing Design Enforcement

## Enforcement Order

| Sequence | Step | What Must Happen |
|---|---|---|
| 1 | Select route | Accept read-only lookup, Create, Update, End Date, Zap, a sealed Correct child DELETE, or a one-action Correct MERGE with an explicit positive SubTypeSequence. |
| 2 | Resolve identities | Resolve exact JobCode and JobId, then jobsLov-derived SetCode with JSON boolean hasMore=false and LDG through one bounded Name LIKE candidate request, and bind them into sealed context. For Create, normalize the date, prove active absence and future absence in that order, stop immediately on either blocked branch, and only then resolve KFF, Job qualifiers, and supplied account Value Sets. Use GET for supported non-Create current state and preserve their existing lookup order. For Correct MERGE, Correct child DELETE, End Date, and Zap, aggregate PayCostSearchVO from offset 0 through JSON boolean hasMore=false with sealed request/response paging and freshness, traverse every sealed history split through its Generic Costing item GET, and seal complete details bound to CostAllocationId, EffectiveStartDate, EffectiveEndDate, LDG, JobId-derived SourceId, JOB, CostAllocationRecordId, and complete child expansion. For Correct MERGE, use a positive REST-resolved sequence when present or ask the user for the exact positive HDL value; never infer it. Correct child DELETE accepts no caller account facts: it selects exactly one bound child by ID and effective date. |
| 3 | Build package | For Create, reject an explicit SourceSubType other than COST; default an omitted subtype to COST and accept explicit COST. For Create and effective-dated Update, enforce SourceType JOB and the established COST account shape, then render official HDL keys, canonical `Segment<N>` attributes for every supplied validated segment, and both DAT members with MERGE; generate only SubTypeSequence serials 1 through N. Reject supplied account SourceType other than JOB and #NULL, JSON null, or blank segment values. For Correct MERGE, render one action with the positive REST-resolved or user-provided SubTypeSequence. A Correct child DELETE is limited to one sealed non-orphaning child and uses returned physical identity, SourceSubType, and proportion without a manufactured SubTypeSequence. For End Date, render the parent-only MERGE with ReplaceLastEffectiveEndDate=Y. For Zap, render DELETE rows for every resolved account child and then the logical parent after JSON boolean true confirmation. |
| 4 | Protect Update | Put SET PURGE_FUTURE_CHANGES N at the beginning of each Update DAT member. |
| 5 | Gate handoff | Require source/schema validation, Task Hook validation, immutable fingerprint, and fresh approval before core.data-loader handoff. |
| 6 | Report and optionally verify | After accepted handoff, report initiated or pending without polling. Only after an explicit user status or verification request and terminal success may the matching read-only verification GET run. |

## Design Rules

| Applies When | Severity | Required Lookup | Blocking Condition | Recommendation | Fix Allowed? |
|---|---|---|---|---|---|
| Create active existence | Error | check_active_job_costing_record | Active existence is JSON boolean true, malformed, or unproven. | Block HDL preparation until exact JSON boolean false is sealed for JobId, LDG ID, and date. | Yes |
| Create future existence | Error | check_future_job_costing_record | Future existence returns a date, an empty body, a missing result, or another malformed or unproven result. | Block Create KFF, qualifier, Value Set, and HDL work until HTTP 200 exact {"result":null} is sealed after active JSON boolean false. | Yes |
| Create account subtype | Error | | An explicit account SourceSubType is anything other than COST. | Reject the supplied subtype; default only an omitted subtype to COST, and accept explicit COST. Do not silently convert SUSP, DFLT, or another requested subtype. | Yes |
| Update | Error | query_job_costing | Exact state, effective date, update purge directive, account identity, or approval is missing. | Build the official two-member HDL MERGE package with SET PURGE_FUTURE_CHANGES N in each member. | Yes |
| Correct MERGE | Error | resolve_job_correct_sequence | A positive SubTypeSequence is missing, invalid, inferred, or conflicts with the REST-resolved value; or required account, KFF, template, or approval evidence is missing. | Use the REST-resolved sequence when present. Otherwise ask the user for the exact positive HDL value, then render one MERGE action. | Yes |
| Correct child DELETE | Error | query_job_costing_history_accounts | Caller-built identity/account data, absent sealed detail evidence, an ambiguous or missing selected child, null/blank/#NULL SourceSubType, an orphaning single-child delete, missing template/approval, or non-boolean confirmation. | Render only one non-orphaning child DELETE selected by CostAllocAccountId and effective date from sealed bound current-state GET evidence. It is distinct from Correct MERGE and has no MERGE readiness override. | Yes |
| Multi-account Correct MERGE | Error | | More than one sibling MERGE action is in an archive, an intermediate total exceeds 100%, a later stage is prepared before the prior stage is explicitly status-checked, terminally successful, and verified, or a stage lacks its positive SubTypeSequence. | Submit only the next Correct MERGE stage after its sequence is resolved or explicitly provided, then fresh validation and approval. | Yes |
| End Date | Error | query_job_costing_history_accounts | The target is not the exact last parent, has a later split, history has not been sealed from contiguous offset pages through explicit hasMore=false, detail evidence is unsealed or incomplete, a detail does not bind its split, sealed LDG, sealed JobId-derived SourceId, JOB, and complete children, end date precedes parent start or exceeds its resolved end, component support for ReplaceLastEffectiveEndDate is absent, or approval is absent. | Build one parent-only CostAllocationV3 HDL MERGE package with ReplaceLastEffectiveEndDate=Y. | Yes |
| Zap (Delete Record And History) | Error | query_job_costing_history_accounts | The sealed complete logical history, exact parent, every history-split child physical identity, sealed bound detail response, source/schema evidence, or fresh destructive JSON boolean true confirmation is missing. | Build one immutable HDL archive with every child DELETE followed by the logical parent DELETE; do not use Delete (ED Split) or REST. | Yes |
| Create or effective-dated Update preparation | Error | | A successful lookup, render, archive, or validation step is treated as an intermediate pause. | Continue through defaults, state checks, DAT render, source/schema validation, immutable ZIP, and Task Hook preview before requesting fresh approval. | Yes |
| Existing allocation detail or one-date verification | Error | query_job_costing | A mutation route is requested instead of governed read-only transport. | Use core.fusion-api.rest-api-client with GET; the two governed read-only Create decision POST actions have separate resolvers. | Yes |
| Unsupported mutation | Error | | Delete (ED Split) or another mutation has no official HDL-only contract. | Stop; do not substitute REST or another execution route. | No |

## Design Lookup Requirements

| Resolver | When Required | Values Needed | Source File |
|---|---|---|---|
| resolve_job_hdl_identity | Create, Update, Correct MERGE, Correct child DELETE, End Date, Zap, or verification. | Exact JobCode, JobId, and jobsLov-derived SetCode with JSON boolean hasMore=false. | ora_reference_lookups.md |
| resolve_legislative_data_group | Create, Update, Correct MERGE, Correct child DELETE, End Date, Zap, or verification. | Canonical LegislativeDataGroupName and positive CostAllocationIdFlexNumber from one exact LDG row after one bounded Name LIKE candidate request. | ora_reference_lookups.md |
| resolve_job_costing_context | Correct MERGE, Correct child DELETE, End Date, Zap, or date-effective history verification. | Immutable exact Job, LDG, and JobId-derived SourceId context. | ora_reference_lookups.md |
| resolve_runtime_costing_kff | Create only after both absence checks, or Update/Correct MERGE with account values under existing prerequisites. | Runtime segment identities, physical columns, canonical `Segment<N>` HDL attributes for every segment, and LOV metadata for the sealed LDG discriminator. | ora_reference_lookups.md |
| resolve_costing_job_segment_qualifiers | Create only after both absence checks and runtime KFF, or Update/Correct MERGE with account values under existing prerequisites. | Job-applicable segments reconciled with runtime KFF metadata and returned ProcessingPriority. | ora_reference_lookups.md |
| validate_costing_segment_value | Create only after both absence checks, runtime KFF, and Job qualifiers; Update/Correct MERGE retain their existing prerequisites. | Exact validated Value and Description bound to the applicable derived `Segment<N>` HDL attribute. | ora_reference_lookups.md |
| check_active_job_costing_record | Create after sealed Job, jobsLov, LDG, and normalized date, before Create KFF or account values. | Exact findExistingRecord result JSON boolean false for sealed JobId, LDG ID, and date. | ora_reference_lookups.md |
| check_future_job_costing_record | Create only after active result JSON boolean false and before Create KFF or account values. | HTTP 200 exact {"result":null} from futureRecordExists for the same sealed JobId, LDG ID, and date. | ora_reference_lookups.md |
| query_job_costing | Update, account detail, or one-date verification. | Parent and account state at one effective date. | ora_reference_lookups.md |
| query_job_costing_history | Correct MERGE, Correct child DELETE, End Date, or Zap preflight and verification. | Sealed complete offset-paged effective history and its unique CostAllocationId and EffectiveStartDate split keys. | ora_reference_lookups.md |
| query_job_costing_history_accounts | Correct MERGE, Correct child DELETE, End Date, or Zap preflight and verification. | Every sealed history-split parent and child identity bound to CostAllocationId, EffectiveStartDate, EffectiveEndDate, sealed LDG, sealed JobId-derived SourceId, and JOB. | ora_reference_lookups.md |
| resolve_job_correct_sequence | Correct MERGE only. | Positive REST-resolved SubTypeSequence when available; otherwise explicit positive user-provided HDL SubTypeSequence. | ora_reference_lookups.md |
