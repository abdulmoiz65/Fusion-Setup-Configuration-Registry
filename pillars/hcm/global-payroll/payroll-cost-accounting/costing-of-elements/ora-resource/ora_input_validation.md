# Costing of Elements Input Validation

Validate Search selectors before resolved HDL inputs. Create, Update and Correct
share discovery and value mappings; their supported write scopes are defined
in ora_design_enforcement.md. End Date closes allocation and EL/LIV costing;
Zap deletes the selected logical costing record and its complete history.

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Lookup phase | Check operation, date, filters and target clues only; retain requested changes separately. | Before Search | |
| Lookup strings | Nonblank when supplied. Reject controls and comma, semicolon or pipe in generic finder values. Reject apostrophe, percent and underscore in LDG text; an explicit ID avoids LIKE. No captured escaping contract exists for these inputs. | Search | |
| LDG selector | Positive decimal ID without floating-point conversion; accept text or ID, clarify conflicting selectors. | Search | |
| Filter scope | Do not discard a supplied constraint or accept raw finder/q text as a business value. | Search | |
| Dates | Valid calendar dates: REST YYYY-MM-DD, HDL YYYY/MM/DD. Keep parent, cost-info and account dates distinct. | All operations | |
| Flags | Accept boolean or explicit Y/N; output Y/N. Missing, null and false remain distinct. | CostedFlag,TransferToGlFlag | |
| Type/group | Requested code/label must resolve in the live LOV and selected LDG. | Requested changes | resolve_element_costing_type |
| Input selection | A name resolves uniquely within the eligibility; a unit-of-measure entry is not an input identity. | Costed inputs | resolve_element_costed_input |
| Priority proportion | Explicit decimal fraction in [0,1] or percentage in [0,100], with units; reject ambiguous quantities and use exact decimal arithmetic. | OVRRIDE input | |
| Account codes | Preserve leading zeros and require runtime-mapped fields. | Account rows | validate_element_costing_segments |
| Null changes | Omitted means preserve on Update/Correct. Explicit clearing requires a nullable live attribute and HDL #NULL; empty text is not an implicit clear. | Update/Correct | |
| Metadata | Every MERGE or DELETE matches its METADATA in attribute count/order. Selected ordinary attributes, operation and identity forms must exist in the current schema. End Date also retains the special ReplaceLastEffectiveEndDate attribute under the design contract; ordinary template omission does not permit removing it. | HDL members | resolve_element_hdl_templates |

## Source Assembly

Mapping ownership stays in ora_reference_lookups.md; defaults stay in
ora_defaulting_rules.md. Use these stable header projections, adding only
requested, schema-validated ordinary attributes and the documented End Date
special attribute. Every row follows its member's header.

| Member | Header projection and rows |
|---|---|
| CostInfoV3.dat | EffectiveEndDate,EffectiveStartDate,SourceType,ElementEligibilityName,ElementCode,LinkInputName,LegislativeDataGroupName,CostableType,CostedFlag,TransferToGlFlag,DistributionSetName. One EL row for costing information; one LIV row per selected input. Leave other source-type attributes empty; unused optional columns may be omitted. |
| CostAllocationV3.dat | EffectiveEndDate,EffectiveStartDate,SourceType,ElementEligibilityName,ElementCode,LegislativeDataGroupName. One EL parent for Create/Update. |
| CostAllocationAccountV3.dat | SourceType,ElementEligibilityName,ElementCode,LegislativeDataGroupName,EffectiveDate,IdFlexNum,SourceSubType,Proportion,SubTypeSequence,ConcatenatedSegment, followed by needed Segment columns in numeric order. Leave unused representation fields empty. |
| End Date CostAllocationV3.dat | One METADATA and one MERGE when the allocation is in the change set. Columns: EffectiveEndDate,EffectiveStartDate,SourceType,ElementEligibilityName,ElementCode,LegislativeDataGroupName,ReplaceLastEffectiveEndDate. Use requested end, selected existing start, EL, canonical user keys and Y. |
| End Date CostInfoV3.dat | One METADATA with EffectiveEndDate,EffectiveStartDate,SourceType,ElementEligibilityName,ElementCode,LinkInputName,LegislativeDataGroupName,CostableType,CostedFlag,TransferToGlFlag,ReplaceLastEffectiveEndDate. Add DistributionSetName when nonnull in the EL baseline. Render one EL MERGE and one LIV MERGE per existing input in the change set, using their retained starts, the same requested end and Y. Preserve applicable flags/type/group; leave nonapplicable cells blank. |
| End Date archive members | For a fully open target set, include CostAllocationV3.dat and CostInfoV3.dat in the same ZIP: one allocation EL, one CostInfo EL and one CostInfo LIV per existing input (three MERGE rows when there is one LIV). Reconcile rows exactly to the validated change set; exclude already-closed rows and omit a member only if it has no changed rows. Always retain the full target set in the expected result. Never include CostAllocationAccountV3.dat. |
| Correct CostInfoV3.dat | CostInfoId,EffectiveStartDate,EffectiveEndDate,SourceType, followed by changed supported attributes of the selected EL/LIV row. Retain its dates and physical ID; no allocation/account member for supported corrections. |

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| End Date source shape | Apply the member and MERGE counts above to the complete change set; reject missing, duplicate or extra target rows. Require unique headers, equal METADATA/MERGE column counts, YYYY/MM/DD dates, the same requested end across both objects and one ReplaceLastEffectiveEndDate header with Y in every MERGE row. Reject blank dates, #RETAIN, #ALL, #NULL, DELETE and every SET instruction, including SET PURGE_FUTURE_CHANGES N and SET REPLACE_LAST_EFFECTIVE_END_DATE. Ordinary identity columns must match the retrieved schemas and selected baseline. | End Date preparation | |
| Rendering | Render UTF-8 METADATA/MERGE files for Create/Update/Correct/End Date; Zap uses the identity-only DELETE contract below. No captured batch ID or REST-only field becomes a header. | Preparation | |
| Embedded delimiter | Use the loader's delimiter/escape contract. With default pipe/backslash, escape embedded pipes in ConcatenatedSegment and literal backslashes; round-trip before packaging. Never replace the KFF delimiter with a dot. | Full accounts or reserved characters | |
| Archive | For the normal submission workflow, package exact touched DAT members in one immutable ZIP through core.data-loader. The explicit End Date artifact-only contract below owns its local ZIP. Its object dependencies govern loading, not ZIP order. Keep sensitive source in its approved local staging, not tracked skills or project diagnostics. | Before preview | |
| End Date artifact-only ZIP | After live identity/history/detail, complete-target scope, both ordinary schemas and local source-shape checks, package the End Date archive members above in one immutable ZIP in ignored local staging. artifact_only changes delivery, not the target scope. Report source_checked=true, loader_validated=false and not submitted. Return the DAT/ZIP links and validation limitation; do not run Task Hook, request load approval or upload. A later submission must restart current-state checks and full core.data-loader validation. | Explicit artifact_only End Date | |
| Source validation | Complete schema/key validation, immutable archive and Task Hook for PAY_MANAGE_ELEMENT_CRITERIA_COSTING before approval. If the shared parser cannot preserve escaping, stop rather than alter values or bypass validation. | Before approval | |

[Oracle reserved-character guidance](https://docs.oracle.com/en/cloud/saas/human-resources/fahdl/how-you-manage-reserved-characters.html)
defines HDL escaping. Preparation does not authorize upload.

## Zap Source Assembly

| Member or check | Required source shape |
|---|---|
| CostAllocationV3.dat | One METADATA and one DELETE row. Columns in order: EffectiveEndDate,EffectiveStartDate,SourceType,ElementEligibilityName,ElementCode,LegislativeDataGroupName. Use the selected logical allocation's actual latest end/earliest start, EL and canonical user keys. An already end-dated history keeps its actual end. |
| CostInfoV3.dat | One METADATA and one DELETE per distinct resolved CostInfoId across all selected history. Columns in order: CostInfoId,EffectiveStartDate,EffectiveEndDate,SourceType,ElementEligibilityName,ElementCode,LinkInputName,LegislativeDataGroupName. Use each ID's own observed earliest start/latest end and bound canonical keys; SourceType is EL or LIV, with LinkInputName populated only for LIV. Validate physical ID plus source-specific user-key agreement and DELETE support before accepting this extrapolated contract. |
| CostAllocationAccountV3.dat | One METADATA and one DELETE per distinct resolved CostAllocAccountId. Columns in order: CostAllocAccountId,CostAllocationRecordId,EffectiveDate,SourceType,ElementEligibilityName,ElementCode,LegislativeDataGroupName,SourceSubType. Use bound account identities and EL parent keys. Omit this member only when every selected historical detail proves zero accounts. |
| Archive coverage | One immutable ZIP contains the allocation and CostInfo DELETE members plus the account member when accounts exist. Match every row one-to-one to the saved target inventory; reject missing/extra targets, duplicate physical IDs, unknown headers or mismatched column counts. No element/eligibility definition objects. Use YYYY/MM/DD dates and the shared HDL escaping contract. |
| Identity-only deletion | Reject MERGE, SET instructions, ReplaceLastEffectiveEndDate, blank dates, #RETAIN, #ALL and #NULL. Omit CostableType, flags, group, Proportion, SubTypeSequence, IdFlexNum, ConcatenatedSegment and all Segment columns. Do not invent a SourceId column or apply Create/Update defaults. |
| Loader validation | Delegate current DELETE capability, published keys, source/archive checks and cross-object dependency processing to core.data-loader. For requested execution, complete its persisted preflight and PAY_MANAGE_ELEMENT_CRITERIA_COSTING Task Hook preview before approval. A validation-only ZIP is not a submission preflight. Any failure stops the whole handoff; do not drop the rejected component or trial alternative keys against Fusion. |
