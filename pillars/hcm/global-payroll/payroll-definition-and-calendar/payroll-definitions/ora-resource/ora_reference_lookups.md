## Lookup Execution Rules

## Consolidation Set Request Serialization

For `resolve_consolidation_group_or_set_by_ldg`, construct the request exactly as this pattern. Replace only `<pod-host>` and `<LegislativeDataGroupId>`; preserve the commas inside the `finder` value. Do not hard-code either replacement value.

```text
https://<pod-host>/hcmRestApi/redwood/11.13.18.05/payrollGeneric/payrollGenericQuery?finder=findByWord;PayRestName=ConsolidationGroupUI_PayrollConsolidationSetVO,DisplayAttributes=LegislativeDataGroupId||ConsolidationSetId||ConsolidationSetName||ConsolidationSetCode||Comments||CreationDate||CreatedBy||LastUpdateDate||LastUpdatedBy,AdditionalViewCriteria=findByLDGId,ParameterKeys=pLegislativeDataGroupId,ParameterValues=<LegislativeDataGroupId>&limit=500&onlyData=true
```

Do not convert the commas after PayRestName, DisplayAttributes, AdditionalViewCriteria, or ParameterKeys to `&`. Do not split DisplayAttributes, AdditionalViewCriteria, ParameterKeys, or ParameterValues into independent URL parameters. This internal runtime route interprets that complete comma-delimited string as the finder value. limit and onlyData remain separate parameters after `&`.

## Payroll Definition Request Serialization

For `resolve_payroll_definition_by_ldg_and_effective_date`, construct the request exactly as this pattern. Replace only `<pod-host>`, `<LegislativeDataGroupId>`, `<SysEffectiveDate>`, and `<PayrollName>`; do not hard-code any replacement value.

```text
https://<pod-host>/hcmRestApi/redwood/11.13.18.05/payrollGeneric/payrollGenericQuery?finder=findByWord;PayRestName=PayrollDefinitionUI_PayrollDVO,DisplayAttributes=LegislativeDataGroupId||LegislationCode||PayrollName||PayrollId||ConsolidationSetId||ConsolidationSetName||ReportingName||PeriodType||EffectiveStartDate||EffectiveEndDate||CreationDate||CreatedBy||LastUpdateDate||LastUpdatedBy,SortBy=PayrollName asc,AdditionalViewCriteria=SearchCriteria,ParameterKeys=pLegislativeDataGroupId||SysEffectiveDateBindVar,ParameterValues=<LegislativeDataGroupId>||<SysEffectiveDate>,SearchTerms=<PayrollName>,FilterAttributes=PayrollName&limit=500&offset=0&onlyData=true
```

Keep all text after `finder=` through `FilterAttributes=PayrollName` as one comma-delimited finder value. Do not change any comma to `&` or split DisplayAttributes, SortBy, AdditionalViewCriteria, ParameterKeys, ParameterValues, SearchTerms, or FilterAttributes into separate query parameters. Only `limit=500`, `offset=0`, and `onlyData=true` are joined with `&`.

## Allow Negative Payments Lookup Serialization

For `resolve_allow_negative_payments_lookup_code`, construct the request exactly as this pattern. Replace only `<pod-host>`; do not hard-code it.

```text
https://<pod-host>/hcmRestApi/resources/latest/payrollGenericLOV?fields=Code,Meaning&finder=findByWord;PayRestName=HcmLookupValuePVO,AdditionalViewCriteria=findByLookupType,ParameterKeys=LookupTypeBindVar,ParameterValues=HRC_YES_NO&onlyData=true
```

Keep the comma-delimited text after `finder=` as one finder value. Do not change its commas to `&`; only `fields=Code,Meaning` and `onlyData=true` are separate query parameters.

| Situation | What Happens |
|---|---|
| A lookup name or value is supplied | Compare that exact unchanged value against both returned Code and returned Meaning; resolve only one matching row and return its actual Code and Meaning. |
| A lookup returns zero matches | Return a field-level not-found error and do not prepare the dependent row. |
| A lookup returns more than one match | Return ambiguity and do not select a row automatically. |
| The same resolved value is needed again in one operation | Reuse the resolved result while its LDG and effective-date scope remain unchanged. |
| A response already contains the required display name | Retain it for end-user details; keep the underlying HDL reference value separate. |
| A runtime REST ID and an HDL reference are both available | Preserve them separately and use only the reference form declared by the target View Business Objects export. |
| A route, finder, response field, eligibility contract, or paging rule is unresolved | Stop before presenting the affected lookup or task as runtime-ready. |
| A live lookup is performed | Treat it as read-only reference resolution; never use the internal UI resource for create, update, delete, import, or calendar adjustment. |
