Use the verified task export for parent and child natural keys and referenced time-definition codes. The public Payroll Time Definitions LOV does not expose TimeDefinitionCode and must never resolve that code or mutate a definition. All Fusion calls in this file are read-only preflights.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Code, name, and ID representations are supplied together | Require every representation to identify the same record; never choose one over an inconsistency. |
| Parent business value or UsageType is unfamiliar | Preserve the trimmed supplied value; examples and export encodings are not allowlists. |
| Task export has COMPLETED_WARNINGS or unavailable optional warning details | Disclose and continue unless evidence is failed, truncated, unusable, inconsistent, or explicitly affects the requested key or LDG. |
| A parent has no usage row | Keep it eligible through either parent ShortName plus LDG or parent DefinitionName plus LDG branch. |
| DefinitionName is supplied for a parent or usage operation | Resolve exactly one parent by DefinitionName plus LDG, derive TimeDefinitionCode from exported ShortName, and use only that code in parent or child DAT keys. |
| Both parent code and name are supplied | Require both exact branches to resolve to the same GroupingKey; stop on inconsistency. |
| BaseTimeDefinitionCode or PeriodTimeDefinitionCode is supplied | Resolve it against exported parent DefinitionName plus LDG; reject missing, ambiguous, cross-LDG, self, or cyclic references and never rewrite it to ShortName. |
| Fresh export has zero parent or child candidates after a create | For a usage operation, evaluate resolve_recent_successful_payroll_time_definition before concluding the target is absent. Only qualified successful terminal ProcessId evidence or authenticated exact read-back can continue. |
| One parent has multiple usage rows | Deduplicate parents by GroupingKey; evaluate a child separately by its complete natural key. |
| Usage child is resolved | Join through parent-qualified ShortName and LDG, compare UsageType meaning rather than UsageTypeCode, and preserve the requested meaning in HDL. An unqualified child TimeDefinitionCode equal to the joined parent DefinitionName is a nonblocking display-name projection; any unreconcilable or cross-parent value blocks. |
| Registered VO mapping is applied | PayrollTimeDefinitionVO maps TimeDefinitionCode to ShortName and resolves BaseTimeDefinitionCode and PeriodTimeDefinitionCode against DefinitionName. TimeDefinitionUsageVO maps child TimeDefinitionCode to parent ShortName. |
| Parent or child natural key resolves | Internal IDs may be retained privately but are not required or substituted in DAT or routine output. |
| Parent delete has no dependent-definition rows and no exposed protected marker | Continue to the single natural-key parent DELETE preview regardless of usage count. Disclose exact usage meanings as cascade-delete impact, delivered ownership not exposed when applicable, and unavailable balance, event, element, and other cross-consumer checks. |
| Parent delete has usage rows | Record each exact UsageType meaning as cascade-delete impact and continue; do not emit TimeDefinitionUsage DELETE rows for complete parent deletion. |
| Parent delete has dependent-definition rows | Stop and report the dependent natural keys and reference fields. |
| Ownership or cross-consumer resolver is unavailable | Preserve the unresolved contract as TBD, disclose the limitation as a nonblocking preview warning, and let Fusion Data Loader enforce referential integrity after approval. |
| Local task context is absent | Bootstrap through bootstrap_task_context and continue when exact metadata are known. |
| Local task context conflicts | Stop and disclose the field; never overwrite or merge silently. |
