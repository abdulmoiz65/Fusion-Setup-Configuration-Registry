# Payroll Time Definition Dependency Readiness

## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Local task context | Resolve a matching local context or bootstrap and schema-validate the minimal task-context.json without separate approval or Fusion access. |
| 2 | Legislative Data Group | Resolve exactly one LDG and retain its identity and legislation context privately. |
| 3 | Fresh Time Definitions task export | Export PAY_MANAGE_TIME_DEFINITIONS and verify both CSV files, metadata, exact headers, joins, and relevant warnings. |
| 4 | Parent and child identity | Resolve supplied parent code against ShortName or supplied display name against DefinitionName, deduplicate by GroupingKey, derive canonical HDL TimeDefinitionCode from ShortName, then resolve any child through parent-qualified ShortName and LDG plus exact UsageType meaning. Treat an unqualified child export value equal to the joined parent DefinitionName as a nonblocking display-name projection. |
| 4a | Recent successful HDL continuity | For usage assignment or removal only, when a usable fresh export has zero candidates after a create, verify exact same-target/task/LDG immutable DAT and successful terminal ProcessId evidence or authenticated exact read-back before treating the export omission as visibility lag. |
| 5 | Operation-specific safety | Enforce zero parent candidates for create, one parent for delete and child operations, zero child matches for assignment, and one child match for removal. |
| 6 | Dependency and batch order | Resolve same-LDG base and period references against DefinitionName and reject cycles and duplicates. Place parent MERGE before child MERGE. Emit child DELETE only when the parent is retained; complete parent deletion emits one parent DELETE and relies on the verified usage cascade. For parent delete, record exact exported usage meanings as cascade impact, block on exported base or period dependents whose reference value equals the target DefinitionName or an explicitly exposed protected marker, and disclose unavailable ownership and cross-consumer resolvers without blocking. |
| 7 | Deterministic DAT | Build the applicable parent or child natural-key DAT without internal IDs and preserve supplied business values. |
| 8 | Live schema and task-rule validation | Validate the unchanged DAT against the registered BO and UCM template, then build the preview and fingerprint. |
| 9 | Authorization and approval | Require authenticated target, task and LDG access, and fresh approval for the exact preview. |
| 10 | Data Loader handoff | Release the unchanged approved file once to core.data-loader in HDL mode with business object PayrollTimeDefinition. |

## Operation-Scoped Contracts

Parent create does not depend on lookup evidence for direct business values, export type encodings, populated ID columns, a clean export status string, or an available optional warning log. Parent delete uses only TimeDefinitionCode and LegislativeDataGroupName in DAT. It is ready for preview when the parent resolves once and the fresh task export shows zero BaseTimeDefinitionCode or PeriodTimeDefinitionCode dependents and no explicitly exposed protected marker, regardless of usage count. Exact usage meanings are disclosed as cascade-delete impact, and complete parent deletion emits no child DELETE rows. Delivered ownership, balance, event, element, and other cross-consumer sources that are not exposed remain **TBD**, but their absence is a nonblocking preview limitation rather than readiness override or pre-preview blocker. Usage assignment and removal use the verified child discriminator and natural key and preserve the supplied UsageType meaning; they never require TimeDefinitionId or TimeDefinitionUsageId. Join child evidence through parent-qualified ShortName and LDG; an unqualified child export code equal to the joined parent DefinitionName is a nonblocking display-name projection, never an HDL key. When a usable fresh export has zero candidates immediately after a create, a qualified exact immutable DAT plus successful terminal ProcessId result from the same target/task/LDG, or authenticated exact read-back, may establish the parent and child key and disclose task export visibility lag. Preview-only, initiated-only, failed, unknown-status, cross-target, or conflicting evidence never qualifies. Parent business-field update is unsupported.
