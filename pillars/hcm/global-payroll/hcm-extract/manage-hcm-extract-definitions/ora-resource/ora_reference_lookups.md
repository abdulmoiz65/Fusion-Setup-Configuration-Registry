## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A lookup request is read-only and declared in this file | Run only when selected by the active task graph and required source values are available |
| A lookup contract is unresolved | Treat the task node as incomplete and stop before preview or live handoff unless the user explicitly accepts a readiness override |
| A lookup has no exact match but exactly one clear partial candidate from the returned rows | Resolve that candidate, fill the LookupCode, and record match mode as `single_candidate_partial` |
| A lookup has no exact match and no clear partial candidate from the returned rows | Stop and ask for a valid value or documented source |
| A lookup has multiple partial candidates | Stop and ask for a more precise value |
| Source values, schema, operation, or business object changes | Re-run the affected lookup before validation and preview |
| A generated value requires lookup resolution | Use only the resolver row declared in this file for that value |
| A value is visible on an existing extract definition, block, record, sample row, or unrelated REST resource | Treat it as diagnostic context only, not resolver output |
| Validation fails | Stop before preview; keep resolver selection within the declared task contract |
