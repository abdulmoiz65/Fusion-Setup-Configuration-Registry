# Legal Entity Calculation Cards Dependency Readiness

## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Payroll statutory unit | Target owner must be supplied and resolved before card-specific preview |
| 1a | Direct Legislative Data Group discovery | A full or partial LDG-name or territory list can run after environment resolution and does not require a PSU selection |
| 2 | FSM launch scope | If a launch URL is supplied, FS_SCOPEINFOS must be parsed and verified before card-specific preview |
| 3 | Functional request and effective date | Resolve the requested business path/value and date; treat create/update/correct verbs as provisional intent |
| 4 | Legal entity calculation card | Search owner-scoped getCardDetails mode=G before mode=ADD. Existing cards supply original dates and CardSequence; only a complete zero-match result selects new-card definition/defaulting |
| 5 | Component definitions and instances | Resolve the intended component against the selected card and CIRComponentPVO. Existing components supply original dates and ComponentSequence; absent components use a proven nonconflicting creation sequence |
| 5b | Complete object-level existence graph | Resolve card, component, override/FLEX/value, assignment/association, and related source-backed history across current, future, and historical intervals |
| 5c | Date-effective action confirmation | When any requested business key exists, notify the user and obtain Update or Correction confirmation before DAT preview |
| 5a | Component flexfield value list | Exact component selection and current/default FLEX rows must come from the selected getCardDetails response before user-facing formatting |
| 6 | Override dependency graph | Dynamic override dependencies must be ordered before LOV validation |
| 9 | HDL mutation contract | Calculation-card business changes use live target `CalculationCard` HDL through `core.data-loader`; CSV/FSM import and direct business REST are not mutation routes |
| 10 | Target environment authority | Active target must come from `core/auth/fusionEnv.properties`; source environment evidence must remain separate |
| 11 | Live CalculationCard template | CalculationCard/CardComponent keys plus the applicable ComponentDetail/FLEX or CalculationValueDefinition/EnterableCalculationValue sections must validate before the DAT preview |
| 11a | HDL override record type | Every requested field must dispatch from active overrideType to FLEX ComponentDetail or OVERRIDE CalculationValueDefinition/EnterableCalculationValue before preview |
| 12 | Staged approvals | Exact DAT preview approval precedes file creation; ZIP, upload, and load initiation require their applicable approvals |

## Dependency Classification

| Result Category | When Used | Can Run Read-Only Lookup? |
|---|---|---|
| Satisfied | Required identifier and approved contract are present | No |
| Verify | Launch context is present but must be checked against payroll statutory unit scope | No |
| Lookup | User supplies a name or display value that must resolve uniquely | Yes, after source contract is supplied |
| Blocked | Lookup path, HDL action contract, or required field mapping is TBD | No |
