## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Read-only flow lookup | Use repository-approved authentication and the shared REST client; record the target, method, relative path, normalized business inputs, requested fields, result count, and exact-match outcome without exposing internal identifiers |
| Data Loader metadata lookup | Invoke only the core.data-loader metadata/sample route for ProcessFlows and preserve the generated editable sample, attribute-details workbook, and key-fields workbook together |
| Setup mutation | Do not call a direct REST create, update, patch, delete, or submitFlow operation; all setup data changes use core.data-loader |
| Authentication or authorization failure | Stop; a 401 or 403 is not evidence that a flow pattern is absent |
| Paging | Follow every page before declaring an exact-name or LDG-scoped collection result complete |
| Public REST and Data Loader metadata differ | Treat current registered ProcessFlows metadata as the writable contract and the public flowPatterns resource as read-only verification; stop if the two cannot be reconciled |
| A reference or LOV code or ID is already supplied | Validate the supplied code or ID under the documented field contract and use it directly when valid; do not perform an additional name or display-value lookup |
| A reference or LOV name or display value is supplied for create, update, or import | Invoke the documented field-specific read-only resolver through the appropriate reference or LOV endpoint, require exactly one match, and place only the returned code or ID in the import payload |
| A reference or LOV name or display value returns no match | Stop with a validation error that identifies the affected field and invalid supplied value |
| A reference or LOV name or display value returns multiple matches | Stop with an ambiguity error and do not select a value automatically |
| A reference or LOV name or display value remains unresolved | Do not include the unresolved name or display value in a payload field that requires a code or ID |
| The same reference value is used more than once in one operation | Reuse the already resolved code or ID within that operation and do not repeat the lookup |
| A required Fusion session is not active before a reference or LOV lookup | Obtain a fresh authorized session through the repository-approved authentication route, then use only the documented reference endpoint; never expose session credentials or tokens |
| Display Type is Value Set and Lookup is supplied by name or display value | Use resolve_flow_parameter_value_set_lookup and place the uniquely matched ValueSetCode in Lookup |
