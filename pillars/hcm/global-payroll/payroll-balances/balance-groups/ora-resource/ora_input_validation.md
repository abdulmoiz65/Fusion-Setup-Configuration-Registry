# Balance Groups FSM Input Validation

These rules validate the requested scope and the supplied local archive. They do not establish that target setup exists. The supplied configuration package is structural reference material; it is not a task CSV template.

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Task identity | ORA_PAY_MANAGE_BALANCE_GROUPS and the selected task context | Stop with TASK_CONTEXT_MISMATCH | Resolve the exact Balance Groups task under Global Payroll / Payroll Balances | Every import | |
| Import artifact | An intact task CSV ZIP containing ASM_SETUP_CSV_METADATA.xml and the task's CSV members | Stop with FSM_CSV_ARCHIVE_REQUIRED | Obtain the task CSV template or export through shared.setup-export.task-level-export | Every import | |
| Create intent | Distinct Balance Group Name, Legislative Data Group, requested level, and requested child selections | Stop with INPUT_REQUIRED or AMBIGUOUS_INPUT | Clarify missing or conflicting business inputs; preserve the full dimension name including commas | Preparing a new group | |
| Field contract | The selected task's CSV template/specification plus the documented minimal parent contract in ora_defaulting_rules.md, or an explicit supported mapping for other scope | Stop with FSM_FIELD_MAPPING_REQUIRED only for mappings outside the documented contract | For a parent-only Employee create, use the known mapping and blank defaults without asking for another populated sample or mapping waiver; obtain missing contracts for additional scope | Constructing or changing CSV rows | |
| Existing balance selection inputs | BalanceName and the complete BalanceDimension for each requested selection | Stop with INPUT_REQUIRED | Obtain both names; do not replace the requested balance with a category or an example search term | Balance definitions are requested | |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Archive format | Reject an XML configuration package containing ASM_MIG_PROCESS_INFO.xml and nested businessObjectData or taskListData ZIPs as FSM_CONFIGURATION_PACKAGE_UNSUPPORTED; do not add a CSV marker or repackage it | Reference or input is a configuration package | |
| Task evidence | Match the selected task code against the export/template provenance; a marker filename alone does not prove task identity or child coverage | Every CSV archive | |
| CSV structure | Parse CSV with quoting rules; match headers, row widths, member names, and field values to its supplied task template/specification; preserve metadata and required companion members | Every CSV archive | |
| Definition selection | Retain Balance Name and the complete Balance Dimension as separate inputs; do not assume a name is a category, turn a comma-separated dimension label into multiple dimensions, or replace it with an AttributeCode | Balance definitions requested | |
| Supported child preparation | Accept the matching task CSV template and supported child structure in ora_reference_lookups.md when target-specific references resolve. Use the existing linked-definition profiles or the Successful Combined Child Preparation profile, including its new definition/group link and numeric-dimension default row. Do not require a trial waiver solely because these structures were previously experimental. Missing target values still return FSM_FIELD_MAPPING_REQUIRED | Adding balance definitions or default inclusions to an existing group | |
| Definition versus default inclusion | Adding an existing balance/dimension association does not request a new payroll balance or a default inclusion. A default inclusion has a category/dimension selection and must be explicitly requested; do not add it merely because the reference HAR contains one | Interpreting child selections | |
| Attribute definition versus balance assignment | Distinguish ORA_PAY_BAL_ATT_DEFINITION.csv identity/definition fields from ORA_PAY_BALANCE_ATTRIBUTE.csv assignment fields. Use the field and helper mapping in ora_reference_lookups.md; a Balance Definitions selection must retain its resolved DefinedBalanceId and either the established AttributeId or the supported new-definition named reference. Category IDs cannot substitute for either identifier, and a service AttributeCode alias must not become a new CSV header | Using the supplied BalanceAttributeDefinitionVO to prepare task CSV rows | |
| Restriction reference result | Require one exact, role-labelled result for each requested category or dimension under Restriction Reference Resolution in ora_reference_lookups.md. Preserve raw category identity separately from its derived FK and keep dimension identity independent. A blank or absent unrequested restriction type is not an instruction to clear existing setup or create a default inclusion | Preparing requested restriction changes | |
| Supported restriction artifact | Accept the three-component field contract in Supported Empty-Group Restriction Preparation when the target and reference preconditions match. Keep actual template columns, numeric category FK/dimension variant, grouping keys and explicit null distinctions; do not require another trial waiver merely because that exact pattern was initially experimental | Preparing the matched Employee restriction update | |
| Captured data isolation | Use HAR field and relationship evidence only; do not substitute captured names, IDs, or selected values for the user's inputs or claim that a successful captured example proves the requested target setup exists | A HAR is supplied as reference | |
| Missing supporting definition | A complete zero-row linked-definition lookup selects the supported new-definition/group-link profile; lack of an existing AttributeId is not a required-user-input failure. Complete reference resolution and package preparation before upload approval | Adding requested children to an existing Employee group | find_balance_group_attribute_links |
| Scope completeness | Account for every requested parent and child change in the prepared archive using its task template; first resolve declared references and apply matching supported defaults; only remaining unverified mappings stop submission with FSM_SCOPE_UNVERIFIED | Any combined request | |
| Legacy business-object requirement | No registered Data Loader business object, pre-existing AttributeCode, DAT header, or HDL identity wrapper is an input requirement for the FSM route | Every FSM request | |
| Supported minimal parent | Accept the matching task template plus supplied group name, LDG, Employee level and optional description; evaluate preparation defaults through BG.APPLY_DEFAULTS | Parent-only Employee create | |
| Default-inclusion category key | For ORA_PAY_BAL_ATT_DEFAULT.csv, require an evidenced category mapping including BalanceCategoryBaseName, its LDG/legislation qualifiers, BalanceCategoryEffStartDate and BalanceCategoryEffEndDate, or a separately verified supported alternative. Numeric BalanceCategoryId plus a successful category LOV match does not establish this CSV mapping. Apply the documented combined-profile date defaults when their conditions match; missing dates outside that contract or unverified qualifiers return FSM_FIELD_MAPPING_REQUIRED before preview | Preparing or retrying default-inclusion rows | |
| Default-inclusion remaining references | Establish the mapping for BalanceDimensionBaseName and AttDefBaseName with their LDG/legislation qualifiers, or prove the corresponding numeric-ID alternative for this component. Successful BalanceAttribute imports do not prove an ID-only BalanceAttributeDefault contract. The Successful Combined Child Preparation numeric-dimension variant is an evidenced alternative and does not require BalanceDimensionBaseName. A header-only template alone cannot supply missing target reference values | Preparing or retrying default-inclusion rows | |
| Export-profile fidelity | Compare the prepared row with the Developer-Supplied Default-Inclusion Mapping in ora_reference_lookups.md. Require target-specific named references and evidence for the component discriminator, grouping key, null values and explicit sentinels. accept the Successful Combined Child Preparation variant when its conditions match; do not mark an arbitrary numeric-ID-only row as matching a supported profile; report exact missing target values as FSM_FIELD_MAPPING_REQUIRED | A default-inclusion row is prepared from the supplied attribute-to-value sample | |
| Reference identity provenance | Retain the source field and evidence for each mapped category, dimension and attribute-definition value. Keep the category LOV row ID separate from BaseBalanceCategoryId; neither a display label nor a numeric AttributeId establishes a base-name field. Apply the service-V3 evidence only within the boundary documented in ora_reference_lookups.md. Return FSM_FIELD_MAPPING_REQUIRED for an unverified FSM assignment | Preparing or retrying default-inclusion rows | |
