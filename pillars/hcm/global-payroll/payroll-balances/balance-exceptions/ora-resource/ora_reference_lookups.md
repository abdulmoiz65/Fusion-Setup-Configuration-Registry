# Balance Exceptions reference lookups

All listed lookups require the active task workflow, project/run book, target
environment, and authentication checks. The harvested UI evidence is from
`BalException_RESTDetails.md` (8 October 2026). The
`scripts/resolve_balance_reference.py` adapter uses the harvested
BalanceExceptionUI source providers through a workflow-approved current UI runtime context. A user-supplied same-pod HAR captured within 24 hours may provide a candidate context after host, route, and timestamp checks; a fresh exact LDG GET must confirm it before dependent requests. Oracle's public payrollGenericLOV route did not confirm the comparison provider in cptczmdqy QA. The Payroll Generic
`PayRestName` values are internal target-pod
contracts, not public APIs or authorization for arbitrary REST calls. No direct
REST mutation is selected here; FSM import remains with `core.data-loader`.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A lookup returns a denormalized display name with the selected identifier | Reuse it for display rather than making another lookup |
| A lookup returns zero or more than one candidate | Stop with a field-specific error and preserve no guessed identifier |
| Target-pod evidence conflicts with repository-derived internal UI evidence | Stop and record a catalog mismatch; use the confirmed target-pod/FSM evidence only |
| A public Balance Exceptions LOV endpoint is requested | Oracle documents /hcmRestApi/resources/11.13.18.05/payrollGenericLOV and findByWord, but the cptczmdqy QA resolver found zero exact Current period matches through that path. The HAR's UI lookup did return Current period. Do not infer the internal UI provider works through that public path or reuse the HAR runtime context. |
| Defined balance or group ID is absent but a name is supplied | Resolve the selected LDG and comparison type first, then use the BalanceExceptionUI balance/dimension or group LOV contract. Never substitute a name, #null, or an ID from another pod. |
| The source-ID adapter is proposed | Require a current workflow context or a recent user-supplied same-pod HAR candidate. Validate the candidate with a fresh exact LDG GET before dependent lookups; never treat the HAR response itself as current ID evidence. Stop if the context is stale, wrong-host, ambiguous, or rejected. The public collection did not confirm the comparison provider in cptczmdqy QA. |
| A generic LOV row is returned | Map ResultKeyN to ResultValueN by field name and cross-check the requested DisplayAttributes; never assume a fixed position when keys are present. |
| A response is limited or hasMore is true | Fetch all pages before asserting uniqueness; use the supported text filter to narrow large balance lists. A 500-row response is not proof that the list is complete. |
| A configured-only target lookup is needed | Verify the live response and contract in the active workflow; the HAR did not exercise these providers. Do not mark a balance-variance reference ready from configuration alone. |

## Captured route and evidence boundary

The read-only LOV route captured in the HAR is `/hcmRestApi/rest/{runtime-context}/payrollGenericLOV`; its runtime context is session-specific. Oracle documents public collections at https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-payrollgenericlov-get.html and https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-legislativedatagroupslov-get.html. A read-only cptczmdqy QA call to the public generic collection yielded zero exact Current period matches in the resolver; the response row count was not retained. The HAR's UI route did return Current period, so the public path is not a verified substitute. Obtain a current context through a declared UI/service workflow before another BalanceExceptionUI lookup. The Balance Exceptions list is a separate
`/hcmRestApi/redwood/11.13.18.05/payrollGeneric/payrollGenericQuery` route with
`PayRestName=BalanceExceptionUI_BalanceExceptionVO`; it returns selected-record
display fields and is not the source of selectable balance or group LOV IDs.

The HAR confirms read-only requests and two successful Creates, but this
resource authoring does not select a mutation route. Persist only selected
IDs/codes, display labels, context, environment, and timestamp in approved
project evidence; exclude raw responses and tokens. Refresh a rejected cached
token once through core.auth and retry read-only GET only when the active
workflow authorizes that lookup.
