## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Existing template | When the user supplies a name, resolve one exact-name match first; then use the returned internal key to read the current parent and all paged shifts and breaks before update, duplicate, assignment-rule maintenance, item view, or delete. For every relevant template, compare the complete aggregate and any available Condition Builder association with the requested configuration and expected behavior; display its Suitable for reuse, Suitable for duplication, or Unsuitable classification and rationale. Offer reuse only when the complete aggregate fully matches. Require Work Pattern Code only for a Data Loader update artifact. |
| 2 | Parent lookup values | Resolve Shift Period Type, Repeat Cycle, and any Workday Definition before validating child content; use an existing Workday Definition only when its configuration and behavior fully match the request |
| 3 | Enterprise Shift candidate lookup | Only for a selected flow that supports Enterprise Shifts, search for candidate Enterprise Shifts when details are supplied without a selection. If a complete match exists, recommend it; do not select a candidate automatically |
| 3.1 | Enterprise Shift selection | Select one complete match automatically. Only when multiple complete matches exist, present all of them and stop for the user's selection. When no complete match exists, continue using supplied local times without prompting for an Enterprise Shift. Then resolve any selected shift before validating cycle coverage, overlap, and duration |
| 3a | New Template correlation | Allocate a unique Data Loader-only WorkPatternTemplateId correlation value for every new template before associating new Shift rows; it is not a Fusion-generated Work Pattern Code or an existing Fusion record identifier |
| 3b | New Shift correlation | Allocate a unique whole-number Data Loader-only WorkPatternShiftId correlation value for every new Shift before associating any new child Break rows |
| 3c | Data Loader submission source | Submit a validated Work Pattern Templates DAT source through core Data Loader. The loader creates the immutable ZIP internally; do not submit that ZIP as the source input. |
| 4 | Break lookup values | Resolve each Break Type, attach each Break to its intended Work Pattern Shift, and derive the Shift's unpaid-break total before validating timing, totals, and overlap |
| 5 | Assignment-rule values | Resolve Selection Type, enterprise, or the type-specific rule object before checking duplicate pairs |

## Dependency Classification

| Result Category | When Used | Can Run Lookup/Create? |
|---|---|---|
| Satisfied | The required identifier and its verified business meaning are already available and consistent | No lookup is required; this file never creates related setup |
| Lookup | A documented read-only resolver can identify the value | Run the named lookup only |
| Verify | A selected value must be re-read and checked for current eligibility such as active status | Run the named lookup only |
| Blocked | A mandatory value is missing, ambiguous, inactive, inconsistent, or cannot be resolved | No; stop and request correction |
