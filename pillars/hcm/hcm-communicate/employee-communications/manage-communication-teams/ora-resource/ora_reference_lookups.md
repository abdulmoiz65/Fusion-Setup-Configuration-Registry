# Manage Communication Teams Reference Lookups

The `communicateUICommTeams` service exposes these child accessors: `CampaignPurposes`, `TeamMembers`, `SenderProfiles`, `EligibilityProfiles`, `HCMLists`, `ContactPreferences`, `Templates`, `MsTeamsBots`, and `SlackApps`, with create enabled for the root and those child accessors. The REST child resource for contact preferences is `contactPreferences`; use the current generated Data Loader `ContactPreferences` worksheet for loader submission. That worksheet maps `ChannelTypeCode`, `ContactPreferenceOrder`, and `ContactPreferenceTypeCode` with the parent `TeamId`. These REST child routes apply only when the target capability check confirms the registered business object and usable current metadata. Lookup paths below resolve referenced child values only.

Use `{version}` for the HCM REST resource version. When the requester does not supply a version, set `{version}` to `latest`.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A setup-data import is evaluated | Run resolve_communication_team_import_route first. When the registered communicateUICommTeams capability is usable, use the REST Data Loader route; otherwise use the current FSM task-export package and its ASM_SETUP_CSV_METADATA.xml. |
| A top-level create or verification is evaluated | Use find_team_by_exact_name_in_export against the current task-level CSV baseline |
| A parent or child verification is requested after a REST load | Resolve the TeamId by exact name from the fresh task export, then call read_communication_team_with_children; do not use communicationTeamsLOV |
| A child association is requested with FSM fallback | Stop: the FSM task-CSV route has no child-association contract. |
| A child association is requested with confirmed REST capability | Use the documented LOV as a read-only dependency lookup, then populate the corresponding current generated Data Loader child sheet with its exact `TeamId` parent reference |
| A REST parent team create succeeds | Read the parent with children, retain CreatedBy and CreatedByDisplayName, run find_team_member_by_word using the recorded creator, and prepare one TeamMembers row in the separate child archive. Stop the child archive on zero or multiple exact worker matches. |
| A first REST team create omits Campaign Purposes or Templates | After the parent TeamId is resolved, resolve only enabled `ORA_GENERAL` and `ORA_GET_RESPONSE` through resolve_campaign_purposes_from_communicate_lookups, then prepare those Campaign Purpose rows and one Basic, Advanced, and HTML Blank Templates row; do not apply either default for FSM. Submit only after the resulting exact child archive is separately approved. |
| An internal ADF operation or internal sender-profile REST call is discovered | Do not use it as a customer API |
| A documented LOV is invoked | Use it only as a read-only dependency lookup and do not infer a submitted child-association mapping |
| Campaign Purposes are requested or defaulted | Delegate `ORA_IRC_EMP_CAMP_PURPOSE` to Manage Communicate Lookups through the Common Lookup view; require exact enabled codes and do not use the UI `rv` Common Lookup route. |
| A Contact Preference channel is requested | Delegate `ORA_HCO_CHANNEL_TYPE` to Manage Communicate Lookups through the Common Lookup view; require exact enabled `ORA_EMAIL` for EMAIL or `ORA_SMS` for SMS and do not use the UI `rv` Common Lookup route. |
| Another common lookup is requested | Use `fscmRestApi/resources/{version}/commonLookupsLOV`; default `{version}` to `latest` |
| A Slack App or Microsoft Teams Bot lookup is requested | Use the documented `hcmRestApi/resources/{version}/communicateUISlackAppsLOV` or `communicateUIMsTeamsBots` endpoint; default `{version}` to `latest` |
| A Sender Profile, Slack App, or Microsoft Teams Bot child association is requested | Run get_communication_team_child_feature_status first; use its exact setting result only for readiness and route any enablement request to Manage External Integrations |
| A Contact Preference is requested with confirmed REST capability | Run verify_contact_preference_profile_option first. Only when it resolves to `Y`, resolve the channel through `ORA_HCO_CHANNEL_TYPE` with Manage Communicate Lookups, resolve the contact type through its documented EMAIL_TYPE or PHONE_TYPE lookup, and use the generated ContactPreferences worksheet; do not substitute a REST child payload for the Data Loader child row |
| A child-association verification is requested | Use read_communication_team_with_children after the fresh export resolves the exact parent TeamId |
| A supplied lookup path omits or varies the hcmRestApi/resources/{version} prefix | Preserve the supplied form; do not synthesize missing path segments |

## Candidate Value Listing

When the requester asks for available, suggested, or top values, call the relevant documented lookup and return at most five results in service response order. State when fewer than five values are returned. Candidate listing is read-only and does not select a value; before a later load, rerun the exact resolver and require one exact match.

For a new-team request that asks for all possible LOVs, enumerate every applicable documented lookup before authoring: `ORA_HCO_CAMP_TEAM_TYPE`, `ORA_IRC_CAMP_COMM_TEAMS_STATUS`, Campaign Purposes from `ORA_IRC_EMP_CAMP_PURPOSE` through Manage Communicate Lookups, `workersLov`, sender profiles, eligibility profiles, HCM lists, Contact Preference channels from `ORA_HCO_CHANNEL_TYPE` through Manage Communicate Lookups, `EMAIL_TYPE`, `PHONE_TYPE`, Basic/Advanced/HTML/Express templates, Slack Apps, and Microsoft Teams Bots. Paginate where the service reports more values and retain service order. Implicit selections are `ORA_GENERAL` and `ORA_GET_RESPONSE` only for CampaignPurposes and, for a first REST create with omitted Templates, one exact active `Blank` template for each Basic, Advanced, and HTML editor type. An explicit list or empty selection overrides either default.
